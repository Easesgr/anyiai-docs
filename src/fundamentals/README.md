## 从一个具体问题开始：模型怎么区分两个“苹果”？

计算机本身只能做数值加减乘除，无法直接读取字符串。当我们把两句话输入给语言模型：

1. “苹果发布了新款手机。”
2. “我买了一箱红富士苹果。”

在自然语言中，这两个“苹果”一个是科技公司，一个是水果。计算机要想处理它们，必须把字符一步步转换成包含了语境信息的数字向量。这个转换过程主要经历三个阶段：**离散 Token 编号**、**静态输入嵌入**，以及**带上下文的隐藏状态**。

理解这三个阶段的变化，是掌握大语言模型计算原理的起点。

---

## 文本处理的三步变换：Token、嵌入与隐藏状态

![从离散 Token 到输入嵌入与动态上下文表示的演化机制](/images/content-rebuild/914738cd43afa552/fig-1.png)

### 1. 离散 Token（分词切分）
文本输入模型的第一步是分词。分词器（Tokenizer）按照预先训练好的词表，把一整段文字切分成一个个子词片段（Token），并给每个片段分配一个固定的整数编号（Token ID）。

例如，“苹果”在词表中可能对应的编号是 `1024`。在这一步：
- 编号只是词表里的索引，数值本身的大小没有任何代数意义（编号 1024 并不比编号 512 “大”一倍，两者之间也没有大小距离可言）。
- 两个词如果不相同，在离散表示下就是完全正交的独立符号。

### 2. 静态输入嵌入（Embedding 查表）
有了编号之后，模型会通过一个矩阵查找（Embedding Lookup），给每个编号分配一行固定维度的稠密向量。

假设嵌入维度是 768，模型内部就有一张行数为词表大小、列数为 768 的大表格。查表操作本质上就是根据编号把对应的那一行取出来：
- 在这个阶段，词表中编号为 `1024` 的向量是完全固定不变的。
- 无论是在“苹果手机”还是“红富士苹果”里，只要编号相同，查出来的初始向量就一模一样。
- 像早期著名的 Word2Vec 就是典型的静态词向量，它无法在初始向量层面解决一词多义的问题。

### 3. 上下文隐藏状态（注意力融合）
为了让“苹果”融入周围词汇的含义，模型需要通过多层注意力机制（Attention）和前馈神经网络（FFN）。

在注意力计算中，当前词的向量会与前后其他词的向量进行点积打分，根据相关性把周围词的特征加权融合进来：
- 在第一句话中，“苹果”融合了“发布”“手机”的信息，向量方向偏向电子产品；
- 在第二句话中，“苹果”融合了“买”“红富士”的信息，向量方向偏向水果食物。

经过多层网络计算后输出的向量，才被称为包含语境的“隐藏状态（Hidden State）”。只有到了这个阶段，模型才真正拥有了区分多义词的数值依据。

### 最小数值验证算例

为了直观看到这个过程，我们用一个简化的小矩阵做一次手工验算。

假设词表只有 4 个词（$|V|=4$），向量维度只有 2 维（$d=2$）。预先设定的嵌入矩阵为：
$$E = \begin{bmatrix} 1.0 & 0.0 \\ 0.0 & 1.0 \\ 0.5 & 0.5 \\ -1.0 & 0.0 \end{bmatrix}$$

如果输入两个词的编号序列为 $[0, 1]$：
1. **查表得到静态输入嵌入**：
   - 词 0 的向量为 $x_0 = [1.0, 0.0]$
   - 词 1 的向量为 $x_1 = [0.0, 1.0]$
   此时直接计算它们的点积：$1.0 \times 0.0 + 0.0 \times 1.0 = 0$。两向量相互垂直，词 0 里面不包含词 1 的任何信息。

2. **经过最简注意力融合**（假设查询和键投影矩阵均为单位阵，且不加因果掩码）：
   - 计算相似度得分并经过归一化，假设得到的注意力权重分别为 0.6（自身）和 0.4（对方）；
   - 那么词 0 输出的新隐藏状态变为：
     $$h_0 = 0.6 \times [1.0, 0.0] + 0.4 \times [0.0, 1.0] = [0.6, 0.4]$$
   此时输出的 $h_0$ 不再是纯粹的自身特征，而是已经包含了上下文信息的动态隐藏状态。

## 为什么是 Transformer：三种序列建模方式的权衡

在深度学习发展过程中，研究人员尝试过多种让序列中各个词发生交互的方式。架构演进的核心权衡在于两点：**两个词之间的信息传递需要跨越多少步（步长）**，以及**训练时能否利用硬件并行计算**。

![RNN、CNN 与 Transformer 在序列建模步长与并行度上的物理差异](/images/content-rebuild/914738cd43afa552/fig-2.png)

* **时序循环网络（RNN）**：
  RNN 像一个串行接力跑队伍，每次读入一个词，把当前信息和上一步遗留下来的隐状态结合，计算出新的隐状态：$h_t = f(h_{t-1}, x_t)$。
  - **步长问题**：如果序列长度为 $N$，第 1 个词的信息传到第 $N$ 个词必须经历 $N$ 步递推。距离越远，中间经过的非线性激活和矩阵乘法越多，容易发生信息遗忘或梯度不稳定。
  - **并行瓶颈**：计算第 $t$ 步时必须等待第 $t-1$ 步完成，在时间维度上无法做大规模矩阵并行训练，无法高效利用现代 GPU 算力。

* **局部卷积网络（CNN）**：
  CNN 使用固定尺寸的卷积核在文本上滑动扫描。
  - **并行优势**：每个窗口的计算相互独立，在整个文本上可以并行展开。
  - **步长问题**：单层卷积只能覆盖局部窗口（如 3 到 5 个词）。要想让第 1 个词与相距很远的第 $N$ 个词发生交互，必须堆叠多层卷积逐步扩大感受野，长距离依赖仍然需要多层间接传递。

* **注意力机制网络（Transformer）**：
  Transformer 完全舍弃了时序循环和卷积，直接通过注意力打分矩阵建立词与词之间的关联（双向编码器允许序列任意两词互算，自回归解码器则通过因果掩码单向关注历史词）。
  - **交互步长为 1**：允许关注的任意两个位置在一层内即可通过点积直接交互，消除了循环网络中多步非线性递推带来的传递衰减。
  - **训练高度并行**：在训练阶段，输入序列一次性送入模型，各位置的注意力和前馈计算可通过矩阵乘法并行执行。
  - **代价与瓶颈**：全序列各位置间注意力矩阵的计算量和中间激活开销随序列长度呈现二次方 $O(N^2)$ 增长。输入序列越长，计算量与显存占用上升越快。

## 本专栏的学习方法：用小算例和代码验证

![基础知识验证规范：数据流向、张量形状与可复现推导](/images/content-rebuild/914738cd43afa552/fig-3.png)

为了避免只停留在抽象概念上，本专栏在拆解每一个核心算子时，均遵循清晰的验证步骤：

1. **交代前置假设**：明确输入张量的形状、维度定义以及当前处于预训练、微调还是推理生成阶段。
2. **追踪数据流动**：标出张量在每一层变换中的维度变化（例如输入从三维形状 $[B, N, D]$ 拆分为多头形状 $[B, H, N, D/H]$）。
3. **小矩阵数值手算**：给出不依赖大型框架的最小算例或纯 Python 代码片断，通过控制台或手算即可复现结果。
4. **指出工程边界**：说明该技术在上下文窗口过长、显存不足或算力受限时的实际开销与性能边界。

要了解注意力机制更深入的矩阵推导与因果掩码实现，可以继续阅读专栏的第一篇核心文章：[Transformer架构](/fundamentals/transformer-arch.md)。

## 基础原理如何连接后续工程

大模型工程落地中的许多性能瓶颈与设计模式，根源都在于底层的计算特征：

* 自注意力的 $O(N^2)$ 计算瓶颈以及解码时的逐步串行生成，直接催生了 KV Cache 缓存技术与 PagedAttention 显存管理机制，这决定了 [AI 工程架构](/architecture/README.md) 中的批处理吞吐与显存调度策略；
* 长文本带来的显存压力与注意力稀释，促使工程师在 [上下文工程](/frontier/context-engineering/README.md) 中研究精确截断、动态压缩与结构化 Prompt 注入；
* 语言模型基于概率采样输出的特点，决定了它在复杂任务中不能只靠单次回答，必须配合确定性程序与外部系统，进而演化出 [AI Workflow](/frontier/ai-workflow/README.md) 与 [Agentic RAG](/frontier/agentic-rag/README.md) 体系。

只有先搞清楚张量如何输入、计算并在层间流动，后续面对高并发推理、长上下文管理和系统编排时，才能做出符合物理规律的工程权衡。
