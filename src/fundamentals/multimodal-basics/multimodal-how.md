如果给大语言模型（LLM）一张小狗在草地上接飞盘的照片，并附带提问“这只狗在干什么？”，模型最终输出文本“这只狗正在草地上跃起接飞盘”。这个过程究竟是如何实现的？

大语言模型本质上只能接收离散 Token 对应的数值向量序列，无法直接读取图片的 RGB 像素点。而像 [CLIP 是什么](/fundamentals/multimodal-basics/clip.md) 中介绍的传统双塔判别模型，其目标是计算图片与文本的匹配相似度，本身并不包含逐字生成文本的解码器。为了让大语言模型具备看图说话的能力，现代生成式视觉语言模型（Vision-Language Model，VLM，例如 LLaVA、Qwen-VL 等）采用了模块化串联架构：先将图片转为[视觉 Token](/fundamentals/multimodal-basics/visual-token.md)，再通过投影层调整维度与向量空间，最后与文本提示词拼接成统一序列，交由自回归大模型生成解答。

![多模态大模型端到端核心数据流与三段式骨架概览](/images/content-rebuild/a5ffe6be59584aa2/cover.png)

## 现代多模态大模型的三段式结构

目前主流的生成式多模态模型并没有推倒语言模型重新训练，而是将成熟的视觉抽取网络与成熟的因果语言模型结合起来。整个系统由三个核心部分协同工作：

1. **视觉编码器（Vision Encoder）**：通常使用在大规模图文数据上预训练好的视觉 Transformer（如 ViT-L/14 或 SigLIP）。它的输入是固定分辨率的图片像素矩阵，输出是保留了图像局部特征的向量序列。
2. **连接器 / 投影层（Connector / Projector）**：负责跨模态的特征映射。视觉编码器抽取的特征向量维度（例如 1024 维）与语言模型隐层维度（例如 4096 维）通常不一致，向量的取值范围和统计分布也不同。投影层的作用就是将视觉特征投影转换到大模型词表向量所在的隐空间中。
3. **大语言模型基座（LLM Backbone）**：负责根据上下文自回归生成回答（如 LLaMA、Qwen 等开源基座）。对 LLM 而言，经过投影层处理后的视觉向量与用户输入的文本 Token 嵌入在结构上完全一样，均以序列形式输入自注意力层，参与后续的逐字推理计算。

![判别式双塔架构与生成式自回归多模态架构的机理对比](/images/content-rebuild/a5ffe6be59584aa2/fig-1.png)

这种设计的核心优势在于工程可复用性：无需从头耗费海量算力预训练一个千亿参数的多模态网络，而是充分复用语言模型强大的语言理解与因果推理能力。

## 投影层的三种主流设计

投影层是连接视觉编码器与大语言模型的转换器。若直接将视觉编码器输出的张量硬塞给 LLM，两者的数值范围与分布不匹配会导致模型注意力混乱。目前工程实践中主要有三类实现机制：

![三种主流视觉投影层的结构与计算方式对比](/images/content-rebuild/a5ffe6be59584aa2/fig-2.png)

### 1. 线性投影层（Linear Projector）
最直接的连接方式是一个可学习的线性变换矩阵 $W \in \mathbb{R}^{d_v \times d_l}$：

$$H_v = Z_v W + b$$

其中 $Z_v$ 是视觉编码器的输出特征序列，$d_v$ 为视觉特征维度（如 1024），$d_l$ 为语言模型隐层维度（如 4096）。早期的 LLaVA-1.0 便采用了单层线性投影。该方案参数量极小、计算速度快，但仅能表达两个空间之间的仿射变换，拟合能力相对有限。

### 2. 多层感知机（MLP Projector）
LLaVA-1.5 及后续许多模型引入了带有非线性激活函数的多层感知机（通常为两层或三层）：

$$H_v = \text{GELU}(Z_v W_1 + b_1) W_2 + b_2$$

通过加入 GELU 等非线性激活层，网络能够学习更复杂的跨模态对应关系，在图表文字识别、细粒度物体属性判断等复杂场景下，特征对齐效果明显优于单层线性矩阵。

### 3. 基于交叉注意力的感知重采样器（Cross-Attention / Resampler）
线性投影与 MLP 采用的是“逐点映射”，输入多少个网格块（Patch），输出给语言模型的就是多少个视觉 Token。例如一张图被切分成 576 个 Patch，送入 LLM 的就是 576 个 Token。如果在一个会话中输入多张图或高分辨率图，视觉 Token 会迅速占满语言模型的上下文窗口。

Flamingo（Perceiver Resampler）与 BLIP-2（Q-Former）采用了一组可学习的固定查询向量（Learned Queries，数量通常设为 32 或 64 个）。通过让这组 Query 向量与视觉编码器的全量特征计算交叉注意力（Cross-Attention），将原本成百上千个视觉特征压缩并提炼为固定数量的 Token：

$$\text{Output} = \text{Softmax}\left(\frac{Q K^T}{\sqrt{d}}\right) V$$

这种设计的优势在于输出 Token 长度固定且简短，大幅减轻下游大模型的推理显存负担；代价是可能会压缩或忽略图片中的部分细小几何信息。

## 端到端张量变化全链路推导

为了展示数据如何在各组件之间流动，我们以一个具体的尺寸配置进行全链路张量推导：
- 输入图像尺寸：$336 \times 336$ 像素，RGB 3 通道
- 视觉编码器：Patch 大小为 $14 \times 14$，视觉隐层维度 $d_v = 1024$
- 连接器：两层 MLP，将维度由 $1024$ 变换至 $4096$
- 语言模型基座：模型隐层维度 $d_l = 4096$，用户输入提问“这只狗在干什么？”，分词后得到 12 个文本 Token

![输入图像到自回归 Prefill 的张量维度变化全链路推导](/images/content-rebuild/a5ffe6be59584aa2/fig-3.png)

### 步骤 1：图像切块与视觉特征提取
输入图像被规则切分成高宽方向各 $336 / 14 = 24$ 个小块，共计 $24 \times 24 = 576$ 个 Patch。每个 Patch 展平后为 $14 \times 14 \times 3 = 588$ 维向量，先经 ViT 的 Patch Embedding 线性层投射为 1024 维。

加上位置编码后，输入 ViT 堆叠的 Transformer 层进行特征提取。去除分类头后，输出视觉特征张量形状为：

$$Z_v \in \mathbb{R}^{1 \times 576 \times 1024}$$

### 步骤 2：投影层维度变换
张量 $Z_v$ 送入两层 MLP 进行变换：

$$H_v = \text{MLP}(Z_v) \in \mathbb{R}^{1 \times 576 \times 4096}$$

输出张量 $H_v$ 包含了 576 个向量，每个向量维度与语言模型的隐层维度 4096 完全对齐。这些向量被称为**视觉 Token 嵌入**。

### 步骤 3：文本分词与词嵌入查找
用户输入的提示词被分词器解析为 12 个 Token ID：

$$\text{input\_ids} = [t_1, t_2, \dots, t_{12}]$$

通过语言模型自带的词嵌入表（Embedding Lookup Table）检索，得到文本嵌入张量：

$$H_t \in \mathbb{R}^{1 \times 12 \times 4096}$$

### 步骤 4：序列物理拼接（Concatenation）
在模型的输入模板中，系统提示词与输入图片占位符 `<image>` 之间按既定位置排列。模型在底层直接将视觉嵌入与文本嵌入沿序列长度维度（维度 1）进行拼接：

$$H = [H_v ; H_t] \in \mathbb{R}^{1 \times (576 + 12) \times 4096} = \mathbb{R}^{1 \times 588 \times 4096}$$

拼接后的单一张量 $H$ 直接作为序列输入送入大语言模型。以下是演示该流程的 PyTorch 最小代码实现：

```python
import torch
import torch.nn as nn

# 设定超参数
batch_size = 1
num_patches = 576       # 336x336 切为 14x14 patch，共 24x24=576
vision_dim = 1024       # ViT 输出特征维度
llm_dim = 4096          # LLM 隐层特征维度
text_seq_len = 12       # 文本输入 Token 数

# 1. 模拟视觉编码器输出
z_v = torch.randn(batch_size, num_patches, vision_dim)

# 2. 定义两层 MLP 投影层
projector = nn.Sequential(
    nn.Linear(vision_dim, llm_dim),
    nn.GELU(),
    nn.Linear(llm_dim, llm_dim)
)

# 3. 视觉特征维度变换与对齐
h_v = projector(z_v)  # 形状: [1, 576, 4096]

# 4. 模拟文本嵌入向量
h_t = torch.randn(batch_size, text_seq_len, llm_dim)  # 形状: [1, 12, 4096]

# 5. 跨模态拼接成单一输入序列
h_combined = torch.cat([h_v, h_t], dim=1)  # 形状: [1, 588, 4096]

print("视觉特征输出形状:", z_v.shape)
print("投影后视觉 Token 形状:", h_v.shape)
print("拼接输入 LLM 序列形状:", h_combined.shape)
assert h_combined.shape == (1, 588, 4096)
```

## 预填充与自回归生成机制

当拼接后的张量送入语言模型后，模型的推理分为预填充阶段（Prefill）与自回归解码阶段（Decode）。

![预填充 Prefill 与逐字自回归 Decode 阶段的因果注意力机制](/images/content-rebuild/a5ffe6be59584aa2/fig-4.png)

### 1. Prefill 阶段：构建全局 KV Cache
在 Prefill 阶段，模型一次性并行处理由 576 个视觉 Token 与 12 个文本 Token 构成的完整序列（共 588 个位置）。

在因果语言模型中，文本部分遵循下三角因果注意力遮罩（Token $i$ 只能关注 $i$ 及之前的位置）。对于视觉 Token 区域，不同架构的掩码设计有所不同：部分模型（如前缀掩码架构）允许视觉 Token 之间双向全可见，而部分模型（如直接复用因果解码底座的实现）则统一沿用下三角因果掩码。但无论何种实现，位于后方的文本 Token 均能完整看到前方的全部 576 个视觉 Token，文本 Token 的 Query 在计算点积时可以直接对图像各区域特征分配注意力权重。

在 Prefill 计算完成后，这 588 个 Token 在所有 Transformer 层的 Key 和 Value 向量全部计算完毕并存入显存，构建出初始的 **KV 缓存（KV Cache）**。

### 2. Decode 阶段：视觉 Token 作为前置上下文常驻显存
进入自回归解码后，模型预测出第一个文本词 $y_1$。在生成下一个词 $y_2$ 时，只有 $y_1$ 对应的单个向量作为 Query 输入模型，它直接结合显存中已有的 588 个位置的 Key 和 Value 计算注意力，无须重新计算历史 Token 的特征。

这表明：**在推理阶段，视觉 Token 与文本 Prompt Token 的地位完全一致，全程占用 KV Cache 显存并参与每一步矩阵相乘。** 一张包含 576 个 Patch 的图片，对推理显存和上下文长度的占用，等同于在会话中输入了一篇 576 个词的长提示词。有关 Token 在注意力计算中的显存开销，可参考 [Token 是什么？如何计算和控制 Token 数量？](/interview/llm-interview/token-basics.md)。

## 为什么不能简单截断或补零？特征空间匹配的原理

一个常见的工程疑问是：既然投影层的目的主要是把 1024 维变成 4096 维，为什么不能直接在 1024 维后面补 3072 个 0，或者将大模型的输入层强行做截断？

这里需要区分“向量的形状尺寸”与“向量数值代表的特征空间分布”：

![维度直接对齐与投影层流形几何变换的本质区别](/images/content-rebuild/a5ffe6be59584aa2/fig-5.png)

1. **语义特征空间不一致**：视觉编码器经过对比学习或分类任务预训练，其输出向量的特征协方差结构与主成分方向，与语言模型经过大规模文本自回归训练得到的词表嵌入完全不同。即使维度强行对齐，语言模型内部权重也无法解析未经映射的视觉特征语义。
2. **破坏层归一化与注意力线性投影**：大模型各层输入均包含层归一化（如 RMSNorm 或 LayerNorm），并由线性变换矩阵 $W_Q, W_K, W_V$ 将隐状态投影至各注意力头。若机械补零到 4096 维，全零分量会导致 RMSNorm 的均方根分母异常偏小，前 1024 维特征被异常拉伸放大；同时，$W_Q, W_K$ 的权重依赖全部 4096 维特征的协同输入，缺失对应维度的信息会导致投影后的 Query 和 Key 严重失真，无法形成有效的注意力分配。

投影层的本质任务是进行**参数化的特征空间对齐**：通过仿射变换与非线性激活，将视觉特征向量映射到大语言模型隐层所适应的数值范围与语义方向中，使视觉 Token 能与文本 Token 产生正常的注意力交互。

## 多模态模型的两阶段训练策略

多模态大模型的权重并非从零一次性端到端训练完成。为了兼顾训练稳定性并降低算力开销，业界广泛采用两阶段递进训练策略：

![多模态大模型两阶段训练策略与参数冻结状态对照](/images/content-rebuild/a5ffe6be59584aa2/fig-6.png)

### 第一阶段：特征对齐预训练（Feature Alignment Pre-training）
- **训练目标**：仅教会投影层（Projector）做模态之间的特征映射，不破坏语言模型已有的语言规律，也不引入复杂的逻辑推理任务。
- **数据来源**：大规模图像-文本配对描述数据（如图像标题 Image Caption 数据集）。
- **参数冻结状态**：**冻结**预训练好的视觉编码器与 LLM 基座，**仅更新**投影层参数。
- **损失函数计算**：对整段描述文本计算自回归交叉熵损失（Cross-Entropy Loss）：

$$\mathcal{L} = - \sum_{i=1}^{L} \log P(x_i \mid X_v, x_{<i})$$

通过这一阶段，投影层掌握了如何把整幅图像的语义特征转换为大模型容易读取的向量表征。

### 第二阶段：视觉指令微调（Visual Instruction Tuning / SFT）
- **训练目标**：让模型具备理解复杂指令、根据图片细节回答问题、多轮对话以及逻辑推理的能力。
- **数据来源**：高质量的多模态问答（VQA）、目标定位标注、多轮对话数据集。
- **参数冻结状态**：视觉编码器通常继续保持冻结（或仅在需要适应特定分辨率时解冻最后几层），**同时解冻投影层与 LLM 基座**（可采用全量微调或 LoRA 微调）。
- **损失函数计算**：依然使用自回归交叉熵损失，但**只对助手的回答部分（Assistant Response）计算梯度**。系统提示词、图片视觉 Token 以及用户提问区域全部被遮罩（Mask），不计入损失计算。

经过这一阶段微调后，模型不仅能识别输入图片，还能根据用户的复杂自然语言指令输出条理清晰的文本解答。
