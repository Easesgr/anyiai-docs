在计算机中，“模态”（Modality）是指信息的物理来源与编码形式。我们日常接触的自然语言文本、数码照片、麦克风录制的音频波形，分别来自完全不同的采集设备，也遵循互不兼容的数据结构。

单模态模型只处理单一类型的数据，例如纯文本的大语言模型只接收和生成字符序列，传统计算机视觉模型只对像素网格做卷积或自注意力运算。**多模态模型（Multimodal Model）**则是通过统一的计算架构，联合处理、对齐或转换两种及以上不同模态信息的人工智能系统。

以一个贯穿任务为例：我们手头有一张“金毛犬趴在绿色草地上”的数码照片，以及一句文本“草地上有一只金毛寻回犬”。多模态模型能够完成以下工作：
1. **跨模态检索**：输入这段文字，从百万张图库中精准挑出这张金毛犬照片；
2. **视觉问答（VQA）**：输入这张照片并提问“图中的狗在做什么？”，模型输出文本“趴在草地上”；
3. **图像描述（Image Captioning）**：仅输入照片，模型自回归生成完整描述文本。

要让计算机同时理解像素和单词，必须解决底层数据结构上的根本差异。

## 数据异构性：为什么不能直接把像素和文字拼在一起？

计算机底层的多模态处理，本质上是不同分布张量之间的映射转换。文本与视觉信号在信息密度、离散程度与局部冗余性上存在显著差异。

### 1. 离散符号与连续网格的物理差异

- **文本数据（离散符号序列）**：人类语言由高度抽象的离散符号构成。在模型内部，每个词或子词对应词表中的一个离散整数 ID（Token ID），词表规模通常在 32,000 到 128,000 之间。文本的信息密度极高，替换单个词（例如将“草地上的金毛”改成“餐桌上的金毛”），全局语义会发生颠覆性变化。
- **图像数据（连续密集网格）**：自然图像是连续光电信号在二维空间上的规则采样。一张常规的 $224 \times 224$ 像素 RGB 图像，包含 $224 \times 224 \times 3 = 150{,}528$ 个取值在 $[0, 255]$（或归一化为 $[0.0, 1.0]$）的连续实数。单个像素的细微明暗变化（如数值从 120 变为 121）几乎不携带独立语义。图像的语义隐藏在边缘、纹理和物体的全局空间拓扑中，相邻像素之间具有极强的统计相关性和局部冗余。

下表直观对比了两者的数学属性：

| 维度 | 自然语言文本 | 自然视觉图像 |
| :--- | :--- | :--- |
| **基本单元** | 离散符号 ID（Token） | 连续实数值（RGB 亮度/色度采样） |
| **信息密度** | 极高（高度抽象的语义提炼） | 极低（单像素语义弱，整体存在空间冗余） |
| **拓扑结构** | 一维顺序序列 | 二维空间网格（视频为三维时空网格） |
| **微小扰动敏感度** | 高（单个符号变动往往颠覆语义） | 低（单个像素扰动通常不改变物体宏观属性） |
| **语义承载方式** | 显式符号组合 | 空间像素强度的隐式统计模式 |

![文本与图像的数据异构性对比：离散符号与密集网格](/images/content-rebuild/239ac048c746c074/fig-1.png)

上图分解了文本符号序列与图像连续网格的内部差异：左侧文本是沿阅读顺序排列的高语义密度离散点，右侧图像则是充满局部相关的密集采样矩阵。这种数据格式与信息密度的天然冲突，决定了我们无法在输入层做简单的数值拼接。

### 2. 原始数值拼接为何不可行？

在深度学习早期，有初学者尝试将展平后的图像像素向量与文本的 One-Hot 向量直接拼接成一个超长向量。这种做法在计算和优化上存在三道无法逾越的障碍：
1. **量纲与度量空间失衡**：文本词表 One-Hot 向量是高度稀疏的二进制指示变量，任意两个不同词向量的欧氏距离恒为 $\sqrt{2}$、点积为 0；图像像素则是密集的连续数值。直接拼接会导致特征量纲严重混乱，数值优化极难收敛。
2. **维度与信息量严重不匹配**：文本与图像的信息密度极不对称。若将 10 个词按离散 Token ID 标量拼入，仅 10 维且缺乏连续度量意义，会被 $150{,}528$ 维连续像素完全淹没；若将 10 个词分别展开为 One-Hot 向量拼接，则会瞬间引入数十万维（如 $10 \times 32{,}000 = 320{,}000$ 维）极端稀疏的特征。无论哪种直接拼接方式，物理维度都脱离了真实信息密度，模型通过无归纳偏置的全连接层学习时，极易拟合到背景像素的表面统计噪声，难以捕捉高密度的文本语义。
3. **缺乏对应的结构归纳偏置**：图像理解需要空间邻域关联与平移不变性（通常由卷积核或二维分块注意力建模），文本处理需要序列因果上下文建模。粗暴拼接抹平了空间几何结构与文本时序结构，无偏置的网络结构需要极度庞大的数据量才可能收敛。

因此，多模态模型的首要共识是：**原始数据必须先由模态专用的编码器提取高阶特征，转换为抽象向量，再进行后续的融合与对齐。**

## 融合架构的演进：早期融合、晚期融合与中间嵌入对齐

按照信息融合发生在计算图的哪一阶段，多模态系统的演进主要经历过三种范式：

![早期融合、晚期融合与中间嵌入对齐的拓扑结构对比](/images/content-rebuild/239ac048c746c074/fig-2.png)

上图清晰展示了三种架构的计算流向：

### 1. 早期融合（Early Fusion / 特征级拼接）
在各模态经过浅层特征提取后，立即将特征向量在通道或维度上物理拼接（例如图像提取 128 维特征，文本提取 128 维特征，拼接为 256 维向量），后续所有层全部为联合计算网络。
- **局限**：浅层特征依然带有强烈的模态私有格式印记。当某个模态受噪声干扰或缺失输入时，拼接向量的数值分布发生大幅偏移，容易导致后续联合网络整体性能骤降。

### 2. 晚期融合（Late Fusion / 决策级加权）
彻底解耦两种模态的推理路径。视觉模型只输入图像，输出分类概率分布 $P(y|I)$；文本模型只输入文本，输出分类概率分布 $P(y|T)$。最终通过加权平均或投票规则得出联合预测：
$$P(y|I, T) = \alpha P(y|I) + (1 - \alpha) P(y|T)$$
- **局限**：工程上易于解耦和维护，但完全切断了跨模态的细粒度交互。例如在视觉问答中，如果问题是“左边戴草帽的男孩手里的气球是什么颜色”，文本模型脱离图像无法解析指代对象，图像模型脱离文本也无法聚焦局部气球，决策级加权无法支撑复杂的条件推理。

### 3. 中间嵌入对齐（Intermediate Alignment）
现代多模态模型的基石方案：文本与图像分别由深度的专用主干网络（如 Vision Transformer 与 Transformer 文本编码器）提取高阶语义嵌入，随后通过投影层（Projector）映射到统一度量空间，或者利用交叉注意力层（Cross-Attention）让两种模态在隐藏层进行深层特征调制。

## 多模态核心任务谱系

输入模态的组合形式与输出空间的数学定义，决定了多模态任务的具体工程实现。

![多模态任务谱系：按输入输出维度划分的分类矩阵](/images/content-rebuild/239ac048c746c074/fig-3.png)

结合上图的任务坐标系，我们梳理四类典型应用：

### 1. 跨模态检索（Cross-Modal Retrieval）
- **输入**：一种模态作为查询（如文本），另一种模态的候选集合（如海量图像库）。
- **输出**：成对相似度标量得分。
- **核心机制**：双塔度量学习。系统不需要逐字生成语言，而是将图文分别映射到同一维度的超球面上，让配对图文的向量夹角尽可能小，非配对样本夹角尽可能大。典型代表即为 [CLIP](/fundamentals/multimodal-basics/clip.md)。

### 2. 图像描述生成（Image Captioning）
- **输入**：单张图像。
- **输出**：离散自然语言词元序列。
- **核心机制**：条件自回归语言建模。视觉特征被转换为引导前缀或键值缓存（KV Cache），驱动语言解码器按概率逐词生成叙述文本。

### 3. 视觉问答（Visual Question Answering, VQA）
- **输入**：图像与针对图像的自然语言提问。
- **输出**：对应答案。
- **核心机制**：早期系统常将 VQA 简化为固定词表上的分类任务；现代多模态大模型（MLLM）统一将其实现为多模态提示工程下的自回归文本生成，模型在注意力计算中同时兼顾图像区域特征与问题上下文。

### 4. 跨模态生成（如文生图 Text-to-Image）
- **输入**：提示词文本。
- **输出**：二维空间连续像素矩阵。
- **核心机制**：生成模型潜空间控制。以扩散模型（Diffusion）为例，文本编码器的输出作为交叉注意力中的引导信号，在潜变量去噪过程中持续矫正空间特征网格的生成轨迹。

## 最小可验证实验：双塔特征投影与余弦度量

为了验证“中间嵌入对齐”如何在数学上消除模态维度差异，我们使用 PyTorch 模拟一个跨模态投影与度量计算过程。本例模拟了视觉编码器输出 768 维特征（如常见 ViT 基线），文本编码器输出 512 维特征，通过线性投影头将两者映射至统一的 256 维空间，并计算匹配相似度。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

# 固定随机种子以便复现
torch.manual_seed(42)

# 1. 模拟异构编码器的输出 (batch_size = 3 个图文样本对)
batch_size = 3
vision_dim = 768  # 图像高阶特征维度
text_dim = 512    # 文本高阶特征维度

vision_features = torch.randn(batch_size, vision_dim)
text_features = torch.randn(batch_size, text_dim)

# 2. 构建模态专用投影头，将特征映射到共享维度 shared_dim = 256
shared_dim = 256
vision_projector = nn.Linear(vision_dim, shared_dim, bias=False)
text_projector = nn.Linear(text_dim, shared_dim, bias=False)

# 3. 特征前向投影
z_v = vision_projector(vision_features)  # 形状: [3, 256]
z_t = text_projector(text_features)      # 形状: [3, 256]

# 4. L2 归一化（映射至单位超球面，向量模长为 1）
z_v_norm = F.normalize(z_v, p=2, dim=-1)
z_t_norm = F.normalize(z_t, p=2, dim=-1)

# 5. 计算余弦相似度矩阵（归一化后的点积即为余弦相似度）
# 模拟 CLIP 的做法：乘以缩放因子（例如 100）以便送入交叉熵损失计算
sim_matrix = torch.matmul(z_v_norm, z_t_norm.T)
logits = sim_matrix * 100.0
probs = F.softmax(logits, dim=-1)

print("对齐后视觉嵌入形状:", z_v_norm.shape)
print("对齐后文本嵌入形状:", z_t_norm.shape)
print("跨模态余弦相似度矩阵:\n", sim_matrix.detach().numpy())
print("样本匹配概率分布:\n", probs.detach().numpy())
```

![跨模态特征经投影层映射至统一单位超球面](/images/content-rebuild/239ac048c746c074/fig-4.png)

上图揭示了该计算的几何意义：两个原本维度互不相通的向量空间，分别经由各自的矩阵变换 $W_I$ 和 $W_T$ 压缩至统一维度的隐藏空间。通过 L2 归一化后，所有向量均落于半径为 1 的单位超球面上。在此几何空间中，向量点积严格等于两向量夹角的余弦值，方向一致性直接反映了跨模态的语义相关程度。

## 失效边界：语义先验与分辨率折损

在真实工程实践中，完成维度投影并不等于模型真正掌握了跨模态推理。多模态系统存在特定的脆弱性边界：

### 1. 语言偏置与虚假对齐（“汉斯马”效应）
多模态大语言模型由强大的预训练语言模型底座驱动，这使得系统对常见文本共现极为敏感。例如在常见 VQA 数据集测试中：
- 如果输入一张被人为处理成**紫色**的香蕉图片，并提问“图中的香蕉是什么颜色？”；
- 模型常常忽视图像中的真实色彩特征，依然以极高概率输出“黄色”。

这是因为在纯文本语料库中，“香蕉”与“黄色”具有极强的统计共现关系。当注意力机制在计算时，文本自注意力的强先验压制了来自视觉特征的弱信号，导致模型产生虚假回答。这种现象警示开发者：多模态输出表面的高准确率，有时只是单模态语言记忆的副产物。

![多模态模型依赖文本先验忽视图像细节的失效案例](/images/content-rebuild/239ac048c746c074/fig-5.png)

上图展示了这种典型的先验压制失效：面对紫色香蕉的图像输入，模型内部由于语言先验分支占据主导，导致视觉细节的反馈被稀释，最终输出了与画面事实相悖的结果。

### 2. 空间下采样导致的细粒度丢失
主流的视觉编码器（如 ViT）通常采用下采样策略，将图像切分为固定尺寸的块（Patch，如 $16 \times 16$ 像素）。对于一张 $224 \times 224$ 的图片，切分后仅剩 $14 \times 14 = 196$ 个网格单元：
- 每一个网格 Token 必须浓缩 $16 \times 16 = 256$ 个像素的信息；
- 细小的表格边框、小号印刷文字、医学图像微小病灶等高频细节，在网格平均化抽象中极易被彻底模糊。

这正是通用视觉模型在面对专业复杂文档、工程图纸时频繁出错的原因。工业级文档解析通常需要多尺度感知与专有 OCR 流程的配合（可参考 [/fundamentals/multimodal-basics/ocr-doc-understanding.md](/fundamentals/multimodal-basics/ocr-doc-understanding.md) 与 [/frontier/document-parsing/what-is-file-parsing.md](/frontier/document-parsing/what-is-file-parsing.md)）。
