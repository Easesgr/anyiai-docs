多模态大模型（Multimodal Large Language Model）通过视觉编码器将图像压缩为向量序列，再由自回归语言模型统一生成回答。这种架构让模型具备了强大的图文语义关联能力，但在面对需要精确定位、识读微小细节或严格物理判断的场景时，模型经常给出违背常识的错误答案。

为了直观理解这些局限，我们可以设想一个典型的园区巡检场景：

管理员上传了一张园区道路的高清监控照片，画面主体是一辆停靠在路边的自行车，车把上栓着一根细狗绳，周围没有行人；远处台阶上方的平台上卧着一只小猫；右下角电气控制箱的角落贴有一张 $60 \times 30$ 像素的条码铭牌。

面对这样一张图，模型常在四个维度出现失误：
1. **空间推断失真**：询问小猫在台阶上方还是下方，模型容易将平面图像上的“靠上”误认为空间位置靠上，甚至把遮挡关系彻底颠倒。
2. **细节特征丢失**：让模型读取电气箱角落的条码编号，模型通常无法准确读取，或者编造一串格式相近的虚假字符。
3. **强语言先验幻觉**：询问画面中正在发生什么，模型看到狗和牵引绳，脱口而出“一位主人正在牵着狗散步”，即便画面中根本没有人。
4. **推理资源膨胀**：为了看清画面细节引入切片分块后，一张图展开为数千个视觉 Token，导致显存占用暴增、首字延迟翻倍。

下面我们逐一剖析这些现象背后的技术原因与边界条件。

## 空间几何感知局限：单目透视丢失深度与二维网格编码

让多模态大模型推断物体的空间绝对距离、朝向或遮挡层级时，输出经常不稳定。这主要是由单目透视成像的几何特性与视觉编码器的位置编码方式决定的。

![空间感知失真与三维投影坍塌机制](/images/content-rebuild/7ef750a6bcb56936/fig-1.png)

### 1. 三维深度信息的物理丢失

现实物理世界是三维空间，而单目相机拍摄的二维图像经过了透视投影矩阵运算：

$$\mathbf{p} = \mathbf{K} [\mathbf{R} \mid \mathbf{t}] \mathbf{P}_w$$

其中 $\mathbf{P}_w$ 为世界坐标系下的三维点，$\mathbf{p}$ 为齐次像素坐标，$\mathbf{K}$ 为相机内参矩阵，$[\mathbf{R} \mid \mathbf{t}]$ 为外参矩阵。透视投影将沿同一条投影射线上的所有三维点压缩到了同一个二维像素坐标上，丢失了沿视线方向的深度信息。从单张二维图像反求三维空间坐标本身是一个病态问题（欠定问题）。

人类之所以能根据单张照片推测前后关系，依赖的是对物体实际尺寸的常识、阴影投射、遮挡边缘以及双目立体视觉经验。但在多模态模型中，Vision Transformer（ViT）接收的是被切分成固定网格的 Patch 图像块，学习目标主要是图像与文本的语义对齐，内部并没有构建可微的三维欧氏几何重构分支，因此缺乏严格的空间测距和几何解算能力。

### 2. 离散位置编码缺乏视点不变性

在[视觉 Token 是什么？](/fundamentals/multimodal-basics/visual-token.md)中我们提到，ViT 使用可学习的一维或二维绝对位置编码（Positional Embedding）标示 Patch 的行列位置。这一机制记录的是像素在当前二维平面的网格坐标，存在两个典型限制：

1. **视点变化导致坐标突变**：当相机机位产生俯仰或平移时，三维空间中相对位置未变的物体，在图像网格中的行列索引会大幅移动，自注意力计算时的相对位置关系发生变化。
2. **平面坐标与物理坐标语义混淆**：在二维画面里，“靠上”既可能表示天空中飞行的鸟（高度更高），也可能表示平铺地面延伸向远处的地平线（距离更远）。模型缺乏重力场与地平面参照，容易把远处台阶上方的猫直接理解为“悬浮在台阶正上方”。

## 细粒度识别局限：降采样模糊与 Patch 线性投影均质化

当我们需要从全景图像中读取微小铭牌、长串数字或密集文本时，多模态模型常常出现漏读或看错。这一瓶颈主要发生在视觉编码阶段的输入缩放与局部特征压缩。

![分辨率降采样与Patch信息丢失对比](/images/content-rebuild/7ef750a6bcb56936/fig-2.png)

### 1. 固化分辨率与高频特征抹除

以 CLIP 或 SigLIP 为骨干网络的视觉编码器，通常具有固定的输入分辨率标准，例如 $224 \times 224$ 或 $336 \times 336$ 像素。若将一张 $3840 \times 2160$（4K）的高清图片直接下采样缩放到 $336 \times 336$，面积压缩比约为：

$$r = \frac{3840 \times 2160}{336 \times 336} \approx 73.4$$

在我们的巡检示例中，控制箱角落一个原本尺寸为 $60 \times 30$ 像素的条码，在缩放后缩减为约 $5 \times 2$ 个像素点。在插值滤波和下采样过程中，微小条码的黑白边缘高频信息被完全抹平，进入模型前就已经失去了辨识所需的必要特征。

### 2. Patch 线性投影的均质化代价

即使采用局部裁剪保持原尺寸，ViT 的切块机制仍有精度上限。ViT 通常将图像切为 $14 \times 14$ 像素的固定 Patch。每个 Patch 内的 196 个像素点通过卷积或全连接层投射为单一向量 $\mathbf{x}_i \in \mathbb{R}^d$：

$$\mathbf{x}_i = \mathbf{E} \cdot \text{Flatten}(\text{Patch}_i) + \mathbf{e}_{pos}$$

如果一个 $14 \times 14$ 像素的区域内同时包含字符笔画、金属反光和阴影，这 196 个像素的色彩数值会被加权求和并压缩为单一向量。后续的 Transformer 注意力机制是在 Patch 之间建立关联，无法回溯定位单个 Patch 内部的亚像素级笔画走势，因此极难稳定解析微小文字的精细轮廓。<ReadMoreLock />

## 多模态幻觉成因：语言共现先验压制弱视觉信号

多模态幻觉（Hallucination）指模型给出了看似流利完整、但与输入图像事实不符的描述。在[多模态大模型怎么工作？](/fundamentals/multimodal-basics/multimodal-how.md)中，我们明确了多模态模型的核心解码器通常是自回归语言模型。强文本先验与弱视觉信号的博弈，是诱发幻觉的关键机理。

![语言先验压制弱视觉信号导致幻觉的机制](/images/content-rebuild/7ef750a6bcb56936/fig-3.png)

### 1. 条件概率生成中的先验覆盖

自回归多模态模型在预测下一个 Token $w_t$ 时，计算的是基于图像特征与已有文本序列的条件概率：

$$P(w_t \mid \mathbf{V}_{tokens}, w_{<t}) = \text{Softmax}(\mathbf{W}_{out} \mathbf{h}_t)$$

其中 $\mathbf{V}_{tokens}$ 是经过投影映射后的视觉特征，$w_{<t}$ 是之前已生成的文本。如果画面中目标过小、存在遮挡或反光，编码器输出的局部视觉向量置信度较低，注意力机制分配给该特征的权重就会分散。

与此同时，语言基座模型在海量文本预训练中沉淀了强大的词语共现分布。当视觉信号特征较弱、无法提供决定性的负向约束时，自回归解码器便会沿着语言模型的统计先验生成最自然的文本组合，填补视觉特征的空白。

### 2. 算例：巡检场景中的先验博弈

在前面的巡检例子中：
- **画面客观输入**：自行车旁有一根细狗绳，系在车把上，周围空无一人。
- **提示词**："请描述画面中的主要活动。"

**模型内部的状态竞争如下**：
1. 视觉编码器提取到了“狗”、“牵引绳”、“自行车”的局部特征；但因牵引绳较细，经过 Patch 离散化后连贯性受损，绳子与车把的连接关系在注意力层中没有建立起高权重。
2. 语言模型在海量文本预训练中，“狗”与“牵引绳”高概率与“散步”、“主人牵着”共同出现：

$$P(\text{“主人”} \mid \text{“狗”}, \text{“牵引绳”}) \gg P(\text{“系在自行车上”} \mid \text{“狗”}, \text{“牵引绳”})$$

3. 解码器在生成阶段被强语言先验引导，输出了“一位主人正在牵着狗散步”。这种幻觉并非简单的随机错误，而是先验统计概率在视觉特征置信度不足时的自然漂移。

## 计算与显存瓶颈：切片带来的 Token 膨胀

为了解决高分辨率图像下采样导致的模糊问题，主流多模态方案引入了动态切片（Dynamic Cropping）机制：把原图切成多个局部网格切片，再搭配一张整图缩略图。这一方案在提升细节的同时，带来了可观的计算与显存开销。

![长视觉Token带来的显存占用与计算延迟](/images/content-rebuild/7ef750a6bcb56936/fig-4.png)

### 1. 视觉 Token 数量展开

以输入分辨率为 $336 \times 336$、Patch 大小为 $14 \times 14$ 的视觉编码器为例：
- 每个切片生成的 Patch 数量为 $(336 / 14) \times (336 / 14) = 24 \times 24 = 576$ 个。
- 采用常见的 $2 \times 2$ 网格切片策略，整图包含 4 个局部切片与 1 个全局缩略图，共 5 个图块。
- 投影至语言空间后的视觉 Token 数量为：

$$L_{vis} = 5 \times 576 = 2880 \text{ 个 Token}$$

用户仅上传一张普通分辨率的巡检截图，语言模型接收到的前缀序列就已经接近 3000 个 Token。

### 2. 推理计算与显存开销算例

我们以一个隐藏层维度 $d = 4096$、Transformer 层数 $N_L = 32$、基于 BF16（2 字节/元素）精度、采用标准多头注意力（MHA，每层 Key/Value 维度与 $d$ 一致）的 7B 模型为例，测算单次请求的基础开销：

#### A. Prefill 阶段自注意力矩阵计算量
在首字生成前的 Prefill 阶段，全注意力机制中计算 Query 与 Key 矩阵乘法的复杂度与序列长度的平方成正比。对比仅有 100 Token 的纯文本提问与加入 2880 个视觉 Token 的图文混合输入（共 2980 Token）：

$$\frac{L_{total}^2}{L_{text}^2} = \frac{2980^2}{100^2} = 888.04 \text{ 倍}$$

虽然前馈神经网络（FFN）等模块的计算量仍与序列长度成线性关系，但注意力矩阵乘法开销的剧增，仍会显著推高多模态请求的首字延迟（Time to First Token, TTFT）。

#### B. 解码阶段 KV Cache 显存占用
在自回归生成回答的过程中，前缀视觉 Token 对应的 Key 和 Value 缓存必须常驻 GPU 显存，供后续生成的每个文本 Token 进行自注意力检索与计算。单次请求中这 2880 个视觉 Token 对应的 KV Cache 显存占用为：

$$\text{Memory}_{KV} = 2 \times N_L \times L_{vis} \times d \times \text{sizeof}(\text{BF16})$$

代入数值计算：

$$\text{Memory}_{KV} = 2 \times 32 \times 2880 \times 4096 \times 2 \text{ 字节} = 1,509,949,440 \text{ 字节} \approx 1.41 \text{ GB}$$

如果服务器需要支撑 32 路并发请求，仅存放输入图像的视觉 KV Cache 就需要大约 $32 \times 1.41 \text{ GB} \approx 45.1 \text{ GB}$ 显存。这意味着在部署多模态模型时，显存容量往往比纯文本服务更快触及瓶颈。

## 工程防护方案：两阶段处理与确定性校验

在需要高准确率的业务中，直接使用端到端多模态大模型判定所有细节容易引发失误。实践中通常在架构层加入两阶段定位与外部规则校验，以规避这些固有局限。

![两阶段裁剪与专用工具结合架构](/images/content-rebuild/7ef750a6bcb56936/fig-5.png)

### 1. 细粒度任务：两阶段定位与裁剪流水线

对于识别微小条码、铭牌或特定瑕疵的场景，推荐将检测与识别拆解为两步：
- **阶段一：目标候选区粗定位**。利用轻量级的专用目标检测模型或文本检测工具，在原始大图上快速提取高置信度的候选边界框（Bounding Box）。
- **阶段二：局部 ROI 裁剪与送检**。在原始分辨率图像上将目标区域无损裁剪出来，单独缩放适配视觉编码器，再送入多模态模型推断属性。
- **阶段三：坐标反算**。模型返回的结果通过边界框坐标映射回原图物理空间，不让多模态模型直接输出绝对像素坐标。

```python
# 伪代码：两阶段微小目标识别流水线示例
def robust_multimodal_inference(full_image, prompt):
    # 1. 使用轻量级专用模型定位微小目标（如条码、文本行）
    candidate_boxes = lightweight_detector.detect(full_image)
    
    if not candidate_boxes:
        # 未定位到微小目标，走全局整图推理
        return vlm_client.generate(full_image, prompt)
    
    results = []
    for box in candidate_boxes:
        # 2. 在高分辨率原图上无损裁剪候选区域
        roi_patch = full_image.crop(box)
        # 3. 将局部区域等比缩放至模型适配尺寸（如 336x336）
        roi_input = resize_preserving_aspect(roi_patch, target_size=(336, 336))
        # 4. 针对局部高清晰度图片进行属性问答
        patch_result = vlm_client.generate(roi_input, prompt)
        results.append({"box": box, "detail": patch_result})
        
    # 5. 将局部推理结果与原图坐标聚合返回
    return aggregate_and_map_back(results, full_image.size)
```

### 2. 规则拦截与一致性校验

针对容易被语言先验带偏的任务，可以构建多视角交叉验证与规则匹配状态机。

![抗幻觉校验与确定性规则拦截状态机](/images/content-rebuild/7ef750a6bcb56936/fig-6.png)

| 校验层次 | 防护机制 | 降级处理分支 |
| :--- | :--- | :--- |
| **提示层** | **反事实测试**：在提问中追加画面中不存在的反向诱导问题（例如“图中未佩戴安全帽的人站在哪？”）。 | 若模型直接顺应诱导编造事实，判定当前会话的视觉信号置信度不足，降低该回答的置信度评分。 |
| **图像层** | **翻转/多尺寸一致性校验**：将图像原图与水平镜像图分别送入模型推断左右朝向或相对关系。 | 若几何变换后给出的事实描述出现逻辑冲突，标记为空间感知失真，触发二次判定或人工复核。 |
| **规则层** | **确定性模式校验**：若任务要求提取金额、订单号或条码，模型输出必须经过正则表达式校验，并与底层专用 OCR 提取的字符集取交集。 | 若大模型生成的长字符串在 OCR 字符流中无任何匹配子串，丢弃大模型输出，回退使用 OCR 基础结果。 |

多模态大模型大幅降低了图文跨模态理解的门槛，但在工程落地时，我们必须清醒认识到单目投影对深度的物理丢失、固定 Patch 对微小细节的均质化压缩、强语言先验引发的幻觉倾向，以及多切片带来的显存开销。通过两阶段裁剪与确定性校验，才能在生产系统中建立稳定可靠的落地闭环。
