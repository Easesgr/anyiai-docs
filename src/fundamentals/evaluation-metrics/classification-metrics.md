评估分类模型时，直接统计“预测正确的比例”往往会掩盖严重的系统缺陷。正如在 [/fundamentals/evaluation-metrics/what-is-evaluation.md](/fundamentals/evaluation-metrics/what-is-evaluation.md) 中所强调的：评估的目的是度量系统表现与业务目标之间的差距。在分类场景中，不同类型的错误带来的代价往往完全不对称——把一封正常邮件误判进垃圾箱，和把一封钓鱼邮件放进收件箱，给业务造成的损失截然不同。

要建立客观可靠的分类评测方案，需要从判定结果的记录工具——混淆矩阵出发，理解准确率在不同分布下的失真条件、精确率与召回率的权衡关系，以及决策阈值滑动对系统全局表现的影响。

## 混淆矩阵：分类结果的四种状态

二分类任务的模型输出经过阈值判定后，与真实标签对比，只会产生四种互斥的结果。这四种组合构成了二分类评测的数据基础——混淆矩阵（Confusion Matrix）。

混淆矩阵的命名规则由两个字母构成：
1. **第一个字母表示判定是否正确**：$T$（True，预测与真实标签一致）或 $F$（False，预测与真实标签相反）。
2. **第二个字母表示模型的预测输出**：$P$（Positive，模型判定为正类）或 $N$（Negative，模型判定为负类）。

组合出的四个状态如下：
- **真阳性（True Positive, TP）**：真实为正类，模型判定为正类（正确检出）。
- **假阳性（False Positive, FP）**：真实为负类，模型判定为正类（误报，统计学上的第 I 类错误）。
- **真阴性（True Negative, TN）**：真实为负类，模型判定为负类（正确排除）。
- **假阴性（False Negative, FN）**：真实为正类，模型判定为负类（漏报，统计学上的第 II 类错误）。

![混淆矩阵四个象限结构与样本流向](/images/content-rebuild/e36e7819efdf80bd/fig-1.png)

在混淆矩阵中，通常横轴代表模型的预测类别，纵轴代表样本的真实类别。真实正样本总量为 $P = TP + FN$，真实负样本总量为 $N = FP + TN$。混淆矩阵不仅记录了总体的预测数量，更完整保留了模型在不同判定路径上的错误分布。

## 准确率的局限：样本极度不平衡下的度量失真

最常见的汇总指标是准确率（Accuracy），即所有判定正确的样本占总样本量的比例：

$$\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}$$

准确率的有效性建立在一个默认前提上：各类别的正误判定代价相当，且测试集中的正负样本比例大致均衡。一旦正负样本量出现数量级差距，准确率就会严重失真。

### 不平衡场景推导

假设在信用卡欺诈识别系统中，测试集包含 $10,000$ 笔交易数据：
- 正常交易（负样本 $N$）：$9,990$ 笔；
- 盗刷交易（正样本 $P$）：$10$ 笔。

如果构建一个极端的简单分类器：无论输入什么特征，一律预测为“正常交易（Negative）”。此时该分类器的混淆矩阵为：
- $TP = 0$
- $FP = 0$
- $TN = 9,990$
- $FN = 10$

计算该分类器的准确率：

$$\text{Accuracy} = \frac{0 + 9990}{0 + 9990 + 0 + 10} = \frac{9990}{10000} = 99.9\%$$

系统取得了 $99.9\%$ 的准确率，但该系统对业务真正关心的盗刷交易检出率为零（$TP = 0$）。

<ReadMoreLock />

失真的原因在于：当 $N \gg P$ 时，$\text{Accuracy} \approx \frac{TN}{N}$。指标数值被占绝大多数的负样本主导，掩盖了模型对少数关键正样本的识别能力。因此，在不平衡分类任务中，脱离样本比例单独看准确率没有实际参考意义。

## 精确率与召回率：误报与漏报的权衡

为了穿透大样本量的掩盖效应，评估体系将视线聚焦于正样本的判别质量，由此拆解出精确率（Precision）与召回率（Recall）。

### 1. 精确率（Precision / 查准率）

精确率衡量模型**预测为正类的样本中，有多少真正是正类**：

$$\text{Precision} = \frac{TP}{TP + FP}$$

精确率的分母是全部被预测为正类的样本数。分母中的 $FP$（误报）越少，精确率越高。精确率反映了系统**控制误报的能力**。在误报代价极高的场景中，应优先监控精确率：
- **典型场景**：垃圾邮件拦截（重要邮件被误判进垃圾箱会导致严重业务遗漏）、自动化大额转账风控、搜索结果前排展示。

### 2. 召回率（Recall / 查全率 / 灵敏度 Sensitivity）

召回率衡量**真实存在的正样本中，有多少被模型成功找出**：

$$\text{Recall} = \frac{TP}{TP + FN}$$

召回率的分母是所有真实正样本的总数。分母中的 $FN$（漏报）越少，召回率越高。召回率反映了系统**控制漏报的能力**。在漏报代价极高的场景中，召回率拥有更高优先级：
- **典型场景**：恶性肿瘤早期筛查、关键设备停机故障预警、高危违规交易初筛。在这类任务中，宁可承受人工复查的成本（容忍部分 $FP$），也不能漏掉潜在隐患。

![精确率与召回率的工程权衡与对抗机制](/images/content-rebuild/e36e7819efdf80bd/fig-3.png)

在模型判别能力固定的前提下，精确率与召回率天然存在拉扯关系：
- 调高判定门槛：模型只在极有把握时判定为正类，误报 $FP$ 减少，Precision 提升；但边缘正样本会被判为负类，漏报 $FN$ 增加，导致 Recall 下滑。
- 降低判定门槛：模型尽量多抓取可能的目标，Recall 提升；但伴随而来的负样本混入会导致 $FP$ 增加，使 Precision 显著下降。

## F1-score 与加权 F-beta：为何采用调和平均

综合考虑 Precision 与 Recall 时，最直观的想法是计算算术平均：$\frac{\text{Precision} + \text{Recall}}{2}$。但算术平均无法防范单项指标极低的极端模型。

考虑一个分类器，其 Precision $= 1.0$，而 Recall $= 0.02$。若使用算术平均：

$$\frac{1.0 + 0.02}{2} = 0.51$$

系统得到一个超过 0.5 的得分，但由于召回率几乎为零，该模型在实际业务中基本不可用。

### 调和平均数的惩罚机制

F1-score 采用精确率与召回率的**调和平均数（Harmonic Mean）**：

$$\frac{1}{F_1} = \frac{1}{2} \left( \frac{1}{\text{Precision}} + \frac{1}{\text{Recall}} \right) \implies F_1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}$$

调和平均数的数学特性在于：**整体数值由较小的一方主导**。当 Precision 或 Recall 中有任意一项趋近于 0 时，$F_1$ 将迅速趋近于 0。调和平均数对极小值有强烈的拉低效应，要求模型在两个维度上都不能出现致命短板。

对前面的例子代入计算：

$$F_1 = 2 \cdot \frac{1.0 \cdot 0.02}{1.0 + 0.02} = \frac{0.04}{1.02} \approx 0.0392$$

得分被直接拉至 0.04 以下，能直观反映出模型的严重可用性缺陷。

### 加权指标：$F_\beta$-score

F1-score 假设 Precision 与 Recall 同等重要。但在实际工程中，业务关注点往往是不对称的。为此可以使用推广形式 $F_\beta$-score：

$$F_\beta = (1 + \beta^2) \cdot \frac{\text{Precision} \cdot \text{Recall}}{(\beta^2 \cdot \text{Precision}) + \text{Recall}}$$

参数 $\beta$ 的业务含义是：**将召回率的重要性视为精确率的 $\beta$ 倍**。
- **$\beta = 1$**：标准 $F_1$，精确率与召回率同等重要。
- **$\beta = 2$（$F_2$-score）**：把召回率看得比精确率重要 2 倍（在倒数权重中引入 $\beta^2 = 4$），适用于医疗诊断、安防排查等漏报成本高昂的场景。
- **$\beta = 0.5$（$F_{0.5}$-score）**：把精确率看得比召回率重要 2 倍，适用于广告点击转化、高成本自动化拦截等误报成本高昂的场景。

## 决策阈值变动：PR 曲线与 ROC-AUC 的适用边界

大部分现代分类器（如逻辑回归、梯度提升树、神经网络）的原始输出不是二元标签，而是属于正类的连续得分或置信度估计 $\hat{y} \in [0, 1]$。必须设定一个决策阈值（Threshold）$\theta$：当 $\hat{y} \ge \theta$ 时判定为正类，否则判定为负类。

阈值 $\theta$ 在 $[0, 1]$ 之间滑动，就会产生不同的混淆矩阵。将不同阈值下的指标画在坐标平面上，便构成了 ROC 曲线与 PR 曲线。

### 阈值滑动算例演练

给定 5 个测试样本及其模型预测得分与真实标签（示意）：

| 样本编号 | 真实标签 | 预测得分 $\hat{y}$ |
| :--- | :--- | :--- |
| $S_1$ | 正类 ($1$) | 0.90 |
| $S_2$ | 正类 ($1$) | 0.80 |
| $S_3$ | 负类 ($0$) | 0.70 |
| $S_4$ | 正类 ($1$) | 0.40 |
| $S_5$ | 负类 ($0$) | 0.20 |

真实正例总数 $P = 3$，真实负例总数 $N = 2$。观察不同阈值下的指标变化：

1. **当 $\theta = 0.75$ 时**：
   - 预测为正：$\{S_1, S_2\}$
   - $TP = 2$（$S_1, S_2$），$FP = 0$
   - $FN = 1$（$S_4$），$TN = 2$（$S_3, S_5$）
   - $\text{Precision} = 2 / (2 + 0) = 1.0$
   - $\text{Recall} = 2 / (2 + 1) \approx 0.67$
   - 假正率 $\text{FPR} = FP / N = 0 / 2 = 0.0$

2. **当阈值下调至 $\theta = 0.50$ 时**：
   - 预测为正：$\{S_1, S_2, S_3\}$
   - $TP = 2$（$S_1, S_2$），$FP = 1$（$S_3$）
   - $FN = 1$（$S_4$），$TN = 1$（$S_5$）
   - $\text{Precision} = 2 / (2 + 1) \approx 0.67$
   - $\text{Recall} = 2 / (2 + 1) \approx 0.67$
   - $\text{FPR} = 1 / 2 = 0.5$

3. **当阈值进一步下调至 $\theta = 0.30$ 时**：
   - 预测为正：$\{S_1, S_2, S_3, S_4\}$
   - $TP = 3$（$S_1, S_2, S_4$），$FP = 1$（$S_3$）
   - $FN = 0$，$TN = 1$（$S_5$）
   - $\text{Precision} = 3 / (3 + 1) = 0.75$
   - $\text{Recall} = 3 / (3 + 0) = 1.0$
   - $\text{FPR} = 1 / 2 = 0.5$

### ROC 曲线与 AUC

ROC 曲线（Receiver Operating Characteristic）以假正率（$\text{FPR} = \frac{FP}{N}$）为横轴，真正率（$\text{TPR} = \frac{TP}{P} = \text{Recall}$）为纵轴。
- **AUC（Area Under Curve）**：ROC 曲线下的面积，取值通常在 $[0.5, 1.0]$ 之间。AUC 具有明确的统计解释：**从正样本集和负样本集中各随机抽取一个样本，模型给正样本给出的打分高于负样本打分的概率**。
- **特性与假设**：若测试集中的正负样本各自的特征得分分布保持不变，仅负样本规模增加（如扩大 100 倍），TPR 的分母只有 $P$，不受负样本扩增影响；FPR 的分子 $FP$ 与分母 $N$ 会大致同比例变化。因此在同分布假设下，ROC-AUC 对正负样本比例变化不敏感，适合评估分类器自身的**整体排序能力**。

### PR 曲线与适用边界对比

PR 曲线以召回率（Recall）为横轴，精确率（Precision）为纵轴。

**不同场景下的表现差异**：
在正样本极度稀缺的场景中（例如测试集有 $100$ 个正样本混杂在 $1,000,000$ 个负样本中），ROC 曲线容易呈现过于乐观的数值假象。
假设模型在某个阈值下误判了 $1,000$ 个负样本（$FP = 1,000$）：

$$\text{FPR} = \frac{1,000}{1,000,000} = 0.001$$

在 ROC 坐标系中，该点横坐标仅为 $0.001$。若此时模型抓出了全部 $100$ 个正样本（$TP = 100, \text{TPR} = 1.0$），在 ROC 图上该点非常靠近左上角，AUC 极高。但查看实际精确率：

$$\text{Precision} = \frac{100}{100 + 1000} \approx 9.09\%$$

这意味着系统输出的报警中，超过 $90\%$ 是误报，业务端会面临大量的误判噪音。而在 PR 坐标系中，Precision 跌至 $9.09\%$ 会直接反映在曲线上。

因此工程选型原则为：
- 当**正负样本比例大致均衡**，或者重点评估模型的**无阈值全局排序质量**时，选用 **ROC-AUC**；
- 当**正样本极度稀缺**，且业务**对假阳性误报非常敏感**时，必须选用 **PR-AUC（或 Average Precision, AP）**。

## 多类别分类下的汇总方式：Macro、Micro 与 Weighted

当分类任务扩展到 $K$ 个类别（$K > 2$）时，系统通常将任务转化为 $K$ 个独立的“一对多（One-vs-Rest）”子问题。对每个类别 $k$，均可单独统计其专属的 $TP_k, FP_k, FN_k, TN_k$，进而计算出独立的 $P_k, R_k, F1_k$。要将这 $K$ 组指标合并为全局指标，有三种不同的汇总方式。

### 1. 宏平均（Macro-average）

先独立计算每个类别的指标，再对各类别指标做算术平均：

$$\text{Macro-Precision} = \frac{1}{K} \sum_{k=1}^K P_k, \quad \text{Macro-Recall} = \frac{1}{K} \sum_{k=1}^K R_k$$

$$\text{Macro-F1} = \frac{1}{K} \sum_{k=1}^K F1_k$$

- **特点**：每个类别的权重完全平等（均为 $1/K$），不论该类别包含 $100,000$ 个样本还是 $10$ 个样本。
- **适用场景**：需要重点关注长尾小类表现的场景。若模型在小样本类别上失效，Macro 指标会剧烈下降。

### 2. 微平均（Micro-average）

先将所有类别的底层计数求和，再统一计算整体指标：

$$\text{Micro-Precision} = \frac{\sum_{k=1}^K TP_k}{\sum_{k=1}^K TP_k + \sum_{k=1}^K FP_k}$$

$$\text{Micro-Recall} = \frac{\sum_{k=1}^K TP_k}{\sum_{k=1}^K TP_k + \sum_{k=1}^K FN_k}$$

- **特点**：每个预测样本权重相等。在**单标签互斥多分类任务**中（即每个样本只能且必须归入一个类别），任何一个样本预测错误，既是真实类别的漏报（$FN$），又是预测类别的误报（$FP$）。因此必有 $\sum FP_k = \sum FN_k$。由于 $\sum TP_k + \sum FP_k$ 等于总样本数，因此在互斥多分类中必然成立：

$$\text{Micro-Precision} = \text{Micro-Recall} = \text{Micro-F1} = \text{Accuracy}$$

- **适用场景**：样本分布相对均衡，或业务目标主要关注大盘吞吐的整体正确率，允许大样本类别主导评估结果。

### 3. 加权平均（Weighted-average）

以每个类别的真实样本占比 $w_k = \frac{N_k}{\sum N_k}$ 为权重，对各类的 $F1_k$ 进行加权求和：

$$\text{Weighted-F1} = \sum_{k=1}^K w_k \cdot F1_k$$

- **特点**：保留各类别独立计算 $F1$ 的非线性结构，但按照实际样本量调节影响，降低长尾偶发波动对全局分数的过大干扰。

![多分类任务中Macro与Micro指标聚合数据流](/images/content-rebuild/e36e7819efdf80bd/fig-6.png)

三种汇总方式的核心差异如下：

| 汇总方式 | 计算顺序 | 多数类影响 | 长尾少数类影响 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Macro** | 先算单类指标，再求简单平均 | 与少数类权重相同 | 权重极高，任一小类崩溃总分剧烈下跌 | 罕见缺陷识别、小样本实体抽取、所有类别均需同等保障的场景 |
| **Micro** | 先汇总全局计数，再统一计算 | 主导最终得分 | 影响较弱，被多数类样本稀释 | 关注整体吞吐正确率、各类样本量大致均衡的场景 |
| **Weighted** | 先算单类指标，再按样本量比例加权 | 权重按样本比例放大 | 权重按样本比例缩小 | 类别不平衡但更关注常见类别表现的场景 |

## 总结与工程选型检查单

在选择评估方案时，可依据以下步骤完成选型：

1. **检查样本分布**：若正负样本比例明显倾斜（如大于 1:10），停用单一的 Accuracy，改用 Precision、Recall 与 $F_\beta$。
2. **核算业务代价**：
   - 误报代价远大于漏报 $\implies$ 锚定 Precision，调高决策阈值 $\theta$，或使用 $F_{0.5}$；
   - 漏报代价远大于误报 $\implies$ 锚定 Recall，调低决策阈值 $\theta$，或使用 $F_2$。
3. **选择综合曲线**：需要在不同阈值间评估模型排序质量时，样本均衡选 ROC-AUC；正样本稀缺且需监控报警质量选 PR-AUC。
4. **多分类汇总**：需均等保护长尾类别选 Macro-F1；追求大盘单样本正确率选 Micro-F1。

对于确定性离散标签分类，系统可以通过布尔匹配完成统计；而对于开放式文本生成任务，模型输出具有一对多的灵活性，传统混淆矩阵不再适用。有关自然语言生成质量的评测原理，请参阅 [/fundamentals/evaluation-metrics/generation-metrics.md](/fundamentals/evaluation-metrics/generation-metrics.md)。如需了解当前主流大模型的通用 Benchmark 设计，请查阅 [/fundamentals/evaluation-metrics/llm-benchmarks.md](/fundamentals/evaluation-metrics/llm-benchmarks.md)；对包含检索与生成的多阶段评测，可参阅 [/fundamentals/evaluation-metrics/rag-evaluation.md](/fundamentals/evaluation-metrics/rag-evaluation.md)；查看评估指标体系全貌，请返回 [/fundamentals/evaluation-metrics/README.md](/fundamentals/evaluation-metrics/README.md)。
