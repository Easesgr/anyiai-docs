在分类任务中，模型输出的是离散标签。判断预测好坏只需对照真实标签，统计准确率、精确率或召回率，具体原理可回顾 [分类任务怎么评估？](/fundamentals/evaluation-metrics/classification-metrics.md)。

但在机器翻译、文本摘要、对话问答或代码生成中，模型的输出是开放的自然语言序列。同一种含义，可以用完全不同的词汇、语序和句式来表达；而评测集通常只能给出有限的几条参考答案（Ground Truth）。

![文本生成任务评测演进封面](/images/content-rebuild/8e944c830423a751/cover.png)

如果单纯比对字面字符，不仅无法客观反映表达质量，还可能惩罚表意精准但用词新颖的回答；反过来，生成的句子即使字面与参考答案高度重合，也可能因为漏掉一个“不”字而颠倒事实。为了科学衡量生成质量，评测技术经历了从**字面重合统计**、**连续向量语义匹配**，到**大模型充当裁判员（LLM-as-a-Judge）**的演进。

---

## 文本生成评测的核心难点

文本生成评估的目标，是衡量**候选文本（Candidate）**与**人类期望质量**之间的契合程度。在有标准答案的场景下，系统通常将候选文本与人工撰写的一条或多条**参考文本（Reference）**进行比对。

这一过程面临三个现实矛盾：

1. **表意多样性与参考有限性的冲突**：同一段事实，可以写成主动句、被动句，或者选用不同的同义近义词。人工基准很难穷尽所有合理的表达方式。
2. **离散匹配对同义改写不敏感**：传统的字符串精确匹配无法识别同义词、上下位词以及长距离从句重组。
3. **字面重合与事实准确的脱钩**：生成文本可能在用词上大量命中参考答案，但因果颠倒；也可能完全没有用到参考答案里的词，却精准表达了同样的事实。

为应对这些问题，业界形成了三套主要的评估路径：基于词元重合统计的 BLEU 与 ROUGE、基于向量语义距离的 BERTScore，以及基于大模型理解推理的 LLM-as-a-Judge。

## 基于 N-gram 重合统计：BLEU 与 ROUGE

词元统计方法基于一个直观假设：**候选文本与参考文本中重合的词片段（N-gram）越多，候选文本的质量越高**。

![BLEU与ROUGE的匹配统计机制对比](/images/content-rebuild/8e944c830423a751/fig-1.png)

### 1. BLEU：裁剪精度与简短惩罚

BLEU（Bilingual Evaluation Understudy）最初用于机器翻译，主要衡量**精确率（Precision）**，即候选文本中生成的词有多少出现在参考文本中。

#### 裁剪精度（Modified N-gram Precision）
如果只算普通精度，当模型重复输出参考文本中出现过的常用词时（例如候选文本全篇输出 `"the the the the"`），每个词都能在参考文本中找到，精度就会被算成 $100\%$。为了解决这个问题，BLEU 引入了**裁剪计数（Clipping）**。

对于候选文本中的每个 N-gram，它计入命中的次数上限，不能超过该 N-gram 在任意单条参考文本中出现的最大频次：

$$p_n = \frac{\sum_{\text{cand}} \sum_{\text{ngram} \in \text{cand}} \text{Count}_{\text{clip}}(\text{ngram})}{\sum_{\text{cand}} \sum_{\text{ngram} \in \text{cand}} \text{Count}(\text{ngram})}$$

#### 简短惩罚（Brevity Penalty, BP）
精确率天然偏向较短的生成结果。如果模型只生成一个高确信度的词（如候选句只有一个词且在参考中出现），其精确率即为 $1$。为平衡长度，BLEU 引入了简短惩罚因子 $BP$：

$$BP = \begin{cases} 1 & \text{if } c > r \\ \exp\left(1 - \frac{r}{c}\right) & \text{if } c \le r \end{cases}$$

其中 $c$ 为候选文本的长度（词元数），$r$ 为参考文本的有效长度。综合 1 到 $N$ 阶 N-gram 精度的几何平均，得到最终得分：

$$\text{BLEU} = BP \times \exp\left( \sum_{n=1}^{N} w_n \ln p_n \right)$$

在标准 BLEU-4 中，通常取 $N=4$，$w_n = 0.25$。

### 2. ROUGE：专注信息召回的度量

ROUGE（Recall-Oriented Understudy for Gisting Evaluation）多用于文本摘要，它更关注**召回率（Recall）**，即参考文本中有多少关键信息被模型成功覆盖。

- **ROUGE-N**：参考文本中的 N-gram 在候选文本中被命中的比例。
- **ROUGE-L**：基于最长公共子序列（Longest Common Subsequence, LCS）。LCS 不要求词元在物理位置上连续，只要求它们的相对出现顺序一致，因此能较好地评估句子主干结构的保留情况。

### 逐步算例：同义改写导致的指标失真

我们设定一个具体的用例，对比字面重合指标在不同生成质量下的数值差异：

- **参考文本（Reference）**：`["今天", "天气", "很好", "适合", "外出"]`（长度 $r = 5$）
- **候选文本 A（高质量同义改写）**：`["今日", "气候", "明媚", "宜于", "郊游"]`（长度 $c_A = 5$）
- **候选文本 B（机械截断半句）**：`["今天", "天气"]`（长度 $c_B = 2$）

**对于候选文本 A**：
- 语义与参考文本完全契合，但由于用词全部替换，1-gram 到 4-gram 的交集全部为 $0$。
- 结果：$\text{Count}_{\text{clip}} = 0 \implies p_1 = 0$，最终 $\text{BLEU-1} = 0$。

**对于候选文本 B**：
- 词元统计：`"今天"` 命中 1 次，`"天气"` 命中 1 次，命中上限均为 1。1-gram 精度 $p_1 = 2/2 = 1.0$；2-gram `"今天 天气"` 命中 1 次，$p_2 = 1/1 = 1.0$。
- 长度惩罚：$c_B = 2, r = 5$，因为 $c_B \le r$，$BP = \exp(1 - 5/2) = \exp(-1.5) \approx 0.223$。
- 指标得分：$\text{BLEU-1} = 0.223 \times 1.0 = 0.223$，$\text{BLEU-2} = 0.223 \times \exp(0.5 \ln 1.0 + 0.5 \ln 1.0) = 0.223$。

（注：候选文本 B 长度仅为 2，没有 3-gram 和 4-gram，若在未平滑的情况下计算 BLEU-4 会因 $\ln 0$ 出现未定义或直接归零，因此实践中短句常对比低阶 BLEU 或配合平滑算法）。

该算例展现了 BLEU 和 ROUGE 的局限：**它们只度量离散字符形态的交集，无法理解语义等价性**。如果模型优化单纯以此类指标为导向，可能诱导模型倾向于照抄参考文本的固定词汇，而非提炼归纳。

## 基于向量相似度：BERTScore

为了克服字符硬匹配的缺陷，研究者提出了基于稠密语义向量表示的评测方案，其中代表性的方法是 BERTScore。

![BERTScore词元级上下文向量贪心匹配机制](/images/content-rebuild/8e944c830423a751/fig-2.png)

### 机制原理

BERTScore 不做字符串哈希对比，而是将候选文本和参考文本分别送入预训练语言模型（如 RoBERTa、DeBERTa），提取每个词元所在层的上下文嵌入向量（Contextual Embedding）。

设候选文本序列编码为 $\mathbf{x} = \langle x_1, x_2, \dots, x_k \rangle$，参考文本序列编码为 $\mathbf{y} = \langle y_1, y_2, \dots, y_l \rangle$。所有向量经过 $L_2$ 归一化后，点乘即为余弦相似度。

1. **成对相似度矩阵**：计算词元级别的相似度矩阵 $S_{i, j} = x_i^\top y_j$。
2. **贪心最大匹配（Greedy Matching）**：
   - **召回率（$R_{\text{BERT}}$）**：对于参考文本中的每个词元 $y_j$，在候选文本中寻找与之语义最相似的词元：
     $$R_{\text{BERT}} = \frac{1}{|y|} \sum_{y_j \in y} \max_{x_i \in x} x_i^\top y_j$$
   - **精确率（$P_{\text{BERT}}$）**：对于候选文本中的每个词元 $x_i$，在参考文本中寻找最相似的词元：
     $$P_{\text{BERT}} = \frac{1}{|x|} \sum_{x_i \in x} \max_{y_j \in y} x_i^\top y_j$$
   - **综合得分（$F_{\text{BERT}}$）**：
     $$F_{\text{BERT}} = 2 \frac{P_{\text{BERT}} \times R_{\text{BERT}}}{P_{\text{BERT}} + R_{\text{BERT}}}$$

此外，算法可选引入逆文档频率（IDF）对词元求和赋予权重，降低常用停用词对得分的干扰。

### 优势与适用边界

- **优势**：
  - **容忍同义替换**：在稠密向量空间中，`"气候"` 与 `"天气"` 的余弦相似度通常在 0.8 以上，解决了字符不重合即判 0 的问题。
  - **上下文消歧**：多义词在不同语境下的词向量不同，能减少因字面同形但含义不同导致的误判。
- **边界与代价**：
  - **推理开销增加**：BLEU/ROUGE 是毫秒级的 CPU 字符串比对，而 BERTScore 需要执行模型前向传播并进行 $O(|x||y|)$ 的点乘匹配，评测大规模测试集时代价明显提升。
  - **逻辑极性盲区**：预训练语言模型的表示容易受到高频主题词的主导。例如“今天可以外出”与“今天不能外出”，虽然仅差一个否定词但全局语义截然相反，深层上下文向量的整体余弦相似度依然较高，BERTScore 难以灵敏识别此类事实颠倒。更多进阶生成度量指标的对比亦可参考 [生成质量如何评价？BLEU、ROUGE、人工评估怎么选？](/llm-100/evaluation/generation-quality-metrics.md)。

## 大模型作为裁判员（LLM-as-a-Judge）

当自然语言生成面向开放指令、多轮对话或复杂推理时，人工预先编写完备的标准参考答案成本过高。行业内逐渐普及利用能力更强的大语言模型作为评估裁判（LLM-as-a-Judge）。

常见的大模型裁判实施方式主要有两类：

![LLM裁判的两种实施范式对比](/images/content-rebuild/8e944c830423a751/fig-3.png)

### 1. 单样本打分（Pointwise）
- **方式**：向裁判模型输入评测提示词、待评估内容以及明确的评分细则（Rubric）。模型直接输出单项指标分值（如 1 到 5 分）或百分制得分，并附带评价理由。
- **典型提示结构**：
  ```text
  你是一名严格的内容质量评估员。请根据以下评分标准对待评测文本进行评分（1-5 分）：
  - 5 分：逻辑严密，无事实错误，完整准确执行了指令。
  - 3 分：基本符合指令，但存在细节模糊或表达冗余。
  - 1 分：偏离指令，存在明显事实错误或严重幻觉。
  [待评测文本]：{candidate_text}
  请先列出评分理由，最后以 JSON 格式输出：{"score": <分值>}
  ```
- **特点与局限**：实施直观，但在缺乏严格锚定的情况下，裁判模型容易出现评分标准漂移，评分往往扎堆在 4 分或 5 分的温和区间（打分膨胀）。

### 2. 成对对比胜率（Pairwise）
- **方式**：针对同一个输入提示（Query），将两个不同模型生成的候选答案（Response A 与 Response B）以匿名方式展示给裁判模型，让裁判判断哪个回答更优，或判定为平局（Tie）。
- **胜率转化**：多次成对对决的结果汇总后，可以通过 Bradley-Terry 概率模型或 Elo 评分算法，转化为全局对齐的战力梯队分值（例如 LMSYS Chatbot Arena 的排位体系）。

成对比较更接近人类的主观优选直觉，避开了绝对刻度的量化分歧；但如果直接调用，该模式极易受到模型固有生成偏好的干扰。

## 裁判模型的常见内生偏差

大语言模型作为裁判员时，并非绝对中立。其评判受自回归生成机制和训练分布影响，常见以下几类系统性偏差：

![模型裁判的三大内生偏见机制](/images/content-rebuild/8e944c830423a751/fig-4.png)

### 1. 位置偏好（Position Bias）
在成对比较任务中，大模型对呈现在前或呈现在后的选项存在显著的统计偏好（首位偏好或末尾偏好）。在实际测试中，模型可能判定位置 A 胜出，但只要将两个候选答案在 Prompt 中的排列顺序互换，裁判可能仍然选择位置 A，哪怕此时位置 A 的内容已经变成了原来的另一方。

### 2. 自好偏好（Self-enhancement Bias）
模型作为裁判时，往往倾向于给同源模型、同一机构训练或具有相似微调风格的输出打出更高分数。例如，某些裁判模型对特定的分点结构、转折过渡词或排版习惯有天然亲和力，容易导致评估结果向自身家族倾斜。

### 3. 冗长偏好（Verbosity Bias）
对于开放式问答，大模型裁判普遍偏好篇幅更长、小标题更多、格式排版更华丽的文本。哪怕长回答中包含大量车轱辘话和无实质意义的铺垫，模型也容易给出“阐述详尽、结构清晰”的高评价；而精炼、一针见血的简短回答容易被扣上“信息量不足”的标签。

## 裁判可靠性校准方案

为了使大模型裁判具备可复现、可监控的工程可用性，通常需要结合以下校准手段：

![裁判可靠性校准工程全流程](/images/content-rebuild/8e944c830423a751/fig-5.png)

### 1. 交换顺序测试（Position Swap）
在进行成对比较时，建议执行双向测试：
- 运行第一轮评测：输入 `(Query, Candidate_1, Candidate_2)`，记录判定结果；
- 交换位置运行第二轮评测：输入 `(Query, Candidate_2, Candidate_1)`，记录判定结果；
- **结果判定规则**：
  - 仅当两次测试中裁判均一致指向同一内容对象时，才计入胜负；
  - 若两次评测均偏向某一固定的物理位置（例如两次都选了排在前面的选项），说明判断受到了位置偏好的强干扰，该样本应降级标记为平局（Tie）或判定为无效样本。

### 2. 评判理由前置与细化量表（Rubric & CoT）
在提示词设计中，应避免要求模型直接输出最终分值。自回归语言模型在逐词生成时，如果首先输出分值词元，此时模型计算该词元时只能依赖输入上下文；而若要求模型“先引用具体依据，再对比量表标准，最后在末尾输出分数”，后续的分数词元就能充分利用前面生成的分析过程。

建议采用分步推理策略：
1. 要求裁判首先引用候选文本中具体存在错误、不合逻辑或偏离指令的片段；
2. 依据各评分维度逐项说明扣分或加分原因；
3. 在最后一行输出格式化的分值结果。

### 3. 少样本示例锚定（Few-shot Anchors）
针对打分尺度漂移问题，在提示词中加入 2 到 3 个代表不同分数段的典型标注样本（如包含满分示例、合格示例与典型错误示例），能为裁判模型建立清晰的打分基准线，抑制随意给高分的膨胀现象。

### 4. 人工一致性校验（Human Agreement）
自动裁判上线前，应抽取部分样本构建专家标注集，验证机器评判与领域专家打分的相关性：
- **Spearman 秩相关系数**：衡量模型打分排序与人类打分排序的单调一致性；
- **Cohen's Kappa 系数**：评估分类或成对胜负判断中扣除偶然一致后的重合度。

当自动化裁判与专家打分保持稳定的一致性时，该套流水线才适合进入常态化评估流程。

## 评测方案选型阶梯

在实际工程实践中，往往需要分层选用不同的评测手段：

![文本生成评测选型阶梯矩阵](/images/content-rebuild/8e944c830423a751/fig-6.png)

| 评测范式 | 代表方法 | 核心优势 | 主要瓶颈 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **字面统计** | BLEU, ROUGE | 零推理算力成本，毫秒级比对，结果确定 | 不理解同义词，无法校验深层事实性 | 自动化持续集成（CI/CD）快速回归、机器翻译初步筛查 |
| **词元嵌入** | BERTScore | 容忍同义替换，具备上下文消歧能力 | 计算开销中等，对长程逻辑与否定词颠倒不敏感 | 摘要生成质量离线筛查、文案重写对齐度分析 |
| **大模型裁判** | LLM Pairwise / Pointwise | 适应复杂指令与无参考场景，具备语义推理力 | API 或算力成本高，存在内生偏差，需做顺序校准 | 模型版本选型对比、复杂对话 Agent 落地评估、偏好对齐数据筛选 |
| **人工金标** | 专家盲评 | 权威基准，能理解隐式业务常识与专业细节 | 成本高、周期长，无法规模化自动化执行 | 自动化裁判一致性校验基底、关键版本发版终审 |

在大模型系统建设中，关于跨通用维度的基准测试可以进一步参考 [大模型常见评测有哪些？](/fundamentals/evaluation-metrics/llm-benchmarks.md)；而针对带外部检索与知识增强的任务，则需要引入更加细分的召回与事实忠实度评估，相关机制请见 [RAG 系统怎么评测？](/fundamentals/evaluation-metrics/rag-evaluation.md)。
