计算机底层的处理器只能执行数值加减和矩阵乘法，无法直接理解人类语言中的汉字、单词等离散符号。要让计算机处理文本，第一步必须将文字转换成可计算的数字。

**Embedding（嵌入）** 是解决这一转换的核心方法。它把离散的文字符号映射到低维连续的实数向量空间中。本篇教程以具体的词和句子为例，解释为什么简单的词表编号行不通、稠密向量如何工作、不同层级上的“向量”有何差异，以及向量表示存在的实际边界。

## 离散符号表示与 One-hot 编码的局限

最直观的数字化方式是给每个词分配一个序号。假设词表有 10,000 个词：
- 「天气」= 2
- 「气候」= 5
- 「吉他」= 88

但序号大小没有任何语言学意义，计算机不能因为 88 大于 2，就认为「吉他」和「天气」之间存在某种数量上的递进关系。

为了消除这种虚假的大小关系，早期自然语言处理常用 **One-hot 编码（独热编码）**。如果词表容量为 $V$，就为每个词分配一个 $V$ 维向量：仅在当前词的索引位置记为 1，其余 $V-1$ 个位置全部为 0：

- $\mathbf{e}_{天气} = [0, 0, 1, 0, \dots, 0]^T$
- $\mathbf{e}_{气候} = [0, 0, 0, 0, 0, 1, \dots, 0]^T$
- $\mathbf{e}_{吉他} = [0, \dots, 1, \dots, 0]^T$

这种表示方式存在直接的几何缺陷：

### 1. 任意两词相互正交，无法衡量相似度
对于词表中任意两个不同的词项 $\mathbf{e}_i$ 和 $\mathbf{e}_j$（$i \neq j$），由于 1 的位置完全不重合，它们的向量内积恒等于 0：

$$\mathbf{e}_i \cdot \mathbf{e}_j = \sum_{k=1}^{V} e_{i,k} e_{j,k} = 0$$

计算两者的余弦相似度（Cosine Similarity）与欧氏距离（Euclidean Distance）：

$$\cos(\mathbf{e}_i, \mathbf{e}_j) = \frac{\mathbf{e}_i \cdot \mathbf{e}_j}{\|\mathbf{e}_i\|_2 \|\mathbf{e}_j\|_2} = \frac{0}{1 \times 1} = 0$$

$$\|\mathbf{e}_i - \mathbf{e}_j\|_2 = \sqrt{\sum_{k=1}^{V} (e_{i,k} - e_{j,k})^2} = \sqrt{1^2 + (-1)^2} = \sqrt{2} \approx 1.414$$

无论词表规模是一千还是一百万，**任意两个词之间的余弦相似度恒为 0，空间距离恒为 $\sqrt{2}$**。「天气」和近义词「气候」的距离，与「天气」和毫无关联的「吉他」的距离完全相同。模型无法通过向量度量出词汇间的近义、上下位或类别关联。

![One-hot 编码的正交几何困境与固定几何距离](/images/content-rebuild/91f259c7d6f5efb2/fig-1.png)

正文图 1 展示了这种几何特性：在三维坐标系中，三个独热向量分别立在各自的坐标轴端点上，两两垂直，端点间距始终固定为 $\sqrt{2}$。此外，当词表扩展到数十万规模时，每个词都要占用数十万维的空间，造成大量无效的稀疏存储。

## 稠密向量：将语义映射至连续空间

现代自然语言处理采用 **稠密向量（Dense Vector）** 来表示文本。它将每个符号映射到一个固定维度 $d$（常见取值为 128 到 4096，且 $d \ll V$）的实数向量中。向量的每个位置不再是简单的 0 或 1，而是由浮点数填充。

### 分布式假说（Distributional Hypothesis）
稠密向量能够表达语义的经验依据，是语言学中的分布式假说：**上下文相似的词，语义往往也相近**。

例如，「猫」和「狗」常与「宠物」、「喂养」、「毛茸茸」等词共同出现。模型在通过海量语料预测上下文的训练过程中，会自然推动这两个词的向量向相近的方向收敛。

### 离散与稠密的对比示例
假设将 4 个词映射到 2 维空间（数值仅作教学示意，已归一化至模长接近 1）：

| 词项 | One-hot 编码 ($V=4$) | 稠密向量 ($d=2$) | 向量模长 $\|\mathbf{v}\|_2$ |
| :--- | :--- | :--- | :--- |
| 狗 | `[1, 0, 0, 0]` | `[0.82, 0.57]` | $\approx 1.00$ |
| 猫 | `[0, 1, 0, 0]` | `[0.79, 0.61]` | $\approx 1.00$ |
| 苹果 | `[0, 0, 1, 0]` | `[-0.15, 0.98]`| $\approx 1.00$ |
| 飞机 | `[0, 0, 0, 1]` | `[-0.92, -0.39]`| $\approx 1.00$ |

在归一化向量下，内积即等于余弦相似度：

$$\cos(\mathbf{v}_{狗}, \mathbf{v}_{猫}) = 0.82 \times 0.79 + 0.57 \times 0.61 = 0.6478 + 0.3477 = 0.9955$$
$$\cos(\mathbf{v}_{狗}, \mathbf{v}_{飞机}) = 0.82 \times (-0.92) + 0.57 \times (-0.39) = -0.7544 - 0.2223 = -0.9767$$

结果显示，「狗」与「猫」的夹角极小，余弦相似度接近 1；而「狗」与「飞机」方向相反，相似度为负。语义关联被直接转换成了空间中的几何夹角。

![稠密向量映射与分布式语义空间](/images/content-rebuild/91f259c7d6f5efb2/fig-2.png)

正文图 2 展示了解析流程：离散的 Token 索引传入查找矩阵（Embedding Table），直接提取出对应的连续浮点数向量。浮点数连续可微，使得神经网络能够通过梯度反向传播不断更新词向量的坐标位置。

## 向量表示的四个层次

在日常交流中，「Embedding」常被泛指各种向量。但在现代大模型和自然语言处理体系中，必须分清以下四种不同层次的概念：

![四种向量表示层级的演进与差异对比](/images/content-rebuild/91f259c7d6f5efb2/fig-3.png)

如正文图 3 所示，这四种向量在上下文依赖与计算成本上层层递进：

### 1. 静态词向量（Static Word Embeddings）
- **代表方案**：Word2Vec、GloVe、FastText。
- **机制特征**：一个词在整张表里只有唯一一个向量。通过在滑动窗口中统计词频共现得到。
- **核心局限**：无法区分一词多义。「苹果发布新手机」与「吃红富士苹果」中的「苹果」，向量完全相同，无法反映当前上下文。

### 2. 模型输入 Token 嵌入（Input Token Embeddings）
- **代表实现**：Transformer 模型最底层的 `nn.Embedding(vocab_size, hidden_dim)`。
- **机制特征**：分词器（Tokenizer）将文本切分成 Token 序号后，直接通过该参数矩阵查表得到向量。
- **技术定位**：这只是静态初始特征，**该阶段的 Token 向量尚未融合任何上下文信息**。只有加上位置编码并经过多层自注意力机制（Self-Attention）计算后，才具备语境特征。

### 3. 模型隐藏状态（Contextual Hidden States）
- **代表实现**：BERT、GPT、LLaMA 等模型中每一层 Transformer Block 的输出张量（形状通常为 `[Batch_Size, Seq_Len, Hidden_Dim]`）。
- **机制特征**：此时的向量具备动态语境感知能力。「苹果」在与「手机」相邻时计算出的隐层向量，与在与「水果」相邻时不同。
- **技术定位**：属于中间计算结果，序列中有多少个 Token 就对应多少个向量，不能直接当作单篇文档的统一表示。

### 4. 句与文档向量（Sentence / Document Embeddings）
- **代表方案**：Sentence-BERT、BGE、text-embedding-3 等专门的文本嵌入模型输出。
- **机制特征**：将整句话或整段文章浓缩为一个固定维度向量（如 768 或 1536 维）。通常由句编码模型通过对最后一层隐状态做池化（Mean Pooling 等），并在对比学习任务下训练得到。
- **技术定位**：专门用于计算整段文本间的语义相似度，是向量数据库检索与向量匹配的载体。其在检索增强中的具体配合方式见 [Embedding 在 RAG 中有什么作用？](/fundamentals/embedding/embedding-in-rag.md)。

## 向量空间的几何直觉与代码验证

将文本转为向量后，语言关系即可用几何方式计算：

### 1. 相似度计算度量
- **余弦相似度（Cosine Similarity）**：关注两向量的方向夹角，不受模长影响，范围在 $[-1, 1]$ 之间。
- **点积（Dot Product）**：同时包含夹角和模长信息。在两向量均已做模长归一化（L2 Norm = 1）的前提下，点积在数值上与余弦相似度完全等价，且计算速度更快。
- **欧氏距离（Euclidean Distance）**：计算多维空间中两点间的绝对直线距离。

不同度量的适用条件和选型建议详见 [/fundamentals/embedding/embedding-similarity.md](/fundamentals/embedding/embedding-similarity.md)。

### 2. 向量平移与局部类比
在早期 Word2Vec 的研究中，人们发现词向量空间内部常常展现出局部的线性平移规律：

$$\mathbf{v}_{国王} - \mathbf{v}_{男人} + \mathbf{v}_{女人} \approx \mathbf{v}_{女王}$$

![向量空间的方向偏移与关系推导](/images/content-rebuild/91f259c7d6f5efb2/fig-4.png)

正文图 4 说明了这一示意：从「男人」到「女人」的差值向量，与从「国王」到「女王」的差值向量方向相近。但需要注意：**这只是在特定预训练语料与局部概念中涌现的统计规律，并不是严格的代数定理**。不能假设所有概念加减都能得出精确的逻辑结果。

### 代码验证：计算句向量的实际相似度
使用开源的 [Sentence Transformers 官方库](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)，通过执行代码查看不同语义句子的向量距离表现：

```python
from sentence_transformers import SentenceTransformer

# 加载通用的紧凑型句编码模型
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

sentences = [
    "The weather is lovely today.",  # 文本 A：今天天气真好
    "It's so sunny outside!",        # 文本 B：外面阳光明媚（同义表述）
    "He drove to the stadium."       # 文本 C：他开车去体育馆（无关话题）
]

# 将句子编码为 384 维浮点数向量
embeddings = model.encode(sentences)

# 计算两两之间的余弦相似度
similarities = model.similarity(embeddings, embeddings)

print("Sentence A vs Sentence B (同义):", f"{similarities[0][1]:.4f}")
print("Sentence A vs Sentence C (无关):", f"{similarities[0][2]:.4f}")
```

官方文档与实际运行给出的输出如下：
```text
Sentence A vs Sentence B (同义): 0.6660
Sentence A vs Sentence C (无关): 0.1046
```
结果显示，尽管句子 A 与句子 B 之间没有直接相同的实词，但句向量模型依然给出了较高的相似度（0.6660），而无关的句子 C 相似度仅为 0.1046。这说明模型根据训练得到的语义关联完成了对齐，而非依赖表面词汇重合。

## 向量表示的实际边界与常见误解

稠密向量解决了正交匹配问题，但在系统设计中需注意其表示边界：

![向量压缩瓶颈与语义失真边界](/images/content-rebuild/91f259c7d6f5efb2/fig-5.png)

### 边界一：空间距离相近不代表逻辑真值一致
最典型的现象是**反义词**。「冷」与「热」、「成功」与「失败」常出现在几乎一致的上下文句式中（例如“天气非常[冷/热]”）。在无监督或通用预训练下，反义词的向量相似度往往居高不下。

另一个问题是**否定句**。「这家餐厅菜品极好」与「这家餐厅菜品并不好」在字面上高度相似。如果模型未经过专门的难负样本（Hard Negatives）微调，二者的向量相似度可能依然偏高，但在逻辑含义上它们完全对立。

### 边界二：固定维度的信息压缩瓶颈
把包含多段因果、转折和具体数字的长文本强制压缩为单个 1024 维的向量，本质上是在做信息摘要与降维。单向量更擅长捕捉整体的主题倾向，但对于精准的数值区间、排他条件或生僻人名，容易在池化过程中被平滑稀释。在复杂的知识库工程中，通常需要结合 [稀疏向量、稠密向量和多向量检索](/fundamentals/embedding/sparse-dense-vectors.md) 配合互补。

### 边界三：各向异性（Anisotropy）
直觉上认为向量在空间中应均匀发散，但实际训练中发现，未经特殊处理的语言模型表征常会出现“各向异性”：大量向量挤在一个狭窄的高维锥形区域内。这会导致原本无关的文本计算出的余弦相似度基线偏高（例如普遍高于 0.5）。工程上通常通过对比学习微调、白化（Whitening）或标准化模块来扩展向量的方向分辨率。

## 工程应用全景

![从离散符号到下游应用的全流程管线](/images/content-rebuild/91f259c7d6f5efb2/fig-6.png)

如正文图 6 所示，以 Embedding 为基础的工程链路主要包括以下方向：

1. **语义检索**：配合近似最近邻（ANN）算法，在海量候选库中毫秒级检索与查询语义最相关的段落，弥补传统 BM25 关键词匹配的遗漏。
2. **RAG 外部知识召回**：在大模型处理复杂问题前，先从私有文档库中提取关联上下文；在动态分支和工具编排中，也可演进为自主规划模式，详见 [Agentic RAG 是什么？它和传统 RAG 最大的区别在哪里？](/frontier/agentic-rag/what-is-agentic-rag.md)。
3. **Agent 长期记忆**：把历史对话记录和任务反思向量化后存入向量数据库，在当前场景下按相似度提取最相关的经验，具体设计见 [AI Agent 的记忆系统是什么？短期记忆、长期记忆和用户画像有什么区别？](/frontier/agent-memory-system/what-is-memory.md)。
4. **文本聚类与去重**：利用向量距离运行 K-Means 或 DBSCAN，对无标注语料进行自动化分类和语义去重。

理解了向量的映射与表示原理后，下一步需要掌握余弦相似度、点积与欧氏距离的计算特性与工程选型依据。请阅读下一篇教程：[Embedding 如何表示语义相似度？](/fundamentals/embedding/embedding-similarity.md)。
