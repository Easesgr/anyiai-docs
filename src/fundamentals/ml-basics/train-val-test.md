如果让你评估一个准备参加高考的学生水平，你绝不会直接拿他做过的课后练习题原题来考他。因为即便他拿了满分，你也无法确定他是真正掌握了解题逻辑，还是仅仅把答案硬背了下来。

机器学习面临完全相同的情况。上一讲我们在 [/fundamentals/ml-basics/linear-logistic-regression.md](/fundamentals/ml-basics/linear-logistic-regression.md) 中，通过最小化损失函数求解了回归与分类模型的参数。但优化算法的本能是迎合给定的数据：只要给模型足够的自由度，它甚至可以记住每一个样本的噪声，从而在已知数据上给出极低的误差。然而，一个在已知数据上表现完美、在未知数据上频繁出错的模型没有任何实用价值。

如何客观衡量模型在未知数据上的预测能力？答案是建立严格的数据集划分机制。

![数据集划分机制全景概览：通过职责隔离防范评估偏差](/images/content-rebuild/be2c61a46a302f61/cover.png)

## 训练误差与泛化误差：模型为什么不能给自己评分？

以预测二手房成交价为例：输入房屋的面积、房龄、朝向等特征，模型输出预测价格。为了衡量模型表现，我们区分两类误差：

1. **训练误差（Training Error / Empirical Error）**：模型在参与权重更新的数据上计算出的平均误差。对于包含 $n$ 个样本的训练集 $D_{\text{train}} = \{(x_i, y_i)\}_{i=1}^n$ 和损失函数 $L$，训练误差为：
   $$\hat{R}(f) = \frac{1}{n}\sum_{i=1}^{n} L(f(x_i), y_i)$$
2. **泛化误差（Generalization Error）**：模型在整个真实数据分布 $\mathcal{D}$（包括所有未见过的未来样本）上的期望误差：
   $$R(f) = \mathbb{E}_{(x, y) \sim \mathcal{D}}[L(f(x), y)]$$

我们构建算法的目标是让泛化误差 $R(f)$ 尽可能小。但真实分布 $\mathcal{D}$ 包含未来所有潜在样本，我们无法直接穷举它，只能依靠有限的样本来逼近。

![经验误差与泛化误差随模型容量变化的走势对比](/images/content-rebuild/be2c61a46a302f61/fig-1.png)

当模型的复杂度（参数量或自由度）增加时，它拟合训练数据的能力会逐渐增强。如果模型复杂度过高，它会把训练集中个别的异常噪声（例如某套房子因为急售而远低于市场价）也当作普遍规律学下来。此时：
* 训练误差 $\hat{R}(f)$ 会持续下降，甚至趋近于 0；
* 泛化误差 $R(f)$ 却会在越过某个拐点后急剧上升，模型陷入过拟合。

因为模型在训练集上直接优化了参数，训练误差天然带有偏向自身的乐观偏差。因此，评估模型在未知数据上的表现，必须依靠独立于训练流程之外的数据。

## 三个数据集的职责边界：训练、调优与终验

在实际研发中，我们不仅要让模型学出参数，还要对比不同算法架构、调节超参数。如果只把数据分成“训练集”和“测试集”，并在测试集表现不佳时回头修改超参数，那么测试集的信息就会通过人工调参的决策过程间接渗入模型，测试结果也将失去客观性。

因此，标准的规范是将全部标注数据划分为三个互斥的集合：**训练集（Training Set）**、**验证集（Validation Set）** 与 **测试集（Test Set）**。

![三数据集的职责隔离与数据单向流动协议](/images/content-rebuild/be2c61a46a302f61/fig-2.png)

三者的职责边界如下：

### 1. 训练集（Training Set）
* **任务**：用于优化模型的内部参数（例如线性回归中的权重 $w$ 与偏置 $b$，神经网络中的权重矩阵）。
* **使用方式**：在训练周期内被多轮（Epochs）遍历，直接参与梯度计算与参数更新。

### 2. 验证集（Validation Set）
* **任务**：用于**超参数寻优**与模型选择。例如挑选决策树的最大深度、正则化系数 $\lambda$、学习率调度策略，或者决定早停（Early Stopping）的时机。
* **为何不能替代测试集**：虽然验证集不直接更新内部参数，但算法工程师会根据验证集指标反复筛选超参数。尝试数十甚至上百种超参数配置后，最终胜出的配置可能恰好契合了该验证集的偶然分布，从而在验证集上产生微弱的乐观偏差。

### 3. 测试集（Test Set）
* **任务**：评估最终定型模型的泛化表现，模拟模型在未知真实数据上的表现。
* **使用方式**：在开发与调参阶段**严格封存**。测试集既不参与梯度反向传播，也不能用于早停或超参数筛选。只有在全部算法选型与参数调优彻底结束后，才载入测试集进行单次评估。

| 数据集类型 | 优化对象 | 是否参与梯度更新 | 是否参与调优决策 | 典型划分比例（中等规模数据） |
| :--- | :--- | :--- | :--- | :--- |
| **训练集** | 内部参数（Weights / Biases） | 是 | 否（仅用于拟合参数） | 60% - 70% |
| **验证集** | 超参数（Hyperparameters / 架构） | 否 | 是 | 15% - 20% |
| **测试集** | 无（仅用于最终泛化评估） | 否 | **否** | 15% - 20% |

> **比例选取的现实条件**：上述比例主要适用于样本量在数千到数十万之间的场景。若样本量达到千万级以上或在大型模型预训练中（参见 [/llm-100/training/README.md](/llm-100/training/README.md)），只要验证集和测试集包含足够数量的绝对样本（例如各保留数万条）即可满足统计检验需求，其相对比例可降至 1% 甚至更低。

## 样本有限时的方案：K 折交叉验证

当总样本量较小（例如只有几千甚至几百条）时，切分出一个固定验证集会面临两难：验证集太小，评估分数的方差过大，结果受偶然切分影响剧烈；验证集太大，留给训练的数据又过少，导致模型欠拟合。

针对这种情况，常用 **K 折交叉验证（K-Fold Cross-Validation）** 来提高评估的稳健性。

![K折交叉验证切分与多轮迭代验证流程](/images/content-rebuild/be2c61a46a302f61/fig-3.png)

### 执行步骤

1. **预先留出测试集**：首先切分出独立的测试集并封存，不参与交叉验证。
2. **K 等分开发数据**：将剩余的数据集均匀切分成 $K$ 个大小相近且互斥的子集（通常取 $K=5$ 或 $K=10$）。
3. **轮流训练与评估**：
   * 共执行 $K$ 轮训练；
   * 第 $k$ 轮中，选用第 $k$ 个子集作为验证集，其余 $K-1$ 个子集合并作为训练集；
   * 计算并记录该轮模型在验证集上的性能得分 $S_k$。
4. **聚合评估指标**：计算 $K$ 轮验证得分的算术平均值 $\bar{S} = \frac{1}{K}\sum_{k=1}^K S_k$。

选定最优超参数后，通常使用包含这 $K$ 折的全部开发数据以该超参数重新训练一个最终模型，再在预留的测试集上做最终评估。

### 机制细节与适用边界

* **偏差与方差权衡**：K 折交叉验证的平均得分并不是严格意义上的“无偏估计”。因为每轮训练仅使用了 $(K-1)/K$ 的数据量，得出的性能评估通常比在全量数据上训练略保守一点（带有轻微的悲观倾向）；此外，由于各轮次训练集之间有大量重叠样本，各折模型并非互相独立。
* **分层采样（Stratified K-Fold）**：在分类任务样本比例极不均衡时（例如违约样本仅占 1%），普通的随机划分可能导致某折中几乎没有少数类样本。分层 K 折要求切分后的每一折中各类样本占比与原始数据保持一致。
* **计算代价**：K 折交叉验证需要将模型完整训练 $K$ 次。在训练耗时很长的深度学习模型上，通常较少采用大折数交叉验证，而是采用单次固定验证集。

## 特征工程中的数据泄漏：隐蔽的评估失效

数据泄漏（Data Leakage）指**在模型训练或特征提取过程中，无意中引入了验证集、测试集或未来才能获取的信息**。这会导致离线评估指标非常漂亮，但在未知新数据上预测能力骤降。

根据 [scikit-learn 常见陷阱文档](https://scikit-learn.org/stable/common_pitfalls.html)，最容易发生数据泄漏的环节是数据预处理与特征工程。

![特征工程标准化处理中数据泄漏与正确隔离的链路对比](/images/content-rebuild/be2c61a46a302f61/fig-4.png)

### 典型案例：划分前的全局标准化

假设输入特征需要进行 Z-Score 标准化处理：$z = \frac{x - \mu}{\sigma}$。

* **错误流程（发生泄漏）**：在调用 `train_test_split` 切分数据之前，先对整个数据集计算全局均值 $\mu_{\text{all}}$ 和标准差 $\sigma_{\text{all}}$ 并完成缩放。此时，测试集的取值已经参与了均值和标准差的计算，测试集的信息提前渗入了训练集特征。
* **正确流程（严格隔离）**：先完成数据集划分；**仅在训练集上计算** 均值 $\mu_{\text{train}}$ 与标准差 $\sigma_{\text{train}}$（调用 `fit`）；然后将这套参数分别应用到训练集和测试集的转换中（调用 `transform`）。

### 最小数值实验

以下极简算例展示了测试集的极端值如何通过全局计算改变训练特征的基准：

```python
import numpy as np

# 假设有一维特征 X，前 3 个分配给训练集，第 4 个分配给测试集
X_train_raw = np.array([[10.0], [20.0], [30.0]])
X_test_raw = np.array([[100.0]])  # 测试集包含一个远端极端样本

# --- 错误做法：在切分前基于全量数据计算均值 ---
X_all = np.vstack([X_train_raw, X_test_raw])
mean_leaked = np.mean(X_all)
print(f"泄漏均值 (包含测试集极端值): {mean_leaked:.2f}")  # 输出: 40.00

# --- 正确做法：只基于训练集计算均值 ---
mean_correct = np.mean(X_train_raw)
print(f"纯净训练均值 (隔离测试集): {mean_correct:.2f}")  # 输出: 20.00
```

![数值算例演示：全局计算如何导致测试集离群值污染训练基准](/images/content-rebuild/be2c61a46a302f61/fig-5.png)

在上述案例中，如果使用包含测试集的均值 40.00 去对训练集做中心化，训练集样本的特征基准被测试集中的离群点人为向右拉高了 20 个单位。模型在训练时提前适应了测试集的极值偏置，离线评估指标就会产生虚高。

类似易引发数据泄漏的预处理操作还包括：
1. **缺失值填充**：在切分前使用全量数据的中位数或众数填充缺失值；
2. **特征筛选**：利用全量数据计算特征与标签的相关系数，挑选高相关特征后再划分；
3. **目标编码（Target Encoding）**：在切分前使用全量数据的标签均值对类别特征进行替换。

在代码实现中，可以使用 `scikit-learn` 的 `Pipeline` 将预处理逻辑与模型串联起来，确保在交叉验证时每次变换的 `fit` 操作都严格限制在当轮训练折内部。

## 结构化与时间序列数据：非独立同分布的切分约束

随机打散切分（Random Shuffle Split）成立的前提是**独立同分布假设（I.I.D.）**：每个样本都是从同一个分布中独立抽取的。当数据本身具有内在关联或因果顺序时，随机打散会直接破坏评估的有效性。

![时间序列前向展开划分与实体分组隔离划分对比](/images/content-rebuild/be2c61a46a302f61/fig-6.png)

### 1. 时间序列数据（Time-Series Data）
* **典型场景**：用电负荷预测、商品销量预估、服务器流量监控等。
* **机制约束**：时间具有单向因果性。如果将时序数据随机打散，训练集中就会包含未来时刻的切片，模型实质上是在用“未来的信息”预测“过去”（前瞻偏差 / Look-ahead Bias）。
* **切分方法**：采用基于时间截断的前向切分（如 `TimeSeriesSplit`）。以某个时间节点为界，节点之前的数据作为训练集，节点之后的连续时间窗口作为验证集与测试集。

### 2. 存在实体聚集或分组的数据（Grouped Data）
* **典型场景**：医疗诊断（同一患者在不同角度拍摄了 5 张胸片）；语音识别（同一说话人录制了 100 句语音）；用户留存分析（同一用户产生多条日志）。
* **机制约束**：来自同一实体的样本之间存在极高的特征相关性。如果随机打散，同一患者的部分胸片会落在训练集，另一部分落在测试集。模型可能没有学到普遍的病理特征，而是记住了特定患者的骨骼形态或设备噪点。这会导致测试集指标虚高，但面对全新患者时预测失效。
* **切分方法**：按实体 ID 进行分组切分（如 `GroupKFold` 或 `GroupShuffleSplit`），确保同一个实体的所有样本只能整体归入训练集，或整体归入测试集。
