在上一讲[《大语言模型是怎么理解文本的？》](/fundamentals/llm-basics/token-to-context.md)中，我们了解了文本如何被切分成词元（Token），并通过自注意力机制组合出上下文表示。但是，一个刚初始化的 Transformer 模型只有一堆随机数字，根本写不出一句通顺的话。让模型掌握语法规则、常识逻辑和世界知识的关键阶段，就是**预训练（Pre-training）**。

预训练的核心做法非常简单：**在几万亿甚至几十万亿个没有人工打标签的词元上，让模型反复根据前面的词预测下一个词。** 这个任务不需要人工雇佣标注员写标准答案，文本本身就是最好的教材。这一步消耗了大模型研发中绝大部分的算力和电力，也决定了模型后续能力的上限。

## 预训练任务：因果语言建模与错位相移

大模型在预训练时采用的是**自监督学习（Self-Supervised Learning）**。所谓自监督，就是数据自己提供监督信号，不需要人工制作“问题-答案”对。

目前主流的生成式大语言模型（如 GPT、LLaMA、Qwen）绝大多数采用**因果语言建模（Causal Language Modeling, CLM）**。这里的“因果”是指时间上的先后顺序：模型只能看前面已经出现的词，去预测紧随其后的下一个词。

### 贯穿示例：如何把一句话变成训练题

假设我们有一句训练语料：“今天天气真好，我们去公园散步”。

分词后假设得到 6 个 Token：`["今天", "天气", "真好", "，", "我们去", "公园散步"]`。在训练时，这句话会同时构造出多个预测任务：

* 输入 `["今天"]` $\rightarrow$ 目标是预测 `"天气"`；
* 输入 `["今天", "天气"]` $\rightarrow$ 目标是预测 `"真好"`；
* 输入 `["今天", "天气", "真好"]` $\rightarrow$ 目标是预测 `"，"`；
* 依此类推，直到输入前 5 个 Token，预测最后一个 Token `"公园散步"`。

数学上，如果一个文本序列有 $T$ 个 Token：$X = (x_1, x_2, \dots, x_T)$，模型对整段话的概率建模，可以拆解为每个位置条件概率的乘积：

$$P(X; \theta) = \prod_{t=1}^T P(x_t \mid x_1, x_2, \dots, x_{t-1}; \theta)$$

其中 $\theta$ 是模型的全部可学习参数。预训练的优化目标就是让模型预测真实下一个词的概率尽可能高，也就是最小化平均**交叉熵损失（Cross-Entropy Loss）**：

$$\mathcal{L}_{\text{CLM}}(\theta) = -\frac{1}{T} \sum_{t=1}^T \log P(x_t \mid x_{<t}; \theta)$$

![讲解员指着错位相移的输入序列与目标序列说明因果语言建模预测机制](/images/content-rebuild/f060d7fb81a57a67/fig-1.png)

### 一次前向传播算完所有位置：错位相移与因果掩码

如果真像上面的例子一样，从 1 个词切片到 5 个词反复执行 5 次前向计算，显卡效率会非常低。为了让一次前向传播同时算完所有位置的损失，工程上依赖两项设计：

1. **因果掩码（Causal Mask）**：在自注意力矩阵中加入下三角掩码，强行把当前位置右侧（未来）的注意力权重置为极小负数（经过 Softmax 后变为 0）。这样即使整句话一次性输入模型，位置 $t$ 也绝对看不到位置 $t+1$ 及之后的内容。
2. **目标序列向右错位（Shift Right）**：模型的输入是原始序列去掉最后一个词（`X[:, :-1]`），而监督的目标标签是原始序列去掉第一个词（`X[:, 1:]`）。这样位置 $t$ 的输出隐状态经线性层映射后，正好对齐并评估对真实词 $x_{t+1}$ 的预测概率。

下面是用 PyTorch 模拟这个计算过程的微型示例：

```python
import torch
import torch.nn.functional as F

batch_size, seq_len, vocab_size = 2, 4, 10
torch.manual_seed(42)

# 模拟输入的 Token 序列 (形状: [批大小, 序列长度])
input_tokens = torch.randint(0, vocab_size, (batch_size, seq_len))

# 模拟模型最后一层输出的未归一化对数概率 logits (形状: [批大小, 序列长度, 词表大小])
logits = torch.randn(batch_size, seq_len, vocab_size, requires_grad=True)

# 核心工程操作：输入截掉最后一个词，标签截掉第一个词，实现错位对齐
shift_logits = logits[:, :-1, :].contiguous()   # 对应位置 0 到 seq_len - 2 的预测输出
shift_labels = input_tokens[:, 1:].contiguous()  # 对应位置 1 到 seq_len - 1 的真实词标签

# 展平为二维矩阵后计算交叉熵
loss = F.cross_entropy(
    shift_logits.view(-1, vocab_size),
    shift_labels.view(-1)
)

print(f"输入序列:\n{input_tokens}")
print(f"对齐标签:\n{shift_labels}")
print(f"计算得到的交叉熵损失: {loss.item():.4f}")
```

通过这种错位与掩码机制，训练时只要一次前向传播就能拿到整句所有位置的预测损失，并同步完成反向传播更新参数。

## 预训练数据工程：语料清洗与配比

大模型训练不仅看模型参数多大，更依赖语料的质量和多样性。现代开源大模型通常会使用 2 万亿到 15 万亿个 Token 进行训练。从互联网直接爬取的数据（如 Common Crawl）包含海量垃圾广告、模板代码和乱码，直接喂给模型会导致模型学出大量噪声。因此，数据流水线通常需要经过严格清洗。

![讲解员展示从网页抓取到规则过滤、去重与毒性清洗的数据处理流水线](/images/content-rebuild/f060d7fb81a57a67/fig-2.png)

典型的数据清洗流水线通常包含以下五个阶段：

1. **格式抽取与语种分流**：解析 HTML，剥离网页标签、样式代码和无意义二进制字符串，使用快速分类工具判断文本语言，按语种归类。
2. **规则过滤（Heuristic Filtering）**：
   * **字符统计**：剔除标点符号占比过高、全大写、超长无空格字符、重复标点堆叠的低质内容。
   * **词法检验**：正常自然语言具备稳定的代词和虚词分布。如果一段文本中完全没有常见停用词，通常是电商关键词堆砌或导航列表，应直接丢弃。
3. **多粒度去重（Deduplication）**：
   * 互联网存在大量镜像网页、转载新闻和自动生成的模板页。重复数据会导致模型死记硬背特定文本，显著削弱泛化能力，还会浪费宝贵的显存和算力。
   * 实践中通常结合精准去重（按文档 URL 或哈希值完全匹配）与模糊去重（使用 MinHash 与局部敏感哈希 LSH 识别高度相似的段落）。
4. **安全与隐私脱敏**：
   * 用正则表达式与规则库识别并替换身份证号、手机号、银行卡号等个人敏感信息（PII）。
   * 通过关键词和轻量模型过滤极端仇恨、低俗涉暴内容。
5. **数据混合与采样配比（Data Mix）**：
   * 仅靠网页文本训练出来的模型缺乏严谨的代码逻辑与长链条推理能力。因此团队会混合多种来源数据，例如：通用网页（50%~60%）、开源高质量代码（15%~20%）、数学与科学论文（10%~15%）、维基百科与高质量图书（5%~10%）。
   * 对于总量较少但信息密度极高的高质量语料（如权威教材或数学题解），通常会增加采样权重或进行多轮次（Multiple Epochs）重复训练。

## 计算预算与扩展法则：参数量与数据量的权衡

预训练需要成百上千张显卡并行运行数周乃至数月，是一笔巨大的成本支出。在既定的算力预算下，应该把模型做大（多加参数），还是把数据做大（多喂 Token）？这需要依据扩展法则（Scaling Laws）进行推算。

![讲解员利用三维坐标与拟合曲面讲解浮点运算量在参数量与数据量之间的最优分配](/images/content-rebuild/f060d7fb81a57a67/fig-3.png)

### 浮点运算量（FLOPs）的基本估算

对于标准的密集（Dense）自回归 Transformer，在序列长度处于常见范围（注意力计算占整体浮点运算比重较小，计算主要由线性变换和 FFN 矩阵乘法主导）时，每个 Token 的运算量有很稳定的经验公式：

* **单次前向传播**：处理 1 个 Token 大约需要 $2N$ 次浮点运算（$N$ 为模型非词表嵌入参数量，矩阵乘中每次乘加算 2 次浮点操作）。
* **单次反向传播**：计算输入与权重的梯度，计算代价大约是前向传播的 2 倍，即 $4N$ 次浮点运算。
* **单步训练总算力**：在不考虑激活值重算（Activation Checkpointing）的理想情况下，训练 1 个 Token 的前向加反向总开销约为 $6N$ 次浮点运算。

因此，当模型非嵌入参数量为 $N$、训练数据量为 $D$ 个 Token 时，总训练浮点预算 $C$ 可近似估算为：

$$C \approx 6 N D$$

> **注**：在显存紧张开启全激活重算时，反向过程会重做一次前向传播，总算力开销会上升到约 $8ND$。同时，训练显存不仅要装模型参数，还需要容纳优化器状态（以 AdamW 为例，每个参数需要额外 8 字节保存一阶和二阶动量）、梯度以及中间激活值，这与推理部署时主要消耗参数权重和 KV 缓存的显存结构截然不同。

### Chinchilla 最优与推理性价比的工程抉择

早期的研究（Kaplan 等人，2020）认为参数规模比数据量更重要，倾向于把模型做大。而 DeepMind 的 Chinchilla 研究（Hoffmann 等人，2022）给出了更平衡的结论：

* **单次训练算力最优**：在算力预算 $C$ 增长时，参数量 $N$ 与训练 Token 数 $D$ 应当以大致相等的比例同比扩展（$N \propto C^{0.5}, D \propto C^{0.5}$）。
* 经验公式折算下来，对于一次性训练成本最低的方案，数据 Token 量大约应为模型参数量的 **20 倍左右**（例如 70B 参数模型，理论最优训练数据量约为 1.4T Token）。

**为什么现代开源模型反而大幅打破这一比例？**

大家会发现，像 LLaMA-3 8B、Qwen-2.5 7B 这类模型，训练 Token 数动辄达到了 15T，数据量达到了参数量的上千倍。

这并非违反规律，而是工程优化目标发生了改变：
* **训练算力最优（Chinchilla）**：追求的是**把这个模型练出来消耗的总电费和算力最低**；
* **推理性价比最优（Inference-Optimal）**：模型预训练只做一次，但训练完成后要在生产环境中服务成千上万用户，每天承载几亿次 API 调用。部署 8B 模型所需的显存和单次调用延迟，远低于部署 70B 模型。因此，团队宁愿在预训练阶段“过度训练（Over-training）”，投入多倍算力把一个小模型的能力榨到极限，来换取后续线上服务长期的低部署成本。

## 基座模型（Base Model）的原生行为与边界

刚完成预训练导出的模型文件，称为**基座模型（Base Model）**或**无条件续写模型**。在这个阶段，它还没有经过任何指令微调（SFT）和人类对齐，其原生行为经常让初学者困惑。

![讲解员对比基座模型的无序概率续写与对话助手的问答表现](/images/content-rebuild/f060d7fb81a57a67/fig-4.png)

### 为什么基座模型经常“答非所问”？

如果你直接向一个未经指令微调的基座模型输入：

> `请列出光合作用的主要阶段。`

它大概率不会回答问题，而是顺着你的句子继续往下打印：

> `
> 请列出细胞呼吸的主要阶段。
> 请简述叶绿体与线粒体的结构区别。
> 本题分值：10分，请将答案写在答题卡指定区域。
> `

很多初学者会以为模型“坏了”或者“听不懂人话”。但实际上，模型恰恰精准完成了它的设计目标：**预测下一个词的概率分布**。

在互联网原始语料库中，“请列出光合作用的主要阶段”这类句式极少出现在日常聊天对话里，绝大多数出现在：
1. 中学或大学生物期末考试试卷；
2. 课后习题册的问答题部分；
3. 考研复习题集。

在试卷这类语料分布里，一个简答题后面跟着的最高概率文本，绝对不是详细答案，而是**下一道简答题**或**考试说明**。基座模型缺乏“我是个AI助手，我应该为提问提供解答”的角色认知，它只是忠实地顺着最匹配的网页统计规律接话。

### 基座模型的原生行为表现

| 行为特征 | 产生原因 | 开发者实际碰到的现象 |
| :--- | :--- | :--- |
| **模式续写** | 严格按照语料上下文统计概率继续接话 | 给出代码开头能补全函数，给出试卷开头则补全整套试题 |
| **无视系统设定** | 无法理解 `<system>` 等特殊元提示标签的权威性 | 会把开发者写在最前面的系统提示词当成普通文章接着续写 |
| **容易被输入带偏** | 极易受输入文本中错别字、情感色彩的影响 | 输入带有拼写错误或激进口气的引导词时，输出也会变成相应风格 |
| **不懂何时闭嘴** | 预训练语料主要是整篇网页，缺少明确的单轮结束标志 | 回答完核心内容后不会停下，而是继续捏造后续段落直到触及长度限制 |

## 预训练学到的是什么？概率关联而非真值表

理解预训练模型的能力边界，关键在于分清**统计相关性**与**真实世界事实**的区别。模型参数本质上是通过数值权重连续逼近自然语言的统计关联，而不是在内部建立了一张绝对可靠的关系数据库或事实图谱。

![讲解员展示隐空间概率密度分布与离散知识图谱的对比](/images/content-rebuild/f060d7fb81a57a67/fig-5.png)

### 为什么把训练损失降得极低，模型依然会产生幻觉？

损失（Loss）下降代表模型在当前训练数据上对真实词分配的平均预测概率提升（平均交叉熵降低），它在数学上不严格等价于每步离散分类准确率的同步上升，更不代表模型掌握了客观真理：

1. **语料源头本身存在冲突与错误**：互联网上充斥着陈旧过时的信息、虚假广告和互相矛盾的观点。模型拟合了语料，就等于把这些矛盾的说法以及各自的上下文概率一起记了下来。
2. **连续数值拟合带来的虚构（幻觉）**：神经网络通过连续向量空间进行泛化。当输入中出现一个训练集里极少出现的生僻实体组合时，自注意力机制会将相似概念的表征进行数值插值，从而生成一段**语法完全正确、逻辑极其流畅，但细节纯属捏造**的高概率文本。
3. **缺乏外部真值校验机制**：交叉熵损失只会告诉模型“你预测的词与训练网页上的下一个词一不一致”，并没有任何机制能校验“网页上的这句话在客观物理世界中到底真不真”。

因此，预训练赋予大模型的是对语言语法、上下文指代、常见常识和模式规律的**通用表征能力**。它记住了人类语言的组织方式和常见表述模式，但并不天然具备事实判别能力。

![讲解员梳理从预训练的通用基座到微调对齐的演进流程](/images/content-rebuild/f060d7fb81a57a67/fig-6.png)

这正界定了现代大模型研发的流水线分工：
* **预训练阶段**：用最经济的自监督方式处理海量无标注文本，建立语言底座与基础知识关联；
* **指令微调与对齐阶段**：通过高质量人类指令数据，纠正基座模型只会无序续写的习惯，教会它识别人类意图、扮演问答角色、遵守输出格式。
