大语言模型（Large Language Model, LLM）在工程视角下不是拥有自我意识的智能实体，也不是按规则检索条目的数据库，而是一个**通过海量文本训练出来的序列条件概率估计器**。

无论一个模型的参数量是 70 亿还是上千亿，因果语言模型在运行时的核心动作始终一致：**根据已经输入的文本前缀，计算词表中每一个候选词在下一个位置出现的概率，再通过采样策略挑出一个词输出**。将新词追加到已有文本末尾后，重复这一过程，就能逐步拼出一篇完整的文章、一段代码或一道题的解答。

### 1. 数学建模：文本切片与条件概率链

计算机无法直接理解人类的自然语言字符，文本在进入模型前必须被切分成离散的符号单元，称为 **Token**。一个 Token 可以是一个词、一个汉字，或者由若干字母组成的子词（Subword）。关于文本切分与向量化的具体计算，在 [/fundamentals/llm-basics/token-to-context.md](/fundamentals/llm-basics/token-to-context.md) 中有逐步推导。

假设模型拥有一个包含固定的词表 $\mathcal{V}$，词表大小 $|\mathcal{V}|$ 通常在 32,000 到 130,000 之间。一段包含 $T$ 个 Token 的文本序列可以写为：

$$X = (x_1, x_2, \dots, x_T), \quad x_t \in \mathcal{V}$$

根据概率论中的链式法则，整段文本出现的联合概率 $P(X)$ 可以拆解为各个位置条件概率的连乘积：

$$P(x_1, x_2, \dots, x_T) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_1, x_2) \cdots = \prod_{t=1}^T P(x_t \mid x_{<t})$$

这里的 $x_{<t}$ 代表位置 $t$ 之前出现过的所有 Token。主流因果语言模型（如 GPT、Llama 等 Decoder-Only 架构）的目标，就是通过包含数亿至数千亿浮点参数 $\theta$ 的神经网络，来逼近真实的语言条件概率分布：

$$P_\theta(x_t \mid x_{<t}) = P_\theta(x_t \mid x_1, x_2, \dots, x_{t-1})$$

模型本身不会直接存储现成的问答库。训练过程学到的所有语法规律、常识关联与逻辑习惯，都被分散固化在这些参数矩阵中。当输入上下文 $x_{<t}$ 时，模型最后一层会为词表中的每个候选 Token 计算出一个概率，且所有候选概率之和严格为 1。

### 2. 自回归解码机制：Prefill、Decode 与采样算例

确定了条件概率的定义后，模型如何把一串文字连续输出出来？因果语言模型遵循**自回归（Autoregressive）**生成机制：当前步预测出的新 Token，会被拼接到已有序列的末尾，成为下一步预测时输入上下文的一部分。

在底层实现上，Transformer 架构使用**因果自注意力掩码（Causal Attention Mask）**限制计算：序列中的任何位置都只能看到当前位置及之前的 Token，不能看到之后的信息。这种单向可见性使得推理过程必须分为两个阶段：

1. **预填充阶段（Prefill）**：模型一次性读入用户输入的 Prompt 序列 $(x_1, x_2, \dots, x_L)$。虽然显卡能并行计算这 $L$ 个 Token 之间的内部特征，但因果掩码决定了最后一个位置输出的隐藏状态仅综合了前 $L$ 个 Token 的信息，由此算出预测第 $L+1$ 个 Token 的概率分布。
2. **解码阶段（Decode）**：从位置 $L+1$ 开始进入单步循环。每次前向计算新增一个 Token 的分布，采样选出一个词后追加到序列中，再触发下一次前向计算。在真实工程中，系统会缓存历史 Token 计算出的键值向量（KV Cache），避免每次都重复计算全部前缀，直到模型输出终止标记（End-of-Sequence, EOS）或达到最大长度限制。

#### 采样计算演示

为了看清从网络输出到文本 Token 的换算过程，假设当前词表被极度简化，仅有 3 个候选 Token：`["苹果", "香蕉", "橙子"]`。

模型最后一层线性映射（LM Head）针对下一个位置输出的未归一化对数得分（Logits）为：

$$z = [z_1, z_2, z_3] = [2.0, 1.0, 0.1]$$

通过带温度系数（Temperature）$T$ 的 Softmax 函数，将 Logits 转化为和为 1 的概率分布：

$$P(x = w_i) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$

假设设定温度 $T = 1.0$：
- $\exp(2.0) \approx 7.389$
- $\exp(1.0) \approx 2.718$
- $\exp(0.1) \approx 1.105$
- 分母之和 $\sum = 7.389 + 2.718 + 1.105 = 11.212$

归一化后的条件概率分布为：

| 候选 Token | Logits ($z_i$) | 分子 $\exp(z_i)$ | 条件概率 $P(x)$ |
| :--- | :--- | :--- | :--- |
| **苹果** | 2.0 | 7.389 | **65.9%** |
| **香蕉** | 1.0 | 2.718 | **24.2%** |
| **橙子** | 0.1 | 1.105 | **9.9%** |

如果采用贪心搜索（Greedy Search），模型直接选择概率最高（65.9%）的“苹果”；如果采用 Top-p 或随机采样（具体采样策略与参数机制参见 [/fundamentals/llm-basics/inference-params.md](/fundamentals/llm-basics/inference-params.md)），则按该概率轮盘随机抽取一个词。抽中后将其拼入上下文，驱动下一步预测。

### 3. 统计模式拟合与逻辑推理的边界

如果大模型底层只是在预测下一个 Token，为什么它能写代码、做翻译甚至推导数学题？

原因在于**语言数据中内嵌了大量人类逻辑与结构化规则**。当模型在数万亿 Token 的语料上持续降低预测误差时，简单的字词浅层共现不足以准确预测后续内容。为了把长文本和复杂推导的损失函数降得更低，多层自注意力机制被迫在参数矩阵中建立丰富的特征关联，从而拟合出语法规则、因果关系和推理链路。

然而，这种统计关联与真实的确定性执行系统有着本质区别：

1. **没有内置算术逻辑单元（ALU）**：要求模型计算 `34891 * 72831` 时，它无法直接调用底层乘法指令，而是通过参数模式模拟出“列竖式或分步计算”的文本表现。数字位数一旦超出常见范围，预测分布容易漂移出错。
2. **单步误差的链式放大**：在长链条推导中，一旦某一步采样选到了低概率词或编造了错误事实（幻觉现象，详见 [/fundamentals/llm-basics/hallucination.md](/fundamentals/llm-basics/hallucination.md)），这个错误的 Token 会不可撤销地成为后续推理的确定前缀，导致后面的推理全盘偏离。
3. **训练覆盖度的限制**：模型在训练语料频繁出现的范式上泛化能力强；面对从没出现过的完全陌生的规则时，无法像形式逻辑系统那样进行严格的公理化演绎。

### 4. 从预训练基座到对话助手的演进

刚完成海量语料训练的模型并不直接适合作为“AI 助手”。模型通常需要经历三个主要阶段：

```
[海量网页/代码/图书文本] 
       │ (无监督预测下一个 Token，最小化交叉熵损失)
       ▼
[预训练基座模型 (Base Model)] ──> 倾向于根据文风续写，无法稳定遵循指令
       │
       ├─> [监督微调 (SFT)]: 引入多轮对话对，建立“问-答”输出范式
       │
       └─> [偏好对齐 (RLHF/DPO)]: 引入排序反馈，抑制有害/拒绝敷衍输出
       ▼
[指令对齐模型 (Instruct / Chat)] ──> 能够遵循要求扮演助手并安全回答
```

#### 阶段一：预训练（Pre-training）
在清洗后的海量无标注语料上进行自回归预测，损失函数为交叉熵损失。基座模型由此获得了语言建模能力与世界常识，具体机制见 [/fundamentals/llm-basics/pretraining.md](/fundamentals/llm-basics/pretraining.md)。但基座模型只会“续写”。如果你输入：“请列举三个中国传统节日：”，它很可能续写出：“四、端午节的起源；五、中秋节的习俗”，因为在它见过的试卷或教科书排版中，后面经常跟着后续序号，而不是解答。

#### 阶段二：监督微调（Supervised Fine-Tuning, SFT）
为了让模型理解“用户在向我提问，我需要作答”，工程上使用成千上万条“提示词-标准解答”结构化样本进行二次训练，具体方法见 [/fundamentals/llm-basics/finetuning-sft-lora.md](/fundamentals/llm-basics/finetuning-sft-lora.md)。SFT 改变了模型在看到问答上下文时的输出偏置，让它在看到问号或请求时，把概率最大值落在“直接回答”上。

#### 阶段三：人类偏好对齐（RLHF / DPO）
SFT 之后的模型仍可能输出不礼貌、编造或有害的内容。通过人类反馈强化学习（RLHF）或直接偏好优化（DPO），使用正负样本对比数据调整权重偏置，引导模型在输出有用解答的同时，主动拒绝越狱与违法要求。

### 5. 大模型与传统软件组件的对比

在将大模型引入具体软件项目前，必须厘清它与数据库和执行引擎的定位差异：

| 维度 | 关系型数据库 (RDBMS) | 代码执行器 (Python/JVM) | 大语言模型 (LLM) |
| :--- | :--- | :--- | :--- |
| **数据存储方式** | 磁盘或内存中的规整行列表格 | 内存中的抽象语法树（AST）与指令集 | 连续的高维浮点权重矩阵（参数化） |
| **查询执行方式** | 索引寻址，B+ 树或哈希精确匹配 | 严格按指令顺序进行状态转移 | 基于上下文特征映射的条件概率采样 |
| **确定性** | 满足 ACID 事务约束，结果完全可重现 | 确定性执行，行为可断点单步跟踪 | 依赖概率采样，存在天然随机波动 |
| **知识更新方式** | 执行毫秒级 `UPDATE` 或 `INSERT` | 修改代码后重新编译或热加载运行 | 需微调或重新训练参数，或在 Prompt 中动态补充 |
| **适用场景** | 账务存储、精确过滤、事实核验 | 代数计算、符号规则匹配、事务编排 | 文本理解、语义转换、多轮交互与意图提取 |

大模型中沉淀的所谓“知识”，是成千上万个词语概念在多层注意力运算中形成的参数统计关联。它无法像关系数据库那样提供行级的精确读写保证，也无法代替传统的精确计算执行器。

### 6. 工程应用：如何为概率模型建立确定性保障

既然大模型的单次输出受概率驱动，在企业级工程系统中，就不能直接把关键业务逻辑交由裸模型决定。通常需要在外部搭配确定性的工程外壳：

1. **外挂文档检索（RAG）**：通过向量数据库或全文检索，将权威参考资料作为已知背景拼进 Prompt。模型从靠“参数记忆胡乱猜”转为“基于参考材料阅读理解”，大幅降低事实幻觉。上下文窗口的处理机制详见 [/fundamentals/llm-basics/context-window.md](/fundamentals/llm-basics/context-window.md)。
2. **外部工具外包（Function Calling）**：把大模型不擅长的数学运算、数据库修改、API 交互等工作，剥离给专门的程序执行。大模型仅负责解析用户输入、组织结构化调用参数，具体协议见 [/fundamentals/llm-basics/function-calling.md](/fundamentals/llm-basics/function-calling.md)。
3. **输出语法约束（Constrained Decoding）**：在解码生成阶段，使用语法状态机强制约束候选 Token 的 Logits 掩码（例如仅允许输出合法的 JSON Schema 字符），从格式层面杜绝非法解析异常。系统架构设计见 [/fundamentals/llm-basics/app-system-design.md](/fundamentals/llm-basics/app-system-design.md)。

### 本讲小结与延伸索引

大语言模型本质是一个**拟合离散序列条件概率的大规模深度神经网络**。它的工作流程是“基于前缀自回归预测下一个 Token”；它的语义泛化能力来自对海量语言模式的统计拟合；它的随机性与事实漂移，同样源于它的概率输出特性。
