## 学习目标：建立准确、可验证的大模型技术直觉

大语言模型（LLM）不是通晓一切的数据库，也不是具有自主意志的智能体。从计算过程来看，它是一个根据前面输入的离散符号序列，在预设词表上计算下一个符号概率分布的条件概率模型。

在实际开发中，如果仅仅把模型当作“聪明的黑盒”，开发者很容易在遇到输出格式漂移、长文本关键信息丢失、置信度虚高时束手无策。本模块的目标是带领开发者理清从自然语言切分、参数训练、推理采样到外围系统设计的技术链条，学会依据计算特性来分析模型行为、定位异常原因，并用严谨的工程代码包裹随机的生成输出。

## 一个贯穿例子：客服退款助手如何运转

为了看清整套体系如何协同工作，我们以一个具体的工程场景为例：构建一个自动处理退款咨询的客服机器人。

用户在前端输入了一句话：
> “我昨天下单的咖啡一直没送到，请帮我退款。”

系统从接收这行文字到最终安全响应，需要经历以下技术环节：

1. **切分与数值化**：计算机无法直接理解汉字。分词器将句子拆分为离散单元（Token），并查表映射为高维数值向量。
2. **上下文关联**：注意力机制计算“退款”与前面的“咖啡没送到”之间的关联，结合提示词里的规则要求生成整句的表征。
3. **词表打分与选词**：模型在数万个词构成的词表上为下一个词输出概率。采样参数决定了是固定挑选概率最高的词，还是允许一定随机度。
4. **调用工具与业务落地**：即便模型在生成的文本里写出“已为您退款 25 元”，真实的银行账户也不会发生资金转移。必须由模型生成符合预定义 Schema 的结构化参数，交由外部后端程序调用真实的支付退款接口。
5. **工程防御**：模型偶尔会漏写 JSON 字段或闭合括号，外围系统必须编写校验拦截、受控重试与失败降级逻辑，确保线上接口不崩溃。

## 区分三个认知层面：教学类比、统计机制与工程防御

在排查问题与架构设计时，混淆概念往往会导致错误决策。我们需要把认知清晰划分为三个层面：

- **教学类比**：例如将模型形容为“知识丰富的助手”或“自动文字接龙”。类比有助于建立第一直觉，但不能作为系统可靠性的依据。
- **统计机制**：模型在数学上是在固定词表 $V$ 上估计条件概率 $P(w_t \mid w_{<t})$。它的输出受训练语料分布、提示词上下文权重以及随机采样算法共同影响。模型缺乏独立的事实检验机制，因此生成流畅但违背事实的文本是一种客观存在的统计现象。
- **工程防御**：生产环境需要稳定的输入输出。单纯将采样温度设为 0（贪心解码）只能保证相同输入下候选词确定，但无法解决模型训练带来的固有先验偏置、字段漏输出或逻辑错误。系统的健壮性必须由外部代码提供保障。

### 示例：结构化输出的概率表现与工程兜底

假设我们要求模型返回一个标准 JSON 响应：

```text
【Prompt 输入】: 
请将提取的信息转换为 JSON 格式：{"user_id": 1024, "action": "refund"}

【机制层表现 (即使 Temperature = 0)】:
模型在自回归解码时，在未施加结构化语法约束（如 JSON Schema 掩码解码）的前提下，
下一个词元的最高条件概率项完全可能落在换行符或提前停止符（EOS）上，产生残缺串：
{"user_id": 1024, "action": "refund"
此时如果后端直接调用 JSON.parse()，将触发 SyntaxError。

【工程防御层介入】:
1. 格式校验：捕获解析异常，不让错误直接穿透到前端；
2. 容错修复：尝试对末尾常见的缺少闭合括号进行正则或栈匹配补全；
3. 受控重试：若修复失败，将错误提示信息加入历史上下文触发单次重新生成；
4. 保底降级：重试耗尽时转入人工审核队列或返回通用错误码。
```

## 常见开发问题与查漏补缺指南

遇到具体业务故障时，可以参考下表定位背后的机制瓶颈与对应知识点：

| 常见故障与疑问 | 可能的机制原因 | 推荐查漏补缺章节 |
| :--- | :--- | :--- |
| 模型自信地编造了不存在的参数或事件 | 训练数据先验偏置、自回归缺乏事实核验机制 | [大模型幻觉是什么？](hallucination.md) 与 [预训练是什么？](pretraining.md) |
| 输入长文档后，中间段落的关键约束被忽略 | 注意力权重分布稀释、上下文位置偏置 | [上下文窗口是什么？](context-window.md) 与 [大语言模型是怎么理解文本的？](token-to-context.md) |
| 提示词越写越复杂，模型遵循度反而下降 | 上下文注入过多干扰、提示词结构混乱使概率空间发散 | [Prompt 是什么？](prompt-basics.md) 与 [大模型到底是什么？](what-is-llm.md) |
| JSON 输出偶尔缺少双引号或字段被截断 | 离散自回归采样波动、未设置强制语法约束（JSON Schema） | [大模型推理参数怎么调？](inference-params.md) 与 [大模型应用系统怎么设计？](app-system-design.md) |
| 模型无法获取企业内部系统最新的工单状态 | 模型权重在训练完成后静态固化，不具备运行时网络感知 | [微调是什么？SFT、LoRA、QLoRA 分别解决什么问题？](finetuning-sft-lora.md) 与 [大模型如何调用工具？](function-calling.md) |
