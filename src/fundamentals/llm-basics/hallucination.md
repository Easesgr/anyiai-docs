在使用大语言模型时，开发者常会遇到这样一种情况：模型的回答语句通顺、论证完整，甚至附带规范的引用格式，但核心结论或引用的数据完全是凭空捏造的。这种生成内容偏离客观事实、或违背用户输入约束的现象，在自然语言处理中被称为**幻觉（Hallucination）**。

在上一讲[/fundamentals/llm-basics/inference-params.md](/fundamentals/llm-basics/inference-params.md)中，我们讨论了采样温度和 Top-p 如何改变词元（Token）生成的随机性。然而在实际测试中，即使将温度设为 0，模型依然可能给出错误的断言。要构建可靠的生成式应用，我们需要弄清幻觉的具体类型、模型产生幻觉的统计机制，以及主流工程防御手段能做到什么、做不到什么。

上图展示了模型接收提示词后，自回归生成文本并流入真实性检验环节的全局过程。图中由卡通讲解员标注出生成流畅度与事实真值的判定路径，以下我们将首先对幻觉的形式化分类建立基准认识。

## 幻觉的分类：内在幻觉与外在幻觉

大模型的输出错误不能一概而论。根据判定依据来自输入文本还是外部现实，通常将幻觉划分为**内在幻觉（Intrinsic Hallucination）**与**外在幻觉（Extrinsic Hallucination）**。

![内在幻觉与外在幻觉分类机制图](/images/content-rebuild/7338c2583aec36d7/fig-1.png)

上图展示了输入信息源、模型输出与两类幻觉判定维度的拓扑关系。卡通讲解员手持评估卡片，清晰指明判断依据是基于给定的上下文还是外部世界事实。

### 1. 内在幻觉（与输入上下文矛盾）
内在幻觉指的是**模型的输出与用户在提示词或上下文中明确给出的信息产生冲突、篡改或逻辑颠倒**。

*   **测试场景**：文档摘要、跨语言翻译、表格问答、长文信息抽取。
*   **具体表现**：用户输入了一段业务报告：“公司第三季度营业收入为 1.2 亿元，净利润亏损 1500 万元。”模型生成的摘要却写道：“公司第三季度实现净利润 1.2 亿元，经营状况良好。”
*   **判定条件**：内在幻觉的判定不需要查阅任何外部知识库，仅比对模型的输入序列与输出序列就能得出结论。其诱因通常是长上下文下的注意力分散，或者模型参数内固化的先验偏好压制了输入信息。

### 2. 外在幻觉（与客观事实冲突或不可验证）
外在幻觉指的是**输出内容在用户提供的上下文中没有依据，且与现实世界事实不符，或者模型捏造了无法查证的实体、事件和引用**。

*   **测试场景**：开放域常识问答、专业学术咨询、代码库接口查询。
*   **具体表现**：询问“爱因斯坦因何获得 1921 年诺贝尔物理学奖？”，模型回答：“爱因斯坦因提出狭义相对论和广义相对论而获得该奖项，相关成果发表于 1905 年的某期刊。”事实上，诺贝尔奖官方当年的授奖理由是“发现光电效应定律”，而非相对论；模型同时还可能随手附带一个符合格式但并不存在的论文 DOI 编号。
*   **判定条件**：外在幻觉发生在模型依赖自身权重记忆回答开放问题时。由于训练语料的覆盖范围和统计优化目标的限制，模型给出的内容虽符合语义连贯性，但在物理世界中为假。

## 为什么会产生幻觉：概率预测与事实真值的错位

大模型出现幻觉并不是因为软件运行时抛出了异常，而是由自回归语言建模的数学目标所决定的。

![大模型知识压缩与自回归累积因果链条流程图](/images/content-rebuild/7338c2583aec36d7/fig-2.png)

上图展示了预训练语料经过参数压缩、进入概率平滑预测、并在自回归解码中引发误差逐步累积的因果链条。卡通讲解员在关键节点标注了概率分布到离散 Token 的流向。

在[/fundamentals/llm-basics/what-is-llm.md](/fundamentals/llm-basics/what-is-llm.md)中我们讲过，语言模型本质上是一个条件概率估算器。预训练的目标是在给定上文的情况下，最大化下一个词的对数似然概率：

$$\mathcal{L}_{LM}(\theta) = \sum_{t=1}^T \log P_\theta(w_t \mid w_1, w_2, \dots, w_{t-1})$$

这一训练机制带来了三个无法避免的客观限制：

### 1. 参数化记忆属于有损压缩
在[/fundamentals/llm-basics/pretraining.md](/fundamentals/llm-basics/pretraining.md)中，模型通过训练将海量文本的统计特征压缩进数十亿到数千亿个浮点参数中。
*   模型不是结构化数据库，并不以“键-值对”形式精确索引事实。
*   事实性知识被分散编码在网络的各层权重中。当某些专业领域概念在训练数据中出现频率较低（即处于长尾分布）时，参数无法保留全部细节，模型在解码还原时就会出现有损失真。

### 2. 词语共现频率不等于事实真值
优化目标要求模型输出“在此类句式中后续最常出现的词”，而不是“客观现实中真实存在的属性”。
*   在自然语言语料中，“爱因斯坦”与“相对论”的共现频率极高，而“爱因斯坦”与“光电效应定律”的直接共现频率相对较低。
*   当提示词询问其获奖原因时，基于统计共现的模型在没有显式事实约束的情况下，更容易倾向于生成与主体关联度更高的“相对论”，从而产生外在幻觉。

### 3. 自回归生成的单向误差累积
在自回归解码中，时间步 $t$ 生成的词元 $w_t$ 会立即作为已知输入，追加到下一步的上下文中。
*   一旦在某一步由于概率平滑选择了一个错误词元，解码器无法自动回退或删除它。
*   为了保持下文的语法连贯与自洽，后续生成的词元会默认以这一错误前提为基准继续展开推导，形成滚雪球式的连续虚构。

## 流畅性陷阱：高生成概率与事实真值的脱节

在工程实践中，幻觉往往伴随着高度通顺的句式结构。这种“一本正经地胡说八道”被称为流畅性陷阱（Fluency Trap）。

![流畅性陷阱：Token 条件概率与事实真值解耦对比图](/images/content-rebuild/7338c2583aec36d7/fig-3.png)

上图对比了模型内部的高 Token 置信度输出与外部事实验证系统的对照状态。卡通讲解员正在对照逻辑语法树与事实数据库，指出两者的解耦现象。

### 词元概率不代表命题真实
我们通过一个具体示例观察这一脱节现象。向模型询问某位历史人物的生卒年份：

```text
输入提示词：某学者逝世于哪一年？
模型生成序列：该学者于 1988 年在故乡安详辞世。
真实客观记录：该学者实际逝世于 1975 年。
```

观察自回归解码时模型给出的局部条件概率 $P(w_t \mid w_{<t})$：

| 生成的 Token | 局部条件概率 $P(w_t \mid w_{<t})$ | 语言模型内部评估 | 客观事实核验 |
| :--- | :--- | :--- | :--- |
| "该学者" | 0.92 | 匹配上下文实体 | 符合语境 |
| "于" | 0.88 | 常见时间前置介词 | 句式正确 |
| "1988" | 0.65 | 分布平滑后的局部峰值 | **事实错误（实际为 1975）** |
| "年" | 0.98 | 强时间单位搭配 | 语法正确 |
| "在故乡" | 0.74 | 传记类惯用状语 | 无法证实（虚构细节） |
| "安详" | 0.82 | 情感色彩修饰词 | 惯用修辞 |
| "辞世" | 0.95 | 典雅句末动词 | 强连贯终结 |

在这个句子中，整段文本的平均 Token 概率高达 0.85，语法完备、逻辑自洽。然而，在模型选中 "1988" 这一 Token 的节点上，其陈述的命题事实真值就已经偏离客观记录。模型追求的是文本的自然与合理，并不会自主校验数字背后的历史档案。

## 降低温度与贪心搜索为何不能根除幻觉

有一种常见的直觉设想：幻觉是否由于采样随机性引入了低概率的噪声？如果把采样温度（Temperature）设为 0，即使用贪心搜索（Greedy Decoding），每一步都取概率最高的词，能否杜绝幻觉？

答案是否定的。

![贪心搜索与温度参数调节下的幻觉现象演示图](/images/content-rebuild/7338c2583aec36d7/fig-4.png)

上图展示了当 Temperature 设为 0 时，贪心搜索依然沿着概率峰值步步前进，最终输出错误命题的过程。卡通讲解员手持放大镜指向被选中的最大概率错误 Token。

贪心搜索在每个时间步只选取模型输出概率分布中的最大值：

$$w_t = \arg\max_{w \in \mathcal{V}} P(w \mid w_{<t})$$

如果模型在预训练时并未牢固编码某个冷门实体的事实信息，或者训练数据中普遍存在的统计共现偏向了另一个错误词汇，那么**当前概率最大的 Token 本身就是偏离事实的**。

下面用一段简化的 Python 代码说明这一过程：

```python
# 伪代码：贪心解码在先验偏置下的生成过程示意
import numpy as np

def mock_softmax(logits):
    exp_vals = np.exp(logits - np.max(logits))
    return exp_vals / np.sum(exp_vals)

def greedy_decode_step(logits, vocab):
    probs = mock_softmax(logits)
    # 温度设为 0 时，直接选取概率最高的候选词
    best_token_idx = np.argmax(probs)
    return vocab[best_token_idx], probs[best_token_idx]

# 假设针对问题“某学者逝世于哪一年”，真实年份为“1923”
# 由于语料中该年份极少与该学者共现，而“1980”等现代年份在通用语料中频率更高
vocab = ["1923", "1980", "1995"]
# 模型由于统计先验偏置输出的 logits
logits = np.array([1.2, 3.8, 0.5])

token, prob = greedy_decode_step(logits, vocab)
# 即使确定性选取，输出仍为概率峰值对应的虚构年份：1980，概率约为 0.90
print(f"生成词元: {token}, 条件概率: {prob:.2f}")
```

调整温度只能控制采样结果的波动范围。当知识本身缺失或参数权重带有统计偏差时，贪心搜索只是让模型以**完全确定、每次相同的方式稳定地复现同一个幻觉**。

## 常见工程缓解策略与工作机制

既然无法仅靠调整采样参数杜绝幻觉，工程上通常采用外部架构补充信息或增加校验约束。

![工程防御三防线：上下文锚定、思维链与一致性校验结构图](/images/content-rebuild/7338c2583aec36d7/fig-5.png)

上图展示了从上下文注入、思维链推理中间状态拆解，到多路径一致性表决的数据流。卡通讲解员站在控制台前，分流并对比不同策略的处理管道。

### 1. 上下文锚定（Context Grounding / RAG）
*   **工作机制**：在提示词中直接注入经过检索核验的权威参考资料，将模型的任务从“依赖内部参数回忆”转换为“依据给定参考文本总结”。详细机制可参考[/interview/rag-interview/rag-hallucination.md](/interview/rag-interview/rag-hallucination.md)。
*   **效果与代价**：显著减少外在幻觉，使回答有据可查；但如果参考文档过长，受注意力分布不均（如中间位置关注度下降）影响，仍可能出现漏读或错读，退化为内在幻觉。

### 2. 思维链显式推导（Chain-of-Thought, CoT）
*   **工作机制**：引导模型在输出最终答案前，先逐条写出推导依据或计算步骤。具体提示技巧将在[/fundamentals/llm-basics/prompt-basics.md](/fundamentals/llm-basics/prompt-basics.md)展开。
*   **效果与代价**：在多步逻辑或数值计算任务中，思维链让前一步的推导结果成为后续生成的注意力依据，降低了一步直接得出结论时的逻辑断层风险；但它无法解决基础事实记忆缺失的问题，前置步骤若包含虚构事实，后续推导同样会被带偏。

### 3. 多路径一致性校验（Self-Consistency）
*   **工作机制**：在带有适当温度（如设置 Temperature > 0）的随机采样下，让模型对同一推理问题生成多条独立的推导路径，然后对最终答案进行投票聚合。
*   **效果与代价**：能够平滑偶发性的随机推理漂移；然而 API 调用成本和耗时呈倍数增加，且若模型对特定事实存在系统性的先验错误，多条路径依然会一致收敛到错误答案。

## 工程边界：为什么提示词与 RAG 无法根除幻觉

在设计大模型系统架构时（参考[/fundamentals/llm-basics/app-system-design.md](/fundamentals/llm-basics/app-system-design.md)），我们需要对现有方案的有效边界保持清晰预期：**纯自然语言提示与外挂检索无法保证 0 幻觉。**

![无外部验证器的纯自提示自我修正失效机制与闭环断言对比图](/images/content-rebuild/7338c2583aec36d7/fig-6.png)

上图对比了两种校验路径：左侧为单纯向自身提问“你确定吗”，由于缺乏外界信息输入，模型陷入强化偏倚；右侧引入外部代码执行沙盒与符号断言库，由客观结果驱动修正。卡通讲解员正在阻断左侧死循环，并将指针引向右侧的确定性校验工具。

### 1. RAG 流程中的薄弱环节
检索增强系统压制了开放域的外在幻觉，但引入了新的出错场景：
*   **切片噪声干扰**：检索阶段召回了关键词重合但语义无关的文档片段，误导模型引用了错误主体。
*   **参数先验冲突**：当检索文档中的内容与预训练参数中的高频模式冲突时（例如冷门论文修正了传统常识），模型注意力可能更偏向其参数内部的强先验，忽略上下文中的明确记录。
*   **跨文档信息缝合失误**：当一个问题的答案分散在两个不连续的文档块中时，模型在组合实体关系时容易出现混淆。

### 2. “纯自省式提问”的逻辑局限
许多开发者尝试通过追加提示词来校验回答：

```text
“请检查你刚才给出的内容。如果有任何事实性错误，请指正并重新生成。必须确保 100% 正确。”
```

在不接入外部工具和新数据的前提下，这种纯自省机制在原理上存在两个瓶颈：

1.  **缺乏独立的真实性判定基准**：自检过程调用的依然是生成原答案的同一套参数分布。如果模型在一开始就不掌握该事实，二次检查无法无中生有地获得外部真值。
2.  **顺从倾向（Sycophancy）**：模型经过人类反馈对齐后，容易顺应提问者的质疑语气。当用户追问“你确定这个结论正确吗？”时，即使原回答完全无误，模型也常会因质疑引导而推翻正确结论，引发反向错误。

要实现有效的生成内容校验，必须让模型通过工具调用（详见[/fundamentals/llm-basics/function-calling.md](/fundamentals/llm-basics/function-calling.md)）与确定性系统对接，例如调用数据库 SQL 查询、运行沙盒代码验证数学计算、或对照权威知识图谱断言。通过外部工具的返回结果作为硬性约束，才能形成真正的闭环纠错。

下一讲我们将进入具体应用开发的基石，探讨[/fundamentals/llm-basics/prompt-basics.md](/fundamentals/llm-basics/prompt-basics.md)，从输入上下文的结构化编排与约束设计开始，掌握系统化控制模型行为的基本方法。
