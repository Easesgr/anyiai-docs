在语言模型的完整生命周期中，预训练消耗了最多的计算资源。它的训练任务在形式上非常专一：给定一段文本，根据前面的词，预测下一个词。

例如面对句子：`"今天气温很低，出门记得穿[羽绒服]"`，模型根据前 12 个字符的上下文，计算词表中每个词出现在下一个位置的概率分布。预训练并不需要人工编写问答对或分类标签，文本序列本身既是输入，也是监督目标。

这种看似简单的单向自回归预测，为什么能让模型沉淀出语法结构、上下文指代消歧乃至常识推理能力？在工程实现上，训练过程如何克服单步生成的串行瓶颈？本篇将梳理因果语言建模的概率定义、计算图设计、损失度量、显存开销及统计拟合带来的知识边界。

## 因果语言建模：条件概率链式法则

因果语言建模（Causal Language Modeling，简称 Causal LM）是一种自监督学习范式。文本序列自身的自然顺序直接提供了监督信号。

设一个由 $T$ 个离散 Token 组成的文本序列为 $X = (x_1, x_2, \dots, x_T)$。根据概率论中的条件概率链式法则，该序列出现的联合概率分布 $P(X)$ 可以拆解为各个位置条件概率的连乘积：

$$P(x_1, x_2, \dots, x_T) = P(x_1) \cdot P(x_2 \mid x_1) \cdot P(x_3 \mid x_1, x_2) \dots = \prod_{t=1}^T P(x_t \mid x_{<t})$$

其中 $x_{<t} = (x_1, x_2, \dots, x_{t-1})$ 表示位置 $t$ 之前的所有历史 Token。

因果语言建模的目标，是用神经网络参数 $\theta$ 拟合这一组条件概率分布 $P_\theta(x_t \mid x_{<t})$。在无标注语料库中，训练目标是最大化整个文本集的对数似然，在数值优化中等价于最小化平均负对数似然损失（Negative Log-Likelihood, NLL）：

$$\mathcal{L}_{\text{NLL}}(\theta) = - \frac{1}{T} \sum_{t=1}^T \log P_\theta(x_t \mid x_{<t})$$

这里的“因果”指时间单向性：计算当前位置的输出时，模型只能依赖历史输入，不能利用未来信息。这与 BERT 等掩码语言模型（Masked Language Model, MLM）不同。BERT 在编码时允许双向注意力同时看到前后文，更适合分类或抽取任务，但无法直接以高吞吐形式支持自然文本的自回归续写。

## 训练并行化：Teacher Forcing 与因果注意力掩码

在推理生成阶段，模型是串行输出的：先生成第 1 个新 Token，将其拼入输入序列，再预测第 2 个 Token。如果训练阶段也按这种串行方式逐步执行，GPU 强大的矩阵乘法吞吐能力就无法发挥。

为了让包含 $T$ 个 Token 的整句在一次前向传播中同时计算完所有位置的损失，现代 Transformer 采用了 **Teacher Forcing** 与 **因果注意力掩码（Causal Mask）**。

### 1. Teacher Forcing 的并行机制

Teacher Forcing 指在训练阶段，模型无论在位置 $t$ 预测对错，送入下一个位置 $t+1$ 的输入始终是语料中的真实历史（Ground Truth）。

因此，整条长度为 $T$ 的序列可以一次性传入模型：
- 位置 1 的输入是 $x_1$，预测目标是语料中的真实词 $x_2$；
- 位置 2 的输入是 $(x_1, x_2)$，预测目标是真实词 $x_3$；
- 位置 $t$ 的输入是 $(x_1, \dots, x_t)$，预测目标是真实词 $x_{t+1}$。

只要将目标标签相对于输入序列在时间步上向左错位偏移一个位置（即输入取序列前 $T-1$ 个词，标签取后 $T-1$ 个词），整个序列的交叉熵损失就可以在一次前向与反向传播中并行完成。

### 2. 因果注意力掩码（Causal Mask）

在自注意力计算中，点积注意力会生成一个大小为 $T \times T$ 的注意力分数矩阵，矩阵元素 $A_{i,j}$ 表示位置 $i$ 对位置 $j$ 的注意力权重。如果不做遮蔽，全注意力机制会让位置 $i$ 读取到位置 $i+1$ 及之后的 Token。

此时模型预测 $x_{t+1}$ 时，就会通过注意力直接读取输入中已经存在的 $x_{t+1}$，造成**标签泄露（Label Leakage）**。一旦发生标签泄露，模型就会学会直接抄写未来位置的答案，训练损失会降到接近 0，但模型并没有学到上下文关联，推理时遮住未来词就会完全失效。

因果注意力掩码通过将注意力权重矩阵的上三角区域（$j > i$）置为一个极大的负数（例如 $-\infty$ 或 $-1e9$），在经过 Softmax 归一化后，未来位置的权重被截断为 0：

$$\text{MaskedAttention}(Q, K, V) = \text{Softmax}\left(\frac{QK^T}{\sqrt{d_k}} + M\right)V, \quad M_{i,j} = \begin{cases} 0 & j \le i \\ -\infty & j > i \end{cases}$$

### 3. 错位对齐与掩码的 PyTorch 验证代码

下面展示因果掩码构造、输入标签错位切分及交叉熵损失计算的核心流程：

```python
import torch
import torch.nn.functional as F

# 设定示例参数：批大小为 1，序列长度为 4，词表大小为 8
batch_size, seq_len, vocab_size = 1, 4, 8

# 真实 token 序列: [3, 5, 2, 7]
input_ids = torch.tensor([[3, 5, 2, 7]])

# 1. 构造因果掩码 (下三角为 1，上三角为 0)
# 阻止位置 i 关注位置 j (j > i)
causal_mask = torch.tril(torch.ones((seq_len, seq_len)))
print("因果掩码矩阵 (1 为保留, 0 为遮蔽):\n", causal_mask)

# 2. 模拟模型输出的未归一化对数概率 Logits (形状: [batch, seq_len, vocab_size])
logits = torch.randn(batch_size, seq_len, vocab_size, requires_grad=True)

# 3. 输入与标签错位对齐 (Shift)
# inputs:  位置 0 到 T-2 (token 3, 5, 2)
# targets: 位置 1 到 T-1 (token 5, 2, 7)
shift_logits = logits[:, :-1, :].contiguous()
shift_labels = input_ids[:, 1:].contiguous()

# 4. 展平并计算交叉熵损失
loss = F.cross_entropy(
    shift_logits.view(-1, vocab_size),
    shift_labels.view(-1)
)

print(f"自回归交叉熵损失: {loss.item():.4f}")
```

## 损失度量：交叉熵与困惑度（Perplexity）

预训练通常用**交叉熵损失（Cross-Entropy Loss）**与**困惑度（Perplexity, PPL）**来监控模型的收敛状态。

### 1. 交叉熵损失

词表中只有真实目标词 $y_t$ 的概率为 1，其余候选词均为 0。单个位置的交叉熵损失等价于模型对真实词预测概率的负对数：

$$\mathcal{L}_t = -\log P_\theta(x_t = y_t \mid x_{<t})$$

对整条序列的所有预测位置求平均，即为该样本的平均训练损失 $\bar{\mathcal{L}}$。

### 2. 困惑度（Perplexity）的直观含义

困惑度定义为平均交叉熵损失的指数函数值：

$$\text{PPL} = \exp(\bar{\mathcal{L}}) = \exp\left(-\frac{1}{T-1}\sum_{t=1}^{T-1} \log P_\theta(x_{t+1} \mid x_{\le t})\right)$$

困惑度可以理解为模型在做下一个词预测时，平均面临的不确定候选词数量。

- **训练初期（均匀猜测参考）**：假设词表大小 $V = 32000$。当模型权重随机初始化时，对每个候选词的预测概率趋近于均匀分布 $P = 1/32000$。此时交叉熵损失为 $\ln(32000) \approx 10.37$，困惑度 $\text{PPL} = \exp(10.37) = 32000$。模型相当于在全词表中盲猜。
- **收敛状态**：在大规模语料充分训练后，如果验证集平均交叉熵损失降至 2.0 左右，困惑度 $\text{PPL} = \exp(2.0) \approx 7.39$。这意味着面对下一个位置，模型平均将选择范围收敛在 7 到 8 个合理的词汇候选之间。

**比较前提注意**：困惑度的绝对数值高度依赖分词器（Tokenizer）的词表大小与切词粒度。使用字符级切词（词表很小）与使用子词级切词（词表数万）的模型之间，PPL 无法直接横向对比。只有在相同词表、相同分词方案和相同测试集上，PPL 的高低才能有效反映建模水平差异。

## 模型在预训练中学到了什么：逐层特征抽象

表面上看，自回归任务只是一个接龙游戏，但为了把全语料的预测损失降到最低，多层 Transformer 必须在内部逐层沉淀语言特征：

### 1. 浅层网络：词汇搭配与局部语法
在 Transformer 靠近输入的前数层，注意力头主要聚焦在较窄的局部窗口。模型表征对词性、主谓宾搭配、介词短语边界以及标点符号闭合高度敏感。这一阶段主要解决词法与局部语法的通顺度。

### 2. 中层网络：长程句法与实体消歧
进入网络中层，上下文向量逐渐脱离字面符号。注意力头能够跨越数十乃至数百个 Token 建立依赖：例如将后文的代词（“它”、“他们”）与前文的特定实体对齐；同时根据上下文语境（如周围出现“发布会”还是“果园”）消除多义词（如“苹果”）的语义歧义。

### 3. 深层网络：上下文状态跟踪与语义关联
在靠近输出的高层网络中，为了准确预测关键事实词或代码逻辑符号，模型必须维护上下文中的状态变化。例如在 Python 代码上下文中追踪变量赋值变化；在复杂论述中维持前提与结论的连贯性。高层表示已经沉淀为包含语法、事实与逻辑模式的连续语义空间。

正因为预训练建立了通用的语义表示能力，后续的监督微调（SFT）阶段才能仅使用数万条对话样本，快速教会模型按问答指令格式输出回答。SFT 的机制与微调流程可参考教程：[/fundamentals/training-and-finetuning/sft.md](/fundamentals/training-and-finetuning/sft.md)。

## 预训练的能力边界：统计拟合不等于真值校验

预训练的核心机制决定了它的能力边界。大模型的底座是**语料分布拟合器**，而不是**真理检验器**。

### 1. 缺乏外部真值校验
自监督预训练的损失函数只评估模型预测与语料文本的相似度，它天然假定语料中出现的文本就是学习目标。如果语料库中包含虚假信息、陈旧观念或逻辑错误，模型会如实拟合这些概率分布，模型自身没有独立判定命题真伪的逻辑机制。

### 2. 参数化记忆的弥散性与概率提取
传统数据库通过结构化索引实现确定性查找，而大模型的事实记忆是以微小的权重变化弥散分布在数十亿乃至数千亿参数中的：
- **非确定性提取**：事实的输出受采样策略、温度参数（Temperature）及前文 Prompt 的影响，存在波动；
- **长尾事实衰减**：语料中低频出现的事实，在频繁的高频通用模式反向传播中，梯度更新信号容易被淹没；
- **无法精准局部更新**：无法像执行数据库 `UPDATE` 语句一样单独修改模型内部的一条错误事实，任何权重调整都可能波及其他无关知识。

### 3. 统计共现导致的伪关联
如果预训练语料中两个词频繁偶然共现，自回归目标会让模型建立强烈的先验偏置。当面对对抗性提示或缺乏明确证据的上下文时，这种统计偏置可能压倒上下文逻辑，导致模型输出不符合现实的幻觉内容。为了解决知识时效性与准确性问题，通常需要结合检索增强生成（RAG），具体选型权衡可参见：[/fundamentals/training-and-finetuning/prompt-rag-finetuning.md](/fundamentals/training-and-finetuning/prompt-rag-finetuning.md)。

## 预训练阶段的显存构成

在预训练工程中，显存是核心约束。训练阶段采用 Teacher Forcing 进行全序列并行计算，模型一次性处理整段序列，**不需要维护自回归推理生成阶段的 KV Cache**。训练显存主要由静态状态与动态激活值两部分构成。

以常见的 16 位混合精度训练（FP16/BF16 参数与梯度）配合 AdamW 优化器为例，显存占用拆解如下：

### 1. 模型参数（Parameters）
设模型参数量为 $\Phi$（例如 7B 模型为 $7 \times 10^9$ 个参数）。前向计算使用 16 位浮点数，每个参数占用 2 字节（Bytes）：
$$\text{Memory}_{\text{param}} = 2 \times \Phi \text{ Bytes}$$
对于 7B 模型，参数本身占用约 $14\text{ GB}$ 显存。

### 2. 反向传播梯度（Gradients）
反向传播时，需要存储每个参数对应的偏导数张量，同样以 16 位浮点数存储，每个参数占用 2 字节：
$$\text{Memory}_{\text{grad}} = 2 \times \Phi \text{ Bytes}$$
对于 7B 模型，梯度张量占用约 $14\text{ GB}$ 显存。

### 3. 优化器状态（Optimizer States）
AdamW 优化器需要为每个参数维护高精度的更新状态：
- 1 份高精度主权重副本（FP32，每个参数 4 字节），避免小梯度更新下溢；
- 1 份一阶动量 Momentum（FP32，每个参数 4 字节）；
- 1 份二阶动量 Variance（FP32，每个参数 4 字节）。

因此 AdamW 优化器状态每个参数需占用 $4 + 4 + 4 = 12$ 字节（若实现中保留一份 FP32 梯度缓存，则为 16 字节）：
$$\text{Memory}_{\text{opt}} = 12 \times \Phi \text{ Bytes}$$
对于 7B 模型，仅优化器状态就占用约 $84\text{ GB}$ 显存。

参数（2 字节）、梯度（2 字节）与优化器状态（12 字节）三者合称为**静态显存**，总计每个参数占用约 16 字节。仅静态显存，一个 7B 模型就需要 $112\text{ GB}$，已超出单张 80GB 显卡的显存上限。因此预训练必须使用分布式切分技术（如 ZeRO-3、FSDP），详细切分机制可参阅：[/llm-100/training/zero-deepspeed-fsdp.md](/llm-100/training/zero-deepspeed-fsdp.md)。

### 4. 前向激活值（Activations）
前向激活值是反向传播求导时所需的中间层输出（例如各层的输入张量、注意力权重等），属于**动态显存**。

激活值的大小与批大小（Batch Size）、序列长度 $S$、隐藏层维度 $H$ 以及网络层数 $L$ 成正比。在未使用显存优化算法时，自注意力权重矩阵的存储与序列长度的平方 $S^2$ 成正比。在长上下文预训练时，若不采用激活检查点（Activation Checkpointing）或序列切分，动态激活值极易引发显存溢出（OOM）。

## 总结

预训练通过最大化条件对数似然这一目标，将无标注的文本转换为自监督信号。在工程实现上，依靠 Teacher Forcing 与因果注意力掩码，模型实现了全序列的并行训练。

理解预训练机制有助于建立对大模型能力的合理预期：它通过在深层网络中沉淀特征表征，获得了强大的语言理解与模式泛化能力；但其本质仍是基于语料分布的统计建模，不具备内生的是非校验逻辑与确定性事实存储机制。

在完成预训练后，底座模型主要具备文本续写能力。若要让模型听懂人类的提问并以对话形式规范回答，就需要进入下一阶段：[/fundamentals/training-and-finetuning/sft.md](/fundamentals/training-and-finetuning/sft.md)。
