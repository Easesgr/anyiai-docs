在微调大语言模型时，很多开发者遇到的第一个阻碍不是数据不足，而是显存溢出（Out Of Memory, OOM）。在[《SFT 监督微调是什么？》](/fundamentals/training-and-finetuning/sft.md)中，我们讨论了全参数微调（Full Fine-Tuning）：它在反向传播时需要计算所有参数的梯度，并为每个参数保存优化器状态。当模型规模达到 70 亿（7B）甚至更大时，普通的单张显卡根本无法承担这笔开销。

为了解决显存瓶颈，参数高效微调（PEFT）技术应运而生，其中应用最广泛的是 **LoRA（Low-Rank Adaptation）** 及其量化版本 **QLoRA（Quantized LoRA）**。

本文通过一个贯穿始终的 7B 模型算例，讲清以下问题：
1. 全参数微调的显存究竟花在了哪里？
2. LoRA 如何通过两个小矩阵替代整个大矩阵的更新？
3. QLoRA 如何在 4-bit 量化的基础上进一步压缩显存？
4. 这两种微调方法的适用场景与物理边界是什么？

---

## 一个贯穿例子：为什么 7B 模型全量微调需要超过 110 GB 显存？

大模型训练时的显存占用主要由两大部分构成：**静态显存**（模型参数、梯度、优化器状态）与**动态显存**（前向计算保存的激活值和临时缓冲）。

![大模型微调显存物理开销构成拆解](/images/content-rebuild/ca29bcd1c1be432e/fig-1.png)

我们以一个 **70 亿参数（7B）的语言模型** 为例。假设训练使用常用的 16 位混合精度（BF16 或 FP16），并采用标准 AdamW 优化器：

1. **模型权重（Weights）**：采用 16 位浮点数存储，每个参数占用 2 字节（Bytes）。7B 参数共需要：
   $$7 \times 10^9 \times 2\text{ 字节} = 14\text{ GB}$$
2. **梯度（Gradients）**：反向传播计算的梯度同样以 16 位浮点数存储，每个参数占用 2 字节。7B 参数共需要：
   $$7 \times 10^9 \times 2\text{ 字节} = 14\text{ GB}$$
3. **AdamW 优化器状态（Optimizer States）**：标准 AdamW 需要维护 FP32 精度的模型参数备份以保证数值累加稳定，同时还要跟踪一阶动量（均值）和二阶动量（方差）。这三个量都使用 32 位浮点数（每个 4 字节）存储：
   $$\text{单参数优化器开销} = 4\text{ (FP32参数)} + 4\text{ (一阶动量)} + 4\text{ (二阶动量)} = 12\text{ 字节}$$
   7B 参数在优化器状态上需要消耗：
   $$7 \times 10^9 \times 12\text{ 字节} = 84\text{ GB}$$

把这三项静态显存相加：

$$\text{静态显存总计} = 14\text{ GB (权重)} + 14\text{ GB (梯度)} + 84\text{ GB (优化器)} = 112\text{ GB}$$

这 112 GB 还没有包含输入文本前向计算所保存的激活值（中间特征）。这意味着，哪怕一张显存高达 24 GB 的消费级旗舰显卡（如 RTX 3090 或 RTX 4090），在全参数微调面前也会瞬间因为显存不足而报错。

要让单张显卡能够微调大模型，最有效的途径就是：**不再对原有参数计算梯度，也不再为它们维护优化器状态**。

## LoRA 的机制：低秩矩阵分解

LoRA 的核心思想非常直观：**冻结预训练模型的所有原始参数，在旁边并联一条可以训练的低秩分支**。

在模型微调时，原本的目标是让权重矩阵 $W_0$ 发生变化，变成 $W_0 + \Delta W$。全量微调需要更新整个增量矩阵 $\Delta W$。

LoRA 提出一个假设：虽然预训练模型矩阵的维度很高，但在特定下游任务微调时，权重的实际有效变化量往往集中在一个低维子空间内（即内在秩 Intrinsic Rank 很低）。

因此，LoRA 将大增量矩阵 $\Delta W$ 拆解为两个小矩阵的乘积：

$$\Delta W = B \cdot A$$

假设输入和输出的特征维度均为 $d$（例如 $d = 4096$），原本的矩阵大小为 $4096 \times 4096$，包含约 1678 万个参数。LoRA 引入一个超参数——秩（Rank，记作 $r$），通常取值为 8、16 或 32：
* 矩阵 $A$ 的形状为 $r \times d$；
* 矩阵 $B$ 的形状为 $d \times r$。

当 $r = 16$ 时，$A$ 和 $B$ 的参数量分别为 $16 \times 4096 = 65{,}536$。两个矩阵加起来只有约 13.1 万个参数，仅为原矩阵参数量的 **0.78%**。

![LoRA 前向计算分支与矩阵初始化因果机制](/images/content-rebuild/ca29bcd1c1be432e/fig-2.png)

### 前向传播计算过程

在线性层计算中，输入向量 $x$ 会同时流经两条路径：

$$h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} (B \cdot A) x$$

其中：
* $W_0 x$ 是主干路径。预训练权重 $W_0$ 完全冻结，不计算梯度，也不更新；
* $(B \cdot A) x$ 是低秩旁路。实际计算时，输入 $x$ 先与矩阵 $A$ 相乘（降维到 $r$），再与矩阵 $B$ 相乘（升维回原维度 $d$），最后乘以缩放系数 $\frac{\alpha}{r}$；
* 两条路径的输出直接相加，作为下一层的输入。

### 为什么矩阵 B 必须初始化为 0？

在 LoRA 的实现中，矩阵 $A$ 和 $B$ 的初始化方式至关重要：
* **矩阵 $A$**：采用高斯分布随机初始化；
* **矩阵 $B$**：必须初始化为**全 0 矩阵**。

这是因为在训练刚开始的第一步（Step 0），低秩分支的输出为：

$$\Delta W = B \cdot A = 0 \cdot A = 0$$

此时，模型的总输出完全等于原始底座模型的输出（$h = W_0 x$）。这确保了微调从预训练好的最优状态平滑起步，不会在第一轮前向计算时引入随机噪声，避免破坏模型原有的语言能力。

如果 $A$ 和 $B$ 都初始化为随机值，初始状态就会包含不可控的随机扰动；而如果两个矩阵都初始化为 0，根据链式法则，两者的偏导数都会因乘以对方的全零权重而恒为 0（$\frac{\partial L}{\partial A} \propto B^T = 0$，$\frac{\partial L}{\partial B} \propto A^T = 0$），导致初始梯度为零而无法启动参数更新。

## LoRA 的三个核心配置参数

在配置 LoRA（例如使用 Hugging Face 的 PEFT 库）时，通常需要调整三个核心参数：

![LoRA 核心超参数配置与作用机制映射](/images/content-rebuild/ca29bcd1c1be432e/fig-3.png)

### 1. 秩 `r`（Rank）
$r$ 代表低秩矩阵的中间维度，决定了适配器能够学习的变化容量。对于大多数指令微调和风格对齐任务，$r=8$ 或 $r=16$ 通常已足够；如果是代码生成或需要掌握复杂新规则的任务，可以尝试 $r=32$ 或 $r=64$。增大 $r$ 会增加可训练参数量和显存占用。

### 2. 缩放系数 `lora_alpha`（$\alpha$）
公式中的 $\frac{\alpha}{r}$ 是低秩分支输出的权重缩放常数。设置这个参数的好处在于：**在调整秩 $r$ 时，只要保持 $\frac{\alpha}{r}$ 的比值不变，通常就不需要大幅度修改学习率**。例如，从 $r=8, \alpha=16$（比值为 2）调整到 $r=16, \alpha=32$（比值仍为 2）时，更新量的初始尺度基本保持恒定。

### 3. 目标层 `target_modules`
早期实践中，LoRA 往往只加在自注意力模块的 Query（$W_q$）和 Value（$W_v$）投影层上。然而，后续研究（包括 QLoRA 论文）表明：**将 LoRA 应用于 Transformer 的所有线性层（`all-linear`），在相同参数预算下能够带来更好的适配效果**。

在现代模型架构（如 LLaMA、Qwen）中，`all-linear` 包括：
* 注意力层：$W_q, W_k, W_v, W_o$
* 前馈网络（MLP）：门控投影（`gate_proj`）、上投影（`up_proj`）、下投影（`down_proj`）

## 权重合并：部署时零额外延迟

在很多外挂模块（Adapter）的设计中，旁路分支在推理时必须保留，这会带来额外的算子调度和推理延迟。而 LoRA 在部署时完全没有这个问题。

因为矩阵乘法满足分配律：

$$h = W_0 x + \frac{\alpha}{r} (B \cdot A) x = \left( W_0 + \frac{\alpha}{r} (B \cdot A) \right) x$$

在训练完成后，我们可以直接把训练好的增量矩阵离线加回到原始主权重中：

$$W_{\text{最终}} = W_0 + \frac{\alpha}{r} (B \cdot A)$$

![LoRA 训练态双分支到推理态矩阵权重合并流程](/images/content-rebuild/ca29bcd1c1be432e/fig-4.png)

合并之后，低秩分支被彻底移除，模型的张量结构和原始模型完全一致。在推理服务上线时：
1. **没有额外的推理延迟**：调用的依然是单次矩阵乘法；
2. **存储成本更低**：服务器上只需要存一份通用的底座模型（如 14 GB），针对不同客户或任务，只需分发几十兆字节的 LoRA 权重文件，在加载时直接执行一次矩阵加法即可。

在代码中，使用 Hugging Face 的 `peft` 库只需要调用 `merge_and_unload()`：

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM

# 1. 分别加载基座模型与 LoRA 适配器
base_model = AutoModelForCausalLM.from_pretrained("base_model_path")
lora_model = PeftModel.from_pretrained(base_model, "lora_adapter_path")

# 2. 将低秩权重合并入基座，并卸载适配器旁路
merged_model = lora_model.merge_and_unload()

# 3. 按照标准 Hugging Face 模型格式保存
merged_model.save_pretrained("merged_model_path")
```

## QLoRA：进一步将底座权重压缩到 4-bit

使用标准 LoRA 后，我们不再为 7B 底座计算梯度和优化器状态，但**原始的 14 GB 权重本身仍然必须以 16 位浮点数常驻显存**。如果是 70B 模型，仅底座权重就需要 140 GB 显存。

QLoRA（Quantized LoRA）在 LoRA 的基础上更进一步：**将冻结的底座模型量化到 4-bit，同时保持 LoRA 分支以 16 位浮点数正常训练**。为了避免 4-bit 量化损伤模型表现，QLoRA 提出了三项关键技术：

![QLoRA 三大核心技术架构与数据流图](/images/content-rebuild/ca29bcd1c1be432e/fig-5.png)

### 1. NF4（NormalFloat 4）数据类型
传统的 4-bit 整数均匀量化（INT4）把数值空间切分为 16 个等间距区间。但神经网络在预训练后的权重并不是均匀分布的，而是高度聚集在 0 附近的**正态分布**。均匀划分会导致大量参数挤在中间少数几个格子里，产生较大的精度损失。

NF4 是一种基于标准正态分布分位数构建的 4-bit 数据类型。它根据正态分布的概率密度函数，将 16 个量化点设定在**等概率间隔**的位置。这样每个区间所容纳的权重参数数量大致相当，最大化了有限 4 位空间内的信息保留能力。

在前向计算时，NF4 权重会被即时反量化（Dequantize）回 16 位浮点数进行矩阵乘法，计算完成后立即释放反量化张量，保证计算精度的同时不占用额外常驻显存。

### 2. 双重量化（Double Quantization, DQ）
在分块量化算法中，每隔 64 个参数就需要保存一个浮点缩放系数（Scale）。如果这个系数使用普通的 FP32（32 位）存储，平均摊到每个参数上会增加：

$$\frac{32\text{ 位}}{64} = 0.5\text{ 位/参数}$$

对于 70B 模型，仅存储这些缩放系数就要消耗近 4.4 GB 显存。双重量化的做法是：**对这批缩放系数再做一次 8-bit 量化**（以 256 为分块大小），将额外开销压缩到约 $0.127\text{ 位/参数}$，为大模型省下数吉字节的显存。

### 3. 分页优化器（Paged Optimizers）
大模型训练中的显存崩溃往往发生在**突发峰值**（例如批次中偶然出现一条很长的文本，导致激活值瞬间暴涨）。QLoRA 利用统一内存机制，在显存告急时把闲置的优化器状态页面临时驱逐到系统主机内存（CPU 内存）中，待需要反向传播更新时再拉回显存，有效避免训练因为瞬时显存峰值而意外中断。

## 7B 模型显存开销完整对比

回到最初的 7B 模型算例（设定序列长度 2048、批次大小 1、开启激活重算 Gradient Checkpointing），我们对比三种方式的显存开销构成：

![全量微调、LoRA 与 QLoRA 显存消耗细分堆叠对比](/images/content-rebuild/ca29bcd1c1be432e/fig-6.png)

| 显存开销构成 | 全量微调（Full SFT） | 标准 LoRA（$r=16$, all-linear） | QLoRA（NF4 4-bit, $r=16$） |
| :--- | :--- | :--- | :--- |
| **底座权重常驻** | 14 GB (BF16) | 14 GB (BF16) | **~3.6 GB** (4-bit NF4 + DQ) |
| **可训练参数量** | 7,000 M (100%) | ~40 M (~0.57%) | ~40 M (~0.57%) |
| **可训练参数梯度** | 14 GB (BF16) | **~0.08 GB** (BF16) | **~0.08 GB** (BF16) |
| **AdamW 优化器状态**| 84 GB (FP32 三份) | **~0.48 GB** (FP32) | **~0.48 GB** (FP32) |
| **激活值与临时缓冲** | ~4 - 8 GB | ~4 - 8 GB | ~4 - 8 GB |
| **实测训练所需显存** | **> 115 GB** (需多卡) | **~19 - 23 GB** (单张 24G 显卡可用) | **~8 - 12 GB** (单张 16G 显卡可用) |

### 注意：LoRA 无法压缩激活值显存

对比表格清晰反映出一个工程事实：**LoRA 和 QLoRA 压缩的是参数、梯度和优化器状态这三项“静态显存”，但无法直接压缩前向传播产生的“激活值显存”**。

即使底座模型被冻结，反向传播算法仍需要将梯度从输出层一步步传导回各个并联的低秩分支，因此中间各层的特征图和注意力矩阵必须保留（或重新计算）。如果训练样本的上下文非常长（如 32k 或 128k），激活值显存依然会急剧膨胀。在长文本微调场景中，必须配合**激活重算（Gradient Checkpointing）**和**FlashAttention**技术，以时间换空间，才能保证显存不溢出。

## 适用场景与边界

### 适合选用 LoRA / QLoRA 的情况
1. **特定领域风格迁移与指令格式对齐**：让通用模型学会输出固定格式（如结构化 JSON、医疗病历摘要、客服话术规范）。这些任务主要依赖模型既有的语言理解能力，低秩微调足够调整特征分布。
2. **硬件条件受限的本地训练**：只有单张 24GB 显卡（如 RTX 3090/4090）甚至 16GB 显卡时，QLoRA 是在本地跑通 7B/14B 模型微调的有效途径。
3. **多任务轻量适配系统**：在一个系统中需要支持多个不同业务场景时，可以常驻一个基座模型，按需挂载或切换几兆到几十兆的 LoRA 权重，极大减少服务器部署成本。

### 表现受限或不适用的边界情况
1. **大规模注入全新领域知识（持续预训练）**：如果你需要模型完整吸收一套前所未见的专业词汇和行业知识库，低秩微调提供的容量通常不够，容易出现欠拟合或遗忘原有能力。这类需求更适合在[《预训练到底在学什么？》](/fundamentals/training-and-finetuning/pretraining-deep.md)中讨论的全量或高秩持续预训练。
2. **弥补基础逻辑与推导短板**：如果模型底座本身在复杂逻辑、数学证明上能力薄弱，微调线性层无法凭空产生高维逻辑能力，输出质量仍受限于底座本身的知识边界。
3. **对量化截断极端敏感的计算场景**：虽然 NF4 大幅减小了量化损失，但在超高精度的数值敏感型任务中，4-bit 量化带来的微小截断误差仍可能对输出质量产生细微影响。如果显存充裕，建议优先选用 16-bit 权重的标准 LoRA 或全量微调。

完成模型在指令和任务层面的参数适配后，若要进一步使模型输出符合人类的偏好和安全伦理要求，就需要进入对齐算法的范畴。下一讲我们将深入讨论[《RLHF 和 DPO 有什么区别？》](/fundamentals/training-and-finetuning/rlhf-dpo.md)，解析人类反馈强化学习与直接偏好优化的底层机制差异。
