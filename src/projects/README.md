在掌握了大语言模型的基础调用后，工程落地的关键挑战在于：如何在概率输出的模型与要求确定结果的业务之间搭建稳定运行的系统。本栏目提供 13 个实战项目，覆盖检索增强生成（RAG）、结构化内容提取、状态机工作流与容器化部署四个方向。

我们以一个常见的“电商技术支持助手”为例贯穿全文：
1. 最初它只需要根据用户输入回复固定格式的礼貌问候（单次调用）；
2. 随着业务增加，它需要翻阅数百页的产品手册回答技术规格（RAG 检索）；
3. 接着它需要处理退货与退款，步骤与分支流转必须严格可控，甚至需要人工介入审批（规则编排的状态图工作流）；
4. 最后在遇到系统日志排错时，它需要自己写排查脚本、在沙箱运行并根据报错输出重新调整查询（带反馈的 Agent 循环）。

工程选型的基本原则非常明确：**凡是能用确定性代码与条件分支解决的逻辑，就写成固定代码；只有在分支不可预先枚举、或者必须依赖外部执行环境的报错反馈来调整动作时，才引入 Agent 动态决策。**

### 1. 技术方案分级：从无状态调用到动态反馈循环

随着系统对上下文持久化、工具交互与错误修正要求的提高，应用架构呈现出明显的层次划分：

1. **无状态管道（Single-step Pipeline）**：输入提示词与用户请求，模型执行单次推理并返回内容。系统通过预设的 JSON Schema 校验输出结构，进程不保留多轮运行状态。
2. **检索增强生成（RAG Pipelines）**：通过文档切分、文本嵌入（Embedding）、向量检索与重排序，把私有文档片段作为参考上下文注入提示词，弥补模型通用知识与特定业务资料之间的断层。
3. **状态图工作流（Stateful Workflows）**：按照预设的有向图拓扑编排多个处理步骤。各节点可以是模型调用，也可以是普通 Python 函数。分支流转由代码规则显式判定，支持在关键操作前暂停等待人工确认（Human-in-the-loop）。需要注意，代码控制分支流转不等于整个工作流完全确定，节点内的模型推理、网络请求与外部状态变化仍会带来运行不确定性。
4. **动态反馈循环（Agentic Loops）**：模型根据环境返回的真实执行结果（如沙箱执行报错、SQL 语法错误、第三方 API 状态码），自主决定下一次工具调用的参数与方向。这类系统必须设置严格的最大迭代次数，防止发散失控。

```text
[系统编排复杂度与模型自主权逐步递增]
单次 Prompt 补全 ──> 外部知识检索 (RAG) ──> 规则编排工作流 ──> 动态反馈 Agent 循环
(输出即结束)        (注入参考背景文档)       (代码控制图流转拓扑)       (模型据环境反馈自主决策)
```

### 2. RAG 系列项目：单文件解析、企业级混合检索与面试复盘

检索增强生成系统的核心目标，是在控制检索延迟的同时，尽可能召回与用户问题高度相关的文本片段。根据数据源规模与检索要求，项目群安排了由浅入深的演进路线：

![RAG 技术路线选型矩阵与演进架构](/images/content-rebuild/53e33902a9e74d13/fig-1.png)

*   **单文档解析与结构化提取**：[AI 文档问答系统](/projects/ai-doc-qa.md) 与 [AI 论文阅读助手](/projects/ai-paper-reader.md) 聚焦于单份 PDF 或 Markdown 文档。重点处理表格结构、标题层级识别与基于目录树的切块，避免暴力按固定字符长度截断导致语义破碎。
*   **海量知识库与外网实时搜索**：当文档数量扩展到跨部门资产库时，[AI 知识库系统](/projects/ai-knowledge-base.md) 采用“稠密向量检索 + 稀疏关键词匹配（如 BM25）”的混合检索方式，并经由 Cross-Encoder 重排序（Rerank）提升精排质量；针对时效性要求高的公网信息，[AI 搜索引擎](/projects/ai-search-engine.md) 则整合搜索引擎接口，完成多来源网页内容的抓取、去重与事实摘要。
*   **完整项目设计与面试复盘**：[PrepRAG 智能问答系统](/projects/rag-project-experience.md) 梳理了生产环境下的系统架构，在 [PrepRAG 详细实现文档](/projects/rag-implementation.md) 中展开向量索引构建、降级策略与工程实现细节，并在 [PrepRAG 面试问题准备](/projects/rag-interview-qa.md) 中解析常见系统设计提问与权衡取舍。

### 3. 生成与分析项目：字段约束与长文本阶段化生成

直接要求模型单次输出数千字的长篇内容，容易出现前后事实冲突、论点重复或格式漂移。针对非 RAG 类文本生成，通常采用结构化约束与分阶段生成策略：

*   **Schema 字段校验与自动重试**：[AI 简历优化助手](/projects/ai-resume-assistant.md) 依赖 Pydantic 校验模型返回的 JSON 数据。当输出字段缺失或类型错误时，系统捕获验证异常，将错误提示回传模型并触发有限次重试，确保下游业务模块能够安全解析。
*   **分阶段长文本创作**：[AI 写作助手](/projects/ai-writing-assistant.md) 与 [AI 视频脚本生成器](/projects/ai-video-script.md) 将创作拆解为“先生成大纲结构 $\rightarrow$ 用户确认大纲 $\rightarrow$ 依据分节上下文扩写正文 $\rightarrow$ 规则化校验违禁词与逻辑一致性”的链式流程，降低长上下文下的逻辑断裂概率。

### 4. 状态图工作流与 Agent 项目：预设规则编排与动态执行反馈

当任务涉及多步骤执行、需要调用外部工具或根据环境反馈做修正时，系统进入状态图与 Agent 阶段：

![工作流确定性管道与 Agent 动态自修正循环对比](/images/content-rebuild/53e33902a9e74d13/fig-2.png)

*   **沙箱执行与错误反馈修正**：[AI 编程助手](/projects/ai-coding-assistant.md) 建立了“生成代码 $\rightarrow$ 在独立安全沙箱运行 $\rightarrow$ 获取标准输出与 Traceback 报错 $\rightarrow$ 组装上下文提示词 $\rightarrow$ 重新生成修改版代码”的循环。模型根据真实运行结果调整代码，直到测试通过或达到最大重试次数。
*   **多轮面试状态控制**：[AI 面试助手](/projects/ai-interview-assistant.md) 维护全局会话状态对象，包含当前考察模块、已覆盖考点清单、各轮得分记录。状态流转逻辑由系统代码推进，模型仅负责针对单点内容出题与评价候选人回答。
*   **图状态编排与人工断点**：[AI 自动化工作流](/projects/ai-workflow-automation.md) 借鉴 LangGraph 的状态图设计，把任务拆分为状态节点。在涉及外部数据写操作或权限变更前设置检查断点，等待人工审批通过后再继续驱动后续图节点。

### 5. 生产环境交付规范：流式响应、容器化与链路追踪

将实验环境的脚本改造成可用服务时，需要遵循 [项目部署上线](/projects/project-deployment.md) 中规定的工程规范：

![生产交付流水线与链路可观测监控](/images/content-rebuild/53e33902a9e74d13/fig-3.png)

1. **流式输出标准**：对终端用户暴露的生成接口应当采用 Server-Sent Events（SSE）长连接逐块推送文本，降低用户的首字等待时间（TTFT），避免全量生成耗时过长导致网关连接超时。
2. **容器与安全隔离**：提供标准化 Dockerfile 配置，容器内使用非 root 普通用户运行；模型 API 密钥与数据库凭证禁止打包进镜像层，统一通过部署平台环境变量或凭据中心注入。
3. **链路追踪与度量**：每个入站请求生成唯一的 `X-Trace-Id` 并在下游组件透传，使用 OpenTelemetry 或 LangSmith 记录检索用时、模型首字延迟、完整推理耗时以及输入输出的 Token 用量，便于快速排查性能瓶颈。

### 6. 实战项目清单与验收基准

建议按照“单文档解析 $\rightarrow$ 结构化输出助手 $\rightarrow$ 混合检索系统 $\rightarrow$ 状态图与 Agent $\rightarrow$ 部署上线”的顺序推进。每个项目均须通过以下测试与验收标准：

| 项目类别 | 对应实战项目 | 核心输入与外部依赖 | 验收通过标准 | 失败分支防御措施 |
| :--- | :--- | :--- | :--- | :--- |
| **文档问答** | [AI 文档问答](/projects/ai-doc-qa.md) / [论文阅读](/projects/ai-paper-reader.md) | 单 PDF/Docx 文件、嵌入模型 | 上传 20 页以上包含表格的文档，能够正确定位事实内容，并在回复中注明具体页码引用 | 文件解析超时时返回友好的截断提示；单文档过长时采用分段摘要处理 |
| **检索系统** | [AI 知识库](/projects/ai-knowledge-base.md) / [AI 搜索](/projects/ai-search-engine.md) | 跨域文本切片、Qdrant 向量库、Web Search API | 混合检索能够召回特定专有名词与语义模糊查询；输出末尾附带去重后的参考链接 | 检索无相关结果时返回确定的无匹配提示，禁止模型凭空捏造事实 |
| **生成助手** | [写作助手](/projects/ai-writing-assistant.md) / [视频脚本](/projects/ai-video-script.md) / [简历优化](/projects/ai-resume-assistant.md) | 用户主题输入、参考材料、校验规则 | 输出符合预先定义的 JSON Schema，多阶段长文本分段生成不发生前后设定冲突 | 模型输出格式损坏时，触发轻量格式修正重试；超过重试上限返回错误响应 |
| **智能体** | [编程助手](/projects/ai-coding-assistant.md) / [面试助手](/projects/ai-interview-assistant.md) / [工作流](/projects/ai-workflow-automation.md) | 代码执行沙箱、会话状态存储 | 编程助手能根据语法报错自主完成单轮修正；工作流支持在指定节点暂停并经人工确认后继续运行 | 设定严格的最大迭代次数（如最多 5 轮），避免沙箱执行死循环耗尽资源 |
| **部署上线** | [项目部署上线](/projects/project-deployment.md) | Docker、FastAPI、OpenTelemetry | 容器正常启动并通过健康检查探针；前端流式逐块打印内容；Trace 完整记录分段耗时 | 网关超限时返回 HTTP 429 提示，上游模型接口超时时提供降级文案 |
