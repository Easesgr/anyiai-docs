在面试中被问及“为什么给大模型挂载了 RAG（检索增强生成）之后，它依然会一本正经地胡说八道”时，很多回答容易停留在“模型参数本身具有随机性”这种宽泛推论上。这种解释无法体现候选人对检索与生成完整链条的排查能力。

RAG 改变了输入大模型的上下文内容，但并没有改变语言模型基于条件概率自回归预测下一个词的运算方式。从原始文档切分、索引建库、向量召回，到重排、上下文拼接与模型推理，任何一个环节引入脏数据或逻辑遗漏，最终都会反映为生成答案的事实性错误。

![RAG系统幻觉诱因与分段治理架构全景图](/images/content-rebuild/183f039769539aef/cover.png)

## 1. 核心口述答案：四类成因与分段拦截

面试时建议先给出清晰分类，再以一套实际案例说明：

> **面试口述范例：**
>
> “RAG 能够提供外部事实依据，但无法完全消除幻觉。从工程链路来看，幻觉主要来自四个节点：
>
> 1. **检索缺失**：相关文档因切分切断、语义漂移或索引未命中，根本没有进入候选集，模型缺乏外部事实约束，转而依赖内部参数记忆强行补全。
> 2. **检索噪声**：召回了文本字面或主题相近、但事实结论完全相反或无关的片段（例如否定句或旧规定），干扰了解码时的注意力分配。
> 3. **推理失真**：必要片段虽然都在上下文中，但受限于长文本位置偏置、多跳因果跨度过大或算术能力不足，模型从正确的事实中推导出了错误结论。
> 4. **上下文冲突**：知识库召回了同一业务在不同版本或不同制度下的冲突切片，模型在缺乏版本元数据仲裁时出现自相矛盾或胡乱折中。
>
> 治理上不能单靠修改提示词，应配合检索阶段的相似度与相关性门禁、Prompt 中的抽取式事实定位约束，以及生成后的轻量级事实一致性校验共同防范。”

为了清晰展示这四类问题是如何发生的，我们以企业知识库中的一个具体问答贯穿全文：
- **用户提问**：“实习生出差是否可以报销高铁一等座？”
- **真实业务事实**：“依据《2024年差旅管理办法》第三条，实习生原则上乘坐二等座；若因紧急业务且经总监审批，可报销一等座；未经审批的一律按二等座标准自理差价。”

## 2. 检索缺失型：依据未召回导致参数记忆补全

当系统没有把能回答问题的文档切片召回给大模型时，传给模型的上下文实际上对该问题是无效的。

![检索缺失导致大模型调用内部参数先验补全的机制图](/images/content-rebuild/183f039769539aef/fig-1.png)

### 诱因与发生过程
语言模型在生成第 $t$ 个词时，依赖前面所有词和给入上下文的条件概率：
$$P(y_t \mid y_{<t}, X_{\text{prompt}}, C_{\text{retrieved}})$$

如果检索返回的内容 $C_{\text{retrieved}}$ 缺少解题事实，提示词在语义上就失去了具体业务边界的约束。大模型在微调训练时通常被训练为“尽量回答提问”，于是在缺乏外部文档锚点时，自回归解码过程就会受模型参数内部存储的通用预训练知识主导。

**贯穿案例表现**：
知识库切片时把“实习生出差政策”切碎在两个不同段落（参见 [文档切分为什么重要？](/interview/rag-interview/chunk-strategy.md)），或者用户提问使用了缩写导致向量检索断流（参见 [Query Rewrite 是什么？](/interview/rag-interview/query-rewrite.md)）。检索器最终返回了两段毫不相干的“办公用品领用制度”。大模型接收到无关上下文后，只能依赖内部常识推测回答：“一般情况下，差旅一等座仅限中高层管理人员报销，实习生不可报销。”——虽然看起来符合一般常识，但直接违背了企业具体的“总监审批可报销”政策。

### 针对性治理
- **相似度截断**：设置合理的召回阈值（参见 [RAG 检索时相似度阈值如何设置？](/interview/rag-interview/rag-similarity-threshold.md)）。若 Top-1 片段的分数明显低于业务经验安全线，判定为检索未命中。
- **程序级拒答门禁**：在调用大模型前直接拦截低置信度结果，返回预置模板（如：“未在知识库中找到关于实习生报销高铁一等座的具体政策，请咨询 HR 服务台”），阻止模型基于泛化参数自由发挥。

## 3. 检索噪声型：高相似度反义或无关切片的误导

有时系统虽然返回了文档，但召回的内容却具有误导性。向量检索主要评估词句在嵌入表示空间的语义聚合程度，并不天然具备严格的布尔命题校验能力。

![高向量相似度语义噪声与反义混淆示意图](/images/content-rebuild/183f039769539aef/fig-2.png)

### 为什么容易召回“反义”切片？
稠密嵌入模型（Dense Embedding）倾向于将话题一致、词汇分布高度重叠的文本投射在相近的向量位置。考虑以下两个切片：
- 切片 A：“按照最新规定，实习生因公出差**经审批可**报销一等座。”
- 切片 B：“按照往年惯例，实习生因公出差**一律不可**报销一等座。”

切片 A 与切片 B 共享了“按照”、“规定/惯例”、“实习生”、“因公出差”、“报销一等座”等核心词汇和语法结构。在通用稠密向量模型下，两者的余弦相似度可能很高。如果知识库中同时存在这两份内容，相似度评分可能无法拉开两者的差距，甚至可能把旧的、否定的切片排在前面。

### 注意力被噪声切片分散
当切片 B 被注入上下文，自注意力机制在计算 Token 间关联时，切片 B 中的否定表述会直接影响下一词的采样概率分布。即便模型看到了切片 A，若噪声切片在提示词中占据了靠前或显眼的位置，模型仍可能倾向于采纳切片 B 的说法，得出“一律不能报销”的错误判定。

### 针对性治理
1. **引入稀疏与稠密混合检索**：将精确匹配关键词（如 BM25）与向量检索结合，强化专有词、限定代词与否定形态的区分（参见 [为什么 RAG 中常用 BM25 + 向量检索的混合召回？](/interview/rag-interview/hybrid-retrieval.md)）。
2. **交叉编码重排（Cross-Encoder Rerank）**：在初筛后使用全交叉注意力的重排模型对候选片段逐一精算，剔除与提问看似相关但答非所问的切片（参见 [Rerank 在 RAG 中解决什么问题？](/interview/rag-interview/rerank.md)）。

## 4. 模型推理失真型：长文本衰减与逻辑断裂

在很多失败案例中，检索系统其实已经把所需切片完整召回，但最终模型输出依然是错的。这类问题出在模型的理解、推理与计算环节。

![上下文过长导致的注意力衰减与推理失真示意图](/images/content-rebuild/183f039769539aef/fig-3.png)

### 常见推理失效模式

1. **位置效应（首尾偏置与中间衰减）**：
   实证研究表明，在长上下文中，模型往往更容易关注靠近提示词开头和结尾的文档（常被称为 Lost in the Middle 现象）。这一现象受预训练语料结构偏置、位置编码衰减特性以及指令对齐习惯的综合影响。如果承载核心豁免条件的片段被夹在十几份无关资料正中间，模型在解码时可能漏掉该条件。
2. **多跳逻辑与条件限定遗漏**：
   如果政策拆分为两段：切片 1 说明“特殊情况可申请一等座，审批流见附件”，切片 2 说明“附件：实习生跨城通勤属于特殊情况”。模型需要将切片 2 的结论代入切片 1 才能给出正确答案，但面对多层推导时，自回归生成容易在第一跳匹配到“原则二等座”后提前下结论。
3. **代数与数量推理失误**：
   当提问涉及报销金额计算（例如“实习生票价 450 元，二等座基准价 300 元，按自理差价规则需扣减多少元？”）时，语言模型输出数字本质是基于语言规律的条件概率生成，并非确定性符号计算，极易在数字运算上得出荒谬答案。

### 针对性治理
- **精简上下文篇幅**：控制送入生成模型的切片数量，不要盲目扩大 $K$ 值，优先给模型提供信息密度高、剔除废话的精简内容。
- **结构化重组**：通过重排把最核心切片置于提示词开头或临近提问的位置，减少重要信息因深埋在长文本中被忽略的概率。

## 5. 上下文冲突型：版本混乱与模型折中

在实际企业知识库中，通常会混杂同一业务在不同阶段的文件。例如未标明作废的旧草案、各部门自编的细则以及正式发布版。

![多文档版本冲突与大模型决策混乱表现示意图](/images/content-rebuild/183f039769539aef/fig-4.png)

### 发生冲突时模型的常见输出行为
当检索同时召回包含事实冲突的切片（如切片 1 标注“经总监审批可报销”，切片 2 标注“必须副总裁审批”，切片 3 标注“任何情况均不可报销”）时，大模型在没有仲裁依据的情况下通常表现为三种模式：

| 失效模式 | 具体表现 | 业务影响 |
| :--- | :--- | :--- |
| **无序采信** | 随机采纳排在最前面或最后的切片 | 答案受检索排序轻微变动而剧烈抖动 |
| **捏造折中** | 自行捏造中间状态（如生成“经总监及副总裁共同审批后可报销”） | 凭空生造未曾存在的审批规则 |
| **内部打架** | 前半句写“实习生不可报销”，后半句写“但在总监审批下可以” | 逻辑前后矛盾，破坏用户信任 |

### 针对性治理
- **元数据时效性注入与过滤**：在切片存入向量库时携带文档有效时间、发布版本与权威层级字段，在检索阶段通过元数据前置过滤淘汰废止文档（参见 [RAG 系统如何利用元数据过滤提升检索精度？](/interview/rag-interview/rag-metadata-filtering.md)）。
- **显式仲裁规则**：在提示词中明确规定冲突处理逻辑：“当多份资料表述不一致时，必须以元数据中发布时间最新的规章为准；若无法判定，须如实指出存在政策冲突，严禁自行折中拼接。”

## 6. 工程治理落地：三层防御流水线

防范 RAG 幻觉不能寄希望于把提示词写得天花乱坠，更可靠的工程方案是构建“前置门禁 - 过程约束 - 后验校验”的三层防御。

![端到端三层降幻觉工程流水线图](/images/content-rebuild/183f039769539aef/fig-5.png)

### 1. 前置门禁：检索质量阈值与拒答
通过程序设定检查点，在进入生成环节前拦截低质量召回：
- **重排绝对分值过滤**：Cross-Encoder 重排给出的相关性分值若低于设定的业务阈值，判定为证据不足；
- **核心实体覆盖度检测**：提取提问中的关键实体（如“实习生”、“高铁一等座”），若检索结果中完全不包含这些词汇，直接切断下游调用，触发降级回复。

### 2. 过程约束：抽取式两阶段生成（Extract-then-Answer）
在编写生成 Prompt 时（参见 [RAG 中如何设计 Prompt 来有效利用检索到的文档？](/interview/rag-interview/rag-prompt-design.md)），禁止模型开门见山直接总结，要求其先列出引用的原文句子：

```text
你是一个严格依据参考资料解答业务问题的助手。
请严格遵循以下三步生成回答：
第一步（原文摘录）：在参考文档中找出支持你结论的连续文字，逐字摘录出来，并标明所在文档序号。
第二步（推理陈述）：根据摘录内容说明推导逻辑。
第三步（明确结论）：用一句话总结最终结论。

硬性约束：如果参考文档中没有任何一句话能够支持得出结论，请直接输出“现有参考文档不足以回答该问题”，严禁使用你以往学到的知识进行推断或补充。
```
让模型在生成结论前先解码事实原文，可以使后续预测以更强的事实上下文作为前置条件，抑制自由发散。

### 3. 后验校验：基于 NLI 的事实蕴含判定
在答案输出给用户前，可挂载一个轻量级的自然语言推理（NLI）校验模块，检验生成的每一条陈述是否能被上下文逻辑蕴含。

```python
# 伪代码示意（Pseudocode），展示事实一致性校验逻辑
def verify_groundedness(context: str, generated_answer: str, nli_model) -> bool:
    """
    将 Context 作为前提（Premise），将模型回答按句子切分为独立陈述（Hypotheses）。
    校验每一句陈述是否能被 Context 蕴含。
    """
    # 1. 切分答案为独立命题句子
    claims = split_into_atomic_sentences(generated_answer)
    if not claims:
        return False

    # 2. 逐句进行自然语言推理判定
    for claim in claims:
        # 模型输出通常为三分类概率或标签：ENTAILMENT（蕴含）、NEUTRAL（未提及）、CONTRADICTION（矛盾）
        label = nli_model.predict(premise=context, hypothesis=claim)
        
        # 只要存在无依据的陈述或矛盾陈述，即视作未通过事实校验
        if label in ["NEUTRAL", "CONTRADICTION"]:
            return False
            
    return True
```
当校验失败时，系统可自动转入兜底回复，或将该请求送入人工复核流。

## 7. 面试追问与常见认知误区

### 追问 1：召回率（Recall）从 70% 提升到 90%，最终生成的幻觉率一定会成比例下降吗？
**答题口径**：
不会成比例下降，两者并不满足线性关系。

![检索召回率与端到端系统准确率的非线性关系图](/images/content-rebuild/183f039769539aef/fig-6.png)

提升检索召回率，通常需要扩大召回数量 $K$ 或放宽匹配条件。这虽然降低了“检索缺失”的概率，但也显著增大了引入语义噪声切片、版本冲突切片的机会。同时，注入模型的上下文变长后，又会受到长文本位置偏置的影响，生成模型的推理失真率反而可能上升。因此，端到端的事实准确率取决于检索质量、重排去噪与模型理解约束的综合平衡。

### 追问 2：为什么在 Prompt 里写“严格遵循上下文、严禁胡编乱造”，依然经常管不住幻觉？
**答题口径**：
因为自然语言提示词属于软约束。大模型解码的物理机制依然是基于前文计算下一个 Token 的概率分布并进行采样。当上下文信息存在逻辑跳跃，或者问题里的词汇与模型内部某些强预训练先验高度共现时，Softmax 输出在候选词上的概率差往往不足以让模型完全避开错误选项。单纯的负向提示（如“不要捏造”）在注意力层面上甚至可能强化该实体的权重。要压制幻觉，不能单靠自然语言提示，必须结合程序级门禁截断、原文前置引用约束以及结果后验校验等多层工程防御手段。

### 常见误区澄清

| 常见错误说法 | 真实底层机制 | 修正口径 |
| :--- | :--- | :--- |
| “上了 RAG 就彻底没有幻觉了” | RAG 仅补充外部上下文输入，不能改变自回归采样的随机性本质与多跳推理缺陷 | RAG 缓解了知识盲区，但带来了噪声干扰、证据冲突等新维度的失真风险 |
| “把所有召回的切片全塞给模型，信息越多越不容易错” | 上下文长度增加会引发长文本注意力分散，且噪声和冲突片段比例上升 | 必须控制上下文规模，以信息密度和相关性为核心进行重排与去重 |
| “只要模型参数足够大，推理就不会出错” | 更大参数的模型确实具备更好的逻辑推导能力，但其内部参数化先验往往也更顽固，在上下文不明确时更容易反客为主 | 依靠单体参数规模无法根除幻觉，仍需工程管线各阶段进行防御与校验 |
