在企业知识库问答中，生成内容的溯源能力直接决定了答案是否可信。如果模型回答没有标注出处，或者引用的标号指向了无关段落，用户很难核实答案的真伪。面试中考察这一问题，核心在于评估候选人是否理解：**精准引用不是简单让大模型在句末打上 `[1]`，而是一条由切片元数据、提示词约束、服务端后置校验和前端定位渲染共同组成的技术链路**。

![信息来源标注与精准引用端到端全景](/images/content-rebuild/a4d339e7ac3eeda7/cover.png)

## 1. 面试口述答案

面试时被问及“RAG系统如何标注来源并生成精准引用”，可以按照以下四个步骤口述：

> **口述核心要点**：
> 精准引用不能只靠大模型的自觉输出，而是贯穿四个阶段的协同流程：
>
> 1. **注入阶段（元数据装配）**：对于支持版面解析的文档（如 PDF），切片时需保留物理页码和文字矩形坐标（Bounding Box）；纯文本或网页场景则保留对应 URI 与文本锚点。组装提示词时，将切片包裹在带有局部序号的标签中（如 `<doc id="1">`），把长文档标识符映射为易于模型理解的紧凑数字编号。
> 2. **生成阶段（断言级约束）**：通过提示词或结构化输出（JSON / 工具调用），强制模型以“单句事实断言”为单位写作，在每个断言句末紧跟来源编号（如 `[1]`），严禁在整段回答结尾笼统堆砌多个编号。
> 3. **校验阶段（后置核验）**：模型生成的引用存在幻觉风险。服务端先做标号越界与关键实体匹配过滤，再用轻量级自然语言推理（NLI）交叉编码器，判断生成句子与对应切片是否构成逻辑蕴含关系，剔除没有证据支撑的伪引用。
> 4. **展现阶段（前端联动）**：后端将回答文本与引用的切片元数据（文档ID、页码、坐标框）一同下发。前端识别 `[1]` 转换为交互锚点，用户点击后自动分屏跳转到原始文档并高亮对应段落。
>
> 质量评测主要看两个指标：**引用精确率**（标了引用的句子中，真实有证据支撑的比例）和**引用召回率**（回答中包含的所有客观事实中，正确标注了引用的比例）。

## 2. 贯穿示例：从切片元数据到上下文组装

为了看清整条链路中数据的流转过程，我们以两篇实际技术文档的问答作为贯穿示例。

### 2.1 切片保留的元数据格式

在解析 PDF 或富文本时，解析器除了提取文本，还必须提取版面物理位置。切片对象存储在向量库或关系库中时，通常包含如下结构：

```json
{
  "chunk_id": "chunk_dc_p14_01",
  "doc_id": "doc_green_datacenter_2024",
  "file_name": "数据中心节能改造白皮书.pdf",
  "page_idx": 14,
  "bbox": [120.5, 340.2, 480.0, 356.8],
  "text": "高压直流供电（HVDC）技术相比传统离线式 UPS，能够减少一次交直流变换，综合电能利用效率可提升约 2% 至 3%。"
}
```

如果省略了 `page_idx` 和 `bbox`，后续前端就只能展示粗糙的纯文本切片，无法在 PDF 原文上自动定位和高亮。

### 2.2 上下文注入时的编号重映射

实际检索出的切片，其全局唯一标识通常是较长的哈希字符串或主键 ID。直接把这类长字符串作为标号拼入提示词，会增加模型的理解负担，容易引起生成错乱。标准做法是在构建上下文时，用临时的递增局部索引（1, 2, 3...）替代，同时在服务端保留映射字典：

```text
参考知识库内容如下：
<documents>
  <doc id="1" title="数据中心节能改造白皮书.pdf" page="14">
    高压直流供电（HVDC）技术相比传统离线式 UPS，能够减少一次交直流变换，综合电能利用效率可提升约 2% 至 3%。
  </doc>
  <doc id="2" title="2024冷链温控标准.pdf" page="5">
    医药冷链仓库蓄冷系统在谷电时段需连续充冷不少于 6 小时。
  </doc>
</documents>
```

映射字典：`{1: "chunk_dc_p14_01", 2: "chunk_cold_p5_03"}`。

## 3. 生成阶段的提示词约束与输出格式

如果不加约束，大模型通常倾向于在整段文字末尾集中写上 `[1][2]`。这种粗粒度标注无法确定哪一句话来自哪份材料，不利于严格核验。

![行内细粒度断言约束机制](/images/content-rebuild/a4d339e7ac3eeda7/fig-2.png)

### 3.1 行内断言约束提示词设计

为了实现断言级引用，需要明确告诉模型将大段推理拆解为单句事实，并在对应的事实句后紧跟标号：

```text
你是一个严谨的事实问答助手。请根据提供的 <documents> 回答问题，并遵守以下要求：
1. 细粒度行内引用：在每一个独立事实断言后紧跟引用标号，格式必须为 [编号]，例如："HVDC 技术可提升电能利用效率 [1]。"
2. 依据事实：回答必须严格基于提供的文档内容。如果提供的文档无法支持某个推论，不要自行脑补，也不要添加不存在的编号。
3. 禁止整段末尾堆砌：不得在整段文字末尾集中列出一串标号；多项事实来自不同切片时，应分别标注在对应单句之后。
4. 编号必须存在：引用的标号必须对应 <documents> 标签中的 id 属性，禁止虚构其他数字。
```

### 3.2 Markdown 文本标号与结构化 JSON 的取舍

实际工程中有两种主流输出协议：

1. **Markdown 行内标号（如 `...提升 2% 至 3% [1]。`）**：
   - **优势**：兼容流式输出（Streaming），首字延迟低，文字能像打字机一样直接推送到前端聊天窗口。
   - **劣势**：需要服务端在流式处理时维护简单的字符缓冲区，识别被网络分包切断的标号（例如 `[` 和 `1]` 分开推送）。
2. **结构化输出（JSON Schema / 工具调用）**：
   - **优势**：字段天然解耦，语句（`statement`）与来源数组（`citations`）分离，程序解析极稳定。
   - **劣势**：大模型需要先输出外层语法结构，前端若无流式 JSON 解析器则需等待字段完整闭合才能渲染，导致用户感知到的有效文本首字上屏时间更长，且包裹语法消耗的额外 Token 略多。

对于面向终端用户的对话场景，通常选用带行内标号的 Markdown 文本；对于自动化合规审查流水线，优先选用 JSON 结构化输出。

## 4. 后置校验（Post-verification）：拦截模型虚假引用

自回归语言模型生成带有 `[1]` 的句子时，并不代表该句子与切片 1 存在真实的因果证据关系。模型可能会凭借自身的预训练记忆生成一段话，顺手附上一个看起来相关的数字，产生引用幻觉。

为了保证系统可靠性，服务端在收到生成结果后，需要使用程序或轻量模型执行二次核验。

![后置自然语言推理 NLI 校验流程](/images/content-rebuild/a4d339e7ac3eeda7/fig-3.png)

### 4.1 两级校验策略

为了平衡计算延迟与识别准确率，推荐采用两级校验：

1. **一级规则快筛（CPU 级，耗时 < 1ms）**：
   - **标号越界检查**：检查标号是否在注入的上下文范围之内（如最大只有切片 2，生成了 `[3]` 即为非法）。
   - **数值与实体覆盖率检查**：检查生成句中的具体数值（如百分比、金额、日期）是否在被引用的切片中完整存在。如果生成句出现“提升 5%”，而切片中只有“2% 至 3%”，判定为引用失效。
2. **二级自然语言推理（NLI 蕴含判定）**：
   - 使用体积较小、运行迅速的交叉编码器模型（Cross-Encoder，如 `deberta-v3-base-nli` 或针对 NLI 微调的小参数模型）。
   - 输入拼接：`前提（Premise）: {切片文本}`，`假设（Hypothesis）: {生成单句}`。
   - 模型输出三种分类的概率：蕴含（Entailment）、中立（Neutral）、矛盾（Contradiction）。
   - 当 $P(\text{Entailment})$ 高于设定阈值（例如 0.70）时，保留该标号；否则判定该切片无法完全支撑该推论，降级剔除标号或打上存疑标记。

### 4.2 规则与实体核验示例代码

以下 Python 示例演示了一级规则核验的逻辑：

```python
import re
from typing import List, Dict, Tuple

def extract_citations(text: str) -> List[Tuple[str, List[int]]]:
    """
    将 Markdown 文本按句号等标点拆分为 (单句断言, 引用标号列表)
    例如: 'HVDC 提升能效 [1]。充冷需 6 小时 [2]。' 
    """
    # 匹配中文或英文句末标点
    raw_sentences = re.split(r'(?<=[。！？!?])\s*', text)
    results = []
    for sent in raw_sentences:
        sent = sent.strip()
        if not sent:
            continue
        # 提取当前句子中的所有 [数字] 标号
        citations = [int(m) for m in re.findall(r'\[(\d+)\]', sent)]
        # 清理掉标号保留纯文本断言
        clean_statement = re.sub(r'\[\d+\]', '', sent).strip()
        results.append((clean_statement, citations))
    return results

def post_verify_citations(context_map: Dict[int, str], parsed_sentences: List[Tuple[str, List[int]]]):
    """
    核验标号越界与数值一致性
    """
    verified_output = []
    for statement, c_ids in parsed_sentences:
        valid_c_ids = []
        for cid in c_ids:
            # 1. 越界检查
            if cid not in context_map:
                continue
            chunk_text = context_map[cid]
            
            # 2. 数值检查：提取断言中的所有数字与百分比
            nums_in_stmt = set(re.findall(r'\d+(?:\.\d+)?%?', statement))
            nums_in_chunk = set(re.findall(r'\d+(?:\.\d+)?%?', chunk_text))
            
            # 如果句子包含了切片中从未出现过的数值，视为潜在幻觉，予以拦截
            if nums_in_stmt and not nums_in_stmt.issubset(nums_in_chunk):
                continue
                
            valid_c_ids.append(cid)
        verified_output.append({"statement": statement, "citations": valid_c_ids})
    return verified_output

# 验证示例
context_data = {
    1: "高压直流供电（HVDC）技术综合电能利用效率可提升约 2% 至 3%。",
    2: "医药冷链仓库蓄冷系统在谷电时段需连续充冷不少于 6 小时。"
}

# 模型生成了两个句子，第二句中的数值 12 小时并未出现在切片 2 中
llm_response = "HVDC 技术可提升电能利用效率 2% 至 3% [1]。蓄冷系统需连续充冷 12 小时 [2]。"

parsed = extract_citations(llm_response)
verified = post_verify_citations(context_data, parsed)
print(verified)
# 输出结果中：第一句验证通过保留 [1]；第二句因数值不匹配，[2] 被过滤
```

## 5. 前端交互与文档定位数据链路

经过校验后，后端返回给前端的数据包必须同时包含清洗后的答案与切片的坐标映射表。

![引用跳转与文档定位数据流全链路](/images/content-rebuild/a4d339e7ac3eeda7/fig-4.png)

### 5.1 数据 Payload 规范

后端向前端下发的标准响应体结构如下：

```json
{
  "answer": "高压直流供电（HVDC）技术能够提升效率 2% 至 3% [1]。",
  "citations": {
    "1": {
      "doc_id": "doc_green_datacenter_2024",
      "file_name": "数据中心节能改造白皮书.pdf",
      "page": 14,
      "snippet": "高压直流供电（HVDC）技术相比传统离线式 UPS...综合电能利用效率可提升约 2% 至 3%。",
      "bbox": [120.5, 340.2, 480.0, 356.8]
    }
  }
}
```

### 5.2 前端渲染与跳转过程

前端通过自定义 Markdown 渲染插件，将文本中的 `[1]` 替换为带有样式的可点击徽标（Badge）：
1. **悬停预览**：鼠标悬停在 `[1]` 上时，弹出浮层显示 `file_name` 和 `snippet` 内容，用户无需打开文件即可快速确认来源。
2. **点击深跳转**：用户点击 `[1]` 时，系统右侧唤起 PDF 查看器（如基于 PDF.js），自动跳至第 14 页，并在 Canvas 上根据 `bbox` 坐标（左、上、右、下位置）绘制半透明黄色高亮矩形。

## 6. 面试高频追问与工程边界

![模型引用幻觉模式与防御对比](/images/content-rebuild/a4d339e7ac3eeda7/fig-5.png)

### 追问 1：大模型在打标时，常见的“引用幻觉”有哪些模式？

在评估引用质量时，常见的引用错误主要分为四类：
- **张冠李戴（Attribution Mismatch）**：生成的句子本身没有事实错误，但引用的标号却指向了无关的切片。模型在注意力计算时错把其他上下文的实体归因到了当前段落。
- **凭空捏造（Phantom Citation）**：生成的内容来自大模型本身的预训练参数记忆，提供的参考切片中根本没有这个结论，但为了满足提示词要求，强行附带了一个存在的切片编号。
- **过度推断（Over-extrapolation）**：切片中只提到“该技术在特定试验台展现出能效改善趋势”，模型却生成“该技术已能彻底降低所有机房成本 [1]”。证据确实存在，但推断强度超出支持范围。
- **标号滥用（Citation Stuffing）**：模型在句子后面连续写上 `[1][2][3][4]`，把大量没有逻辑关联的切片编号拼在一起，试图以此应对打标约束。

### 追问 2：如果使用流式传输（Streaming SSE），后置校验如何不拖慢首字延迟？

如果等到模型整篇回答生成完毕并完成 NLI 校验后再返回，流式输出的即时响应优势就会丧失。工程中主要有两种权衡方案：
- **方案 A（前端乐观渲染 + 异步修剪）**：后端正常将生成的文字流式推送给前端，前端遇到 `[1]` 时先渲染为灰色“待核验”状态。后端侧线程并行缓冲句子，完成规则或 NLI 校验后，在 SSE 流末尾推送校验结果事件。前端收到后，将有效标号高亮点亮，将无效标号静默剔除。
- **方案 B（双通道分句校验）**：文本主通道继续以极低延迟打字；当后端检测到句号生成时，将该完整句子异步分发给轻量校验模块，校验完成后单独推送对应的锚点元数据。虽然锚点可点击状态比文字出现略微慢 100~300ms，但保证了阅读的连贯性。

### 追问 3：文档切片（Chunk）大小对引用精度有什么影响？如何折中？

切片颗粒度是影响引用体验的核心参数：
- **切片过大（如单片 1500 tokens）**：切片内包含过多与问题无关的信息。模型就算标注对了标号，前端跳转时高亮整整一两页文字，用户依然找不到具体依据在哪句话；大切片中的无关信息也会干扰模型注意力，增加归因错误。
- **切片过小（如单片 50 tokens）**：单句话可能破坏了段落因果上下文，模型难以综合理解；同时，一个结论可能分散在两个小切片中，模型被迫引用 `[1][2]`，造成检索召回断裂。
- **典型解法（父子切片索引 Parent Document Retriever）**：索引库中保存 150~200 tokens 的子切片，用于精确的向量检索和前端 Bounding Box 绘制；但在喂给大模型组装上下文时，根据子切片向上检索出其所属的 600~800 tokens 父段落。这样既兼顾了大模型的上下文理解完整度，又保留了前端高亮定位的高精度。

![长上下文与小切片索引的精准引用权衡](/images/content-rebuild/a4d339e7ac3eeda7/fig-6.png)

### 常见错误认识

- **错误说法**：“提示词里加上‘必须根据参考文档生成并标注编号’，大模型就能百分之百杜绝引用错误。”
  - **实际情况**：自回归生成机制决定了模型生成下一个 Token 时只依赖条件概率分布，没有确定性的事实一致性保障。提示词只能降低引用幻觉的概率，服务端的后置规则与模型核验是生产系统的兜底手段。
- **错误说法**：“做引用标注只要在答案最后附上搜索出的文件名就可以了。”
  - **实际情况**：这只是粗粒度的参考来源展示，无法证明答案中的具体断言到底来自哪一页、哪一段。对于合规审计与可追溯性要求较高的业务场景，通常建议推进到断言级的精准行内对齐，以便人工逐条复核与责任追溯。
