在检索增强生成（RAG）系统中，检索模块决定了输入给大语言模型的参考上下文质量。工程实践中常有一种误解，认为“向量检索比传统关键词检索更先进，可以直接替代后者”。但在真实业务场景中，单一检索方式往往存在明显的盲区：向量检索可能在精确型号上漏检，而关键词检索则容易受困于同义表达。

理解稠密向量检索（Dense Retrieval）、稀疏关键词检索（以 BM25 为代表的 Sparse Retrieval）与混合检索（Hybrid Retrieval）的工作机制与边界，是构建稳定检索链路的基本功。

---

## 1. 口述答案：三分钟技术选型陈述

在面试中遇到“向量检索、关键词检索与混合检索有什么区别？如何选型？”时，建议按照“定义特征 + 优势场景 + 失效盲区 + 选型建议”的结构作答：

> **面试口述要点：**
>
> 1. **稠密向量检索（Dense Retrieval）**：利用文本嵌入模型（Embedding）将查询与文档映射为低维连续浮点向量（常见维度如 768、1024），使用余弦相似度或内积衡量语义距离。**优势**是语义泛化能力强，能处理同义替换、口语化表达和跨语言检索；**局限**是对专有名词、错误码、版本号等离散符号不敏感，且索引构建和向量计算开销相对较高。
> 2. **稀疏关键词检索（Sparse Retrieval，如 BM25）**：基于倒排索引和词频统计，使用词频（TF）和逆文档频率（IDF）对文档打分并做长度归一化。**优势**是字面匹配精确度高、可解释性强、计算资源开销小、无需模型微调冷启动；**局限**是存在“词汇鸿沟（Vocabulary Mismatch）”，当用户查询与文档没有重合词时，往往完全无法召回。
> 3. **混合检索（Hybrid Retrieval）**：采用“双路并行召回 + 排序融合”架构，同时运行关键词检索与向量检索，各自获取候选集后，通过倒数排名融合（RRF）或打分归一化进行综合排序。**选型建议**：对于既包含专业实体又存在口语化表述的知识问答系统，混合检索是兼顾查全率与查准率的常见基线方案。

## 2. 贯穿场景：IT 运维知识库的检索挑战

为了清晰理解三者的差异，我们设定一个具体的业务场景：**IT 运维排障知识库**。

知识库中收录了两类典型文档：
* **文档 1（强实体配置与错误码）**：“当服务出现告警代码 `ERR-404-XYZ` 时，应进入配置中心修改 `pool_timeout` 参数至 30 秒。”
* **文档 2（口语化日常排障）**：“移动终端电池无法补充电量且机身发热时的硬件检测指导规范。”

当用户发起不同类型的查询时，单一检索机制会暴露出截然不同的问题。

## 3. 稠密向量检索（Dense）：连续空间里的语义泛化

关于文本向量化的基础机制，可参考 [Embedding 在 RAG 中的作用](/interview/rag-interview/embedding-in-rag.md)。稠密向量检索通常依赖双塔（Bi-Encoder）模型，分别将查询（Query）和文档（Document）映射到同一多维连续空间中。

### 3.1 相似度度量与语义聚类

在向量空间中，两段文本的相关性通常使用向量点积或余弦相似度计算：

$$\text{Cosine Similarity}(q, d) = \frac{\mathbf{v}_q \cdot \mathbf{v}_d}{\|\mathbf{v}_q\| \|\mathbf{v}_d\|}$$

嵌入模型在预训练与微调阶段学习了大量的上下文语义关联。即使 Query 与 Document 没有出现相同的词汇，只要表达的意图相近，它们在向量空间中的位置也会相对靠近：

* **意图匹配**：输入“退烧方法”，能较好地匹配到包含“发热物理降温指南”的文档。
* **多语言泛化**：输入英文“heart attack symptoms”，能关联到中文“心肌梗死的早期征兆”。

![稠密向量语义映射机制](/images/content-rebuild/0111996fbb90f0dc/fig-2.png)

### 3.2 向量检索的失效点

连续空间的平滑过渡赋予了向量模型强大的泛化能力，但也带来了特定场景下的表征缺陷：

1. **子词分词打碎离散标识**：多数通用嵌入模型采用 BPE 或 WordPiece 子词分词器。遇到未在词表中完整收录的专有代码（如 `ERR-404-XYZ`）时，会被切碎成多个通用子词或单字符碎片（如 `e`、`##r`、`##r`、`-`、`404`、`-`、`x`、`##y`、`##z`）。特征被拆解稀释后，反而容易被局部的常见子词（如 `404`）主导，与通用 404 网页错误的向量距离拉近，产生误召回。
2. **相邻实体区分度不足**：在连续向量空间中，高度相似的代际名词（如“iPhone 15”与“iPhone 14”，或软件版本“v1.2”与“v1.3”）往往余弦相似度极高。当用户明确查询版本差异时，模型可能无法精准隔离相邻版本。
3. **否定词与局部限定不敏感**：双塔模型通常将整个句子的 Token 压缩为一个全局向量，容易削弱微小的限定词影响。例如“不需要冷藏的药品”与“需要冷藏的药品”，在向量空间中的相似度往往依旧处于较高区间。

#### 验证代码：分词器拆碎专有实体的现象

以下 Python 示例展示了通用分词器在处理技术代码时的分词结果：

```python
from transformers import AutoTokenizer

# 以常见的通用中文预训练分词器为例
tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")

query = "ERR-404-XYZ 故障"
tokens = tokenizer.tokenize(query)

print("分词结果:", tokens)
# 输出示例: ['e', '##r', '##r', '-', '404', '-', 'x', '##y', '##z', '故', '障']
# 专有名词被切碎为离散字母碎片，导致关键标识特征被稀释，且常见子词（如 404）权重失衡
```

## 4. 稀疏关键词检索（Sparse / BM25）：离散符号的统计精确性

与向量检索不同，经典关键词检索以倒排索引（Inverted Index）和 BM25 算法为代表。它将文档视作词项（Terms）的集合，根据词项在单篇文档和全库的统计分布计算相关性得分。

### 4.1 BM25 评分公式分解

BM25 算法通过对词频（TF）、逆文档频率（IDF）以及文档长度进行归一化综合打分：

$$S_{\text{BM25}}(q, d) = \sum_{i=1}^{n} \text{IDF}(q_i) \cdot \frac{\text{TF}(q_i, d) \cdot (k_1 + 1)}{\text{TF}(q_i, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right)}$$

其中各项参数的具体含义如下：
* **$\text{IDF}(q_i) = \ln \left(\frac{N - n(q_i) + 0.5}{n(q_i) + 0.5} + 1\right)$**：逆文档频率。$N$ 为全语料库文档总数，$n(q_i)$ 为包含词项 $q_i$ 的文档数。语料库中越罕见的特殊词项（如故障代码），其 IDF 权重越高；高频常见词（如“的”、“配置”）权重会被抑制。
* **$\text{TF}(q_i, d)$ 与饱和度参数 $k_1$（通常设为 1.2 至 2.0）**：限制词频对打分的无限提升。当词项在文档中出现次数增加时，得分增长会逐渐变缓并趋向饱和，防止单篇文档靠堆砌关键词刷分。
* **文档长度惩罚系数 $b$（通常设为 0.75）**：$|d|$ 为当前文档长度，$\text{avgdl}$ 为语料库所有文档的平均长度。该项用于消除长文档因篇幅长、包含词项多而天然占有的评分优势。

![BM25倒排索引检索与评分流程](/images/content-rebuild/0111996fbb90f0dc/fig-3.png)

### 4.2 关键词检索的优势与“词汇鸿沟”

* **精准匹配确定性**：对于人名、电话号码、特定参数、唯一错误码等明确符号，分词系统一旦配置好规则，BM25 凭借高 IDF 加权能够提供可预测的精准检索效果。
* **词汇鸿沟（Vocabulary Mismatch）**：如果用户输入“手机充不进电”，而文档严格写作“移动终端电源模块检修”，两者在分词后没有任何公共词项，BM25 得分将为 0，导致完全漏检。

## 6. 混合检索（Hybrid）：双路召回与融合策略

混合检索将稀疏关键词检索的**离散字符命中能力**与稠密向量检索的**连续语义理解能力**结合，是目前生产系统中覆盖多样化查询的常用方案。

### 6.1 混合架构的数据流流程

混合检索的执行链路主要分为三个环节：

```
                       ┌──> [BM25 倒排索引 (如 ES/OpenSearch)] ──> 候选集 A (Top-K) ──┐
用户查询 (Query) ──────┤                                                              ├──> [排名融合 (RRF / 加权)] ──> 综合候选集
                       └──> [向量数据库 (如 Qdrant/Milvus)]    ──> 候选集 B (Top-K) ──┘
```

![混合检索双路召回与融合拓扑](/images/content-rebuild/0111996fbb90f0dc/fig-6.png)

1. **双通道并发查询**：应用层接收到 Query 后，同时发起对向量数据库（如 Qdrant、Milvus）和关键词搜索引擎（如 Elasticsearch、OpenSearch）的检索请求。
2. **候选集拉取**：两路通道各自返回 Top-$K$ 条候选结果（如各取前 50 条）。
3. **结果去重与排序融合**：将两份候选文档集合并，通过算法重新计算排序得分，输出最终的候选列表。关于具体代码实现与调优，可参考 [BM25 与向量混合召回的工程实现](/interview/rag-interview/hybrid-retrieval.md)。

### 6.2 排序融合算法：加权归一化与 RRF

在融合两个独立列表时，由于 BM25 得分与向量相似度的计算方式不同，不能直接相加。

#### 策略 1：线性加权归一化（Score Normalization & Weighting）
先将两路检索的得分分别通过 Min-Max 归一化映射到 $[0, 1]$ 区间，再进行线性加权：

$$S_{\text{hybrid}}(d) = \alpha \cdot \hat{S}_{\text{dense}}(d) + (1 - \alpha) \cdot \hat{S}_{\text{sparse}}(d)$$

* **适用场景**：已知业务场景更偏向语义还是精确字符（可通过调节超参数 $\alpha$ 控制权重）。
* **局限**：不同查询返回的得分分布动态范围差异较大，Min-Max 归一化容易受到极端高分或低分（离群值）的影响。

#### 策略 2：倒数排名融合（Reciprocal Rank Fusion, RRF）
RRF 放弃直接使用打分绝对值，只依赖候选文档在各个通道中的**相对排名**计算融合分：

$$RRF\_Score(d \in D) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$

* $M$：参与融合的检索通道集合（如 $\{\text{BM25}, \text{Dense}\}$）。
* $r_m(d)$：文档 $d$ 在通道 $m$ 中的排名位置（从 1 开始计）。若文档未在某个通道的前 $K$ 名中出现，则对应项不计入或赋予一个极大排名。
* $k$：平滑常数（经验值通常设为 60），用于避免排名前列的文档权重差距过大，平滑高位项得分。

**RRF 的工程优势**：无量纲依赖，无需调参归一化，即使两路打分系统的分布差异极大，也能稳定平衡两者的排序结果。

## 7. 面试深度追问与常见误区

### 追问 1：在混合检索中，为什么不能直接把 BM25 的原始得分和向量余弦相似度直接相加？

**口述要点**：
> 两者的打分量纲和数值分布完全不同：
> 1. 余弦相似度的取值区间是有界的（通常在 $[-1, 1]$，经标准化后常映射到 $[0, 1]$）。
> 2. BM25 的得分是无界的非负实数，受词频、文档长度和语料库大小共同影响，在长文档或关键词多次命中的情况下，得分可能达到数十甚至上百。
>
> 若直接相加，BM25 的数值会占据主导地位，导致向量检索通道的语义打分失去作用。因此必须经过归一化，或直接采用基于位置排名的无量纲算法（如 RRF）进行融合。

### 追问 2：既然混合检索已经兼顾了关键词与语义召回，为什么很多系统后置还需要 Rerank（重排）模型？

**口述要点**：
> 召回阶段采用的双塔向量模型和 BM25 均属于**浅层或独立表征交互**：
> * 双塔模型在计算相似度前，Query 和 Document 分别独立编码，两者在编码阶段没有词与词之间的交互。
> * BM25 仅统计离散词频，缺乏对长句复杂句法和修饰关系的理解能力。
>
> 这导致多路召回虽然能快速从几十万甚至上千万文档中筛选出 Top-100 候选，但在处理逻辑反转、细微修饰语或长上下文推理时精度仍显不足。后置的 **Rerank 模型（Cross-Encoder 交叉编码器）** 将 Query 与候选 Document 拼接后共同输入模型，通过全注意力机制逐字计算相关性。将高计算复杂度的交叉注意力限制在少量的候选集（如 Top-30）上，能以可控的计算延迟换取更精确的排序。具体机制可参考 [Rerank 在 RAG 中的重排定位](/interview/rag-interview/rerank.md)。

### 常见误区排雷

* **误区 1：有了结构化元数据过滤（Metadata Filtering），就完全不需要关键词检索了。**
  * *澄清*：元数据过滤依赖于预先提取好的结构化字段（如 `author: admin` 或 `year: 2024`）。但当用户在自由文本中输入特定型号、流水号或未被提炼为标签的专有名词时，系统无法预知并生成对应的过滤条件，此时仍需要依赖文本全文的倒排索引进行召回。
* **误区 2：只要对嵌入模型进行充分微调，就能彻底解决专有名词和错误码的检索问题。**
  * *澄清*：微调可以在一定程度上改善模型在特定训练集内的词汇分布，但无法解决所有未登录词（OOV）和动态新增标识符的识别问题。现实业务中，新版本发布、新错误码生成属于日常高频事件，频繁重训模型和重新刷取全库向量的维护成本较高；而倒排索引具备毫秒级近实时增量更新的特性，在处理动态实体时更轻量高效。
