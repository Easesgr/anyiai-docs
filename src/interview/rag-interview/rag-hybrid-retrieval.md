在检索增强生成（RAG）系统中，单纯依赖稠密向量检索容易漏掉生僻专有名词和精确代码符号；而单纯依赖关键词（如 BM25）检索又难以理解同义改写与口语化表达。我们在[为什么 RAG 中常用 BM25 + 向量检索的混合召回？](hybrid-retrieval.md)中讨论过双路召回的必要性。然而，两路检索返回的结果评分体系完全不同：向量检索的余弦相似度一般在 $[-1, 1]$ 之间，而 BM25 则是无上限的正实数。如何把这两份列表合二为一，决定了最终送入大模型的上下文质量。

本文通过一个贯穿前后的排查场景，拆解多路融合的两种主流方案——**基于分数的加权归一化**与**倒数排名融合（RRF）**，给出可直接用于面试口述的标准回答、数学推导及工程选型依据。

## 1. 核心口述答案：多路打分融合的两大技术路线

面试中被问到“向量检索和关键词检索的结果如何合并”时，可以按以下三层逻辑清晰作答：

> 混合检索的结果融合主要有两条路线：**基于分数的加权归一化（Score-based Fusion）**与**基于排名的倒数排名融合（Rank-based Fusion / RRF）**。
>
> 1. **基于分数的归一化融合**：先将各路检索器的原始打分缩放到同一区间（通常用 Min-Max 线性缩放），再通过加权公式 $S_{final} = \alpha S_{dense} + (1 - \alpha) S_{sparse}$ 计算综合得分。这种方法的优点是保留了得分差距的大小；缺点是极值不稳定，极易受到离群高分和不同查询下分数分布漂移的干扰，固定的权重 $\alpha$ 很难在各种问题类型上保持稳定。
> 2. **倒数排名融合（RRF）**：忽略原始分数值，仅依据文档在各路列表中的排位名次（Rank）进行倒数累加，经典计算公式为 $\sum \frac{1}{k + r}$。它的优点是完全无量纲，不受两路打分尺度影响；平滑常数 $k$（学术基准通常取 60）能平抑单一检索器排头的极端垄断，天然奖励在两路检索中都排进前列的“共识文档”。
> 3. **工程选型建议**：如果混合召回之后配置了 Cross-Encoder 重排序模块（参见[Rerank 在 RAG 中解决什么问题？](rerank.md)），召回阶段应优先选用 RRF，以最低的调优成本保证候选集的多样性；如果系统没有下游重排模块，且评测表明某一检索源在当前业务数据下明显更强，可采用带权重的加权 RRF（例如 Qdrant 的加权实现）或经过校准的分数融合。

## 2. 分数归一化加权融合：Min-Max 缩放与实际缺陷

基于分数的线性加权融合是最容易想到的策略，目标是把不同度量体系下的分数拉到相同的区间内，使其具备可加性。

### 2.1 常见的归一化公式

假设某个检索器 $m$（例如向量检索或 BM25）为当前查询返回了一组候选文档集合 $D_m$。文档 $d$ 在该检索器中的原始得分为 $S_m(d)$。最常用的 Min-Max 缩放公式为：

$$S_{norm, m}(d) = \frac{S_m(d) - \min_{x \in D_m} S_m(x)}{\max_{x \in D_m} S_m(x) - \min_{x \in D_m} S_m(x)}$$

缩放后，所有候选文档的得分被限制在 $[0, 1]$ 之间。随后根据人为设定的权重 $\alpha_m$（满足 $\sum \alpha_m = 1$）进行线性相加：

$$S_{fusion}(d) = \sum_{m \in M} \alpha_m \cdot S_{norm, m}(d)$$

### 2.2 影响排序稳定性的三个问题

虽然加权计算直观，但在实际工程中，局部的 Min-Max 缩放会引入以下问题：

1. **分布拉伸与噪声放大**：
   如果某次向量检索的候选结果在语义上都比较接近，候选集第 1 名得分为 0.84，第 50 名为 0.81。Min-Max 缩放会把仅有 0.03 的微小差距拉满到 $0$ 至 $1$ 的全量程。此时微小的向量余弦波动被数倍放大，导致排名发生不合理的跳动。
2. **离群点压缩有效方差**：
   BM25 没有理论上限。如果某篇文档命中了极罕见的精确错误码，BM25 评分可能达到 45.0，而第 2 名只有 8.0。经过 Min-Max 处理后，第 1 名是 1.0，但其余所有候选文档的分数全被压制在 0.1 以下，稀疏检索分支在第 2 名以后的排位区分度基本丢失。
3. **跨查询权重无法泛化**：
   不同的问题类型依赖不同的检索器。查询特定配置项 `log_min_duration_statement` 需要 BM25 主导（例如稀疏权重设为 0.8）；而语义理解问题“数据库响应变慢怎么排查”更依赖向量检索（稠密权重设为 0.8）。单一全局固定的权重配置，在面对不同类型的 Query 时很难兼顾准确率。

## 3. 倒数排名融合（RRF）：算法公式推导与共识奖励

为了消除不同评分尺度带来的不稳定，Cormack 等人在 2009 年提出了倒数排名融合（Reciprocal Rank Fusion, RRF）。该算法完全放弃原始分数值，仅利用文档在各路列表中的排位名次（Rank）。

### 3.1 数学公式推导

设 $M$ 为检索系统集合（如 $M = \{\text{Dense}, \text{BM25}\}$），$D$ 为两路召回结果的并集。对于任意文档 $d \in D$，经典 RRF 得分计算公式为：

$$RRF\_Score(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$

其中：
- $r_m(d) \in \{1, 2, 3, \dots\}$ 为文档 $d$ 在检索器 $m$ 列表中的从 1 开始计数的名次；
- 若某文档未出现在检索器 $m$ 的截断候选池（例如 [Top-K 截断](rag-topk.md)）中，则该项得分记为 0（等价于 $r_m(d) = \infty$）；
- $k$ 为平滑常数，原作者在信息检索实验中推荐基准默认值为 60。

### 3.2 平滑常数 $k$ 的机制分析

$k$ 的作用是调节“排在榜首的单路高分”与“在多路都排在中游的共识文档”之间的得分对比：

- **如果 $k = 0$**：第 1 名得分为 $\frac{1}{1} = 1.0$，第 2 名为 $\frac{1}{2} = 0.5$。排位越靠前，名次差带来的得分落差越陡峭。一篇仅在 BM25 拿到第 1 名、向量路未召回的文档，得分达到 $1.0$；而在两路都稳定拿到第 2 名的高质量文档，得分仅为 $0.5 + 0.5 = 1.0$。此时单路第一的权重极大。
- **当 $k = 60$ 时**：第 1 名得分为 $\frac{1}{61} \approx 0.01639$，第 2 名为 $\frac{1}{62} \approx 0.01613$。相邻位次的递减变得非常平滑。此时，一篇在两路分别排名第 3 和第 4 的共识文档，得分约为 $\frac{1}{63} + \frac{1}{64} \approx 0.03150$，能够明显超越单路拿第 1、另一路排在 15 名之外的偏科文档。

通过平滑常数 $k$，RRF 降低了单路偶然排在第一位的垄断效应，给予在多路检索中都靠前的文档更高的综合权重。

### 3.3 贯穿算例推导

我们以开发者的技术咨询查询 `PostgreSQL 慢查询日志配置 log_min_duration_statement` 为例。假设稠密向量检索与 BM25 分别返回候选，取学术基准值 $k = 60$，候选文档的位次如下：

| 文档编号 | 内容主题 | 稠密向量排位 $r_{dense}$ | BM25 排位 $r_{sparse}$ |
| :--- | :--- | :--- | :--- |
| **Doc A** | 官方手册：专门讲解 `log_min_duration_statement` 配置 | 10 | 1 |
| **Doc B** | 运维故障记录：排查系统变慢，未直接提及该配置项 | 1 | 15 |
| **Doc C** | 最佳实践指南：同时覆盖慢查询配置与连接池调优 | 3 | 4 |

逐步计算各个文档的 RRF 得分（四舍五入保留五位小数）：

- **Doc A**：
  $$RRF(A) = \frac{1}{60 + 10} + \frac{1}{60 + 1} = \frac{1}{70} + \frac{1}{61} \approx 0.01429 + 0.01639 = 0.03068$$
- **Doc B**：
  $$RRF(B) = \frac{1}{60 + 1} + \frac{1}{60 + 15} = \frac{1}{61} + \frac{1}{75} \approx 0.01639 + 0.01333 = 0.02972$$
- **Doc C**：
  $$RRF(C) = \frac{1}{60 + 3} + \frac{1}{60 + 4} = \frac{1}{63} + \frac{1}{64} \approx 0.01587 + 0.01563 = 0.03150$$

**排序结果**：最终得分为 $\text{Doc C} (0.03150) > \text{Doc A} (0.03068) > \text{Doc B} (0.02972)$。

Doc C 虽然在任意单一检索器中都不是第 1 名，但由于在两路检索中均获得了前排的名次（第 3 和第 4），其融合得分成功超过了单路夺冠但另一路落后的 Doc A 和 Doc B。这直观体现了 RRF 奖励“多路共识”的特点。

## 4. Qdrant 加权 RRF 实现与权重配置

标准 RRF 隐含了一个前提：所有参与融合的检索系统能力相当、权重平等。但在实际业务中，向量模型与 BM25 的可靠程度往往并不一致。为了解决这一问题，主流向量数据库引入了加权 RRF（Weighted RRF）。

### 4.1 理论加权公式与 Qdrant 纯倒数加权实现

在学术界文献中，带平滑常数的加权 RRF 表达为：

$$Score_{academic}(d) = \sum_{m \in M} \frac{w_m}{k + r_m(d)}$$

但在工业实现中，如果保留较大的 $k=60$，$k$ 会稀释权重的直观比例（例如 $w_1=3$ 对应的首位为 $\frac{3}{61}$，第 3 位为 $\frac{3}{63}$，两者的比值非常微弱），难以直观理解权重参数与录取结果的关系。

以 Qdrant（v1.17.0 起支持的加权 RRF）为例，官方在实现时直接采用了**纯排位倒数的加权组合**：

$$Score_{Qdrant}(d) = \sum_{m \in M} \frac{w_m}{r_m(d)}$$

这一实现直接带来了两个确定的行为特性：

1. **位次得分的确定等价性**：
   若稠密与稀疏通道分别配置权重 $w_{dense} = 3.0$ 与 $w_{sparse} = 1.0$。当文档 $A$ 仅在稠密路排第 3、文档 $B$ 仅在稀疏路排第 1 时：
   $$Score(A) = \frac{3.0}{3} = 1.0, \quad Score(B) = \frac{1.0}{1} = 1.0$$
   两者的得分严格相等。也就是说，**权重为 3.0 的检索源中的第 3 名，与权重为 1.0 的检索源中的第 1 名具备相同的录取优先级**。
2. **候选集不重叠时的交替比例**：
   若两路返回的候选集没有任何交集：
   - 稠密路（$w=3.0$）各名次得分为：$3.0$（第 1）、$1.5$（第 2）、$1.0$（第 3）、$0.75$（第 4）、$0.6$（第 5）、$0.5$（第 6）……
   - 稀疏路（$w=1.0$）各名次得分为：$1.0$（第 1）、$0.5$（第 2）、$0.33$（第 3）……
   合并降序排列后，前几名依次为：稠密第 1（3.0）、稠密第 2（1.5）、稠密第 3 并列稀疏第 1（1.0）、稠密第 4（0.75）、稠密第 5（0.6）、稠密第 6 并列稀疏第 2（0.5）。稠密路与稀疏路候选的录取频次比例保持在 3:1。这与 Qdrant 官方文档的解释一致。

![Qdrant加权RRF运作机制与权重配置](/images/content-rebuild/c86e13e227f71d43/fig-4.png)

### 4.2 Qdrant 加权 RRF 代码示例

以下是使用 Qdrant Python SDK 构造混合检索 Prefetch 与加权 RRF 查询的代码：

```python
from qdrant_client import QdrantClient, models

client = QdrantClient(url="http://localhost:6333")

# 定义预检索（Prefetch）并配置加权 RRF 融合
result = client.query_points(
    collection_name="tech_docs",
    prefetch=[
        # 第一路：稠密向量检索（预取 50 条）
        models.Prefetch(
            query=[0.021, -0.043, 0.089, ...], # 查询向量
            using="dense_vector",
            limit=50,
        ),
        # 第二路：稀疏 BM25 检索（预取 50 条）
        models.Prefetch(
            query=models.SparseVector(indices=[102, 4059, 881], values=[1.2, 0.8, 2.1]),
            using="bm25_sparse_vector",
            limit=50,
        ),
    ],
    # 使用加权 RRF 合并，权重数组对应 prefetch 的先后顺序
    query=models.RrfQuery(
        rrf=models.Rrf(
            weights=[3.0, 1.0],  # 稠密权重 3.0，稀疏权重 1.0
        )
    ),
    limit=10  # 最终融合后取 Top 10
)
```

### 4.3 依据评测集确定权重

多路权重的比例不宜凭直觉设定，而应借助离线评测集（参见[如何评估一个 RAG 系统？](rag-evaluation.md)）进行调优：

1. 准备覆盖典型提问形式的测试集（包含标注好的相关文档标注）。
2. 选定评估指标（如 NDCG@10 或 MRR@10）。
3. 对两路权重比例（例如 $\frac{w_{dense}}{w_{sparse}}$ 在 $0.1$ 到 $5.0$ 之间）进行网格搜索（Grid Search）。
4. 选取验证集上指标最高的权重组合部署，并根据线上 Query 分布的变化定期重新校验。

## 5. 去重合并与深度分页的工程开销

多路召回在执行层属于“扇出-汇聚（Fan-out / Gather）”架构，需要清楚其在内存和网络上的开销特点。

### 5.1 候选池膨胀与去重开销

为了保证 RRF 能统计到两路之间的重叠共识，单路召回的预取数量（Prefetch Limit）通常设置为最终需要数量 $K$ 的 3 到 5 倍（如各取 50 条）：

- **汇聚去重**：汇聚节点通过以文档主键（`DocID`）为 Key 的哈希表维护候选集状态，累计 `total_rrf_score`。
- **内存开销**：在最极端无重叠的情况下，汇聚节点需要维护 $2N$ 条完整候选文档数据并进行快速排序。因此，不宜把两路的预取量设得过大。

### 5.2 深度分页（Deep Pagination）的开销放大

传统关系型数据库可以通过单索引游标实现流式分页，但在 RRF 混合架构下，**跨系统的深度分页会产生二次放大效应**：

1. **前缀全量预取**：如果客户端要求获取第 10 页数据（`page=10, page_size=10`，即第 91 到 100 名的结果），由于最终排名是非线性融合得到的，汇聚节点不能直接跳过前 90 条。稠密与稀疏两路检索器**必须各自扫描并返回前 100 条候选**到汇聚节点。
2. **传输与序列化瓶颈**：页码越深，需要拉取和合并的元数据越多，网络传输与反序列化耗时线性增加。
3. **工程建议**：在面向 RAG 的应用中，粗排融合阶段通常应限制最大拉取深度（例如最多只获取前 50 到 100 条）。深层知识发掘应借助下游的[Rerank 在 RAG 中解决什么问题？](rerank.md)进行重排，或者通过[Query Rewrite 是什么？](query-rewrite.md)优化提问，而不是在粗排阶段开放无限制的深翻页。

## 6. 面试追问与避坑指南

- **追问 1：学术界经典 RRF 的常数 $k$ 设为 60，为什么不能直接设为 0？**
  *口述要点*：若无权 RRF 中 $k=0$，位次倒数按 $\frac{1}{r}$ 极速衰减（第 1 名为 1.0，第 2 名腰斩为 0.5）。此时只要某篇文档在单一分支侥幸排在第 1，哪怕在其他分支毫无踪影，其得分也能打平在两路中均排在第 2 的优质共识文档（$0.5 + 0.5 = 1.0$）。设置 $k=60$ 可以让名次衰减更加平缓，确保在两路都有稳定排名的文档能胜出。

- **追问 2：RRF 融合后的分数，可以直接拿来做大模型生成上下文的相关度阈值过滤吗？**
  *口述要点*：**不能**。RRF 得分是一个相对序数统计值，其绝对大小受检索源数量和平滑常数的影响（例如在两路 $k=60$ 下，单个文档的理论满分只有 $\frac{1}{61} + \frac{1}{61} \approx 0.0328$），并不代表文本与问题的语义相关度。阈值过滤应当在各路检索的原始阶段执行（如向量余弦相似度必须 $>0.7$），或者在融合后交由 Cross-Encoder 模型输出校准后的置信度打分。

- **追问 3：在什么场景下，基于分数的加权融合可能优于 RRF？**
  *口述要点*：当检索源的原始打分具有物理置信度，且候选集头部存在断层式差距时。例如，当向量检索中命中了一篇与用户问题几乎完全一致的高置信文档（相似度高达 0.999），而第 2 名骤降到 0.4 时，RRF 只能将其识别为普通的“第 1 名”和“第 2 名”，抹平了绝对差距。在置信度极端明显的场景中，校准后的分数融合对这种断层差距更敏感。
