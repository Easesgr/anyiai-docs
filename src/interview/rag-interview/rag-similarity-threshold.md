在检索增强生成（RAG）系统中，单纯依赖 [Top-K 数量截断](/interview/rag-interview/rag-topk.md) 往往会引入无关噪声。

假设我们搭建了一套企业行政知识库 RAG 系统。当用户提问一个库里完全没有记录的问题（例如“隔壁大楼的食堂几点开门？”）时，如果系统仅固定取相似度最高的前 3 个片段，检索模块依然会强行把库内最“接近”的无关文档（如“公司班车发车时间表”、“加班就餐补贴细则”）送给大模型。大语言模型看到这些似是而非的资料，极易顺应上下文编造出虚假答案。

为了过滤低质量候选片段，并在知识库缺乏证据时及时止损，检索管道需要引入**相似度阈值（Similarity Threshold）**与**静默拒答机制**。

---

## 1. 核心口述答案：阈值控制与拒答机制

在面试中遇到“RAG 检索中相似度阈值如何设置？如何实现静默拒答？”时，可直接给出如下回答结构：

> **核心口述回答：**
>
> 相似度阈值是 RAG 检索链路中的**相关度质量过滤器**，核心作用是剔除排在 Top-K 内但实际不相关的低分文档块，防止上下文受到噪声干扰。
>
> 在实际工程中，不能只依靠单一的静态固定阈值（例如写死 0.8）。因为向量空间存在分布集中（各向异性）现象，且不同领域的术语稀缺度不同，会导致相似度分数整体漂移。通常采用组合过滤策略：
> 1. **保底绝对阈值（Floor Threshold）**：设定一个较低的底线分数，快速剔除明显不相关的极端负样本。
> 2. **最高分相对截断（Relative Truncation）**：以本次检索的最高分为基准，仅保留得分达到最高分一定比例（如 80%）的文档。
> 3. **断崖式截断（Score Gap Fall-off）**：监测相邻候选块的得分落差，在分差发生突降的位置直接切断。
>
> 当所有候选文档都低于保底阈值时，检索层触发**静默拒答**：代码直接拦截后续流程，不调用大模型，返回预设提示（如“未找到相关参考资料”）。这既能降低推理成本，又能避免模型因缺乏依据而胡乱编造。

![检索阈值门控与拒答触发全流程](/images/content-rebuild/35b250d0ab47724b/fig-1.png)

*图 1 标明了从 Query 输入到最终响应的条件分流：检索得到的候选文档先经过阈值过滤器，若所有分值低于设定底线，流程直接短路触发拒答，不调用大语言模型；达标文档则送入上下文生成模块。*

## 2. 单一固定绝对阈值的局限：分数漂移与分布不均

许多初学者习惯在向量检索后写死一个固定的阈值（例如固定余弦相似度必须 $\ge 0.8$）。在真实业务场景中，这种硬编码往往会导致大量误判。

向量相似度并不是绝对的概率置信度，它受限于嵌入模型的表示特性和实际语料分布：

### 2.1 向量空间分布集中（各向异性）
部分预训练 Transformer 嵌入模型生成的句向量在空间中并不均匀分布在整个超球面上，而是挤在狭窄的局部区域内（常被称为各向异性或锥体效应）。相关原理可参考 [Embedding 语义相似度表示](/fundamentals/embedding/embedding-similarity.md)。

这种分布不均会导致：即便两句含义毫不相干的文本，它们之间的[余弦相似度](/interview/rag-interview/rag-similarity-algorithms.md)基础分也可能高达 0.6 到 0.7。这意味着在一个模型里 0.7 只是负样本的平均基准，而在另一个经过校准的模型里 0.7 可能已经代表强相关。

### 2.2 跨领域分布漂移与文本长度差异
- **专业领域与通用领域的词频差异**：专业医疗、工业设备型号或法律条款中的特定词汇，在通用预训练语料中出现频率低，向量表示往往偏向空间边缘。哪怕用户查询与文档语义完全吻合，计算出的余弦相似度也可能只有 0.72；而通用常识类查询（如“如何提交请假流程”），匹配分数往往容易超过 0.88。若统一使用 0.8 的硬阈值，专业领域的正确文档会被大量剔除。
- **长短文本匹配的分数稀释**：短查询（3 到 5 个词）包含的信息量少，与包含数百字的长文档块计算点积或余弦时，受到池化与信息稀释的影响，得分通常系统性低于长查询对长文档的匹配分数。

![余弦分数分布漂移与各向异性示意](/images/content-rebuild/35b250d0ab47724b/fig-2.png)

## 3. 动态截断策略：相对比率与断崖式截断

为了兼顾不同查询之间的分数波动，工程上常使用**相对分数截断**与**断崖式截断**。

### 3.1 规则定义
假设一次向量检索返回了按相似度降序排列的 $K$ 个候选文档得分：
$$\mathcal{S} = \{s_1, s_2, \dots, s_K\}, \quad \text{其中 } s_1 \ge s_2 \ge \dots \ge s_K$$

我们配置三个控制参数：
1. $T_{\text{floor}}$：保底绝对阈值。若排序第一的最高分 $s_1 < T_{\text{floor}}$，说明本次检索连一篇稍微相关的候选都没有，直接判定为无证据并拒答。
2. $\alpha$：最高分相对比率（通常取 $0.75 \sim 0.90$）。仅保留满足 $s_i \ge \alpha \cdot s_1$ 的文档，防止后排低分碎片混入。
3. $\Delta_{\text{gap}}$：相邻断崖差值阈值（通常取 $0.10 \sim 0.20$）。若相邻两篇文档的分数落差 $s_i - s_{i+1} > \Delta_{\text{gap}}$，说明相关度在此处出现明显分水岭，直接在 $s_i$ 处截断。

![相对截断与断崖式截断机制原理](/images/content-rebuild/35b250d0ab47724b/fig-3.png)

*图 3 展示了序列分数的衰减曲线。最高分锚定相对阈值划出一条随首项漂移的动态门槛，而断崖阈值则在斜率剧烈突降的位置执行物理切断，二者共同确定有效候选集。*

### 3.2 运行算例
假设检索返回 5 个候选文档块，配置参数为：$T_{\text{floor}} = 0.50$，相对比例 $\alpha = 0.85$，断崖差值 $\Delta_{\text{gap}} = 0.15$。

各文档得分为：
- 文档 1: $s_1 = 0.88$
- 文档 2: $s_2 = 0.84$
- 文档 3: $s_3 = 0.62$
- 文档 4: $s_4 = 0.58$
- 文档 5: $s_5 = 0.42$

**筛选流程：**
1. **首位保底检查**：$s_1 = 0.88 \ge 0.50$，通过保底校验，不触发全局拒答。
2. **相对比率动态门槛**：$T_{\text{rel}} = \alpha \cdot s_1 = 0.85 \times 0.88 = 0.748$。
   - $s_2 = 0.84 \ge 0.748$（保留）
   - $s_3 = 0.62 < 0.748$（低于动态线）
3. **断崖差值检测**：
   - $s_1 - s_2 = 0.88 - 0.84 = 0.04 \le 0.15$（过渡平缓）
   - $s_2 - s_3 = 0.84 - 0.62 = 0.22 > 0.15$（分差超过断崖阈值，在文档 2 之后执行截断）
4. **输出结果**：最终进入上下文的仅有文档 1 和文档 2，后续的文档 3、4、5 全部被剔除。

![断崖截断算法算例执行过程](/images/content-rebuild/35b250d0ab47724b/fig-4.png)

*图 4 标注了该算例中的具体数值流转：首项通过保底校验，在 $s_2$ 与 $s_3$ 之间检测到超过 0.15 的落差，断崖截断立即生效，成功在送入 LLM 前清洗掉了后排相关度偏弱的 Chunk。*

## 4. 阈值设置不当的影响对比

阈值调整是在**查准率（Precision）**与**查全率（Recall）**之间做权衡。极端设置会导致系统出现不同形态的异常：

| 对比维度 | 阈值设置过高（例如固定 0.92） | 阈值设置过低（例如固定 0.30） |
| :--- | :--- | :--- |
| **召回状态** | 大量正样本被过滤，检索结果频繁为空 | 召回大量低质量、仅有微弱字面关联的边缘段落 |
| **系统现象** | **检索饥饿**：系统频繁报告“未找到相关内容” | **上下文污染**：无关信息挤占输入窗口 |
| **模型表现** | 若未做代码拦截，模型在无资料参考时容易调用参数记忆编造 | 模型受到无关内容误导，发生“迷失在中间”或跑偏 |
| **用户体验** | 正常业务提问无法得到解答，系统可用性下降 | 模型给出夹杂事实错误的推论，产生[事实性幻觉](/interview/rag-interview/rag-hallucination.md) |

![阈值两极设置对上下文与生成的破坏](/images/content-rebuild/35b250d0ab47724b/fig-5.png)

*图 5 对比了阈值过高导致的证据链断裂（大模型退回到不稳定的参数记忆并胡编）与阈值过低导致的噪声漫灌（关键证据被边缘无关段落稀释甚至冲突覆盖）。*

## 5. 静默拒答机制：代码短路与 Prompt 兜底

只靠大模型“自觉”按要求拒答并不稳妥。由于语言模型本身的文本延续倾向，在面对无关或半相关内容时，模型依然可能强行拼凑解释。成熟的设计应由**代码层短路拦截**与 **Prompt 兜底**共同构成：

### 5.1 代码管道短路拦截（Pipeline Circuit Breaker）
在代码逻辑中，候选文档块经阈值过滤后，若保留列表为空，直接终止调用大语言模型：
- **节省开销**：完全避免空召回时昂贵的大模型推理 Token 成本与排队延迟。
- **行为可控**：由服务端直接返回固定的结构化响应（例如附带标准提示“知识库中未检索到与该问题相关的参考内容”）。
- **监控明确**：系统能精准记录空召回查询，帮助运营团队发现知识库盲区并针对性补充资料。

### 5.2 Prompt 约束兜底（Prompt-level Grounding）
如果检索出的文档通过了阈值，但其内容仅涉及问题的一部分、不足以支持完整推导时，需要依靠 [Prompt 提示词工程设计](/interview/rag-interview/rag-prompt-design.md) 来防止模型越界推断：

```text
你是一个严格依据参考资料回答问题的助手。
【规则】：
1. 仅依据下列【参考资料】中明确提及的内容作答。
2. 如果参考资料不足以完整支持回答，或者资料中未提及相关细节，请直接说明：“根据现有参考资料，无法确认相关信息”，严禁自行推测或编造。

【参考资料】：
{context}

【用户问题】：
{query}
```

![双层拒答闭环系统拓扑](/images/content-rebuild/35b250d0ab47724b/fig-6.png)

*图 6 描绘了双层拒答防御体系：第一道为网关级的检索短路拦截，文档列表为空即直接终止；第二道为大模型输入端的上下文事实硬约束，从工程拦截与提示词约束两端协同降低与抑制无证据幻觉。*

## 6. 面试追问与常见误区

### 追问 1：引入 Rerank 重排模型后，相似度阈值应该放在哪一步生效？
**回答要点**：
主要判定阈值应放在 **Rerank 之后**；向量检索（粗排）阶段仅保留较宽松的保底过滤。
- **区分度差异**：向量粗排通常采用双塔架构（Bi-Encoder），只计算 Query 和 Chunk 独立编码后的向量夹角，语义交互粒度较粗，分数区分度较低；而 [Rerank 模型](/interview/rag-interview/rerank.md)（Cross-Encoder）将 Query 与 Document 拼接后进行全注意力交互，能直接计算字词间的交叉相关性，打分分辨率显著高于初检向量分数。具体实现可参考 [RAG 中的 Rerank 实现](/interview/rag-interview/rag-rerank.md)。
- **推荐做法**：粗排阶段放大 Top-K（如取 30 到 50 个候选），配合宽松的低保底阈值放行潜在文档；重排模型输出分数后，再应用相对比率和断崖截断，筛选出最终送入大模型的上下文。

### 追问 2：如果采用混合检索（BM25 + 向量检索），两类分数的量纲不同，怎么设置阈值？
**回答要点**：
BM25 得分通常为非负数且没有固定上限，而余弦相似度通常落在 $[0, 1]$ 或 $[-1, 1]$ 区间，两者无法直接比较绝对数值。
- **不建议的做法**：直接给两类分数做简单的线性相加，或强行划定统一数值线，这会导致某一检索源在极端值下主导结果。
- **更平稳的方案**：在[混合检索](/interview/rag-interview/hybrid-retrieval.md)召回阶段不设硬阈值，统一采用倒数排名融合（RRF, Reciprocal Rank Fusion）生成综合排序，或者直接把混合召回的多路候选输入到重排模型中重新打分，最终在重排模型的归一化分数上统一卡阈值。

### 常见错误说法辨析
- ❌ **错误说法**：“余弦相似度大于 0.8 就一定相关，低于 0.8 就一定是不相关。”
  - **辨析**：脱离具体嵌入模型和语料领域谈绝对数值是不严谨的。不同模型在未经过针对性校准前，其正负样本的分割线在不同垂直领域可能相差很大。
- ❌ **错误说法**：“只要在 Prompt 里写上‘不知道就说不知道’，大模型就不会产生幻觉，检索层不需要做空结果拦截。”
  - **辨析**：语言模型受到顺应倾向影响，当输入了一堆看似相关但实际没有支撑事实的段落时，模型很可能会依据其中的零散字词强行给出解答。代码层拦截能直接切断无意义的推理请求，是防范幻觉的重要保障。
