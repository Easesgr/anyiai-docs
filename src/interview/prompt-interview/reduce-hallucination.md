在上一讲 [/interview/prompt-interview/prompt-failure.md](/interview/prompt-interview/prompt-failure.md) 中，我们排查了提示词失效的常见原因（如指令竞争、格式漂移与长度超出）。在实际业务与面试场景中，大模型最常见也最棘手的失效现象是**事实幻觉（Hallucination）**与**答非所问（Off-topic / Unfaithful Generation）**。

大模型依赖上文预测下一个 Token，本身并没有事实真值库。如果在提示词里只写一句“请不要胡说八道”，模型往往依然会编造答案。本篇通过一个贯穿前后的电商售后问答案例，拆解如何通过限定封闭上下文、前置引用、退避机制与双阶段核对，把回答压制在给定的参考事实之内。

## 面试速答：Prompt 抑制幻觉的三原则

当面试官询问“如何通过 Prompt 减少大模型的幻觉或答非所问”时，可以用以下三点概括核心思路：

> **面试口述核心结论：**
>
> 减少模型幻觉不能依赖“禁止编造”这种模糊的负向提示，核心是给模型建立**可验证的事实约束与退避机制**：
>
> 1. **限定封闭知识源与赋予拒答权（Grounding & Fallback）：** 明确要求模型仅依据 Prompt 内给定的材料回答，严禁调用未列出的外部常识；同时给出标准退避话术（如“材料未提及”），允许模型在信息不足时安全拒答，打破模型强行迎合用户的倾向。
> 2. **前置引用证据（Quote-First）：** 要求模型先逐字提取材料中的原文证据，再基于该证据输出结论。因为自回归生成是一步步往后预测，先生成的证据 Token 会进入后续推理的上下文，显著增加模型按证据回答的概率。
> 3. **两阶段生成与独立核对（Draft & Verify）：** 在高准确率场景下，把任务拆成两步：第一步生成包含引文的初稿，第二步换用独立的审查提示词核对初稿与原文是否一致，过滤无依据的断言。
> 
> 需要向面试官客观说明：Prompt 只能通过构造上下文约束降低幻觉概率，无法从概率采样的数学机制上完全杜绝长尾错误。

## 贯穿案例：电商售后退换货规则

为了直观理解这套方法，我们设定一份简短的《售后退换货规则》作为贯穿全篇的参考资料：

```text
【售后规则文本】
1. 普通商品自签收次日起支持 7 天内无理由退货，商品需保持原包装且不影响二次销售。
2. 生鲜冷冻食品、定制类商品一经拆封，不支持无理由退货。
3. 符合退货条件的订单，退款将在仓库收到退货并质检合格后 3 个工作日内按原路返还。
```

如果用户提出两个不同的问题：
* **问题 A（材料完全覆盖）：** “我买的冷冻牛排已经拆封了，能退货吗？退款几天到账？”
* **问题 B（材料未提及）：** “我买的外套签收 15 天了，衣服没拆吊牌，能申请退货吗？”

在开放式 Prompt 下，模型面对问题 B 很容易自作主张：“外套通常支持退货，但由于已过 7 天，建议联系人工客服申请特批。”——这就是典型的顺应性幻觉，模型调用了外部电商经验，编造了资料中不存在的“特批”规则。

## 幻觉机理：为什么模型容易答非所问？

模型在处理参考资料问答时产生幻觉，通常来自两个相互作用的因素：

1. **迎合偏置（Sycophancy / Helpfulness Bias）：** 经过指令微调（SFT）和人类偏好对齐（RLHF）训练后的模型，普遍具有“尽量给用户有用回答”的先验偏置。当用户提问超出给定资料时，如果提示词没有明确规定“不知道时该输出什么”，模型就会优先倾向于补充细节，顺着用户的问法顺水推舟。
2. **因果上下文漂移：** 大模型按从左到右的顺序逐字生成。在长回复生成过程中，模型后续步骤的注意力会被自己刚刚生成的词吸引。一旦前几句话因为微小的概率扰动偏离了原文，后续的生成就会把这个偏差当作“已知事实”继续推演，导致整段回答越来越偏离材料。

![模型顺应性偏置与注意力漂移的诱发机制对比](/images/content-rebuild/8d736437ac0186d9/fig-1.png)

如图所示，如果没有显式设立安全退出点和事实锚点，生成序列很容易顺着训练语料中的常见语言模式滑向自由发挥。关于大模型幻觉的更多评测与分类，可参考 [/fundamentals/llm-basics/hallucination.md](/fundamentals/llm-basics/hallucination.md) 与 [/llm-100/evaluation/hallucination-causes.md](/llm-100/evaluation/hallucination-causes.md)。

## 规则一：限定封闭上下文与显式退避

防范幻觉的第一步，是把“开卷自由问答”收拢为“封闭文档判读”，并给模型一个明确的“认输”出口。

常规的不规范提示词往往写成：“请根据资料回答用户问题，不要编造。”这种负向提示词只说了“不要做什么”，模型在面对未提及的信息时依然不知道该输出什么。防御性 Prompt 必须用正向规则给出确定的退避路径。

### 防御性 Prompt 结构设计

```markdown
### 任务目标
你是一名售后规则问答助手。你的唯一任务是依据【参考规则】回答用户的问题。

### 执行规则
1. 封闭依据：所有回答必须直接推导自【参考规则】。严禁使用任何规则外的外部常识、行业惯例或个人推测。
2. 标准退避：如果【参考规则】中的文字不足以直接回答用户问题（哪怕问题在日常生活中很常见），必须且只能回复固定语句：“参考规则中未包含该信息，无法为您解答。”不得输出任何推测性建议。
3. 保守判定：对于条件模糊或未穷尽的情况，按“未提及”处理，不得自行假设补充条件。

### 参考规则
<<<{{CONTEXT}}>>>

### 用户提问
{{QUESTION}}
```

![诚实兜底机制的决策退避路径](/images/content-rebuild/8d736437ac0186d9/fig-2.png)

### 贯穿案例效果验证

当用户提出**问题 B**（“外套签收 15 天能否退货”）：
* **未设退避的输出：** “15天已经超过了普通的7天无理由退货期限，但如果您衣服包装完好，可以尝试联系客服申请售后协商。”（产生非预期的外溢承诺）
* **设有退避协议的输出：** “参考规则中未包含该信息，无法为您解答。”（安全截断，防止误导用户）

## 规则二：前置引用证据（Quote-First）

许多开发者习惯让模型先写出结论，最后在句尾加上“来源参考”。但在自回归语言模型中，这种顺序削弱了证据对结论的约束作用。

### 为什么生成顺序至关重要？

自回归模型每一步预测下一个 Token 时，依赖的条件是：输入文本加上**当前已经生成的前序 Token**：

$$P(y_t \mid y_{<t}, x)$$

* **先结论后引用：** 生成结论词时，模型已生成的上下文里只有用户的提问和初始 Prompt。模型依靠注意力回看很长的上下文，仍有较大概率受到参数记忆中常见模式的干扰，先蹦出错误的结论；等到结论写完再去材料中“硬凑”引文时，往往会出现引文与结论自相矛盾的情况。
* **先引用后结论（Quote-First）：** 要求模型必须先逐字复制原始文本作为 `evidence_quote`。在模型写完这段引文开始预测结论词时，精确的原文已经变成了紧邻前缀上下文 $y_{<t}$ 的一部分。自注意力机制在局部能对这段刚刚写下的文字分配更高的注意力权重，使后续结论直接由引文字符串驱动得出。

![引用归因顺序对自回归注意力的物理约束对比](/images/content-rebuild/8d736437ac0186d9/fig-3.png)

### 结构化引用输出格式

结合 [/interview/prompt-interview/structured-output.md](/interview/prompt-interview/structured-output.md) 的标准，我们可以要求模型以结构化 JSON 格式输出：

```json
{
  "evidence_quote": "摘录参考资料中的原文支持句。如果资料未提及，必须严格填 null",
  "reasoning": "简要说明该证据如何对应用户问题。若引文为 null，写'无有效依据'",
  "answer": "基于上述 evidence_quote 得出的最终答复。若 quote 为 null，输出标准退避文案"
}
```

### 贯穿案例效果验证

面对**问题 A**（“拆封冷冻牛排能否退货，退款几天到账”）：

```json
{
  "evidence_quote": "生鲜冷冻食品、定制类商品一经拆封，不支持无理由退货。",
  "reasoning": "用户购买的是冷冻牛排且已拆封，属于规则第二条明确不支持无理由退货的情形。因为不满足退货条件，后续退款时效条款不适用。",
  "answer": "您好，生鲜冷冻食品拆封后不支持无理由退货。"
}
```

配合一到两个 Few-shot 示例（见 [/interview/prompt-interview/few-shot-learning.md](/interview/prompt-interview/few-shot-learning.md)），这种前置引用的结构不仅能压制模型随意回答的冲动，也方便调用方在代码层直接检查 `evidence_quote` 是否确实在原始资料中存在。

## 规则三：两阶段生成与独立核查流

在单次生成中，模型有时会出现“自圆其说”的盲区：哪怕证据摘录有细微偏差，它也会强行推导一个看似合理的答案。在合规初筛、专业资料辅助核对等对事实一致性要求较高的场景下，建议使用两阶段核查（Draft & Verify）作为人机协同的辅助过滤层（注意：高风险业务的核心决策仍需人工把关或硬性规则约束，不能单靠模型核查替代人工裁决）。

![两阶段草稿生成与核查管线流程](/images/content-rebuild/8d736437ac0186d9/fig-4.png)

### 阶段一：初稿生成（Drafting）
使用前述的前置引用提示词，要求模型生成初稿，提取引文和初步结论。

### 阶段二：独立审计（Verification）
启动一个全新的会话上下文，剥离第一阶段的推理噪音，让模型专门扮演“严格事实核查员”的角色，逐字比对初稿与原始资料。

**审计阶段提示词模板：**

```markdown
### 任务要求
你是一名客观严苛的事实核对员。请对照【原始资料】，对【待审核初稿】中的每一个陈述逐句核对。

### 核对标准
- SUPPORTED：该陈述在原始资料中有直接对应的文字支持。
- UNSUPPORTED：该陈述在原始资料中没有依据，或属于主观引申。
- CONTRADICTED：该陈述与原始资料直接矛盾。

如果存在 UNSUPPORTED 或 CONTRADICTED，请直接将答案重写为退避文案；若全部为 SUPPORTED，则保留初稿。

【原始资料】：{{CONTEXT}}
【待审核初稿】：{{DRAFT_ANSWER}}
```

### 策略权衡比较

引入核查流需要消耗额外的推理调用，工程选型时需要权衡延迟与质量：

| 防御策略 | 端到端耗时示意（1k token 输入） | 额外 Token 开销 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **单次防御性 Prompt** | 单次推理（约 1-2 秒） | 基准消耗（1x） | 常见搜索摘要、客服日常问答、效率助手 |
| **两阶段核查流（Generate-Verify）** | 两次串行推理（约 2-4 秒） | 显著增加（约 2.2x - 2.5x） | 合规初筛辅助、专业文档核验、售后争议初审（人机协同） |
| **Prompt + 后端代码严格匹配** | 单次推理 + 代码微秒级比对 | 无额外模型 Token | 具有固定事实摘录要求的结构化信息提取 |

*注：耗时基于常见商业模型在常规网络条件下的典型端到端时延估算，实际开销取决于并发、上下文长度与所选模型架构。*

## 原理边界：为什么 Prompt 无法 100% 根除幻觉？

在面试中被问及“Prompt 能否彻底解决大模型幻觉”时，切忌给出绝对肯定的回答。大模型的内在工作机制决定了 Prompt 工程只能降低幻觉概率，而无法提供绝对的事实保证。

![自回归概率长尾分布与 Prompt 防御边界](/images/content-rebuild/8d736437ac0186d9/fig-6.png)

1. **概率采样的离散长尾：** 模型输出是基于词表的多项分布采样。即使将采样温度（Temperature）设为 0（贪心解码），模型挑选的也是“概率最大的下一个 Token”，而不是“客观逻辑正确的 Token”。如果训练数据中某种偏见词频更高，最可几的序列依然可能包含事实错误；若开启随机采样（$T > 0$），在离散长尾中总存在选中非预期词元的概率。
2. **长上下文注意力分散：** 随着上下文材料变长，注意力分布会被稀释。当材料达到几万甚至数十万 Token 时，模型即使在理论上下文窗口内，也可能发生关键约束指令检索不到或注意力被噪声淹没的问题（可参考 [/llm-100/evaluation/reducing-hallucinations.md](/llm-100/evaluation/reducing-hallucinations.md)）。
3. **缺乏真正的未知状态：** 关系型数据库查询不到记录时会明确返回 `NULL` 或 `EmptySet`，但神经网络的参数是一组稠密浮点数，它内部没有专门的“未知状态标记”。模型输出“材料未提及”，本质上仍然是在模仿人类表达“不知道”的文本序列。遇到极具欺骗性或逻辑陷阱的提问时，模型仍可能被诱导回生成模式中。

## 面试追问深度准备

### 追问 1：为什么在提示词中只说“不要撒谎/禁止编造”，基本不起作用？

> **参考回答：**
> 负向提示词存在两个缺陷：
> 1. 它没有给出具体的正向替代路径。模型在上下文不全时，不知道该输出哪些确定的 Token，因此只能继续按语篇连贯性补全；
> 2. 从注意力与词表示角度看，“撒谎”、“胡编”这些高频词出现在提示词中，反而会在局部上下文引入这些语义概念的关联，不能转化为程序上的硬性拦截分支。有效的提示词必须正向定义退避语句（如“若无信息，请回复‘未提及’”）。

### 追问 2：如果在 RAG（检索增强生成）场景中，召回的知识库片段本身存在两篇矛盾的文档，Prompt 该如何处理？

> **参考回答：**
> 不能要求大模型自己去主观裁决哪篇文档是客观事实，这极易引发推测性幻觉。提示词应将任务转化为“多方观点陈述”：
> 1. 要求模型分别摘录文档 A 与文档 B 中关于该问题的具体语句；
> 2. 显式告知：“若文档间结论不一致，请指出双方分歧及各自来源，严禁自行折中或猜测结论。”关于知识检索与提示词编排，可参阅 [/interview/prompt-interview/rag-prompt.md](/interview/prompt-interview/rag-prompt.md)。

### 追问 3：在工程上线时，如何将 Prompt 防御与传统代码校验结合起来？

> **参考回答：**
> 单纯依赖 Prompt 是不够的，应采用“Prompt 约束格式 + 代码断言兜底”的双层架构：
> 1. Prompt 强制输出包含 `evidence_quote` 和 `answer` 的 JSON 格式；
> 2. 后端接收到响应后，先用确定性代码进行一致性校验：若 `evidence_quote` 非空，校验其是否确实存在于参考材料中（如 `evidence_quote in context`）；若为 `null`，则校验 `answer` 是否严格符合预设退避语句。一旦发现引文非空却无法在材料中找到，说明模型捏造了证据，程序直接截断响应并触发重试，或降级返回预设安全文案。这种确定性校验把语义检查转化为了确定的程序判定。

## 避坑指南

* **不要为了抑制幻觉盲目启动全量微调：** 大部分事实答非所问是提示词缺乏上下文边界与退避分支导致的。盲目微调不仅成本高，还可能导致模型泛化能力退化或拒答过度泛化（相关权衡见 [/interview/prompt-interview/prompt-vs-finetuning.md](/interview/prompt-interview/prompt-vs-finetuning.md)）。
* **事实性任务避免混入文学化指令：** “请生动形象、幽默风趣地根据资料回答”会让模型在用词多样性与事实严谨性之间产生冲突。事实类问答应将采样 Temperature 调至 0 或接近 0，并剔除所有文采修饰要求。
* **规则避免碎片堆砌：** 提示词中如果堆叠了数十条互不相干的“不要这样、不要那样”，容易引起指令间的注意力竞争，导致核心上下文被忽略。尽量精简为“限定来源、前置引文、标准退避”三条核心主干。
