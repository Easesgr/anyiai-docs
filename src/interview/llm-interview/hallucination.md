在大模型应用落地中，模型生成看似流畅严谨、实则毫无根据的内容，被称为“大模型幻觉（Hallucination）”。很多初学者容易将幻觉简单归结为“训练语料太少”或“提示词写得不够细”，但在面试与工程实践中，必须从自回归生成的概率机制出发，分清幻觉的类型与成因，并给出系统化的工程防御方案。

![大模型幻觉全景剖析封面](/images/content-rebuild/b59b8b90b319e626/cover.png)

## 30秒口述核心回答

> **面试口述模板**：
> 大模型的“幻觉”不是传统软件意义上的逻辑 Bug，而是**自回归语言模型按条件概率逐词采样时的副产物**。
>
> 大模型通过海量语料建立词表条件概率分布 $P(w_t \mid w_{<t})$，它的核心优化目标是让生成的文本流在语义和句法上连贯通顺，并不内置验证客观事实真伪的逻辑判定器。因此，幻觉无法仅凭 Prompt 优化彻底消除。
>
> 在实际业务中，幻觉通常分为两类：
> 1. **事实性幻觉**：输出内容与现实世界的客观常识、知识相悖（例如虚构不存在的奖项或论文）；
> 2. **忠实性幻觉**：输出内容违背了当前用户给定的参考上下文（例如财报写着利润 100 万，模型总结成 500 万）。
>
> 在工程落地中，缓解幻觉需要构建组合防护：通过 **[RAG 证据注入](/projects/rag-interview-qa.md)** 限制上下文边界、收紧 **[采样温度与截断策略](/interview/llm-interview/sampling-temperature-topp.md)** 减少尾部扰动、引入后置自然语言推理（NLI）做命题级交叉验证，并在模型置信度不足时触发**校准拒答机制**。

## 幻觉分类：事实性幻觉 vs 忠实性幻觉

评估和治理幻觉的第一步，是明确“判定模型出错的对照基准是什么”。业界通常以真理基准源的不同将幻觉划分为两类：

![事实性幻觉与忠实性幻觉的分类与基准对比](/images/content-rebuild/b59b8b90b319e626/fig-1.png)

### 1. 事实性幻觉（Factuality Hallucination）
* **判定基准**：现实世界的客观事实、百科知识、科学规律或行业常识。
* **表现形式**：
  * **事实虚构**：凭空造假。例如询问“某学者在哪一年获得了诺贝尔数学奖”，模型回答“他在 2018 年因代数几何成果获奖”（现实中没有诺贝尔数学奖）。
  * **事实冲突**：与已知事实矛盾。例如将历史事件的发生年份记错，或者把两家不同公司的创立背景混淆。
* **发生场景与原因**：常见于无参考资料的开放式问答。主要源于[预训练阶段](/interview/llm-interview/pretraining-objective.md)对长尾低频知识的表征不足，或海量知识在模型参数压缩过程中的信息丢失。

### 2. 忠实性幻觉（Faithfulness Hallucination）
* **判定基准**：用户在当前请求中明确提供的输入内容（包括 Prompt 指令、参考文档、历史对话）。
* **表现形式**：
  * **上下文冲突**：上传的文档明确写着“该药物临床试验每日推荐剂量为 5mg”，模型生成的报告却写成“每日推荐剂量为 20mg”。
  * **指令背离**：提示词要求“仅根据文章第三段提取三个结论”，模型却自行发散补充了文章中未提及的外部推测。
* **发生场景与原因**：常见于 RAG（检索增强生成）、长文档摘要、结构化抽取任务。主要由于长上下文注意力分散，或者模型自身参数中的记忆偏见压倒了外部输入的上下文证据。

## 生成机制：为什么模型会自然而然地“胡说”？

要解释幻觉的产生机理，需要从文本预测的数学形式、自回归解码过程以及微调对齐偏差三个层面分析。

![自回归生成中一步走偏导致错误级联放大的链式反应](/images/content-rebuild/b59b8b90b319e626/fig-2.png)

### 1. 概率似然不等于逻辑真值

因果语言模型生成文本时，是在最大化序列的联合概率分布：

$$P(W) = \prod_{t=1}^T P(w_t \mid w_1, w_2, \dots, w_{t-1}; \theta)$$

其中 $\theta$ 是模型在[预训练阶段](/interview/llm-interview/training-pipeline.md)学到的参数权重。自回归生成每一步挑选下一个 Token，选的是**条件概率最高的或者符合采样规则的词**，而不是“逻辑为真”的词。

* **相关性统计**：模型学习的是海量语料中词与词、短语与短语的共现关联。高频出现的句式结构在统计上更容易被激活，但模型内部并没有一个专门用于验证事实命题的布尔计算器。
* **参数的有损压缩**：几百亿或几千亿参数相对于互联网的海量知识而言是高度压缩的。模型对高频常识记忆牢固，但对于生僻、长尾知识，参数只记录了模糊的上下文模式。在解码时，模型为了拼凑出通顺的句式，很容易抓取常见词汇生硬拼装。

### 2. 错误级联放大（Error Cascade）

推理阶段是按步（Step）依次生成 Token 的，每生成一个新的 Token，它就会被写入 [KV Cache](/interview/llm-interview/kv-cache.md)，变成后续生成的已知输入：

1. 在步骤 $k$，由于长尾概率采样或先验知识模糊，模型输出出了一个轻微偏离事实的词 $w_k$（例如误写了一个年份）；
2. 从步骤 $k+1$ 开始，条件概率依赖的上下文变成了包含错误词的序列：$P(w_{k+1} \mid w_{<k}, w_k)$；
3. 自注意力机制为了让后文符合语法逻辑和语义顺畅，会倾向于把 $w_k$ 当作既定事实继续往后编造。模型会寻找能让“错误假说”显得合理的词汇，导致整段输出在虚构的方向上越走越远。

这就是为什么模型编造出来的内容往往语言极其自然、逻辑看似闭环，但结论完全错误。

### 3. 微调与对齐中的偏好诱导

幻觉不仅来自预训练阶段的概率建模，也受到后续[微调与对齐阶段（SFT / RLHF）](/interview/llm-interview/rlhf-pipeline.md)的直接影响：

![人类反馈强化学习中的偏好奖励偏差导致模型宁编勿弃](/images/content-rebuild/b59b8b90b319e626/fig-3.png)

* **详尽性奖励偏差**：在人类反馈标注中，测试人员通常给回答完整、信息量大、语气自信的回答打出更高分数；而对“我不知道”或过于简短的诚实回答打分较低。奖励模型学到了这种偏好，并在优化中强化了该倾向。
* **惩罚拒答导致过度自信**：策略模型受到惩罚后，即使在自身知识不完备或输入信息不足的情况下，也会倾向于强行编造一个看似完整的回答，而不是保守地拒绝作答。

## 生产环境缓解幻觉的四步方案

在业务落地的工程设计中，不能依赖模型自身“不再犯错”，而是需要建立分层的防线：

![生产级缓解大模型幻觉的四步漏斗流向图](/images/content-rebuild/b59b8b90b319e626/fig-4.png)

### 第一步：证据注入（RAG Grounding）
* **实施方式**：将开放式的无约束记忆问答，转为有据可查的材料阅读理解。在系统 Prompt 中注入检索到的真实文档，并添加硬性指令约束（如“仅根据给定的参考资料回答，如果资料未提及，请明确说明无法回答”）。
* **工程价值**：将治理重心从难以捉摸的事实性幻觉，收缩到相对容易监控的忠实性幻觉。

### 第二步：解码参数控制（Decoding Control）
* **实施方式**：
  * 在事实严谨型任务中，将 [Temperature](/interview/llm-interview/sampling-temperature-topp.md) 调为 `0`（或切换为 Greedy Search 贪心搜索）；
  * 如果需要保留少量多样性，可将 Top-P 限制在 `0.1 ~ 0.3` 的狭窄范围内，截断概率分布尾部的不稳定候选词。
* **工程价值**：阻断偶然采样到低概率错误词后引发的错误级联放大。

### 第三步：自验与 NLI 过滤（Claim Verification）
* **实施方式**：
  * 将大模型输出的长段落拆解为独立的命题声明（Atomic Claims）；
  * 接入轻量级的自然语言推理（NLI）小模型，将拆解出的命题逐条与参考文档比对，计算蕴含（Entailment）、中立（Neutral）与矛盾（Contradiction）标签；
  * 过滤掉被判定为矛盾或缺乏依据的句子，必要时触发重写。

### 第四步：校准拒答与置信度兜底（Abstention Calibration）
* **实施方式**：
  * **Logprob 监测**：监控生成答案中核心实体词的对数概率（Log-probability），若关键实体置信度低于阈值，系统降级为拒答；
  * **自一致性投票（Self-Consistency）**：在适度温度下并行采样 3~5 次输出。若关键数值或结论无法达成多数共识，判定模型内部不确定性过高，直接触发兜底模板或转人工流。

## 认知误区：上了 RAG 就没有幻觉了吗？

在面试中，许多人会认为“外挂检索后模型就不会产生幻觉了”。这是一个典型的工程认知漏洞。引入 RAG 会消除一部分参数事实遗忘，但也引入了新的失效链条，被称为**二次幻觉**：

![RAG 场景下引发二次幻觉的四种典型链路失效](/images/content-rebuild/b59b8b90b319e626/fig-5.png)

1. **检索噪声污染（Noise Injection）**：
   召回模块命中了语义相似但内容过期、甚至本身就是错误的文档，模型完全忠实地依据该错误文档输出了结论。此时模型没有发生忠实性幻觉，但生成结果依然构成了事实性幻觉。
2. **先验记忆冲突（Prior-Context Conflict）**：
   检索到的外部新证据与模型预训练学习到的先验发生冲突时，模型往往会忽视给定的参考文档，顽固输出预训练中的旧知识。
3. **长上下文注意力稀释（Lost in the Middle）**：
   拼接的上下文很长时，注意力机制往往集中在文本头部和尾部，位于中间段落的关键事实容易被模型忽略，导致模型在缺乏依据处自行脑补。
4. **多跳逻辑拼接错位（Synthesis Error）**：
   文档 A 提到“员工张三属于研发部”，文档 B 提到“研发部负责人上个月获得了技术奖”。模型在综合回答时，可能错误推断为“张三获得了技术奖”，将无因果关联的碎片信息强行拼凑成虚假命题。

## 面试追问深度拆解

### 追问一：在不微调参数的前提下，如何设计一个生产级问答防幻觉架构？

> **参考回答路径**：
> 在模型参数不可动的情况下，重点在于构建**检索校验双闭环的确定性工程防护**：

![端到端生产级防幻觉系统架构与双闭环校验流水线](/images/content-rebuild/b59b8b90b319e626/fig-6.png)

1. **意图路由分流**：对业务结构化数据或简单常识查询，直接走 SQL / 知识图谱 / 规则引擎，不进入大模型概率生成链路；
2. **检索与精排重排**：采用向量检索与 BM25 混合搜索，后接 Cross-Encoder Reranker，设定严格的相关性分数截断阈值，拒绝喂给模型低质参考材料；
3. **结构化 Prompt 约束**：要求模型输出必须带有对应段落的引用标注（Citation），将开放式论述改为限定段落的内容归纳；
4. **后置命题校验与熔断**：将生成内容切分为单句断言，利用 NLI 模型比对召回原文。若出现事实冲突，带上校验错误反馈自动重试一次；若两次重试依然不通过，触发标准兜底话术拒答。

### 追问二：为什么把 Temperature 设为 0，模型依然会产生幻觉？

> **参考回答路径**：
> Temperature（温度）控制的是 Softmax 概率分布的平滑程度：
>
> $$P(w_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$
>
> 当 $T \to 0$ 时，采样退化为贪心搜索（Greedy Search），模型在每一步仅仅选取未归一化得分（Logit）最大的那个 Token。但这无法消除幻觉，原因如下：
>
> 1. **概率最大不等于客观真实**：如果模型的参数中原本就缺失该知识，或者预训练数据中本身就充斥着高频的错误说法，那么模型算出的 Logit 最大值对应的 Token 本身就是错的；
> 2. **贪心搜索只消除了随机扰动**：设为 0 只能确保“输入相同 Prompt 时，每次输出结果严格一致”（消除采样随机性），但它无法修复模型参数中的认知偏差。也就是说，模型会**极其确定地重复输出同一个错误答案**。

## 读者自测与思考

1. **自测题 1**：在知识库问答中，知识库文档写着“系统最大支持 100 个节点”，大模型却回答“系统最大支持 1000 个节点”。在排查幻觉时，应该先检查哪些环节？
   * *考查点*：忠实性幻觉判定。排查顺序通常为：Prompt 是否施加了严格依据 Context 约束、输入 Token 长度是否触发了“中间迷失”、以及模型的参数先验是否与文档数值冲突。
2. **自测题 2**：为什么评估问答系统幻觉率时，不能简单采用 BLEU 或 ROUGE 等传统自然语言处理指标？
   * *考查点*：BLEU/ROUGE 仅衡量表面词重叠率（N-gram overlap），无法衡量命题的逻辑蕴含与真实性。一个多写了一个“不”字的句子在 BLEU 上得分极高，但在事实逻辑上完全相反。工业界通常采用 NLI 蕴含分类模型，或基于大模型裁判（LLM-as-a-Judge）的方法（如 Ragas 框架中的忠实度指标）进行命题级验证。
