在面试中被问到 Transformer 的位置编码时，许多候选人只能背诵“BERT 用可学习编码、原始 Transformer 用正弦编码、LLaMA 用 RoPE”，却很难解释清楚：既然 ALiBi 展现出了出色的免微调长度外推表现，为什么主流开源大模型依然普遍采用 RoPE？

自注意力机制本身只依赖 Token 之间的特征匹配，在未引入位置信息时具备**置换等变性**（Permutation Equivariance）而非置换不变性。如果把句子“小明 借了 一本 书”随意打乱词序，在不考虑因果掩码的标准自注意力中，任意两词之间的内容匹配打分完全不变，输出向量也仅随输入位置作同步置换，模型无法感知词与词之间的先后顺序与相对距离。位置编码的作用就是显式打破这种对称性，注入序列的空间几何结构。

关于正弦位置编码的基础数学公式可参考 [Transformer 的位置编码是怎样的？](/interview/llm-interview/transformer-positional-encoding.md)，关于 RoPE 的二维旋转分块与复数推导可参考 [了解 LLaMA 中的旋转位置编码吗？](/interview/llm-interview/llama-rope.md)。

## 30 秒口述结论

面试中遇到“请横向对比常见位置编码并说明 RoPE 为什么成为主流”时，可以按以下三层逻辑回答：

1. **绝对位置编码（如 BERT 可学习编码、Vaswani 正弦编码）**：直接在输入端把位置向量加进词向量。实现简单，但点积展开时混入了内容与绝对坐标的交叉项；且可学习编码使用固定大小的参数表，遇到超出训练长度的输入会直接越界报错，无法直接外推。
2. **相对注意力偏置（如 T5 对数分桶、ALiBi 线性衰减）**：不在输入端相加，而是在自注意力打分矩阵（$QK^T$）上直接加上与相对距离 $i - j$ 相关的偏置。ALiBi 依靠预设的单调负斜率惩罚，避免了长文本时 Softmax 概率发散，但强烈的远距离衰减会削弱跨长文本的强相关检索（如“大海捞针”任务），且动态加偏置不如纯点积与标准 FlashAttention 契合。
3. **旋转位置编码（RoPE）**：在计算注意力之前，通过正交旋转矩阵对 Query 和 Key 分别做坐标旋转。旋转后的向量点积，在代数上严格等价于一个只依赖相对距离 $m - n$ 的函数。它**以绝对坐标的形式计算，产生相对位置的效果**。自回归生成时只需旋转当前新 Token，历史 [KV Cache](/interview/llm-interview/kv-cache.md) 完全无需重算，且注意力打分维持标准点积形式，原生兼容 FlashAttention 算子融合，配合后续的基频插值扩展方案非常成熟，因此成为现代大模型的主流选择。

## 绝对位置编码：输入叠加与点积交叉项

绝对位置编码为序列中的每个离散索引 $i \in [0, L_{\text{max}} - 1]$ 分配一个 $d$ 维向量 $p_i$。在进入第一层 Transformer 之前，直接与词嵌入向量 $e_i$ 相加：

$$x_i = e_i + p_i$$

在 BERT 和 GPT-2 中，$p_i$ 存放在一个大小为 $L_{\text{max}} \times d$ 的可学习权重表中；而在原始 Transformer 中，$p_i$ 由固定的不同频率正余弦三角函数生成。详细推导见 [Transformer 为什么需要位置编码？](/fundamentals/transformer-arch/positional-encoding.md)。

![绝对位置编码的输入叠加与点积交叉项展开](/images/content-rebuild/08e194d2931fd310/fig-1.png)

### 点积展开带来的交叉项问题

当输入向量经过投影矩阵 $W_Q, W_K$ 产生 Query 和 Key 时，第 $i$ 个词与第 $j$ 个词的未归一化注意力打分可展开为四部分：

$$\begin{aligned}
\text{Score}_{ij} &= (x_i W_Q) (x_j W_K)^T \\
&= (e_i W_Q + p_i W_Q)(e_j W_K + p_j W_K)^T \\
&= \underbrace{e_i W_Q W_K^T e_j^T}_{\text{内容 - 内容}} + \underbrace{e_i W_Q W_K^T p_j^T}_{\text{内容 - 绝对位置}} + \underbrace{p_i W_Q W_K^T e_j^T}_{\text{绝对位置 - 内容}} + \underbrace{p_i W_Q W_K^T p_j^T}_{\text{绝对位置 - 绝对位置}}
\end{aligned}$$

从展开式中可以观察到两个计算特征：

1. **内容与绝对坐标耦合**：中间两项将具体的词语义与第 $j$ 或第 $i$ 个绝对坐标绑定。模型在学习“当前词是什么”的同时，还要拟合“这个词出现在第 500 个位置”的交叉特征。
2. **平移不对称**：即使两个词的相对位移 $\Delta = i - j$ 相同，第四项 $p_i W_Q W_K^T p_j^T$ 在序列开头（如 $i=2, j=1$）和序列末尾（如 $i=1002, j=1001$）的计算数值通常并不一致，无法天然保证平移不变性。

### 超出训练窗口时的越界与漂移

绝对位置编码在面对超过预训练长度的文本时，会遇到明确的瓶颈：

![绝对位置编码超出训练窗口时的截断越界](/images/content-rebuild/08e194d2931fd310/fig-2.png)

* **可学习编码物理越界**：如果可学习矩阵预先只分配了 $L_{\text{max}} = 2048$ 行，推理时 [上下文窗口](/interview/llm-interview/context-window.md) 达到第 2049 个 Token，底层查表会直接抛出索引越界异常（`IndexError`），完全无法运行。
* **固定正弦编码数值漂移**：正弦编码虽然可以套用公式计算超出 2048 的坐标向量，但因为高维投影层在预训练中从未见过该区域的坐标取值，输出的打分值可能出现不可控的漂移，导致 Softmax 分布失真。

## 相对位置偏置：在注意力矩阵上直接注入距离

文本理解更依赖局部词语之间的相对跨度（例如“借了”与“书”相差 2 个词），而不是它们在整本书中的绝对索引（如第 12,050 个词）。

相对位置偏置放弃了在输入端做向量叠加，转而在计算自注意力打分矩阵时，根据位置差 $i - j$ 引入偏置：

$$\text{Score}_{ij} = \frac{q_i k_j^T}{\sqrt{d}} + \text{Bias}(i, j)$$

### 1. T5 的对数分桶偏置

Google 在 T5 模型中，将 $\text{Bias}(i, j)$ 定义为一个通过相对距离查找的可学习标量 $b_{\text{bucket}(i-j)}$。为了控制参数量并覆盖长距离，T5 采用对数分桶：

![T5 相对位置偏置分桶机制](/images/content-rebuild/08e194d2931fd310/fig-3.png)

* **近距离精细分辨**：当相对距离较小（如 $|i-j| < 8$）时，每个距离差对应一个独立的桶编号，保证近邻语法关系的独立建模。
* **远距离对数压缩**：当相对距离超出阈值时，使用对数映射划分区间。距离越远，同一个桶覆盖的相对跨度越大。
* **最大阈值截断**：超过预设的最大相对距离后，所有更远的 Token 共享同一个偏置参数。

**局限**：一旦测试距离超出设定的最大截断距离，所有远端词得到完全相同的偏置值，无法再对更细粒度的长程距离做出区分。

### 2. ALiBi：基于固定斜率的无参数线性偏置

ALiBi（Attention with Linear Biases）去掉了可学习的位置参数，在自注意力打分中直接减去一个与相对距离成正比的惩罚项：

$$\text{Score}_{ij} = \frac{q_i k_j^T}{\sqrt{d}} - m \cdot |i - j|$$

在因果自回归场景下，当前 Token 只能关注前面的 Token（$j \le i$），惩罚项简化为 $-m \cdot (i - j)$。

![ALiBi 线性偏置与多头斜率衰减机制](/images/content-rebuild/08e194d2931fd310/fig-4.png)

#### 斜率 $m$ 的配置规则

ALiBi 的斜率 $m$ 是在模型初始化时固定分配给每个注意力头的常量，不参与梯度反向传播。以头数 $H = 8$ 为例，各个头的斜率构成为公比为 $\frac{1}{2}$ 的几何级数：

$$\left\{ \frac{1}{2^1}, \frac{1}{2^2}, \dots, \frac{1}{2^8} \right\} = \left\{ \frac{1}{2}, \frac{1}{4}, \frac{1}{8}, \frac{1}{16}, \frac{1}{32}, \frac{1}{64}, \frac{1}{128}, \frac{1}{256} \right\}$$

* 斜率较大的头（如 $m = \frac{1}{2}$）对距离施加极大的压制，只保留局部相邻 Token 的注意力。
* 斜率较小的头（如 $m = \frac{1}{256}$）惩罚平缓，允许模型在更宽广的上下文范围内捕获依赖。

## 长度外推失效的原因分析

当模型在训练长度 $L_{\text{train}}$（例如 2048）下训练，直接输入更长长度 $L_{\text{test}}$（例如 8192）进行测试时，困惑度（Perplexity）常会出现大幅恶化。主要原因包含以下两点：

![长文本外推时注意力分布的稀疏性崩塌机制](/images/content-rebuild/08e194d2931fd310/fig-5.png)

1. **未见坐标导致的打分发散**：
   对于未经外推平滑的编码方式，大于训练长度的坐标进入未曾充分训练的投影区间。若个别位置的点积打分异常偏高，Softmax 的指数运算会迅速放大极值，把注意力集中在异常坐标上，导致局部关键信息被忽略。
2. **背景噪声累积与注意力稀释**：
   在自回归解码中，Softmax 的分母需要累加历史所有 Token 的指数项：
   $$A_{ij} = \frac{\exp(\text{Score}_{ij})}{\sum_{k=1}^i \exp(\text{Score}_{ik})}$$
   Softmax 的指数放大会优先凸显高打分项，分母项数增加在数学上并不必然稀释显著相关项。但在长文本外推中，若模型未能在未见过的超长距离上有效抑制无关背景词的打分，海量弱相关 Token 的指数累加会抬高分母基数，在经验上导致关键上下文的注意力权重被噪声摊薄。

ALiBi 之所以具备较好的免微调外推表现，是因为其在 Softmax 输入前施加了 $-m(i-j)$，在概率层面对应引入了 $\exp(-m(i-j))$ 的衰减因子。随着距离增大，远端项的贡献迅速衰减，分母的累加主要由局部窗口决定，因此即使序列从 2k 拉长到 8k，注意力分布形态依然保持相对稳定。

## 深度追问：ALiBi 外推能力好，为什么大模型普遍选择 RoPE？

这是大模型架构考查中的核心问题。ALiBi 虽然外推效果显著且无参数，但现代主流大模型（LLaMA 系列、Qwen 系列、Mistral、DeepSeek 等）依然选择了 RoPE，原因主要在**长程任务能力**与**GPU 工程算子实现**上。

![RoPE 在 KV Cache 与 FlashAttention 算子融合中的架构协同](/images/content-rebuild/08e194d2931fd310/fig-6.png)

### 1. 强单调衰减对长程检索任务（Needle In A Haystack）的压制

ALiBi 的先验假设是“越远的词通常越不重要”。这在自然语言建模与续写任务中通常成立，但在长文档问答、跨多文件代码调用分析、多轮对话召回首轮 Prompt 等场景下会遇到明显限制。

如果关键证据位于 16,000 个 Token 之前，ALiBi 的 $-m \cdot \Delta$ 惩罚项会直接扣减大量点积分值，远端的高匹配度 Key 极易被距离惩罚压制，无法获得足够的注意力权重。而 RoPE 没有强加硬性的全局距离衰减，模型保留了根据语义在长距离下建立高权重的选择空间。

### 2. FlashAttention 算子融合的工程契合度

长上下文能够高效训练和推理，关键依赖于 FlashAttention 等算子融合技术。FlashAttention 的优势在于将 $QK^T$ 的乘积保存在片上高速 SRAM 中，分块完成在线 Softmax，避免频繁将 $L \times L$ 大矩阵写回显存（HBM）。

* **RoPE** 是在生成 $Q$ 和 $K$ 之后，对向量本身做二维旋转变换。旋转完成后，$Q$ 和 $K$ 的维度没有发生任何变化，送入后续注意力计算时仍是标准的向量内积。计算核心可直接调用原生的 FlashAttention 原语。
* **ALiBi** 要求在点积之后、Softmax 之前，向打分矩阵显式叠加一个与相对距离相关的偏置矩阵。虽然 FlashAttention 支持传入 Bias 矩阵，但向计算流水线注入非标量动态偏置会增加 Kernel 编译复杂度，并在长上下文切块并行（Context Parallelism）通信调度时引入额外的协调成本。

### 3. KV Cache 的增量写入零成本

在自回归逐字生成时，模型每一步只需计算当前单个 Token 的 Query、Key 和 Value：

* 使用 **RoPE** 时，当前第 $t$ 步的 Key 向量只需根据当前绝对坐标 $t$ 完成自身的正交旋转，随后直接追加写入 [KV Cache](/interview/llm-interview/kv-cache.md)。已经保存在 Cache 中的历史 Key 向量**完全无需修改或重算**。
* 虽然 ALiBi 和 T5 也不需要回溯重算历史 Key，但 RoPE 同样保持了这一增量写入特性，且无需在解码时为历史 Key 维护额外的距离偏置查找逻辑。

### 4. 频率插值（Interpolation）扩展技术的成熟

原始 RoPE 遇到超出预训练长度的输入时同样会面临发散。但由于 RoPE 将位置信息编码在不同维度的旋转频率中，学术界和工程界发展出了成熟的坐标插值理论（如 Position Interpolation、NTK-aware Scaled RoPE、YaRN）。

通过对高低频分量进行精细的坐标缩放，模型能以极低数量的长文本微调代价，将 4k 窗口稳定扩展至 32k、128k 甚至更长。而 ALiBi 采用单调硬衰减，在需要扩展窗口并兼顾长短分辨率时，调优手段相对受限。

## RoPE 原理拆解：用绝对变换实现相对位置

RoPE（Rotary Position Embedding，旋转位置编码）的核心思路是：**寻找一个正交坐标变换操作，使得分别对位置 $m$ 的 Query 和位置 $n$ 的 Key 施加变换后，两者的点积结果只与相对距离 $m - n$ 有关。**

设输入向量投影后为 $q_m, k_n \in \mathbb{R}^d$。RoPE 将 $d$ 维向量切分成 $\frac{d}{2}$ 个二维子空间，在每个二维切片上乘以一个旋转矩阵：

$$R_{\theta, m} = \begin{pmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{pmatrix}$$

旋转矩阵是正交矩阵，满足 $R_{\theta, m}^T = R_{\theta, -m}$。当经过旋转的向量做内积时，正交性质发挥了作用：

$$\begin{aligned}
\tilde{q}_m^T \tilde{k}_n &= (R_{\theta, m} q_m)^T (R_{\theta, n} k_n) \\
&= q_m^T \left( R_{\theta, m}^T R_{\theta, n} \right) k_n \\
&= q_m^T R_{\theta, (n - m)} k_n
\end{aligned}$$

贯穿例子：句子“小明 (0) 借了 (1) 一本 (2) 书 (3)”。

当位置 3 的“书”作为 Query 去检索位置 1 的“借了”作为 Key 时，$m=3, n=1$。点积结果中的旋转量为 $R_{\theta, (1 - 3)} = R_{\theta, -2}$，完全只取决于两者相隔的 2 个位置差，原有的绝对坐标 3 和 1 在矩阵乘积中被相互抵消。

这展示了 RoPE 的双重优势：
* **编码形式是绝对的**：每个 Token 只需根据自己当前的位置标号独立旋转，适合 KV Cache 增量写入。
* **点积结果是相对的**：进入点积计算后自动转化为相对距离函数，维持平移不变性。

## 常见面试混淆与勘误

* **误区 1：认为 T5 相对位置偏置可以处理任意长文本。**
  * **勘误**：T5 采用了对数分桶截断策略，超出预设最大距离的所有相对间隔都会落入同一个桶中。这意味着对相差 200 个词和相差 20,000 个词，模型赋予的位置偏置是完全一样的，长程分辨能力在截断点后退化。
* **误区 2：以为 ALiBi 的斜率 $m$ 参与梯度训练。**
  * **勘误**：ALiBi 的设计目标就是消除位置相关的可学习参数。斜率 $m$ 是在模型搭建时按几何级数固定下来的超参数（例如 $2^{-8h/H}$），整个训练期间保持冻结。
* **误区 3：以为 RoPE 在无微调的情况下可以直接无损支持任意超长文本。**
  * **勘误**：原始 RoPE 仅具备有限的外推能力。当测试长度大幅超过训练长度时，部分高维低频旋转分量在训练期间未经历过完整周期的旋转，模型在高维空间遭遇未见过的相位组合，困惑度仍会急剧上升。实际将上下文从 4k 扩展至 32k、128k 时，必须配合插值微调方法（如 NTK-aware、YaRN）。
* **误区 4：以为相对位置编码在自回归生成时每一步都要回溯重算历史缓存。**
  * **勘误**：在因果注意力中，历史 Token 之间的相对关系早已固化。使用 RoPE 时，只需要对当前步生成的单点 $q_t, k_t$ 施加基于标号 $t$ 的旋转，然后将旋转后的 $k_t$ 写入 KV Cache。历史存放在 Cache 中的条目不需要任何回溯或重新计算。
