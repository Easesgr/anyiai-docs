在视觉语言（Vision-and-Language, V&L）多模态模型的发展历程中，特征提取的计算开销分配一直是架构设计的关键分水岭。在 ViLT（Vision-and-Language Transformer）提出前，主流的多模态模型通常依赖预先训练好的目标检测器（例如基于 Visual Genome 数据集训练的 Faster R-CNN）来提取物体候选区域（RoI）特征。这种方法语义明确，但目标检测过程极其缓慢，直接阻碍了模型的在线推理。ViLT 将纯视觉模型 [ViT（Vision Transformer）](/interview/llm-interview/vit-vision-transformer.md) 的 Patch 切分方案迁移到图文多模态任务中，通过移除复杂视觉骨干网络，给出了轻量特征提取的工程解法。

![ViLT架构演进封面](/images/content-rebuild/7dd3e0c8d489a365/cover.png)

---

## 30秒口述结论

面试中被问到“请介绍 ViLT 模型及其核心创新”时，建议按以下逻辑作答：

> **核心思路**：ViLT 彻底移除了计算昂贵的目标检测器（Faster R-CNN）与卷积神经网络主干，将视觉特征提取简化为单层线性 Patch 投影。
>
> **网络架构**：采用“视觉轻、文本轻、交互深”的单塔结构。图像切块投影后的 Patch 向量与分词查表得到的文本词向量分别加上位置编码和模态类型编码（Token Type Embedding），拼接成单一序列，直接送入标准 Transformer 编码器做统一的全自注意力交互。
>
> **工程收益与代价**：在端到端推理时，视觉特征提取耗时从原先占总延迟 90% 以上的数百毫秒骤降至 1 毫秒以内，整网推理速度提升数倍至数十倍；其代价是模型缺乏卷积归纳偏置与目标定位先验，在依赖小目标定位和密集空间推理的复杂任务（如 GQA 数据集）上，效果落后于基于检测框的传统重型模型。

## 一个贯穿示例：图文配对如何在 ViLT 中流转

为了直观理解 ViLT 的数据流动，我们以一个具体的输入样本为例：

- **文本输入**：`"一只橘猫趴在沙发上"`，经分词后得到 5 个 Token，加上开头的分类标记 $t_{\text{class}}$，共 6 个向量。
- **图像输入**：一张分辨率为 $384 \times 384$、通道数 $C=3$ 的照片，采用 $P=32$ 的 Patch 边长进行非重叠切分。

整个前向处理分为四步：

1. **图像切块与线性投影**：整图被切为 $(384 / 32) \times (384 / 32) = 12 \times 12 = 144$ 个 Patch。每个 Patch 展平成 $32 \times 32 \times 3 = 3072$ 维的向量，经过一个全连接层（无偏置矩阵乘法）映射为 $D=768$ 维的向量。ViLT 的图像分支不追加额外的分类标记，共计 144 个视觉向量。
2. **叠加位置与模态标识**：文本向量加上一维文本位置编码和模态标识 $t_{\text{type}}=0$；视觉向量加上一维视觉位置编码和模态标识 $v_{\text{type}}=1$。
3. **拼接单序列**：将 6 个文本向量与 144 个图像向量首尾拼接，组合成长为 $L_{\text{total}} = 150$ 的单序列。
4. **单塔自注意力计算**：这 150 个向量共同输入 12 层 Transformer 编码器。在多头自注意力计算中，每个文本 Token 都能同时注意到其他文本 Token 和所有的图像 Patch；反之亦然。最后抽取输出序列中 $t_{\text{class}}$ 对应的隐藏向量，通过一个线性层判断图文是否匹配。

## 传统瓶颈：为什么基于检测器的多模态模型推理极慢？

在 ViLT 之前，以 UNITER、OSCAR、Pixel-BERT 为代表的早期主流多模态模型均采用区域特征（Region Features）：

![多模态架构分类象限](/images/content-rebuild/7dd3e0c8d489a365/fig-1.png)

ViLT 论文将多模态预训练模型按“特征提取器轻重”与“跨模态交互深度”划分为四条路线：

1. **视觉重、文本轻、交互深（V-Heavy / T-Light / Deep Interaction）**：
   以 UNITER、OSCAR 为代表。文本端仅需简单的词表查表（Embedding Lookup），开销极小；视觉端则需运行完整的 Faster R-CNN，提取 36 到 100 个 RoI（感兴趣区域）特征，再送入深层 Transformer 进行全交互。这种架构的瓶颈在于视觉特征提取极其耗时。
2. **视觉重、文本重、交互浅（V-Heavy / T-Heavy / Shallow Interaction）**：
   以 CLIP、ALIGN 为代表的双塔架构。图像和文本分别使用深层独立网络提取特征，最后仅靠点乘（Dot Product）计算余弦相似度。该结构非常适合海量图文检索的离线建库与向量比对，但因缺乏细粒度交互，不适合深度图文推理任务。
3. **视觉重、文本轻、交互浅（V-Heavy / T-Light / Shallow Interaction）**：
   早期传统检索模型，采用预训练 CNN 加单层循环神经网络或浅层投影，表达能力有限。
4. **视觉轻、文本轻、交互深（V-Light / T-Light / Deep Interaction —— ViLT）**：
   将图像特征提取简化为一层线性 Patch 投影，省下的计算资源全部投入到深层多模态交互 Transformer 中。

### 延迟瓶颈拆解

以处理一张 $800 \times 1000$ 分辨率的图片为例，传统区域特征模型与 ViLT 的耗时分布差异显著：

![特征提取耗时对比](/images/content-rebuild/7dd3e0c8d489a365/fig-2.png)

- **传统区域特征模型**：
  1. **卷积主干计算**：图片前向通过 ResNet-101 生成特征图，耗时约数十毫秒。
  2. **候选框生成与过滤（RPN + NMS）**：区域候选网络生成数千个候选框，在 CPU/GPU 上执行非极大值抑制（NMS）串行筛选，耗时剧烈增加。
  3. **RoI 特征池化与全连接**：对保留下来的 36 到 100 个框逐一做 RoIAlign 并通过多层全连接头提取 2048 维向量。
  在常见服务器配置下，该提取过程通常在 800ms 至 900ms 左右，而后续 Transformer 多模态交互层仅耗时 15ms 到 25ms。视觉提取占用了全流程 95% 以上的时间。
- **ViLT 极简方案**：
  直接切块并通过一个线性矩阵映射为特征，耗时通常小于 1ms。端到端推理完全受限于 Transformer 的前向耗时，整体耗时在 15ms 到 30ms 级别，吞吐量提升了一个数量级。

## ViLT 输入表征与序列构建细节

ViLT 能够彻底摒弃卷积网络，核心在于将图像 Patch 与自然语言 Token 映射到完全相同的向量空间：

![ViLT输入向量构建机制](/images/content-rebuild/7dd3e0c8d489a365/fig-3.png)

### 1. 图像分块与线性投影（Patch Projection）

给定输入图像 $I \in \mathbb{R}^{H \times W \times C}$：
1. 将其沿空间维度划分为不重叠的块，每个块大小为 $P \times P$。整图被切出 $N = \frac{HW}{P^2}$ 个 Patch。
2. 每个 Patch 展平成一维向量 $v_i \in \mathbb{R}^{P^2 C}$。
3. 乘以可学习的投影矩阵 $W_v \in \mathbb{R}^{(P^2 C) \times D}$ 映射到隐藏维度 $D$：
   $$e_i^v = v_i W_v$$

在代码工程实现中，这等价于一个卷积核大小为 $P \times P$、步长为 $P$、输入通道为 $C$、输出通道为 $D$ 的单层 2D 卷积，之后再将空间维度展平。

### 2. 文本嵌入（Text Embedding）

输入文本切分为 $L$ 个离散 Token，通过常规词表矩阵查表得到：
$$e_j^t = \text{Embedding}(w_j) \in \mathbb{R}^D$$

### 3. 三维嵌入叠加与序列拼接

为了让单塔 Transformer 能够区分 Token 的空间/时间顺序以及模态来源，ViLT 在文本分支前置分类标记（Class Token $t_{\text{class}}$），并分别为文本和图像追加了位置编码（Position Embedding）和模态类型编码（Token Type Embedding）（图像分支不设单独的类别标记）：

| 模态分量 | 基础向量序列 | 位置编码 | 模态类型编码 |
| :--- | :--- | :--- | :--- |
| **文本分支** | 前置 $t_{\text{class}}$，后接词嵌入 $e_1^t, \dots, e_L^t$ | 一维可学习向量 $p_j^t \in \mathbb{R}^D$ | 标号为 0 的模态向量 $t^t \in \mathbb{R}^D$ |
| **图像分支** | 块投影 $e_1^v, \dots, e_N^v$（无额外类标记） | 一维可学习向量 $p_i^v \in \mathbb{R}^D$ | 标号为 1 的模态向量 $t^v \in \mathbb{R}^D$ |

最终送入单塔 Transformer 的初始输入序列 $\bar{z}_0$ 形式为：
$$\bar{z}_0 = \left[ \bar{t}_{\text{class}}; \bar{t}_1; \dots; \bar{t}_L; \bar{v}_1; \dots; \bar{v}_N \right]$$
其中：
$$\bar{t}_{\text{class}} = e_{\text{class}}^t + p_0^t + t^t, \quad \bar{t}_j = e_j^t + p_j^t + t^t, \quad \bar{v}_i = e_i^v + p_i^v + t^v$$

通过模态类型编码的加入，单塔结构不需要修改底层的注意力算子，就能让各层注意力权重动态感知向量是来自文本还是图像。

## 预训练目标与对齐机制

没有了目标检测器提取好的物体边界框与类别标签，ViLT 必须依赖预训练任务直接在端到端参数中建立跨模态语义对齐。ViLT 主要包含三个监督任务：

![ViLT三大预训练目标](/images/content-rebuild/7dd3e0c8d489a365/fig-5.png)

### 1. 图像文本匹配（Image-Text Matching, ITM）
- **机制**：以 50% 概率随机将正确配对的图像或文本替换为批次内的负样本。提取顶层 $t_{\text{class}}$ 输出向量，通过一个全连接层输出二分类预测分数。
- **难负例挖掘（Hard Negative Mining）**：在训练批次中，通过预先计算的图文相似度，特意挑选出表征相似但不配对的样本作为负例，迫使模型关注图文细节中的细微差异。

### 2. 掩码语言建模（Masked Language Modeling, MLM）
- **机制**：沿用 BERT 策略，以 15% 概率随机遮蔽文本 Token。由于图像特征没有经过离散化处理，模型需要综合未遮蔽的文本上下文以及全图各个 Patch 提供的视觉线索，还原被遮蔽的单词。

### 3. 词块对齐（Word-Patch Alignment, WPA）
- **机制**：为了在没有锚框的情况下建立词与局部区域的对应关系，论文探索了基于最优传输（Optimal Transport）的对齐目标。通过 IPOT 算法计算文本 Token 向量集与图像 Patch 向量集之间的 Wasserstein 距离，在弱监督下显式拉近实体词与其对应的 Patch。
- **工程消融结论**：实验表明，WPA 能够在一定程度上加速细粒度收敛，但由于最优传输迭代求解计算较重，在整体训练吞吐权衡下，ViLT 的标准预训练配置主要依赖 ITM 和 MLM。

## 面试深度追问

### 追问 1：ViLT 速度虽然快，但在 GQA 等强推理视觉问答任务中表现弱于 VinVL，原因是什么？

**考察意图**：评估候选人是否理解 Patch 方案的理论上限与缺陷，而非片面夸大“轻量化”收益。

**核心原因**：
1. **计算复杂度与分辨率的矛盾**：
   单塔全自注意力的计算复杂度为 $\mathcal{O}((L + N)^2)$，其中 $N = \frac{HW}{P^2}$。若要识别画面中的细小物体（如杯子上的文字或远处的飞鸟），必须使用更小的 Patch（如从 $32 \times 32$ 缩小至 $16 \times 16$ 甚至更小），此时 Patch 数量 $N$ 会呈 4 倍增加，使得注意力计算量和显存占用呈平方级暴增。因此 ViLT 在训练和推理时被迫采用较大的 Patch，丢失了高频局部几何细节。
2. **缺失多尺度检测先验（Inductive Bias）**：
   基于 Faster R-CNN 的特征提取器具有特征金字塔（FPN）、预设锚框（Anchors）和池化对齐（RoIAlign），对尺度变化和物体边界具有极强的空间先验；而 ViLT 的单层线性投影对边界和几何尺度毫无先验，全靠 Transformer 暴力拟合，对小目标和密集重叠目标的定位能力显著受限。
3. **单塔前几层的表达负担**：
   在重型骨干模型中，ResNet 前置层已完成了初级视觉特征（边缘、纹理、轮廓）的提取。而在 ViLT 中，单塔 Transformer 的前几层必须同时承担“从零学习低阶像素特征组合”与“文本句法分析”的双重负担，消耗了用于跨模态深度推理的有效参数容量。

![细粒度目标丢失分析](/images/content-rebuild/7dd3e0c8d489a365/fig-6.png)

### 追问 2：如果去掉模态类型编码（Token Type Embedding），模型能正常收敛吗？

**核心原因**：
能跑通前向计算，但训练效率和最终性能会显著下降。
图像 Patch 投影与文本词嵌入虽然初始维度一致（均为 $D$），且各自带有位置编码，但自注意力机制的核心计算 $Q K^\top$ 本质上只衡量向量在投影子空间中的点乘相似度。加入模态类型编码后，相当于在初始输入中人为注入了一个常量偏置，使模型在第 1 层自注意力中就能区分“模态内注意力分布”与“跨模态注意力分布”。如果没有这个偏置，模型需要花费更深的层数和更多的训练数据去隐式解耦两个模态的几何分布空间。

### 追问 3：ViLT 对后来大语言模型与多模态模型（如 BLIP、LLaVA）产生了什么启示？

**核心原因**：
1. **确立了 Patch-based 视觉编码的主流地位**：ViLT 证明了“无需经过繁琐耗时的目标检测器，直接用 Patch 方式切分图像也能完成多模态对齐”，这一结论为后续 BLIP、Flamingo、CLIP 以及现代多模态大模型（MLLM，如 LLaVA 使用 CLIP-ViT 作为视觉编码器）铺平了道路，彻底将 Faster R-CNN 淘汰出多模态主流工程管线。
2. **修正了单塔全交互的极端做法**：ViLT 试图用“单塔处理一切”，导致视觉分辨率受限且缺乏更强大的预训练视觉特征。后续的 BLIP 和 LLaVA 转向了折中方案——采用独立预训练好的深层 ViT 提取视觉 Token，再通过 Q-Former 或单层投影连接至大语言模型（LLM），在保留 Patch 便捷性的同时兼顾了高分辨率特征与强大的语言推理能力。

## 常见答题误区

1. **把 ViLT 当成双塔架构**：
   部分面试者容易将 ViLT 与 CLIP 混淆。CLIP 是双塔架构，图文两端各有一个完整的编码器，仅在末端做余弦相似度计算；而 ViLT 是典型的**极简输入 + 单塔全自注意力交互**架构。
2. **误以为 ViLT 内部包含轻量级 CNN 骨干**：
   ViLT 没有任何深层卷积层或残差块。所谓的卷积仅仅是单层线性投影矩阵 $W_v$ 在 PyTorch 中的等价算子实现（卷积核大小和步长均等于 Patch 边长 $P$）。
3. **断言去掉目标检测器实现了“性能全面超越”**：
   面试时切忌单向吹捧。ViLT 的优势在于**速度与延迟**（端到端耗时大幅降低数十倍）以及在粗粒度图文检索、分类任务上的性价比，但在目标重叠、小物体密集的复杂视觉问答场景中，其准确率与基于目标检测器的传统重型模型仍有客观差距。
