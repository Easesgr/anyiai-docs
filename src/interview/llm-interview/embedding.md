在大语言模型的入口和出口处，分别存在着两个负责词表与向量转换的关键模块：

1. **输入词嵌入（Input Embedding）**：负责将分词器输出的离散整型 Token ID 转换成连续稠密向量。
2. **输出解嵌层（LM-Head，亦称输出投影层）**：负责将 Transformer 最后一层输出的隐层向量映射回词表大小的对数几率（Logits），用于计算下一个词的生成概率。

理解这两个模块的物理实现与权重绑定关系，是搞清大模型显存分配、分布式切分以及词向量空间特性的基础。

## 面试速记回答

- **输入与输出的作用与实现**：从数学角度看，输入 Embedding 相当于单热向量（One-Hot）与词表矩阵相乘；但 GPU 底层为了规避稀疏矩阵运算的显存浪费，实际采用连续内存的**查表操作（Index Lookup）**。计算基地址偏移只需 $O(1)$ 寻址，读取搬运整行向量则与隐层维度成正比（单 Token 耗时 $O(d)$）。输出 LM-Head 则是稠密矩阵乘法（GEMM），将隐藏向量映射到整个词表维度的得分。
- **权重共享（Tie Weights）机制**：该机制直接令输出层权重等于输入词嵌入矩阵的转置（$W_u = W_e^T$）。其假设是“输入表征相近的词，在作为预测输出时也应具有接近的产生概率”。在参数量较小的早期模型（如 GPT-2）中，这一做法可以节省 15% 到 30% 以上的参数量，大幅减少显存占用。
- **现代大模型放弃共享的原因**：LLaMA、Mistral、Qwen 等现代大模型普遍采用独立权重（Untied Weights）。主要原因有三点：第一，输入端需要平滑的特征分布，而输出端受词频长尾规律影响，高频词需要更大的向量模长来匹配先验概率，强行共享会造成**模长冲突与表征退化**；第二，在数十亿参数以上的模型中，词表参数占比已被稀释到很低水平，省参数的边际效益大幅降低；第三，在分布式张量并行下，解绑权重可以避免跨显卡的权重转置通信，使流水线更简洁。

## 贯穿示例：从 Token ID 到下一个词预测

为了直观说明，我们设定一个具体的运行参数：
- 词表大小 $V = 50,000$（每个词对应一个 0 到 49,999 的整型 ID）；
- 模型隐藏层维度 $d = 4096$；
- 浮点精度采用 BF16（每个数值占 2 字节）。

假设输入文本经分词后得到两个词的 ID：`[1024, 88]`。

```
Token ID: [1024] ──(输入 Embedding: 查表)──> 向量 e_1 ∈ R^4096
Token ID: [88]   ──(输入 Embedding: 查表)──> 向量 e_2 ∈ R^4096
                           │
                 [多层 Transformer 计算]
                           │
最后一个位置隐状态: 向量 h ∈ R^4096
                           │
               ──(输出 LM-Head: 矩阵乘法)──>
Logits ∈ R^50000 ──(Softmax)──> 下一个词在 50,000 个候选中的概率分布
```

接下来，我们依次拆解输入端与输出端的具体运算与显存行为。

## 输入 Embedding：从数学乘法到 GPU 内存寻址

### 1. 数学形式：稀疏单热向量相乘

在概念公式中，对于 ID 为 $i$ 的 Token，我们可以构造一个长度为 $V$ 的单热向量 $\mathbf{x} = [0, \dots, 1, \dots, 0]$（仅第 $i$ 位为 1）。

设输入词嵌入矩阵为 $W_e \in \mathbb{R}^{V \times d}$，矩阵的每一行对应一个词的向量表示。将符号投影为稠密向量的公式为：

$$\mathbf{e} = \mathbf{x} W_e$$

根据矩阵乘法规则，$\mathbf{x} W_e$ 的结果就是矩阵 $W_e$ 的第 $i$ 行。

![查表与矩阵乘法的等价机制对比](/images/content-rebuild/c12c6a6af25e05c0/fig-1.png)

### 2. GPU 工程实现：避免单热张量的显存膨胀

如果在显卡中真的生成维度为 $[B, S, V]$ 的 One-Hot 浮点张量并执行矩阵乘法（GEMM），显存会立刻溢出。以批大小 $B=4$、序列长度 $S=2048$、词表 $V=151,936$（如常见现代词表）为例，仅存放该 One-Hot 张量在 BF16 下就需要：

$$4 \times 2048 \times 151,936 \times 2 \text{ 字节} \approx 2.49 \text{ GB}$$

因此，PyTorch 中的 `torch.nn.Embedding` 在底层完全不执行矩阵乘法，而是将其转化为显存上的**指针偏移寻址（Gather / Index Select）**：

```python
# 概念伪代码：通过显存基地址与偏移量直接读取切片
# base_ptr 为 Embedding 权重在显存中的起始物理地址
# stride 为单行字节大小：hidden_dim * sizeof(bfloat16)
offset = token_id * hidden_dim * 2  # 每个 BF16 占 2 字节
vector_address = base_ptr + offset
# 从全局显存直接读取连续 4096 个数值
```

这一操作属于典型的访存受限型任务（Memory-bound）。首地址换算只需 $O(1)$ 索引计算，但搬运整行切片需要连续读取 $d$ 个浮点数（单 Token 前向数据搬运复杂度为 $O(d)$），耗时主要取决于 GPU 的全局显存带宽。

### 3. 反向传播：稀疏梯度的原子加法累加

在前向计算中，查表只是读取显存切片；而在未启用权重共享的前提下，反向传播计算损失 $\mathcal{L}$ 对输入嵌入矩阵 $W_e$ 的直接偏导是**极度稀疏**的。

在当前批次中，若整段文本只用到了 100 个互不相同的 Token 且输入权重独立，那么矩阵 $W_e$ 中其余 49,900 行来自输入的直接激活梯度全为 0（若与 LM-Head 权重共享，输出端的反向传播仍会给全词表注入稠密梯度）。如果某个高频 Token（例如标点或助词）在一个批次中出现了多次，它在各个位置传回的激活梯度需要累加到同一行中：

$$\frac{\partial \mathcal{L}}{\partial W_e[k, :]} = \sum_{t \in \text{位置}(k)} \frac{\partial \mathcal{L}}{\partial \mathbf{e}_{k, t}}$$

![反向传播中稀疏梯度的原子累加](/images/content-rebuild/c12c6a6af25e05c0/fig-2.png)

在底层 CUDA 实现中，通常使用原子加法（`atomicAdd`）将各位置传回的切片梯度累加写回。需要注意，虽然独立权重下未命中行的直接激活梯度为 0，但在使用带有权重衰减（Weight Decay）的 AdamW 优化器时，这些未命中的行在参数更新步仍会被执行衰减更新；同时优化器依然必须为整个 $V \times d$ 的参数矩阵维护一阶动量与二阶方差状态。

## 权重共享（Tie Weights）：原理与显存对比

在 Transformer 顶层，最后一个 Token 输出的隐藏向量 $\mathbf{h} \in \mathbb{R}^{1 \times d}$ 需要映射回词表大小以预测下一个词。这通过语言模型头（LM-Head）完成：

$$\mathbf{z} = \mathbf{h} W_u \in \mathbb{R}^{1 \times V}, \quad P(y = j \mid \mathbf{h}) = \frac{\exp(z_j)}{\sum_{k=1}^V \exp(z_k)}$$

其中 $W_u \in \mathbb{R}^{d \times V}$ 是解嵌矩阵。

### 1. 权重绑定的对偶假设

权重共享（Weight Tying）的做法是直接令解嵌矩阵等于输入矩阵的转置：

$$W_u = W_e^T$$

此时预测词 $j$ 的得分（Logit）变为隐藏向量与输入词向量的点积：$z_j = \mathbf{h} \cdot \mathbf{w}_j$。

这一设计的假设是：如果词 A 和词 B 含义接近，那么它们作为输入时应当有相似的向量表示（$\mathbf{w}_A \approx \mathbf{w}_B$）；反过来，当上下文输出一个特征向量 $\mathbf{h}$ 时，它与 $\mathbf{w}_A$ 和 $\mathbf{w}_B$ 的打分也应当接近，即预测生成它们的概率倾向应当一致。

![权重共享机制与数据流转图](/images/content-rebuild/c12c6a6af25e05c0/fig-3.png)

### 2. 小模型中的显存节省算例

在隐层较小、参数量不大的早期架构（如 GPT-2 Small）中，词表权重在全模型中占据非常显著的比例。

**算例配置假设**：
- 词表大小 $V = 50,257$
- 隐层维度 $d = 768$
- Transformer 层数 $L = 12$

计算参数分布：
- 12 层 Transformer Block 的参数量约为 85M（注意力投影与前馈网络等）；
- 单个输入词嵌入矩阵 $W_e$ 的参数量为 $50,257 \times 768 \approx 38.6\text{M}$；
- **若不共享权重**：输出解嵌矩阵 $W_u$ 同样需要 38.6M 参数。两个词表矩阵合计约 77.2M 参数，占模型总参数（$85 + 77.2 = 162.2\text{M}$）的 **47.6%**；
- **若启用权重共享**：直接省去解嵌矩阵的 38.6M 参数，模型总参数降至约 123.6M，缩减近四分之一。

在 16 位浮点训练下，静态显存直接节省：

$$38.6 \times 10^6 \times 2 \text{ 字节} \approx 77.2 \text{ MB}$$

若按标准混合精度 AdamW 优化器计算（假设为主权重 4 字节、一阶动量 4 字节、二阶方差 4 字节、梯度 4 字节，每个参数维护开销约 16 字节），训练时节省的显存为：

$$38.6 \times 10^6 \times 16 \text{ 字节} \approx 617.6 \text{ MB}$$

对于小模型而言，这笔显存收益非常可观。具体显存构成可参考 [Transformer 显存开销拆解](/interview/llm-interview/transformer-memory.md)。

## 现代大模型为何普遍放弃权重共享？

在 LLaMA 系列、Mistral、Qwen 等现代大模型中，几乎都采用了输入与输出权重独立的做法。这一转变主要源于以下三方面的权衡。

### 1. 模长矛盾与表征退化

词向量在输入端和输出端承担的统计目标存在内在冲突：

- **输出端的词频先验依赖向量模长**：输出 Logit 计算为 $z_j = \mathbf{h} \cdot \mathbf{w}_j = \|\mathbf{h}\| \|\mathbf{w}_j\| \cos \theta$。自然语言中词汇出现频率差异极大（齐夫定律，Zipf's Law）。为了让常见的高频词（如“的”、标点符号）在无强语义偏向时也能获得较高的基线生成概率，输出矩阵中对应高频词的行向量倾向于学习出**更大的模长（Norm）**。
- **输入端需要模长均衡的语义空间**：如果在输入端强制复用这些高模长向量，高频词在刚进入模型第一层时就会在数值上压制语义更丰富、但模长较小的低频实词，破坏初始特征的平衡。
- **自由度限制导致表征退化**：强行令 $W_u = W_e^T$ 剥夺了输出层独立表达词频偏置的自由度，更容易导致所有词向量挤在一个狭窄的角度范围内（各向异性），降低模型的表征容量。

![输入与输出端向量模长与几何分布的冲突分析](/images/content-rebuild/c12c6a6af25e05c0/fig-4.png)

### 2. 大模型中参数占比急剧稀释

随着模型规模从几亿扩展到数十亿甚至数百亿，Transformer 主干层数增加、隐层大幅拓宽，主干参数量呈二次方增长，而 Embedding 层仅随隐层线性增长。

以 Qwen2-7B 为例：
- 词表大小 $V = 151,936$
- 隐层维度 $d = 4096$
- 单个嵌入矩阵参数量：$151,936 \times 4096 \approx 0.622\text{ B}$
- 额外解绑输出层所增加的 0.622B 参数，占 7B 总参数量的比例仅为：

$$\frac{0.622}{7.0} \approx 8.89\%$$

到了 70B 级别的模型中，该比例会进一步稀释到 1% 以下。为节省不到 2% 的参数而牺牲优化自由度与收敛指标，在工程上并不划算。

### 3. 分布式张量并行中的通信开销

在多卡张量并行（Tensor Parallelism）实现中：
- **输入 Embedding**：通常按词表维度切分，前向计算后需要同步隐藏向量。
- **输出 LM-Head**：通常按列切分，每张 GPU 计算一部分词表的局部 Logits，直接就地计算局部的交叉熵损失，最后通过单次跨卡通信得到总损失。

![张量并行下权重绑定引发的跨卡转置通信与解绑对比](/images/content-rebuild/c12c6a6af25e05c0/fig-5.png)

如果强行绑定权重，同一份物理权重在反向传播和前向传播中需要以不同切分形式进行计算，往往需要跨显卡做转置重排（All-Gather 或 Scatter-Gather 转置通信）。而解绑权重后，输入层与输出层在拓扑图上互不干扰，计算流水线更规整，更容易实现计算与通信的重叠掩盖。

## 面试追问与常见误区

### 追问 1：可以直接拿大模型第一层的 Token Embedding 算欧氏距离来衡量语义相似度吗？

**答案是不能。** 实际计算语义文本相似度（STS）时，标准做法是通过句子表征模型提取经过对比学习对齐的句向量，并计算余弦相似度。

根据 [Sentence Transformers 官方文档](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html) 的示例机制：

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

# 提取两组句子的向量表征
embeddings1 = model.encode(["The new movie is awesome"])
embeddings2 = model.encode(["The new movie is so great"])

# 计算相似度矩阵（默认计算余弦相似度）
similarities = model.similarity(embeddings1, embeddings2)
```

直接在 LLM 的第一层 Token Embedding 上计算欧氏距离存在以下三个问题：

1. **模长差异主导距离数值**：欧氏距离公式为 $d(\mathbf{u}, \mathbf{v}) = \sqrt{\|\mathbf{u}\|^2 + \|\mathbf{v}\|^2 - 2\mathbf{u} \cdot \mathbf{v}}$。若未做单位归一化，向量模长的差距会直接左右欧氏距离。两个语义相同但模长差距大的词，其欧氏距离可能反而大于两个模长相近但语义无关的词。
2. **静态符号缺乏上下文语境**：第一层的 Token 向量仅对应词典中的单一静态符号，无法反映多义词在特定句子中的具体含义。只有经过多层注意力融合后，隐藏状态才具备语境信息。
3. **未经对比学习对齐**：生成式语言模型的目标是预测下一个词，而不是优化向量空间的空间角度。第一层向量往往存在表征坍缩或方向集中现象，直接计算几何距离的判别力很差。更多语义空间分析可参考 [Embedding 到底是什么？](/fundamentals/embedding/what-is-embedding.md) 与 [Embedding 如何表示语义相似度？](/fundamentals/embedding/embedding-similarity.md)。

![模长偏差对欧几里得距离判别语义相似度的扭曲机制](/images/content-rebuild/c12c6a6af25e05c0/fig-6.png)

### 追问 2：词表中新加入特殊 Token（如 `<|im_start|>`）时，它的 Embedding 初始值怎么设？

常见的工程处理方式包括：
- **均值初始化**：取已有所有常用词向量的平均值，作为新 Token 的初始向量，避免引入过大的初始偏置。
- **微小正态分布采样**：从 $\mathcal{N}(0, 0.02)$ 或与原权重标准差一致的分布中随机初始化。
- **多模态投影层对齐**：对于视觉或音频 Token，通常用专用的线性投影层将多模态编码器的输出映射到文本 Embedding 相同的维度空间，并在预训练第一阶段冻结语言模型主干，专门训练该投影层进行表征对齐。

### 常见认知错误对比

| 常见错误观点 | 物理现实与事实依据 |
| :--- | :--- |
| **“Embedding 查表快是因为底层维护了哈希表”** | **错误**。底层是连续虚拟显存的基地址直接偏移寻址（Direct Offset Addressing），通过下标直接换算内存地址，没有哈希计算与冲突解决开销。分词与 ID 映射逻辑参见 [Token 分词算法详解](/interview/llm-interview/tokenization.md)。 |
| **“权重共享必定会提升模型泛化能力”** | **不全面**。虽然共享机制减少了参数量、对小模型有正则化效果，但强行引入的对称性约束限制了输出层表达词频偏置的自由度，导致大模型容量受限。 |
| **“输入 Embedding 只要加上绝对位置编码就锁定了词序”** | **不准确**。相加只是引入加性偏置；在采用 RoPE（旋转位置编码）的现代主流架构中，输入层通常不叠加绝对位置编码，而是在每一层注意力计算时动态注入相对旋转变换。详见 [Decoder-only 架构解析](/interview/llm-interview/decoder-only.md)。 |
| **“只要把生成模型的隐藏向量做平均池化，就能直接拿来当检索向量”** | **错误**。未经对比学习微调的生成式隐藏状态存在均值偏移与方向集中问题，直接用于向量检索通常显著逊色于专门训练的检索模型。 |
