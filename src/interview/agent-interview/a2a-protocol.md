# 什么是 A2A 协议，它的核心架构及主要组件有哪些？

这道题考的是 AI 智能体通信协议的基础认知。面试官想看你能不能说清楚：智能体之间是怎么"打电话"的，这套通信标准长什么样、由哪些部分组成。

我从三个方面来讲：先说 A2A 是什么、再拆解它的七大核心组件、最后对比它和 MCP 的关系。

---
## A2A 协议是什么

A2A 是 Agent-to-Agent 的缩写，Google 在 2025 年推出的智能体通信开放标准。它解决的问题很简单：**让不同供应商、不同架构的 AI 智能体能够互相通信、协作完成任务**。

打个比方你就懂了。A2A 就像 USB 接口协议——不管你用的是苹果电脑还是 Windows 主机，不管 U 盘是金士顿还是三星的，只要接口对了，就能互相传输数据。A2A 就是智能体世界的"统一接口"，有了它，一个厂商的智能体可以调用另一个厂商的智能体，不用管对方底层怎么实现的。

它的技术底子很务实：

- 基于 HTTP 协议，你熟悉的 Web 技术栈就能跑
- 用 JSON-RPC 做请求响应，就是 JSON 格式的远程调用
- 支持 SSE（Server-Sent Events），能处理耗时长的任务，智能体不用干等着

所以 A2A 的本质就是：**一套基于 Web 标准的智能体间通信协议，让"找谁协作"这件事变得标准化**。

## 七大核心组件

A2A 协议定义了七个核心组件，理解了它们就理解了整个协议的运转逻辑。

**1. Agent Card——智能体的"名片"**

这是智能体的元数据描述文件，包含：智能体叫什么、能做什么、擅长什么、使用什么协议。所有智能体启动时会发布自己的 Agent Card，其他智能体通过查询 Agent Card 来发现"谁能帮我干这件事"。就像你去参加会议，先看签到表上的名片，知道谁是谁、谁负责什么。

**2. Client Agent——发起请求的那一方**

Client Agent 是主动发起协作请求的智能体。它负责：找到目标智能体、建立连接、发送任务请求。就像你要找人帮忙，会先翻电话簿找到人，然后拨通电话。

**3. Remote Agent——处理请求的那一方**

Remote Agent 是接收请求并执行任务的智能体。它暴露 A2A 接口，接收来自 Client Agent 的请求，执行后返回结果。它不需要暴露内部实现细节，对外只通过 A2A 协议通信。

**4. Task——任务管理**

A2A 用 Task 来追踪每个协作请求的生命周期。Task 有状态：submitted（已提交）、working（进行中）、completed（已完成）、failed（失败）。就像快递单号，你能实时看到任务进展到哪一步了。

**5. Message——消息传递**

Message 是智能体之间传递的信息单元。每次对话、每个指令、每条反馈都封装成 Message。Message 包含发送方、接收方、内容、时间戳等字段。

**6. Artifact——输出成果**

Artifact 是智能体产生的"硬成果"，比如生成的文档、代码文件、分析报告。跟即时消息不同，Artifact 是需要持久化保存的输出物。

**7. Parts——基本组件**

Parts 是 Message 和 Artifact 的基本构建单元。一个 Message 可以包含多个 Parts，每个 Part 可以是一段文本、一张图片、一个文件，或者其他类型的数据。就像乐高积木，Message 和 Artifact 都是由这些小零件拼起来的。

这七个组件配合起来的工作流程是：

1. Client Agent 通过 Agent Card 发现 Remote Agent
2. Client Agent 创建一个 Task，发起请求
3. 通过 Message 传递任务指令
4. Remote Agent 执行任务，生成 Artifact 作为成果
5. Task 状态实时更新，直到任务完成或失败

## A2A 与 MCP——各司其职

这是面试里经常被问到的问题：A2A 和 MCP 有什么区别？

**MCP（Model Context Protocol）解决的是"用什么工具"的问题**。MCP 定义了智能体怎么调用工具、怎么读写资源。比如智能体要用浏览器、查数据库、调用 API，这些都走 MCP。MCP 就像一个**工具箱**，告诉你有什么工具、怎么用。

**A2A 解决的是"找谁协作"的问题**。A2A 定义的是智能体之间怎么建立连接、怎么传递任务、怎么返回结果。就像一个**电话簿**，告诉你有事找谁、怎么联系。

它们不是竞争关系，是互补关系。实际系统里，两者往往一起用：

举个例子，零售库存管理智能体的完整工作流程：

- 智能体先用 MCP 调用数据库工具，查询当前库存
- 发现库存低于阈值，通过 A2A 联系供应商智能体，下达采购订单
- 供应商智能体返回确认，智能体再用 MCP 更新库存数据

**先有工具做事，再找人配合**——这俩协议各管一摊。

## 面试怎么答

**基础版**（100字左右）：

> A2A 是 Google 2025 年推出的智能体间通信协议，基于 HTTP/JSON-RPC/SSE 构建。它的核心组件有七个：Agent Card 用于智能体发现、Task 管理任务生命周期、Message 传递信息、Artifact 输出成果、Parts 作为基本数据单元。A2A 和 MCP 是互补协议——MCP 连接工具，A2A 连接智能体。

**加分版**（150-200字）：

> A2A 是 Google 推出的智能体通信开放标准，让不同供应商的智能体能跨系统协作。它的设计基于 Web 标准栈，优势在于：不暴露内部实现保障安全性、支持异步处理长时间任务、跨供应商互操作性良好。
>
> 核心组件包括 Agent Card（发现机制）、Task（状态管理）、Message、Artifact、Parts。实际应用中，A2A 和 MCP 往往配合使用——用 MCP 调用工具查数据，用 A2A 联系其他智能体协作。比如库存智能体查完数据库，发现缺货，就用 A2A 找供应商智能体下订单。
>
> 目前协议托管于 Linux 基金会，仍在早期发展阶段。

## 一句话总结

A2A 就是智能体世界的"统一通信标准"，它定义了智能体之间怎么发现彼此、怎么传递任务、怎么返回结果，配合 MCP 使用效果更佳。
