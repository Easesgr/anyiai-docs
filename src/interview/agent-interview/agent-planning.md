# Agent 如何进行任务规划？Plan-and-Execute 和 ReAct 有什么区别？

开头直接切入，介绍这道题考什么。

---

## 1. Agent 任务规划到底是什么？

先记住一个核心公式：**Agent = LLM + Planning + Memory + Tools**

LLM 是大脑，负责理解和推理；Memory 是记忆，存放过往经验；Tools 是工具，让 Agent 能实际操作；而 **Planning（规划）** 就是把大目标拆成小步骤的能力——这是 Agent 能否高效完成任务的关键。

打个比方，Planning 像一位将军制定作战计划。面对"打赢这场战役"这个大目标，将军不会直接喊"给我冲"，而是先理解战略意图，再拆解成具体战役、分配兵力、规划进攻路线。Agent 的 Planning 模块干的也是这事：把"帮我写一份市场分析报告"这样的模糊目标，拆成"搜索竞品数据→整理行业趋势→生成结论建议"这样的可执行步骤。

## 2. ReAct 范式——边想边做的探索者

ReAct 的全称是 **Reasoning + Acting**，核心就一句话：**每做一步之前，先想清楚再动手**。

它的执行循环是这样的：

**Thought → Action → Observation → Thought → Action → Observation → ...**

具体怎么跑？拿"找附近评分最高的餐厅"举例：

- **Thought**：用户想知道附近评分最高的餐厅，我需要先获取位置信息
- **Action**：调用工具获取当前位置
- **Observation**：得到位置是"北京市朝阳区"
- **Thought**：现在知道位置了，下一步搜索附近的餐厅
- **Action**：调用餐厅搜索工具
- **Observation**：得到3家餐厅，评分分别是4.5、4.8、4.2
- **Thought**：4.8分最高，就是这家了

看到了吗？**每一步都不是闷头干，而是先想再干**。这让 Agent 能根据上一步的结果动态调整策略，灵活应对意外情况。

ReAct 的优点：
- **灵活性高**：能根据实际情况随时调整方向
- **适合开放式任务**：不知道答案在哪，摸索着前进

ReAct 的缺点：
- **缺乏全局视角**：像蒙眼走路，可能绕远路
- **效率不稳定**：复杂任务可能反复试错

就像在陌生城市找路，没有地图，边走边问，偶尔会走冤枉路，但总能找到。

## 3. Plan-and-Execute 范式——谋定后动的规划者

Plan-and-Execute 正好相反：**先想好完整计划，再一步一步执行**。

它的流程分两阶段：

**第一阶段（Plan）**：分析目标，生成完整执行计划
**第二阶段（Execute）**：按计划顺序逐个执行，遇到问题可以回溯调整

还是"找附近评分最高的餐厅"：

**Plan 阶段**：
1. 获取用户当前位置
2. 搜索附近所有餐厅
3. 按评分排序
4. 返回评分最高的餐厅

**Execute 阶段**：
- 执行步骤1：调用位置工具 → 获得"北京市朝阳区"
- 执行步骤2：搜索餐厅 → 获得列表
- 执行步骤3：排序 → 确定最高分
- 执行步骤4：返回结果

就像按旅游攻略出行，先规划好今天去哪些景点、按什么顺序逛，到了现场就按计划执行，不用临时想下一步去哪。

Plan-and-Execute 的优点：
- **全局视角清晰**：一开始就看到完整路线，不容易跑偏
- **步骤依赖清晰**：哪些先做、哪些后做，一目了然
- **适合流程型任务**：步骤相对固定的任务，执行效率高

Plan-and-Execute 的缺点：
- **灵活性差**：计划赶不上变化，任务中途有变数就得重新规划
- **动态调整能力弱**：遇到意外情况不如 ReAct 应对自如

## 4. 两种范式怎么选？

直接说结论：**没有最好的范式，只有最适合的场景**。

| 对比维度 | ReAct | Plan-and-Execute |
|---------|-------|------------------|
| 灵活性 | 高 | 低 |
| 全局视角 | 弱 | 强 |
| 动态调整 | 强 | 弱 |
| 执行效率 | 不稳定 | 稳定 |
| 试错成本 | 可能较高 | 较低 |
| 适用场景 | 探索型、开放式 | 流程型、确定性 |

选 ReAct：当任务目标不明确、步骤不固定、需要灵活应对时。比如"帮我调研一下这个新领域"。

选 Plan-and-Execute：当任务步骤相对固定、有明确流程时。比如"帮我自动化处理这批订单"。

**但实际项目中，更聪明的做法是——混合使用**。

想象一下盖楼：先让 Plan-and-Execute 做全局规划——挖地基、打框架、砌墙、装修，这是大方向。然后每个步骤内部用 ReAct 灵活处理细节——地基遇到岩石怎么绕、墙面不平怎么补。

这就是混合策略：**Plan-and-Execute 做外层全局规划，ReAct 做内层局部执行**。

## 面试怎么答？

**基础版**（能说出来就过关）：

Agent 的任务规划主要有两种范式。ReAct 是"边想边做"，每一步都先思考再行动，灵活性高但可能走弯路，适合开放式探索类任务。Plan-and-Execute 是"谋定后动"，先生成完整计划再执行，全局视角清晰但灵活性差，适合流程固定的任务。实际选型要根据任务类型来定，没有绝对的优劣之分。

**加分版**（面试官眼前一亮）：

Agent 的规划能力本质是把大目标拆成可执行步骤。ReAct 的核心是 Thought-Action-Observation 循环，每步执行前先思考，适合目标不明确、步骤不固定的任务，但缺乏全局规划可能反复试错。Plan-and-Execute 则先规划再执行，用全局视角保证步骤有序，适合流程型任务，但动态调整能力弱。

我个人更倾向于**混合策略**：用 Plan-and-Execute 做外层全局规划，确定任务拆解和大方向；用 ReAct 做内层局部执行，保证每个步骤的灵活应对。这样既能保持全局清晰，又不失局部灵活性。比如开发一个客服 Agent，先用规划模块确定"查订单→退款→回访"的大流程，每个环节内部用 ReAct 灵活处理用户的各种追问。

---

## 一句话总结

Agent 任务规划的核心是**目标拆解能力**，ReAct 适合灵活探索，Plan-and-Execute 适合流程执行，**混合策略才是实战主流**。
