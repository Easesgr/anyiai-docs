在学习大模型与人工智能工程时，开发者常遇到两种困惑：要么停留在零散的提示词写法上，不清楚模型底层如何计费、为何响应变慢；要么一上来就尝试搭建高度动态的自主智能体，却缺乏程序校验与容错机制，导致线上运行经常出错。本文以一个“企业工单自动化处理系统”的演进为贯穿案例，把 AI 技能划分为五个可以实际验证的学习阶段，并提供明确的技术选型与路线入口。

## 1. 五阶段学习阶梯与交付产物

以开发工单处理系统为例，从最初写脚本到最终上线稳定服务，开发者经历的技术能力可以拆解为五个层级：

1. **L1 基础调用与接口认知**：搞清模型不是魔法函数，而是按 Token 计费且按序列输出的概率模型。目标是写出稳定的 API 调用脚本，正确解析响应格式，并能处理超时和限流。
2. **L2 模型原理与计算开销**：理解 Transformer 的注意力计算、Prefill 与 Decode 的差异，以及显存与文本长度的关系。当长工单导致推理延迟变高或模型产生幻觉时，能从机制上解释原因，而不是盲目调整提示词。
3. **L3 业务流水线与质量受控**：把模型放进真实业务逻辑。为工单配置知识库检索（RAG）以获取公司规程，使用模式校验（如 JSON Schema）锁死输出结构，用可控的工作流替代不可控的自由文本生成。
4. **L4 系统架构与服务稳定性**：面对多租户并发访问，通过反向代理网关实现模型切流、请求重试、幂等防护和链路追踪（Trace），保障生产环境可用性。
5. **L5 综合推演与技术复盘**：能够在系统设计与技术面试中，完整推导显存开销、说明检索召回评价指标（如 MRR、Recall@K），并解释复杂系统出现故障时的降级方案。

## 2. 读者起点与目标路线选择

不同背景的开发者技术储备不同，不需要按单一路线从头通读，可以根据自己的开发经验选择切入点。

![不同技术背景读者的路线选择决策图](/images/content-rebuild/6a94bc602df4b014/fig-1.png)

结合上图的分流逻辑，建议的路线入口如下：

- **Web 与后端开发工程师**：已经熟悉 API 设计、数据库与微服务架构。建议从 [AI 工程师入门学习路线](/learning-path/ai-engineer.md) 开始熟悉模型调用，随后进入 [大模型应用开发学习路线](/learning-path/llm-app-dev.md)，重点掌握受控工作流、多步审批分支和数据持久化。
- **数据密集与搜索系统开发者**：对全文检索、向量数据库或知识库感兴趣。建议直接进入 [RAG 实战学习路线](/learning-path/rag-practice.md)，搞清文本切分粒度对召回的影响、混合检索排序策略，并参考 [Agentic RAG 前沿专题](/frontier/agentic-rag/README.md) 了解检索前的意图重写与动态路由。
- **分布式与自主系统开发者**：在具备确定性工作流经验后，进入 [Agent 工程师学习路线](/learning-path/agent-engineer.md)，学习工具调用协议（如 MCP）、环境反馈循环与带有边界约束的自主规划。
- **算法理论与高校学习者**：希望从数学推导与张量运算切入。建议从 [从原理到 AI 工程学习路线](/learning-path/from-principles-to-ai-engineering.md) 开始，结合矩阵运算理解模型前向传播与训练收敛逻辑。
- **技术面试与求职准备**：根据目标岗位，选择 [AI 面试备战学习路线](/learning-path/ai-interview-prep.md) 复盘工程架构权衡，或通过 [算法工程师面试学习路线](/learning-path/algorithm-interview.md) 准备核心推导与算法细节问答。

## 3. 设计原则：确定性程序与概率模型的边界

工程落地的核心原则是：**能够用确定性程序、代码断言或业务规则保证的逻辑，不要完全交由大模型自由推断**。

为什么不能全交给模型？假设一个自动审批流程包含 3 个连续的推断步骤（如：识别工单分类、核对退款金额、给出处理决议）。在各步骤相互独立、无中间程序校验且无重试修正的理想化假设下，如果每一步的模型推断成功率均为 90%，那么 3 步连乘后的整体成功率仅为：

$$0.90 \times 0.90 \times 0.90 = 72.9\%$$

这意味着近三成的请求会在级联中出错。在实际工程中，不能放任这种错误扩散。解决办法是在步骤之间加入强类型校验与分支路由：

![确定性工作流与动态自主智能体的架构演变对比](/images/content-rebuild/6a94bc602df4b014/fig-2.png)

如上图对比所示，工作流（Workflow）采用有向无环图（DAG），每个节点都有明确的结构体校验；而动态智能体（Agent）引入了循环反馈。在进入智能体之前，先写好严格的输出校验：

```python
from pydantic import BaseModel, Field, ValidationError
from typing import Literal

class ApprovalDecision(BaseModel):
    """工单审批节点的强类型输出定义"""
    action: Literal["APPROVE", "REJECT", "ESCALATE"] = Field(
        description="审批动作：APPROVE通过，REJECT拒绝，ESCALATE升级人工"
    )
    risk_level: int = Field(
        ge=1, le=5, description="风险等级1到5"
    )
    audit_reason: str = Field(
        min_length=10, description="依据制度给出的合规说明，不少于10字"
    )

def parse_llm_output(json_text: str) -> ApprovalDecision | None:
    """用确定性代码校验模型输出，校验失败走降级处理"""
    try:
        return ApprovalDecision.model_validate_json(json_text)
    except ValidationError:
        # 校验失败时不直接崩溃，转入人工兜底或触发限定重试
        return None
```

在编写复杂业务流程前，建议先阅读 [AI Workflow 前沿专题](/frontier/ai-workflow/README.md)，掌握图编排中的状态快照、重试策略与人工介入节点的设计方式。

## 4. 阶段产物与自测验收基准

学习过程应当以能否写出运行代码、能否验证指标为衡量标准，避免只看不练：

| 学习阶段 | 阶段核心交付物 | 可执行的自测验收基准 |
| :--- | :--- | :--- |
| **L1 基础调用** | 封装好的模型请求客户端与 Token 统计器 | 遇到网络中断或 HTTP 429 能正确触发退避重试，统计的 Token 数量与账单对齐 |
| **L2 原理机制** | 简易自注意力运算与掩码矩阵计算脚本 | 编写的张量维度完全匹配，能手算出因果掩码如何阻断当前位置对未来 Token 的注意力关注 |
| **L3 业务流水线** | 混合检索知识库与工单审批工作流 | 输出格式 100% 满足 Pydantic 校验，在测试集上计算并验证检索的 MRR 与召回率 |
| **L4 系统架构** | 包含限流、重试与链路追踪的 API 网关 | 模拟后端模型超时或故障，客户端能平滑降级，分布式链路面板中可见各步延迟耗时 |
| **L5 综合推演** | 完整架构设计方案与显存测算推导 | 能在白板上推导长上下文对 KV Cache 显存的占用大小，并能清晰解释故障隔离方案 |

## 5. 路线依赖关系与进阶指引

站内的各个学习模块相互衔接，形成清晰的进阶图谱。

![站内学习路线依赖拓扑与子模块跳转图谱](/images/content-rebuild/6a94bc602df4b014/fig-3.png)

进阶步骤建议如下：

1. **打牢基础**：无论做应用还是做算法，先通过 [AI 工程师入门学习路线](/learning-path/ai-engineer.md) 或 [从原理到 AI 工程学习路线](/learning-path/from-principles-to-ai-engineering.md) 掌握模型接口调用与计算机制。
2. **业务集成**：以工单系统为例，如果需要检索规章制度并完成多步骤审批，应结合 [RAG 实战学习路线](/learning-path/rag-practice.md)（负责文档切分与召回）与 [大模型应用开发学习路线](/learning-path/llm-app-dev.md)（负责结构化输出与业务系统集成）。
3. **架构与自治**：当工单需要自主调用外部查询接口并进行动态规划时，进入 [Agent 工程师学习路线](/learning-path/agent-engineer.md)；同时结合 [AI 工程架构](/architecture/README.md) 搭建生产级网关，配置多租户鉴权与监控指标。
4. **复盘检验**：完成阶段学习后，通过 [AI 面试备战学习路线](/learning-path/ai-interview-prep.md) 检验全栈工程交付能力，或通过 [算法工程师面试学习路线](/learning-path/algorithm-interview.md) 验证理论深度与推导准确性。
