## 硬件准备与基准评估检查清单

大模型在单请求自回归生成（Decoding）阶段，每次生成一个 Token 都需要读取一次模型权重，属于典型的**内存带宽受限（Memory-Bound）**场景。评估硬件可行性时，除了看计算峰值算力（TFLOPS），更要优先排查显存容量与显存带宽：

### 1. 显存容量估算

加载模型所需的显存由静态模型权重、KV Cache 缓存和框架运行时开销三部分组成。

设模型参数量为 $P$（单位：十亿/Billion），每个参数平均量化位宽为 $b$（单位：bit）。静态权重显存约为：

$$M_{\text{weights}} \approx P \times \frac{b}{8} \times 1.1 \quad (\text{GB})$$

其中 $1.1$ 为量化模型中尺度参数（Scales）、偏差（Biases）等元数据的开销系数。

在推理过程中，模型还需要显存保存历史上下文的键值对（KV Cache）。KV Cache 的显存占用随并发批次大小（Batch Size）和上下文长度（Tokens）线性增长。再加上 CUDA Context 及框架固定缓冲区（约 $0.5\sim 1.5\text{ GB}$），典型配置参考如下：

* **7B 模型 4-bit 量化（如 Q4_K_M）**：静态权重约占 $4.2\text{ GB}$。在 $4\text{K}$ 上下文单并发下，建议显存不低于 $8\text{ GB}$。
* **14B 模型 4-bit 量化**：静态权重约占 $8.5\text{ GB}$。在 $4\text{K}$ 上下文单并发下，建议显存不低于 $16\text{ GB}$。
* **72B 模型 4-bit 量化**：静态权重约占 $42\text{ GB}$。单张 $24\text{ GB}$ 消费级显卡无法完整装下，需多卡张量并行（Tensor Parallelism）切分，或配备 $48\text{ GB}$ 以上显存的专业显卡。

### 2. 生成吞吐与内存带宽

在单并发（Batch Size = 1）自回归解码时，每个 Token 的生成都需要把模型权重从显存读取到计算核心中。当上下文相对较短、计算量未打满算力时，最大生成速度受限于内存读取速率：

$$\text{理论最大生成速率 (Tokens/s)} \approx \frac{\text{内存或显存带宽 (GB/s)}}{\text{模型权重占用 (GB)}}$$

例如，一个 $4.2\text{ GB}$ 的 7B 量化模型：
* 在带宽为 $1000\text{ GB/s}$ 的显卡（如 RTX 4090）上，理论解码速率上限约为 $1000 / 4.2 \approx 238\text{ Tokens/s}$；
* 在双通道 DDR5 内存（理论带宽约 $60\sim 80\text{ GB/s}$）的 CPU 上运行时，理论解码上限仅为 $70 / 4.2 \approx 16.7\text{ Tokens/s}$，实际通常在每秒数个到十几个 Token 之间。

*注：当并发请求数增加（Batch Size 变大）时，同一批权重读取可以为多个请求计算，计算密度提高，系统瓶颈会逐步从内存带宽受限转向算力受限（Compute-Bound）。*

![显存与系统内存带宽瓶颈差异对比](/images/content-rebuild/073e91a6dcbeac0f/fig-2.png)

上图对比了显存带宽与常规内存带宽对生成吞吐的影响。单纯为 PC 扩展 128GB DDR5 内存并不能显著提高解码速度，因为决定单并发生成速率的关键在于传输带宽。
