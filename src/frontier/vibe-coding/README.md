自然语言驱动编程（通常被称为 Vibe Coding）是指开发者或非专业技术人员通过多轮日常对话描述需求，由大语言模型直接编写、修改和组合代码，快速拼装出可运行软件的开发方式。这一模式明显缩短了从想法到原型的初始距离，但生成的代码依然运行在确定性的计算机环境里。

本专题旨在梳理自然语言写代码背后的实际运行逻辑，理清它能解决什么、不能解决什么，并给出可执行的质量控制建议。

## 一、核心结论：语言灵活度与运行确定性的冲突

大语言模型基于提示词自回归预测下一个 Token（词元），生成看似连贯的代码文本。自然语言天生允许省略、隐含假设和多义表达，而操作系统、运行时和编译器则对类型、空值、并发与边界条件要求绝对确定。只要自然语言中存在未明确的细节，模型就会基于训练分布进行概率填充。这种填充在常见模式下能碰巧正确，但在边缘场景下极易带来静默错误。

因此，用自然语言写代码并不意味着软件工程规则失效。要想持续得到可运行的软件，关键在于用明确的输入输出契约、可自动执行的测试以及小步迭代，为生成代码建立约束。

## 二、对比示例：模糊描述与契约约束的生成差异

通过一个简单的数据清洗函数，可以清楚观察到提示词约束对代码稳定性的影响：

![契约约束下自然语言生成代码的实验验证](/images/content-rebuild/71f0399c5535fada/fig-2.png)

### 示例输入 A：模糊自然语言

> **输入提示词**：
> “写个函数清洗数据，去掉空格并转大写。”

**模型典型输出**：
```python
def clean_data(text):
    return text.strip().upper()
```

* **问题分析**：该实现默认输入必然是合法字符串。当上游传入 `None`、整数 `123` 或空列表时，程序会在运行时直接抛出 `AttributeError: 'NoneType' object has no attribute 'strip'`，导致流程中断。

### 示例输入 B：契约化约束与测试用例要求

> **输入提示词**：
> “实现函数 `clean_name(val: object) -> str`。要求：若输入为 None 或非字符串类型，返回空字符串 `''`；若为字符串，去除首尾空白字符并转为大写。同时写出覆盖 None、整数、带空格字符串等情况的 pytest 单元测试。”

**模型典型输出**：
```python
def clean_name(val: object) -> str:
    if not isinstance(val, str):
        return ""
    return val.strip().upper()


def test_clean_name():
    assert clean_name(None) == ""
    assert clean_name(123) == ""
    assert clean_name("  alice  ") == "ALICE"
    assert clean_name("") == ""
```

* **对比结论**：大语言模型本身具备编写防御性逻辑的能力，但它无法凭空猜测未经说明的边界期望。提示词中对类型、异常输入及预期断言的形式化约束越明确，生成的代码越稳健。

## 四、使用建议：建立防护栏

在日常尝试或使用自然语言编写功能时，建议建立以下三项习惯：

1. **用可执行测试作为验收条件**：生成功能代码前，先明确输入输出断言，让模型生成测试用例，用运行结果验证功能正确性，而不是肉眼浏览代码。
2. **小步迭代并借助版本管理**：单次交互只改动少量文件或单个函数。每次通过测试后立即提交版本库（如 Git），确保随时可以退回稳定状态。
3. **人工核查依赖与敏感操作**：对模型引入的第三方库、网络请求和本地文件系统操作保持警惕，避免引入不存在的弃用包或危险的执行指令。
