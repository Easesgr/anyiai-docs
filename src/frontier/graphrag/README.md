在检索增强生成（RAG）工程中，主流实现通常采用“文本切块（Chunking）+ 向量检索（Dense Retrieval）”的组合。这套方案在处理具体事实查找时表现很好，比如从用户手册中查询某个具体的配置参数或错误代码。然而，当面对“跨多篇文档推导因果”或“对全库资料进行宏观总结”这类问题时，单纯依赖切块向量相似度往往会出现召回断裂。

本专题旨在拆解 GraphRAG（图增强检索生成）的工作机制，解释知识图谱与分层社区摘要如何补足向量检索的短板，厘清从离线抽取、图聚类到在线查询的完整技术链路。

## 向量分块检索在两类问题上的局限

基于文本切块的向量检索依赖单段文本与用户提问在嵌入空间中的余弦相似度。这种点对点的匹配方式在遇到以下两类查询时容易失效：

### 贯穿案例：跨文档故障排查

假设运维知识库中包含两份独立的记录：
* **切片 1（应用监控日志）**：“订单结算服务在 10:15 出现大量请求超时，排查发现底层数据库与缓存的连接池全部处于耗尽状态。”
* **切片 2（基础设施变更单）**：“网络组于凌晨 04:00 对核心交换机实施了固件升级，部分端口在新版本下的 TCP 握手重传率偶发升高。”

当技术负责人提问：“**今天上午订单超时故障的根因链路是什么？**”

传统向量切块检索在处理该问题时会遇到两个阻碍：

1. **抽象提问与具体事实的表征差异**：提问中的“根因链路”、“故障”属于高度概括的词汇。切片 1 和切片 2 记录的是具体的“连接池耗尽”和“TCP 握手重传”，两者在向量空间中的相似度得分可能并不突出。系统反而容易召回一些包含“故障根因分析规范”、“系统排障手册”等高频抽象词但没有实质事实的通用切片。
2. **跨文档的因果断链**：切片 1 和切片 2 存放在不同文档中，彼此独立切块并编码。切片向量本身只表征当前段落的语义，不包含跨文本的拓扑关联。即便检索召回了切片 1，向量检索机制也无法自动沿着“订单超时 $\rightarrow$ 连接池耗尽 $\rightarrow$ 网络重传 $\rightarrow$ 交换机固件”这条链路把切片 2 检索出来。

## 知识图谱与分层社区摘要如何解决问题

GraphRAG 并不是丢弃向量检索，而是在离线索引阶段引入知识图谱技术：先用大语言模型从切片中抽取**实体（Entity）**、**关系（Relationship）**及其**上下文描述（Description）**，构建出一张关联图谱；随后利用图聚类算法（如 Leiden 算法）将紧密相连的实体划分为多层级的“社区（Community）”，并自底向上为每个社区预生成**社区摘要（Community Summary）**。

![传统向量检索与分层图索引在全局归纳查询下的召回差异对比](/images/content-rebuild/c079b6901b48a278/fig-1.png)

如图 1 所示，图增强后的检索体系通常演进出两种互补的查询模式：

* **局部检索（Local Search）**：适合回答多跳关联问题。系统先从用户提问中提取核心实体（例如“订单结算服务”），在图谱中定位对应节点，沿着关系边向外遍历 1 到 2 跳（如找到“连接池”及关联的“交换机固件变更”），将这一子图相关的文本描述和原始切片组装为上下文输入模型，完成因果链条的拼接。
* **全局检索（Global Search）**：适合回答无明确单点实体的宏观总结问题（例如“系统本周有哪些主要风险点？”）。系统跳过细粒度的底层文本块，转而在预先生成的不同层级社区摘要中进行检索和加权聚合，由大模型并行提炼中间答案后再做最终汇总，避免单次上下文窗口被海量细节切片撑爆。

引入图结构的代价是高昂的离线开销：抽取全库三元组和生成分层社区摘要需要消耗大量的模型调用 Token 与计算时间。工程落地时必须评估任务类型与成本投入的平衡。

## 专题三篇主讲的渐进逻辑

本专题按“核心原理 $\rightarrow$ 构建实现 $\rightarrow$ 场景选型”三步展开：

![GraphRAG 专题三篇核心文章的递进学习链路与知识依赖](/images/content-rebuild/c079b6901b48a278/fig-2.png)

1. [GraphRAG 是什么？为什么知识图谱能增强传统向量检索？](what-is-graphrag.md)
   * **核心焦点**：对比切块向量检索与图检索的数据组织形式，讲清局部检索（Local Search）与全局检索（Global Search）的具体执行链路与适用问题类型。
   * **案例对照**：用同一个多跳因果问答用例，比对标准分块召回断片与图遍历召回完整链路的过程差异。
2. [GraphRAG 如何从文档中抽取实体、关系和社区摘要？](entity-extraction.md)
   * **核心焦点**：拆解离线构建流水线，包括大模型结构化抽取实体与关系、实体消歧与对齐（Entity Resolution），以及 Leiden 层次聚类算法构建社区摘要的实际流程。
   * **实现要点**：给出标准的实体抽取 Prompt 模版与数据结构，演示自底向上的社区摘要生成步骤。
3. [GraphRAG 适合哪些场景？长文档、多实体关系和企业知识库怎么用？](graphrag-scenarios.md)
   * **核心焦点**：落地选型决策逻辑、离线索引与在线查询的 Token 成本测算模型、动态混合路由架构。
   * **权衡分析**：对比何时仅需元数据过滤，何时需要轻量实体链接，何时才必须构建全量分层社区摘要，避免不必要的算力浪费。
