像 GPT 和 Llama 这类主流生成式大语言模型，都属于**自回归语言模型**（Autoregressive Language Model）。它的核心任务非常明确：**给定前面的上下文文本，预测下一个最可能出现的词（Token，词元）**。

很多初学者会遇到一对看似矛盾的问题：
1. 如果模型的任务是一步一步生成下一个词，为什么在训练时可以整句同时输入、全序列并行计算？
2. 既然训练时能够整句并行，为什么在线使用（推理生成）时，模型又必须一个词一个词地串行吐字？

要彻底搞懂这两个问题，我们需要顺着一条主线来看：数学上的条件概率分解、工程训练中的**因果掩码**（Causal Mask）与**教师强制**（Teacher Forcing），以及推理解码阶段的自回归循环和 **KV Cache**（键值缓存）。

## 贯穿例子：句子概率是怎样拆解的？

假设我们要让模型处理一句话：“小猫 喜欢 吃 鱼”。分词后得到 4 个词元：$x_1 = \text{小猫}$、$x_2 = \text{喜欢}$、$x_3 = \text{吃}$、$x_4 = \text{鱼}$。

在概率语言模型中，整句话出现的联合概率记为 $P(x_1, x_2, x_3, x_4)$。根据概率论的**链式法则**（Chain Rule of Probability），联合概率可以严格分解为每个词在给定历史上下文时的条件概率连乘：

$$
P(x_1, x_2, x_3, x_4) = P(x_1) \times P(x_2 \mid x_1) \times P(x_3 \mid x_1, x_2) \times P(x_4 \mid x_1, x_2, x_3)
$$

推广到任意长度为 $T$ 的文本序列 $X = (x_1, x_2, \dots, x_T)$：

$$
P(X) = \prod_{t=1}^T P(x_t \mid x_{<t})
$$

其中 $x_{<t} = (x_1, \dots, x_{t-1})$ 表示位置 $t$ 之前出现过的所有历史词元。

![序列联合概率的条件分解公式与单向因果依赖](/images/content-rebuild/ceac7ad067871d38/fig-1.png)

### 什么是“单向因果”？

这里的“因果”（Causal）并不是哲学上的因果关系，而是指**时间方向上的单向依赖**：模型在预测位置 $t$ 的词时，**只能参考历史词元 $x_{<t}$，绝不能参考未来词元 $x_{>t}$**。

神经网络参数 $\theta$ 的任务，就是学习逼近每个位置的条件概率分布 $P_\theta(x_t \mid x_{<t})$。训练的目标是在海量文本数据上，最大化所有真实词元的对数似然，也就是最小化全序列的**负对数似然损失**（Negative Log-Likelihood, 对应交叉熵损失）：

$$
\mathcal{L}(\theta) = - \sum_{t=1}^T \log P_\theta(x_t \mid x_{<t})
$$

请注意这个公式的结构：**全句的总损失，恰好等于每个位置单步损失的直接相加**。这意味着，只要我们在一次计算中能同时拿到所有位置的预测结果，就能一次性算出整条序列的损失并更新梯度，不需要真的等待前面的词计算完才开始算后面的词。

## 训练阶段如何并行？因果掩码遮蔽未来

在标准的 Transformer 自注意力机制中，输入序列中任意两个位置之间都会计算点积打分：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V
$$

如果不加任何限制，位置 1 的 Query 会去查询位置 2、位置 3 的 Key。这就发生了**信息泄露**：模型在预测“小猫”后面接什么词时，直接看到了“喜欢”甚至“鱼”。这样模型就会投机取巧，只需原样抄写下一个词，而根本无法学会根据前文推断下文的能力。<ReadMoreLock />

为了在保持矩阵乘法并行计算的同时阻断未来信息，自回归模型引入了**因果注意力掩码**（Causal Attention Mask）。

![Causal Attention Mask 下三角矩阵阻断未来信息计算流](/images/content-rebuild/ceac7ad067871d38/fig-2.png)

### 掩码矩阵的计算步骤

对于长度为 $T$ 的序列，注意力打分矩阵 $S = \frac{Q K^T}{\sqrt{d_k}}$ 的形状是 $[T, T]$。其中第 $i$ 行代表位置 $i$ 对所有位置的原始打分。

1. **构造掩码矩阵**：构造一个与 $S$ 大小相同的矩阵 $M$，保留主对角线及左下角（设为 $0$），把右上角（即所有 $j > i$ 的未来位置）全部设为 $-\infty$：
   $$
   M_{i, j} = \begin{cases} 0, & \text{if } j \le i \\ -\infty, & \text{if } j > i \end{cases}
   $$
2. **相加并进行 Softmax**：
   $$
   \tilde{S} = S + M
   $$
   对每一行执行 Softmax 归一化时，因为 $\exp(-\infty) = 0$，右上角的所有权重全部精准变为 $0$：
   $$
   A = \text{softmax}(\tilde{S}) = \begin{bmatrix}
   1.0 & 0 & 0 & 0 \\
   A_{2,1} & A_{2,2} & 0 & 0 \\
   A_{3,1} & A_{3,2} & A_{3,3} & 0 \\
   A_{4,1} & A_{4,2} & A_{4,3} & A_{4,4}
   \end{bmatrix}
   $$
3. **加权求和**：每个位置的输出向量 $O_i = \sum_{j=1}^i A_{i, j} V_j$，只融合了自身以及历史位置的特征，未来位置的权重被彻底阻断。

因为 GPU 能够高效完成批量的下三角矩阵乘法，所以即便每个位置看到的历史长度不同，整条序列的所有位置依然可以在**单次前向传播**中全部计算出来。

## 教师强制（Teacher Forcing）与张量移位切片

解决了“不能看未来”的问题后，另一个疑问随之而来：训练时，预测第 3 个词所需要的上下文“小猫 喜欢”，是从哪里来的？是模型自己先猜出第 2 个词再喂给第 3 个词吗？

不是。在训练中，工程上普遍采用 **教师强制（Teacher Forcing）**：**无论模型在前一个位置预测出了什么，输入给下一个位置的永远是训练语料里的真实词（Ground Truth）**。

![Teacher Forcing 训练模式下的张量错位切片与计算传递](/images/content-rebuild/ceac7ad067871d38/fig-3.png)

### 输入张量与目标标签的移位对齐（Label Shift）

继续用“小猫 喜欢 吃 鱼”为例。在代码实现中，我们只需要把原始 Token 序列做一次切片错位：

- **输入张量（Input IDs）**：去掉最后一个词，保留前 $T-1$ 个词：
  $$\text{input\_ids} = [\text{小猫}, \text{喜欢}, \text{吃}]
  $$
- **目标标签（Labels）**：去掉第一个词，保留后 $T-1$ 个词：
  $$\text{labels} = [\text{喜欢}, \text{吃}, \text{鱼}]
  $$

模型前向计算的过程如下：
- 模型输入 `小猫`，在第 1 个输出位置得到对词表的概率预测分布，与标签 `喜欢` 计算交叉熵损失；
- 模型输入 `小猫 喜欢`，在第 2 个输出位置得到概率预测分布，与标签 `吃` 计算交叉熵损失；
- 模型输入 `小猫 喜欢 吃`，在第 3 个输出位置得到概率预测分布，与标签 `鱼` 计算交叉熵损失。

因为这 3 个位置的输入都直接来自真实样本，它们之间在输入数据上没有上下步的依赖关系，所以可以在 GPU 上并行完成前向传播与反向传播。这就是训练时速度极高的根本原因。

## 为什么推理解码必须单步串行？KV Cache 的角色

到了推理阶段，情况发生了彻底改变：**我们手里没有完整的真实句子，未来文本是完全未知的**。

![训练期全序列并行计算与推理期逐步生成的计算图对比](/images/content-rebuild/ceac7ad067871d38/fig-4.png)

用户只给了一个 Prompt，例如“小猫”。
1. 模型输入“小猫”，输出词表概率分布，经过采样策略（如贪心采样、Top-p 采样）选出下一个词：“喜欢”；
2. 此时必须把“喜欢”拼接到输入中，形成“小猫 喜欢”，再次送进模型，预测出“吃”；
3. 再次拼接为“小猫 喜欢 吃”，送进模型预测出“鱼”。

因为**每一步的新输入必须等待上一步的离散采样结果**，无法提前预知，所以推理过程必然是串行循环的。

| 对比维度 | 训练阶段（Training） | 推理解码阶段（Inference Decode） |
| :--- | :--- | :--- |
| **输入已知性** | 目标文本已知，整句一次性传入 | 未来内容未知，仅有前置 Prompt |
| **执行模式** | **全序列矩阵并行**（单次前向处理整句） | **自回归单步串行**（逐步循环前向） |
| **输入来源** | 真实训练语料（Teacher Forcing） | 模型自身在上一步采样生成的 Token |
| **计算特征** | 通常为计算密集型（Compute-bound），整序列并行吞吐高 | 中小批次下常受显存带宽限制（Memory-bound），逐步迭代延迟显著 |
| **梯度反传** | 计算全序列损失并反向传播更新权重 | 无反向传播，仅做前向推断与采样 |

### 推理加速：KV Cache 避免重复计算

在串行循环中，如果每次生成新词都把整个句子从头算一遍，计算量会随着生成长度呈现平方级增长。

仔细观察注意力公式：当我们在第 $t$ 步计算新词时，历史词元的 Key 和 Value 向量是由模型固定权重对历史词元做线性投影得来的，**只要历史上下文不变，这些 Key 和 Value 的数值就不会变**。

![自回归解码中的 KV Cache 增量追加机制](/images/content-rebuild/ceac7ad067871d38/fig-5.png)

因此工程上引入了 **KV Cache（键值缓存）**：
- **Prefill 阶段（首字生成）**：把 Prompt 一次性送入模型，计算并缓存 Prompt 中所有词的 Key 和 Value。
- **Decode 阶段（增量生成）**：每生成一个新词，**只为这一个新词计算 Query、Key 和 Value**。计算出的新 Key 和 Value 追加保存到缓存末尾，Query 则与缓存中全部的 Key 计算注意力。这样就省去了重复计算历史词元投影的开销。

需要区分的是：**KV Cache 占用的是推理阶段的动态显存**，随生成长度和并发请求数线性增长；而**训练阶段的显存**主要由模型参数、优化器状态（如 Adam 动量）、反向传播所需的中间激活值和梯度构成，二者的来源和机制完全不同。

## 教师强制的副作用：曝光偏差（Exposure Bias）

教师强制带来了极高的训练吞吐，但也引入了一个理论与实际中的经典偏差——**曝光偏差**（Exposure Bias）。

![曝光偏差引发的自回归累积误差扩散链](/images/content-rebuild/ceac7ad067871d38/fig-6.png)

- **训练环境**：上下文全部是人类写好的标准语法序列。即使模型在某个位置预测出了低概率或错误选项，下一步的输入仍会被强行拉回真实语料的正确轨道。
- **推理环境**：模型必须消费自己采样出来的输出。一旦某一步采样出了一个不恰当的词（例如罕见搭配或事实错误），这个带有偏差的词就会成为后续步骤的既成历史。

这可能带来误差的逐步扩散：面对在预训练数据中少见的上下文分布，模型后续预测的不确定性可能增加，进而增加生成逻辑混乱或重复复读等异常现象的概率。需要说明的是，现代大语言模型通过海量数据预训练、指令微调（SFT）和强化学习偏好对齐（RLHF/DPO），已经在很大程度上具备了上下文纠偏与容错能力，单步采样偏差并不意味着推理过程必然发生失控崩溃。

## 机制验证：自注意力掩码与标签移位代码

以下是一段基于 PyTorch 的最小验证代码，演示因果掩码如何截断未来注意力，以及输入与标签是如何通过切片错位计算损失的：

```python
import torch
import torch.nn.functional as F

# 1. 验证因果注意力掩码（Causal Mask）的张量行为
seq_len = 4
hidden_dim = 8
torch.manual_seed(42)

# 模拟 Query 和 Key 张量 (Batch=1, Seq=4, Dim=8)
Q = torch.randn(1, seq_len, hidden_dim)
K = torch.randn(1, seq_len, hidden_dim)

# 计算原始点积打分 (1, 4, 4)
scores = torch.matmul(Q, K.transpose(-1, -2)) / (hidden_dim ** 0.5)

# 构造上三角掩码矩阵（主对角线上方为 True）
causal_mask = torch.triu(torch.ones(seq_len, seq_len, dtype=torch.bool), diagonal=1)
print("因果掩码布尔矩阵 (True 代表未来位置，需要被遮蔽):")
print(causal_mask)

# 将未来位置替换为负无穷大
masked_scores = scores.masked_fill(causal_mask, float("-inf"))

# Softmax 归一化
attention_weights = F.softmax(masked_scores, dim=-1)
print("\n经过 Softmax 后的注意力权重矩阵 (未来位置权重严格为 0):")
print(torch.round(attention_weights[0], decimals=3))

# 2. 验证 Teacher Forcing 的切片移位损失计算 (Shifted Cross-Entropy)
vocab_size = 10
# 假设模型输出的 Logits: (Batch=1, Seq=4, Vocab=10)
logits = torch.randn(1, seq_len, vocab_size)
# 假设实际输入的 Token ID: 对应 [小猫, 喜欢, 吃, 鱼]
input_ids = torch.tensor([[3, 7, 2, 5]], dtype=torch.long)

# 移位切片：输入取前 3 个词对应的预测，标签取后 3 个词的真实 ID
shift_logits = logits[..., :-1, :].contiguous()  # 预测: 对应位置 0, 1, 2
shift_labels = input_ids[..., 1:].contiguous()  # 目标: 词 7, 2, 5

loss = F.cross_entropy(
    shift_logits.view(-1, vocab_size),
    shift_labels.view(-1)
)

print("\n切片后用于计算损失的预测形状:", shift_logits.shape)  # [1, 3, 10]
print("切片后的监督目标标签:", shift_labels)              # [[7, 2, 5]]
print("单次前向计算出的标量损失:", round(loss.item(), 4))
```

运行上述代码可以看到：
- 权重矩阵的第 0 行只有第 0 列为 `1.0`，其余全为 `0.0`，位置 0 完全无法看到位置 1、2、3；
- `shift_logits` 与 `shift_labels` 实现了错位一位的对齐，模型用单次前向传播完成了 3 个预测步的联合监督。
