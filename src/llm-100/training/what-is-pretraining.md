在构建大语言模型（LLM）的整个生命周期中，**预训练（Pre-training）**耗费的算力和数据最多。初学者常常产生两种误解：一种认为模型在死记硬背互联网上的百科全书；另一种认为模型已经具备了像人类一样的推理思考能力。

实际上，预训练的机制非常具体：**给定一段由离散词元（Token）构成的文本，模型根据当前已知的前文，预测下一个可能出现的词元，并通过海量语料的参数更新，将文本序列中的统计规律压缩进浮点数权重中。**

为了把这个过程讲清楚，本文以一个贯穿始终的例子展开：输入文本序列“小明 在 周末 踢 足球”。我们将追踪模型如何把这句话拆解成自监督任务、如何计算损失、知识如何沉淀进参数，以及为什么这种训练方式天然会导致基座模型无法直接作为日常助手。

---

### 训练目标：最大化下一个词元的条件概率

计算机无法直接理解字符的含义，文本在输入模型前，首先会经过分词器（Tokenizer）映射为词表中的整数索引（Token ID）。假设在词表中：
- “小明”对应 ID 101
- “在”对应 ID 205
- “周末”对应 ID 309
- “踢”对应 ID 412
- “足球”对应 ID 520

整句话构成的离散序列为：$x = (w_1, w_2, w_3, w_4, w_5) = (101, 205, 309, 412, 520)$。

语言模型的目标，是计算这个完整句子在人类语言中出现的联合概率 $P(x)$。根据概率论的乘法链式法则，任何联合概率都可以分解为单向条件概率的连乘：

$$P(w_1, w_2, w_3, w_4, w_5) = P(w_1) \cdot P(w_2 \mid w_1) \cdot P(w_3 \mid w_1, w_2) \dots P(w_5 \mid w_1, w_2, w_3, w_4)$$

![序列联合概率分布极大似然估计的数学分解与优化目标示意图](/images/content-rebuild/cca3bf3fe094d738/fig-1.png)

模型参数用 $\theta$ 表示。如果模型能够对真实语料库中数万亿个类似序列都给出尽可能高的联合概率，就说明模型掌握了这门语言的词汇搭配与叙事模式。在数学上，这一优化准则称为**极大似然估计（Maximum Likelihood Estimation, MLE）**。

为了便于计算机进行数值计算与梯度求导，工程上通常对联合概率取自然对数，并将“最大化似然”转换为“最小化负对数似然损失（Negative Log-Likelihood, NLL）”：

$$\mathcal{L}(\theta) = -\sum_{t=1}^T \log P(w_t \mid w_{<t}; \theta)$$

以“小明 在 周末 踢 足球”为例，模型在第 5 步的任务，就是在已知上文为“小明 在 周末 踢”的条件下，输出整个词表大小的概率分布，并让属于“足球”（ID 520）的那一项概率尽可能接近 1。

关于自回归因果注意力的具体掩码机制，可参考 [自回归语言模型为什么能预测下一个词？](autoregressive-lm.md)；损失函数的批量张量计算实现，可参考 [大模型训练中的 Loss 是怎么计算的？](loss-calculation.md)。

### 标签从何而来：自监督的时间错位切片

在传统的图像分类等有监督任务中，每张图片都需要人工打上“猫”或“狗”的标签。但在数万亿 Token 的预训练中，并没有人工标注员为每个句子打标签。

因果语言模型（Causal Language Model, CLM）采用**自监督学习（Self-Supervised Learning）**：文本本身既是输入，也是标签。训练时通过把原始序列向后错开一位（Shift-by-One），自动生成成对的特征与标签：

- **输入特征（Input Tokens）**：去掉最后一个 Token，取序列的前面部分 $X = (w_1, w_2, \dots, w_{T-1})$。
- **目标标签（Target Labels）**：去掉第一个 Token，取序列的后续部分 $Y = (w_2, w_3, \dots, w_T)$。

![自监督信号构造过程：输入序列与右移监督标签对齐机制](/images/content-rebuild/cca3bf3fe094d738/fig-2.png)

沿用贯穿案例，长度为 5 的原始序列 `[101, 205, 309, 412, 520]` 会被切分为：
- 输入 $X$：`[101, 205, 309, 412]`（对应“小明 在 周末 踢”）
- 标签 $Y$：`[205, 309, 412, 520]`（对应“在 周末 踢 足球”）

此时，在同一个前向传播批次中，模型同时并行执行了 4 次单步预测：
1. 输入 `[小明]` $\to$ 预测 `在`
2. 输入 `[小明, 在]` $\to$ 预测 `周末`
3. 输入 `[小明, 在, 周末]` $\to$ 预测 `踢`
4. 输入 `[小明, 在, 周末, 踢]` $\to$ 预测 `足球`

在主流训练框架（如 [Hugging Face Transformers Causal Language Modeling](https://huggingface.co/docs/transformers/tasks/language_modeling)）中，开发者只需传入分词后的张量，框架底层的损失函数会自动对输入和标签完成切片对齐并计算交叉熵。

### 知识如何存储：参数化隐式表征与参数干涉

当模型在互联网语料上完成了成千上万轮梯度更新后，它的权重矩阵（嵌入层、自注意力投影矩阵 $W_q, W_k, W_v, W_o$ 以及前馈网络 MLP 权重）就记录下了语言规律与世界知识。这种存储机制与数据库有着本质区别。

![结构化数据库精确检索与神经网络隐式参数化知识存储机制对比](/images/content-rebuild/cca3bf3fe094d738/fig-3.png)

在传统的关系型数据库中，事实“法国的首都是巴黎”被显式存放在特定表的行与列中，查询具有确定性，更新或删除只需改动对应单元格。

但在神经网络中：
1. **分布式存储（Distributed Representation）**：事实并没有独立的物理存储地址。当模型读取“法国的首都是”时，注意力机制将上下文向量汇聚到特定模式，MLP 层的激活权重经过多层非线性映射，最终在输出层为“巴黎”分配最高概率。知识被稀释、打碎在成千上万个连续浮点数张量中。
2. **参数重叠与干涉（Parameter Interference）**：数十亿条事实共用同一套权重参数。模型通过共享权重获得了泛化能力（理解“A 的首都是 B”的抽象句式），但同时也带来了权重冲突。更新关于“某新兴公司 CEO 变更”的参数时，可能会轻微扰动其他长尾人物的关联表征。

如果应用场景要求数据 100% 准确、随时可查、支持秒级增删改，单纯依靠预训练参数是不可行的，通常需要配合外部检索与动态知识库，具体方案可参考 [/frontier/agentic-rag/what-is-agentic-rag.md](/frontier/agentic-rag/what-is-agentic-rag.md)。

### 统计相关性与模型幻觉的产生机理

理解了预训练的损失函数，就能清楚大模型为什么会产生**幻觉（Hallucination）**。

预训练的目标是拟合语料中词元共现的**统计相关性**，而不是验证物理现实的**真值逻辑**。

![统计概率高频共现与客观事实真实性之间的偏差成因分析](/images/content-rebuild/cca3bf3fe094d738/fig-4.png)

模型在生成文本时，只关注当前词元在给定前文下的条件概率。这导致了两个常见现象：

1. **流畅的废话与合理捏造**：如果模型学习了大量学术论文的写作范式（如“实验表明……”、“参考文献：……”），当它被要求引用某领域的论文时，输出最流畅、最符合学术用语习惯的词组合往往能拿到极高的对数似然分，即便该作者和论文标题在现实中完全不存在。
2. **长尾知识概率平坦**：高频出现的事实（如“地球绕着太阳转”）对应强烈的梯度信号；而冷门学科知识、小众人物生平在数十亿网页中只出现过一两次，相关参数很容易被更具普遍性的高频词汇冲淡。当被问及这些长尾问题时，模型的预测分布十分平缓，随机采样极易偏向常见但错误的词元。关于数据规模与模型拟合程度的关系，可阅读 [训练大模型为什么需要海量数据？](why-massive-data.md)。

因此，幻觉并非工程代码写错了，而是仅靠文本序列自监督概率建模必然存在的统计副产物。

### 基座模型的行为特征：续写引擎而非问答助手

直接从预训练产出的模型被称为**基座模型（Base Model）**。很多刚接触大模型的开发者直接给基座模型发指令时，经常觉得它“答非所问”。

这是因为基座模型被训练成了一个**纯粹的文本续写器**，它没有“我是 AI 助手、你在向我提问”的对话意识。

![基础预训练模型接收提问时的自然续写与对话意图偏差对比](/images/content-rebuild/cca3bf3fe094d738/fig-5.png)

例如，向基座模型输入：“请问如何用 Python 读取 CSV 文件？”

在互联网语料的分布中，这句话后面接的内容往往不是一段标准解答，而是来自问答论坛或习题集：
- 续写可能一：“有懂的大佬帮帮忙吗？急用！”（论坛回帖特征）
- 续写可能二：“A. pd.read_csv  B. np.load  C. open（请选出正确答案）”（考卷特征）

基座模型输出了高概率的合理续写，但这违背了用户的问答意图。要让模型从“接话引擎”转变为“听从指令、遵守安全边界的助手”，必须在预训练之后进行指令微调（SFT）和偏好对齐（如 RLHF / DPO）。

![从预训练基座能力到可交互指令助手的演化路径与技术边界](/images/content-rebuild/cca3bf3fe094d738/fig-6.png)

预训练赋予模型语言能力、语法结构与广博的常识基础，决定了模型理解力与智力水平的上限；而后训练则规范其交互格式，教会模型何时停顿、如何遵从安全准则与用户指令。

### 动手实验：用 PyTorch 实现最小因果切片与损失计算

通过下面这段可运行的 Python 代码，直观观察自监督切片机制与交叉熵损失的计算流程：

```python
import torch
import torch.nn as nn

# 设定固定随机种子以保证结果可复现
torch.manual_seed(42)

# 模拟超参数
batch_size = 1
seq_len = 5
vocab_size = 10

# 模拟一条已完成分词的 Token ID 序列: [1, 4, 2, 8, 5]
input_tokens = torch.tensor([[1, 4, 2, 8, 5]], dtype=torch.long)

# 1. 自监督时间错位切分 (Shift-by-One)
# input_ids 作为特征输入: 取前 4 个 Token [1, 4, 2, 8]
input_ids = input_tokens[:, :-1]
# target_labels 作为监督标签: 取后 4 个 Token [4, 2, 8, 5]
target_labels = input_tokens[:, 1:]

print("输入序列 X (input_ids):", input_ids.tolist()[0])
print("标签序列 Y (target_labels):", target_labels.tolist()[0])

# 2. 模拟 Transformer 最后一层的未归一化输出 (Logits)
# 形状为 [batch_size, seq_len - 1, vocab_size]
simulated_logits = torch.randn(batch_size, seq_len - 1, vocab_size, requires_grad=True)

# 3. 计算交叉熵损失 (CrossEntropyLoss 内部自动计算 Softmax 并计算负对数似然)
loss_fn = nn.CrossEntropyLoss()

loss = loss_fn(
    simulated_logits.view(-1, vocab_size),  # 展平为 [4, 10]
    target_labels.view(-1)                  # 展平为 [4]
)

# 4. 反向传播更新梯度
loss.backward()

print(f"计算所得损失值 Loss: {loss.item():.4f}")
print(f"Logits 梯度张量形状: {simulated_logits.grad.shape}")
```

**实验现象说明**：
- 原始序列长度为 5，切分后生成了 4 个单步监督标签。
- 无需任何外部标注文件，仅仅依靠序列自身的移位操作，梯度就能沿 `simulated_logits` 正常回传，这正是自监督预训练能够无限吞吐无标注文本的关键。

### 课后自测练习

1. **维度计算**：若批次大小为 8，文本序列长度截断为 1024，词表大小为 32000。在单次前向传播中，用于计算交叉熵损失的有效预测步总共有多少步？
2. **机制分析**：为什么基座模型在没有经过任何人工对话标注时，有时也能以很小概率接出正确的回答？请从语料库构成的角度解释。
3. **代码实验**：若在上述实验代码中，错误地将 `target_labels` 赋值为 `input_tokens[:, :-1]`（即输入与标签完全重合，没有后移一位），模型在长期训练后会学出什么策略？这种策略在生成新文本时会导致什么后果？
