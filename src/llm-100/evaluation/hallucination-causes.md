在上一讲 [/llm-100/evaluation/generation-quality-metrics.md](/llm-100/evaluation/generation-quality-metrics.md) 中，我们讨论了评估大模型文本质量的指标与人工评测方法。在实际开发中，最让工程师头疼的生成缺陷就是**幻觉（Hallucination）**：模型用极其流畅、笃定的语气，输出完全捏造的事实，或者直接推翻用户给定的参考资料。

先看一个直观的例子。如果我们提问：
> “爱因斯坦在哪一年因为发现万有引力定律获得了图灵奖？”

很多人期望模型纠错：“万有引力定律是牛顿发现的，图灵奖设立于 1966 年，爱因斯坦从未获得过图灵奖。”但在没有检索增强或强化校验时，模型很容易顺着提示词给出以下回答：
> “爱因斯坦于 1954 年因万有引力定律与相对论研究获得了图灵奖。”

如果在提示词中提供一段参考资料：“公司 2023 年第三季度营业收入 5000 万元，净亏损 1200 万元”，模型在生成摘要时却写道：“公司 2023 年第三季度营业收入 5000 万元，实现净利润 1200 万元”。

为什么参数量达到数百亿、上千亿的语言模型会出现这种低级错误？这并非代码出现偶然 Bug，也不是因为“模型记忆力不够”，而是现代自回归语言模型的**训练目标、数据分布、解码方式与注意力特性共同作用的结果**。

## 1. 幻觉的分类：事实性幻觉与忠实度幻觉

在学术界与实际评测体系中，“幻觉”指大模型生成的文本包含了**无事实依据、不可验证或与输入上下文直接冲突的信息**。工程评估时，幻觉通常被划分为两类：

1. **事实性幻觉（Factuality Hallucination）**：模型生成的内容违背了现实世界公认的客观事实。例如上述“爱因斯坦获得图灵奖”的例子，违背了物理世界与历史事实。这类问题常见于开放域问答和闭卷常识生成中。
2. **忠实度幻觉（Faithfulness Hallucination）**：模型生成的内容违背了用户明确给定的上下文线索。例如财报明确写着“净亏损 1200 万元”，模型摘要却输出“净利润 1200 万元”。尽管句子语法完全正确，但它背离了输入文档的约束。这类问题在文档摘要、阅读理解和 RAG（检索增强生成）场景中危害尤其严重。

![幻觉的双层分类体系](/images/content-rebuild/131a221cffc4bc6e/fig-1.png)

区分这两种类型对工程调试至关重要：
- **事实性幻觉**考察的是模型**参数内部记忆的知识**是否准确、是否被正确激活。
- **忠实度幻觉**考察的是模型在**上下文注意力机制引导下，提取与整合输入证据的能力**。

有关基础概念的定义与工程排查，读者亦可交叉参考 [基础教材中的幻觉解析](/fundamentals/llm-basics/hallucination.md) 与 [面试高频概念辨析](/interview/llm-interview/hallucination.md)。在工程落地上，为了替代主观随意的“人工感觉测试”（vibe checks），业界通常借助 Ragas 等评测框架，分别构建事实一致性与忠实度的自动化指标来进行持续评估。

## 2. 自回归生成的本质：优化连贯概率，而非形式真理

大模型之所以产生幻觉，最直接的原因是它的学习目标是**序列联合概率建模**，而不是形式逻辑系统。

主流自回归语言模型（如 GPT、LLaMA 系列）的自监督预训练目标，是最大化语料库序列的对数似然：

$$\mathcal{L}_{\text{LM}}(\theta) = - \sum_{t=1}^{T} \log P_\theta(x_t \mid x_{<t})$$

在推理生成阶段，模型依赖自回归循环，逐步预测下一个 Token 的条件概率分布：

$$P(X) = \prod_{t=1}^T P(x_t \mid x_1, x_2, \dots, x_{t-1})$$

![自回归联合概率推演与逻辑真理的脱节机制](/images/content-rebuild/131a221cffc4bc6e/fig-2.png)

模型生成每一个 Token 时，驱动其排名的仅仅是条件概率 $P(x_t \mid x_{<t})$，即**“统计上哪个离散词接在当前文字后最逼真、最流畅”**，而不是**“这句话在真实世界中是不是真理”**。模型内部并没有一个独立的“世界事实校验器”。

### 逐步采样算例：流畅的错误链条

为了看清错误是如何滚雪球般放大的，我们来看一个逐步生成的**教学示意算例**（注意：以下概率数值仅用于阐明条件转移过程，非实测模型输出）：

假设输入提示词为：`“提出万有引力定律的物理学家是”`。
模型在第一步解码时，预测下一个词的候选概率可能为：
- `“牛顿”`：$P = 0.82$
- `“伽利略”`：$P = 0.08$
- `“爱因斯坦”`：$P = 0.05$

如果采样时因为随机扰动或提示词引导，意外选中了概率较低的 `“爱因斯坦”`，上下文序列立即变为：`“提出万有引力定律的物理学家是爱因斯坦”`。

在第二步生成时，模型的预测条件完全变了。它需要计算：

$$P(x_{t+1} \mid \text{“提出万有引力定律的物理学家是爱因斯坦”})$$

在海量预训练语料中，“爱因斯坦”与“狭义相对论”、“光电效应”、“1905 年”等词汇高频共现。模型为了在局部维持上下文的语法与语义连贯性，接下来极大概率会顺着错误的轨迹继续生成：`“，他在 1905 年发表了这一里程碑论文……”`。

标准自回归模型在生成时是单向向前推进的，缺乏全局事后回溯重写的机制。一旦前置 Token 偏离事实，后续解码就会全力在这个错误前提下“自圆其说”，产出一段语法自然、逻辑自洽但事实全错的文本。

## 3. 预训练语料分布：齐普夫长尾与高频虚假共现

模型参数中存储的世界知识来自训练语料，但自然语言中的实体和知识分布呈现典型的**齐普夫定律（Zipf's Law）**长尾形态：少数高频实体（如“北京”、“太阳”、“相对论”）拥有极高的出现频次，而海量的专业术语、冷门历史、小众参数则分布在极其平缓的长尾末端。

![长尾知识分布与统计共现偏差](/images/content-rebuild/131a221cffc4bc6e/fig-3.png)

这种数据分布引发了两种典型的统计偏差：

1. **长尾实体的欠拟合（Parametric Underfitting）**：
   对于某个冷门开源工具的作者、偏远乡村的代码编号，模型在整个预训练阶段可能只遇到过一到两次。反向传播时，这些微弱的梯度更新很容易被海量高频文本覆盖。当提示词涉及这些盲区时，模型无法激活清晰的参数记忆，但自回归机制必须输出下一个词，于是模型只能根据上下文的句式模式，随机拼凑一个语义相近的实体填补空白。
2. **高频共现掩盖因果关系（Spurious Correlation）**：
   神经网络极其擅长捕捉词汇共现的捷径特征。如果实体 A 和概念 B 在语料中频繁同时出现（例如“图灵”与“诺贝尔奖”），即使语料中经常出现否定句（如“图灵生前未曾获得过诺贝尔奖”），自注意力机制对否定限定词的敏感度也往往容易被极高频的实体关联掩盖。在预测后续 Token 时，高频共现的统计偏置占了上风，模型便会输出“图灵曾获得诺贝尔奖”。

## 4. 对齐微调的副作用：强答机制与谄媚倾向

为了让预训练模型能够听懂指令、礼貌作答，工程上会进行指令微调（SFT）和基于人类偏好的强化学习（RLHF / DPO）。这些流程规范了回答的格式与基调，却也带来了意想不到的副作用。

![对齐微调诱发的强答机制与谄媚倾向](/images/content-rebuild/131a221cffc4bc6e/fig-4.png)

### 副作用一：SFT 训练集中的“无知强答”

在很多指令微调数据集中，几乎每个问题都对应着一段详尽、肯定且结构完整的答案，极少包含“我不知道”、“公开资料中没有记载”等诚实拒答样本。

如果微调数据中包含模型预训练参数中根本不存在的新领域知识，使用标准交叉熵损失进行微调，就会迫使模型在没有事实记忆支撑的前提下强行拟合目标输出。这无形中教会了模型一种行为模式：**即使不知道答案，也要用笃定确信的句式编造内容**。

### 副作用二：偏好对齐带来的谄媚性（Sycophancy）

在人类偏好标注中，标注员普遍存在认知偏差：回答字数多、列出详细步骤、语言客气且顺从提问者假设的回复，更容易得到高分；而指出用户提问有误、或者简短拒绝的回答，容易被判定为敷衍。

当强化学习奖励模型拟合了这种偏好后，大模型会表现出明显的谄媚倾向。如果用户提问：“请列举李白在第二次世界大战中使用的武器”，模型不仅不纠正“李白是唐代诗人”的荒谬前提，反而可能会一本正经地编造李白使用某种武器的伪历史来迎合提问。

## 5. 解码采样配置：贪婪生成与随机漂移

在模型生成阶段，模型输出的未归一化分数（Logits）$z$ 经过带有温度（Temperature, $T$）的 Softmax 计算得到概率分布：

$$P(x_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

![解码策略在概率空间中的漂移效应](/images/content-rebuild/131a221cffc4bc6e/fig-5.png)

不同的解码配置对幻觉有明显影响，但没有任何一种参数设置能单独消除幻觉：

1. **贪婪解码（Greedy Decoding，$T \to 0$）**：
   - *原理*：每一步只挑选概率最高的单一 Token（$x_t = \arg\max P(x_t \mid x_{<t})$）。
   - *局限*：**贪婪解码绝不等于事实正确**。它只能保证每一步的局部条件概率最大，既不能保证全局序列概率最大，更不代表现实真理。如果模型因高频共现而给错误答案赋予了更高的局部概率，贪婪解码会以最大的确定性走向错误。此外，贪婪解码在长文本中容易出现短语循环和模板僵化。
2. **核采样（Top-p Nucleus Sampling）与高温设置**：
   - *原理*：Top-p 只保留累积概率达到 $p$ 的候选词集合；温度 $T$ 调高则平滑概率分布，让低概率词有更多机会被选中。
   - *局限*：温度越高、Top-p 越宽，长尾中的不确定词汇被采中的概率就越大。一旦在某一关键实体上选错了 Token，由于自回归的单向不可逆性，后续所有步骤都会沿着偏差路径继续衍生，忠实度迅速下滑。

## 6. 长上下文衰减：“迷失在中间”与信噪比失衡

在 RAG（检索增强）或长文档分析场景下，开发者经常发现：参考资料明明包含了答案，模型却视而不见，给出了完全无关甚至自相矛盾的输出。这种忠实度幻觉通常源于注意力机制在超长文本下的表现衰退。

这种现象在工程中被称为**“迷失在中间（Lost in the Middle）”**。需要说明的是，这种退化并不是简单从 Softmax 归一化分母的算术变化就能推导出的必然数学定理（因为 Softmax 具有指数放大效应，如果相关 Key 与 Query 的内积足够突出，权重依然能高度集中）。在实际系统与模型架构中，这一现象是多种工程与数据因素共同导致的经验结果：

![长上下文注意力衰减与迷失在中间](/images/content-rebuild/131a221cffc4bc6e/fig-6.png)

1. **干扰信息堆积导致信噪比（SNR）下降**：
   当输入序列从几百 Token 扩张到上万 Token 时，与当前问题无关的段落和背景词呈数量级增长。尽管单个无关词的注意力权重极低，但海量弱相关词向量叠加在一起形成的背景噪声，会干扰模型对关键证据实体的精准聚焦。
2. **语料结构带来的首尾归纳偏置**：
   大多数人类书写的文章、论文、新闻，都具有“开头提出主旨、结尾进行总结”的特点。模型在海量文本上预训练后，注意力头自然形成了对输入序列首部（Prompt 开头）和尾部（靠近待生成位置）赋予更高权重的经验偏置（Primacy & Recency Bias）。放在中间区域的核心事实往往更难被有效提取。
3. **位置编码的长程建模限制**：
   主流位置编码（如 RoPE 旋转位置编码）在设计上具有随着相对距离增大、内积衰减的特性。当关键证据与生成位置相隔过远时，远距离相对位置的引导能力可能发生衰减，导致模型放弃从上文中寻找证据，转而依赖自身参数中不可靠的统计联想，从而产生幻觉。

关于 RAG 与工程提示词防幻觉的具体落地方案，可参考 [RAG 幻觉排查要点](/interview/rag-interview/rag-hallucination.md) 与 [提示词防幻觉实践](/interview/prompt-interview/reduce-hallucination.md)。

## 7. 总结与课后检验

大模型幻觉是概率生成模型在特定训练方式与架构设计下的内在特征：

| 诱发维度 | 幻觉类型倾向 | 核心原因 |
| :--- | :--- | :--- |
| **生成目标** | 事实性 + 忠实度 | 拟合人类语言接续概率而非物理世界真理；单向自回归导致一步错步步错 |
| **数据分布** | 事实性 | 齐普夫长尾知识欠拟合留下盲区；高频共现诱发虚假因果关系 |
| **对齐微调** | 事实性 | SFT 缺乏“不知道”样本诱发强答；偏好学习放大了顺从与谄媚倾向 |
| **解码采样** | 忠实度 | 贪婪解码无法纠正先验统计偏置；高随机采样导致路径漂移 |
| **注意力分配** | 忠实度 | 超长上下文中信噪比降低；位置编码与首尾偏置诱发“迷失在中间” |

理解这些机制，是设计防御策略的前提。在下一讲 [/llm-100/evaluation/reducing-hallucinations.md](/llm-100/evaluation/reducing-hallucinations.md) 中，我们将系统讨论如何通过外置检索、结构化约束、采样参数控制与解码干预来降低大模型的幻觉发生率。

### 课后检验

1. 为什么把采样温度设为 0（贪婪解码）无法彻底杜绝事实性幻觉？请结合条件概率给出一个简要推导说明。
2. 在设计 RAG 系统时，如果检索召回了 5 个文档片段，其中包含核心答案的片段应该放在提示词的最前面、中间还是最后面？为什么？
