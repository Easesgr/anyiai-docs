在上一讲[/llm-100/prompt-engineering/Zero-shot_Few-shot_Chain-of-Thought_有什么区别.md](/llm-100/prompt-engineering/Zero-shot_Few-shot_Chain-of-Thought_有什么区别.md)中，我们对比了普通提示与思维链（Chain-of-Thought, CoT）的表层应用形态。许多工程人员常把思维链解释为“模型学会了像人类一样一步一步思考”。这种拟人化的描述掩盖了自回归神经网络运行的真实过程。

大语言模型本质上是基于上下文预测下一个 Token 概率分布的统计模型，并不具备独立于前向传播之外的隐蔽思考空间。思维链之所以能在复杂多步推理中带来显著的正确率提升，关键在于两个机制：**让模型生成更多 Token，从而获得更多次前向传播的计算步数**；以及**将推导出的中间变量写入上下文，降低后续预测的条件熵**。本文将拆解自回归推理的内部机制，并界定显式思维链的忠实度局限与失效模式。

> **图面说明**：黑色短发、蓝色上衣、黄色内搭的讲解员正在展示思维链的底层机制。画面左侧是一个被展开的自回归计算序列，展示每生成一个中间 Token 就对应一次完整的前向传播；右侧呈现中间状态通过 KV 缓存注入后续计算，并明确标注忠实度与误差放大的边界。

### 贯穿示例：一道多步算术题的不同解法

为了直观理解这个机制，我们先看一个具体问题：
> “果篮里原有 15 个苹果。小明拿走 4 个，小红拿走的数量是小明的 2 倍，果篮里还剩几个苹果？”

如果要求模型**直接给出答案**，提示词形式为：
```text
问：果篮里原有 15 个苹果。小明拿走 4 个，小红拿走的数量是小明的 2 倍，果篮里还剩几个苹果？
答：剩余苹果数量是：[待生成]
```
此时模型必须在输出第一个数字 Token 时，就完成从原始问题到最终数字 `3` 的全部复合运算。

如果使用**思维链提示**，让模型输出中间步骤：
```text
问：果篮里原有 15 个苹果。小明拿走 4 个，小红拿走的数量是小明的 2 倍，果篮里还剩几个苹果？
答：我们一步一步计算：
1. 小明拿走 4 个；
2. 小红拿走 4 * 2 = 8 个；
3. 两人一共拿走 4 + 8 = 12 个；
4. 果篮剩余 15 - 12 = 3 个。
所以最终剩余 3 个。
```
表面上看是写出了解题过程，但在计算层面，模型在得出 `3` 之前，多执行了数次完整的神经网络前向传播，并且每一步计算得到的新数字都被作为输入提供给下一步。

### 1. 计算分配：生成更多 Token 对应更多前向传播计算步数

要理解思维链为什么有效，首先要看 Transformer 解码器（Decoder-only）在生成文本时的计算方式。

在自回归生成（Autoregressive Generation）阶段，模型每生成一个离散 Token，都需要将当前完整序列作为输入，执行一次前向传播（Forward Pass）。这意味着：**模型在推理阶段消耗的总浮点计算量（FLOPs），与最终生成的 Token 数量直接成正比。**

在标准稠密（Dense）Transformer 模型中，针对单个新 Token 的解码计算主要由权重矩阵乘法构成，计算量约为 $2N$ FLOPs（其中 $N$ 为模型非嵌入参数量）。注意力计算在生成阶段还会访问已缓存的历史键值对。

![直接输出与思维链的计算量分配对比](/images/content-rebuild/bf389c516bd75a1e/fig-1.png)

> **图面说明**：讲解员站在算力图表前，对比两种模式的计算分配。上方通道展示“直接输出答案”，模型在单步前向传播中强行完成从输入到答案的复杂映射；下方通道展示“思维链模式”，模型生成连续中间 Token，每步均执行完整的网络计算，将总计算预算显著拉长。正文在下文解释计算分配对表达能力的根本限制。

当要求模型直接给出最终答案时：
$$\text{输入: } x \implies \text{输出: } y$$
网络必须在**单次前向传播**内，通过固定的网络层数（如 32 层或 80 层），把输入文本的表征直接映射为最终答案。对于简单实体检索任务（如“法国的首都是哪里”），单次网络传递足以激活对应权重；但对于多步算术或逻辑约束问题，单步前向传播的网络计算深度（Circuit Depth）是固定的，模型无法动态增加层数来完成复杂复合函数的求值。

当引入思维链提示后，生成过程变为：
$$\text{输入: } x \implies \text{中间步骤: } z_1, z_2, \dots, z_K \implies \text{最终输出: } y$$
模型在输出最终答案 $y$ 之前，显式生成了 $K$ 个中间 Token。这意味着**模型额外获得了 $K$ 次前向传播的计算预算**。复杂任务被拆解为多个子目标，每次前向传播只需解决一个局部的单步变换（如先求出 $4 \times 2 = 8$），显著降低了单步计算的拟合难度。

### 2. 中间状态约束：复杂联合概率的多步序贯分解

除了计算量的增加，思维链生效的数学依据在于**重塑了条件概率的建模路径**。

如果直接让模型预测最终答案 $y$，模型求解的是跨度极大的直接条件概率 $P(y \mid x)$。在长链条推理任务中，从初始问题到最终答案的跨度过大，候选空间分布分散，采样时选中正确答案的概率较低。

思维链依据概率论中的链式法则，将联合概率拆解为多步序贯条件概率：
$$P(y, z_1, z_2, \dots, z_K \mid x) = \prod_{k=1}^K P(z_k \mid x, z_{<k}) \cdot P(y \mid x, z_{\le K})$$

![条件概率分解与 KV 缓存工作机制](/images/content-rebuild/bf389c516bd75a1e/fig-2.png)

> **图面说明**：讲解员指引黑板上的公式演进。中间状态序列 $z_1, z_2, \dots, z_K$ 逐一生成并存入 KV 缓存区，后续生成的每个 Token 都通过因果自注意力（Causal Self-Attention）读取已落盘的中间状态向量，以此缩减候选输出的熵空间。正文接下来说明 KV 缓存如何充当模型的外部物理草稿纸。

在生成中间步骤 $z_k$ 的过程中：
1. **状态显式输出**：Transformer 的因果自注意力掩码（Causal Mask）限制模型只能关注当前及之前的 Token。如果模型不把思考过程输出成文本，上一层前向传播计算出的中间隐藏激活在当前步生成结束后就会丢失，无法跨步暂存临时数值。
2. **KV 缓存充当工作记忆**：当模型生成了“小红拿走 8 个”这串文本后，这串 Token 对应的 Key 和 Value 向量会被保存在显存的 KV Cache 中。在计算下一步“两人一共拿走多少”时，自注意力机制可以直接读取此前算好的“4”和“8”，模型不必在内部隐式记忆这些数值。
3. **局部搜索空间收敛**：在计算第 $k$ 步时，模型的输入条件不再是抽象宽泛的原始问题 $x$，而是带有前序推导结论的具体上下文 $(x, z_{<k})$。局部的推导步骤更加确定，降低了下一步预测的条件熵。

### 3. Zero-shot CoT 与 Few-shot CoT 的触发机制

工程实践中常见的思维链有两种触发方式：Few-shot CoT（少样本示例）与 Zero-shot CoT（零样本触发短语）。二者在自回归过程中的引导机制各有侧重。

![Zero-shot 与 Few-shot 触发机制对比](/images/content-rebuild/bf389c516bd75a1e/fig-3.png)

> **图面说明**：讲解员正在比对两组提示词的生成路径。左侧 Zero-shot CoT 输入“让我们一步一步思考”，促使输出分布向分步格式转移；右侧 Few-shot CoT 通过“输入-步骤-答案”的范例上下文，直接锁定了多步输出的结构与句法模式。正文在下文阐明两种触发方式的技术本质。

#### Few-shot CoT：上下文学习（In-Context Learning）示范推导范式
在 Few-shot 场景下，Prompt 中包含若干组完整的 `[问题 -> 推导过程 -> 答案]` 样例。自注意力机制在读取这些样例时，捕捉到了推导步骤的组织格式、分步粒度以及输出标记规则。在解码阶段，模型沿用样例中的格式规范，稳定输出相似结构的推理链。

#### Zero-shot CoT：提示短语对预测分布的偏置
在 Prompt 末尾加入“让我们一步一步思考”（Let's think step by step）等短语，即可在无少样本示例的情况下提升推理表现。其作用机制包括：
- **抑制直接输出标签的统计倾向**：预训练语料中存在大量问答对，遇到问号结尾时，模型在统计上有较高概率直接接续简短的答案标签。加入引导短语后，接续预测的概率分布转向逻辑连接词（如“首先”、“根据题意”）。
- **激活逐步陈述的语篇模式**：该类短语在教材解答、推导教程等文本中高频出现。一旦写入 Prompt 末尾，模型的注意力权重会倾向匹配这类详细解答语料的接续模式。

关于如何从系统层面对提示词结构进行标准化约束，我们在[/llm-100/prompt-engineering/结构化_Prompt_应该怎么写.md](/llm-100/prompt-engineering/结构化_Prompt_应该怎么写.md)中有深入探讨。

### 4. 思维链的局限：推导过程的“不忠实性”

使用思维链时需要警惕一个认知误区：**模型生成的推导文本，不一定等于其内部计算做出决策的真实原因。**

思维链是**自回归生成的外显文本**，受采样随机性和统计模式驱动，并不等同于深度网络内部的实际参数计算路径。近年关于语言模型忠实度（Faithfulness）的研究发现了显式推导与内部状态脱节的两种典型表现：

![外显思维链的不忠实性与事后合理化陷阱](/images/content-rebuild/bf389c516bd75a1e/fig-4.png)

> **图面说明**：讲解员站在模型透视结构图前。左侧展示模型内部隐藏层在极浅层已经因上下文中的偏差先验激活了特定答案候选；右侧展示模型在后续输出端却生成了一套逻辑严密但纯属“事后编造”的中间推导文本，指向该错误答案。正文分析这种脱节现象的技术根源。

#### 现象一：事后合理化（Post-hoc Rationalization）
当输入 Prompt 带有强烈的先验偏置（例如在上下文中多次暗示“选项 A 是正确答案”）时，模型内部可能在前几步就已经倾向于输出选项 A。但在要求分步推导时，自回归机制会继续生成看似符合逻辑、步步推导向选项 A 的中间文本。这种推导本质上是在“为既定结论寻找合理借口”，而不是从事实出发推导出结论。

#### 现象二：反事实干预下的推导失效
如果人工篡改模型生成的中间步骤（例如将第二步算式计算结果强行改成错误数值），让模型基于被篡改的推导继续生成，模型仍有一定概率直接输出最初那个正确的答案，或者完全无视篡改数字的逻辑约束。这表明：模型的最终输出往往受原始输入全局注意力的影响，外显的推导文本只是条件约束的一部分，并不构成绝对的因果绑定。

因此，在金融核算、医疗问诊或司法合规等场景下，不能将模型吐出的 CoT 文本直接当作具备严格因果效力的审计依据。

### 5. 级联错误累积与工程成本权衡

思维链在降低单步计算难度的同时，也放大了序列生成的级联失效风险，并带来了计算资源开销。

![级联错误的雪崩效应传播图](/images/content-rebuild/bf389c516bd75a1e/fig-5.png)

> **图面说明**：讲解员正在排查一条逐步推导链路。第一步输出正确，第二步因温度采样出现一个细微逻辑偏倚；到了第三步与第四步，该偏倚作为不可撤销的输入条件进入 KV 缓存，迫使后续生成步步错位，最终答案出现彻底崩塌。正文在此阐述马尔可夫决策误差放大的因果链。

#### 误差在自回归链条中的单向累积
在自回归贪心搜索或采样生成中，模型没有内建的回溯（Backtrack）机制。一旦中间某一步 $z_m$ 出现计算错误或幻觉，该错误 Token 会被立即写回上下文并存入 KV 缓存。由于后续每一步都是以历史所有 Token 为条件的条件概率计算：
$$P(z_{k} \mid x, z_{1}, \dots, z_{m}^{\text{错误}}, \dots, z_{k-1})$$
模型只能在错误前提上继续推导，从而导致最终结论完全偏离。

#### 计算资源的物理成本权衡

| 评估维度 | 直接回答（Direct Output） | 思维链提示（CoT） | 工程影响分析 |
| :--- | :--- | :--- | :--- |
| **生成 Token 数量** | 极少（1 ~ 20 Tokens） | 较多（100 ~ 1500+ Tokens） | 按生成 Token 计费场景下调用成本成倍增长 |
| **首字延迟（TTFT）** | 取决于输入 Prompt 长度 | Zero-shot 时接近；Few-shot 因示例增多而显著变长 | TTFT 由 Prefill 阶段输入长度决定，Few-shot CoT 会增加首字耗时 |
| **端到端耗时（E2E Latency）** | 极低（几十毫秒至数百毫秒） | 较高（数秒至数十秒） | 受制于 Decode 阶段逐 Token 读写权重的内存带宽瓶颈 |
| **KV 缓存显存占用** | 随生成结束快速释放 | 随着长文本生成显存持续累积 | 高并发时单卡并发 Batch 数量受限 |
| **适用场景** | 事实问答、格式转换、简单文本抽取 | 算术推导、多步约束求解、复杂规划 | 需根据任务复杂度分类启用 |

![思维链在工程实践中的准确率与成本权衡曲线](/images/content-rebuild/bf389c516bd75a1e/fig-6.png)

> **图面说明**：讲解员在监控控制台上调出两条曲线。蓝色曲线上升后逐渐趋于平缓，表示推理 Token 增长带来的准确率边际收益递减；红色曲线呈线性直线上升，表示延迟与 Token 费用开销。讲解员标出合理选型的黄金平衡点。正文结合此图给出工程落地方案。

在不需要多步规划的简单任务中，盲目添加思维链提示不仅徒增时延与成本，还会因为生成序列拉长而增加采样出错的暴露面。正如 [Anthropic 提示工程指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview) 所指出的，提示工程应先建立量化评估体系，仅在多步逻辑或复杂规划确实需要时再引入逐步推导。

### 6. 机制验证实验：模拟自回归步进与误差累积

以下 Python 脚本构建了一个离散的 3 步推导过程模拟。请注意：**该脚本用于教学演示“前序错误成为不可撤销条件”的传播机制，单步失误率采用假设常数，不代表真实大语言模型在具体任务中的精确故障率**。

```python
import random

def simulate_step_inference(current_state: str, step: int, step_error_rate: float = 0.1) -> str:
    """
    教学模拟：演示自回归步进生成中，前序状态如何对后续步骤形成硬性约束。
    假设每步推导存在独立的局部失误概率。
    """
    # 模拟当前步自身的局部推理成功率
    local_success = random.random() > step_error_rate
    
    if step == 1:
        return "Step1_OK" if local_success else "Step1_ERROR"
        
    elif step == 2:
        # 第二步解码时，第一步的内容已写入上下文并作为前置条件
        if "ERROR" in current_state:
            # 前序前提已损坏，即便局部计算正确，结果依然建立在错误假设上
            return current_state + " -> Step2_CONDITIONED_ON_ERROR"
        return current_state + (" -> Step2_OK" if local_success else " -> Step2_ERROR")
        
    elif step == 3:
        # 第三步得出结论，任何上游错误都会导致最终答案失效
        if "ERROR" in current_state or "CONDITIONED_ON_ERROR" in current_state:
            return current_state + " -> Final_FAIL"
        return current_state + (" -> Final_SUCCESS" if local_success else " -> Final_FAIL")
        
    return current_state

def run_simulation(trials: int = 2000, step_error_rate: float = 0.1):
    success_count = 0
    cascade_fail_count = 0
    
    for _ in range(trials):
        state = ""
        state = simulate_step_inference(state, step=1, step_error_rate=step_error_rate)
        state = simulate_step_inference(state, step=2, step_error_rate=step_error_rate)
        state = simulate_step_inference(state, step=3, step_error_rate=step_error_rate)
        
        if "Final_SUCCESS" in state:
            success_count += 1
        else:
            # 最终失败样本中，检查是否由第 1 步或第 2 步等前序错误引发
            if "Step1_ERROR" in state or "Step2_ERROR" in state or "CONDITIONED_ON_ERROR" in state:
                cascade_fail_count += 1
                
    fail_count = trials - success_count
    cascade_ratio = (cascade_fail_count / fail_count * 100) if fail_count > 0 else 0.0
    
    print(f"模拟运行轮次: {trials}")
    print(f"单步假设失误率: {step_error_rate * 100:.1f}%")
    print(f"最终整体推导成功率: {success_count / trials * 100:.2f}%")
    print(f"失败样本中因前序步骤出错引发的级联失败占比: {cascade_ratio:.2f}%")

if __name__ == "__main__":
    # 运行模拟实验
    run_simulation(trials=2000, step_error_rate=0.1)
```

运行上述模拟可以清晰看到：在每步失误率仅为 10% 的假设下，经过 3 步累积，整体推导的失败样本中绝大部分都源于早期的状态污染。为了缓解这种级联误差，工程中常使用多数投票（Self-Consistency）或引入带有独立验证节点的架构，相关方案可参考[/frontier/loop-engineering/Loop_的灵魂不是执行_而是验证.md](/frontier/loop-engineering/Loop_的灵魂不是执行_而是验证.md)。

---

### 可检验练习

1. **显式篡改测试**：选取一个三步算术问题，让模型输出完整推导。记录模型输出后，手动将推导过程的第 1 步计算结果改成错误数值，拼接在 Prompt 中作为已生成内容，命令模型继续完成推导。观察最终结论是根据错误的第 1 步顺延计算，还是依然输出了原题的正确数值？这反映了什么机制？
2. **延时与吞吐对比**：在本地环境或 API 调用中，记录同一道逻辑题在“直接回答”与“包含详细思维链”两种模式下的生成 Token 数量及端到端延迟，验证生成阶段耗时与输出长度的关系。

---

### 总结

思维链不是一种神秘的推理能力，而是利用 Transformer 解码特性的工程方法：
1. **计算预算扩展**：利用生成中间 Token，为复杂问题争取更多的前向传播步数，突破单步计算深度限制。
2. **KV 缓存暂存**：通过因果注意力将中间结果保留在上下文中，将复杂联合概率拆解为逐步收敛的条件概率。
3. **不保证忠实度**：外显推导是文本采样结果，存在事后合理化偏误，不可等同于神经决策证据。
4. **误差雪崩与开销**：自回归无回溯机制导致中间单步错误会被持续放大，并伴随延迟与显存成本的显著上升。
