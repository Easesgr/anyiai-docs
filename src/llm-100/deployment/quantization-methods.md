以部署一个标准的 70 亿参数（7B）开源大模型为例：在 16 位浮点数（FP16/BF16）格式下，每个参数占 2 个字节，仅模型权重就需要静态占用 $7 \times 10^9 \times 2 \approx 14\text{ GB}$ 显存。如果要在一张 16GB 显存的显卡（如 RTX 4080 或 T4）上运行，启动后留给输入上下文和中间激活状态（KV Cache）的显存只剩不到 2GB，一旦输入稍长或并发稍高，程序就会因为显存不足（OOM）直接崩溃。

量化（Quantization）解决这个问题的思路很直接：将原本占用 16 位的连续浮点数，映射到占用 8 位甚至 4 位的低比特整数或低精度浮点数上。如果能将权重压到 INT4（4 位整数），14GB 的权重立刻缩减到约 3.5GB，显卡就能腾出超过 10GB 显存处理长文本和并发。

但低比特必然带来数值精度的丢失。本文以这个 7B 模型的部署为贯穿案例，讲清楚从基础线性映射，到 GPTQ、AWQ 误差补偿算法，再到 KV Cache 量化的完整逻辑与工程选型边界。

### 1. 线性量化原理：对称与非对称映射

量化是有损的数据压缩过程，目标是用有限的离散整数点表示一段连续的实数区间 $[\alpha, \beta]$。

#### 非对称量化（Asymmetric Quantization）

当数据的取值范围关于 0 不对称时（例如经过激活函数 ReLU 或 SwiGLU 后输出的大量非负数），需要引入**缩放系数（Scale, $S$）**与**零点（Zero Point, $Z$）**两个参数：

$$S = \frac{\beta - \alpha}{q_{max} - q_{min}}$$

$$Z = \text{round}\left(-\frac{\alpha}{S}\right) + q_{min}$$

浮点数 $x$ 映射到定点整数 $q$ 的量化公式为：

$$q = \text{clip}\left(\left\lfloor \frac{x}{S} \right\rceil + Z,\; q_{min},\; q_{max}\right)$$

从定点整数 $q$ 还原近似浮点数 $\hat{x}$ 的反量化（Dequantization）公式为：

$$\hat{x} = S \cdot (q - Z)$$

其中 $\lfloor \cdot \rceil$ 表示四舍五入取整，$\text{clip}$ 确保数值不超出目标位宽表示范围。零点 $Z$ 是一个整数，它的作用是让浮点数 $0.0$ 能够被精确映射到一个整数上，防止在 Padding 填充 0 时引入额外偏移误差。

#### 对称量化（Symmetric Quantization）

对称量化强制浮点区间的中心对准 0，即固定 $Z = 0$。截断边界由张量中的绝对值最大值决定：

$$\alpha_{max} = \max(|x_{min}|, |x_{max}|)$$

以有符号 8 位整数 INT8（取完全对称区间 $[-127, 127]$）为例：

$$S = \frac{\alpha_{max}}{q_{max}} = \frac{\alpha_{max}}{127}$$

$$q = \text{clip}\left(\left\lfloor \frac{x}{S} \right\rceil,\; -127,\; 127\right)$$

$$\hat{x} = S \cdot q$$

![对称量化与非对称量化的浮点实数到定点整数映射机制对比](/images/content-rebuild/0c99271a987832ae/fig-1.png)

#### 为什么矩阵乘法硬件更偏好对称量化？

在计算线性层输出 $Y = X W$ 时，若输入激活 $X$ 与权重 $W$ 都使用非对称量化，展开式为：

$$Y \approx \left(S_x (Q_x - Z_x)\right) \left(S_w (Q_w - Z_w)\right) = S_x S_w \left( Q_x Q_w - Z_w Q_x - Z_x Q_w + Z_x Z_w \right)$$

这意味着硬件计算核心在执行整数矩阵乘 $Q_x Q_w$ 的同时，还必须额外维护 $Z_w \sum Q_x$ 和 $Z_x \sum Q_w$ 的跨行、跨列规约累加。这会显著增加寄存器占用和控制流开销。

如果权重采用对称量化（$Z_w = 0$），式子直接化简；若两者均采用对称量化（$Z_x = 0, Z_w = 0$），公式简化为：

$$Y = S_x S_w \cdot (Q_x Q_w)$$

GPU 的 Tensor Core 可以直接流水线执行纯整数乘加 $Q_x Q_w$，最后仅需对结果乘以一个浮点标量 $S_x S_w$。因此在大模型权重量化中，对称量化是更主流的选择。

#### 数值对比算例

设一段包含 5 个数值的浮点向量 $X = [-2.40, -0.60, 0.00, 1.20, 3.60]$，目标映射至有符号 8 位整数范围 $[-127, 127]$：

1. **对称量化**：
   * $\alpha_{max} = \max(|-2.40|, |3.60|) = 3.60$
   * $S = 3.60 / 127 \approx 0.028346$
   * $q = \text{round}(X / S) = [-85, -21, 0, 42, 127]$
   * 反量化值 $\hat{X} = S \cdot q = [-2.4094, -0.5953, 0.0000, 1.1906, 3.6000]$
   * 最大绝对误差为 $|-2.40 - (-2.4094)| = 0.0094$
2. **非对称量化**（映射到无符号 UINT8 范围 $[0, 255]$）：
   * $\alpha = -2.40, \beta = 3.60$，动态跨度为 $6.00$
   * $S = 6.00 / 255 \approx 0.023529$
   * $Z = \text{round}(-(-2.40) / 0.023529) = 102$
   * $q = \text{round}(X / S) + Z = [-102, -26, 0, 51, 153] + 102 = [0, 76, 102, 153, 255]$
   * 反量化值 $\hat{X} = S \cdot (q - 102) = [-2.4000, -0.6118, 0.0000, 1.2000, 3.6000]$
   * 步长从 $0.028346$ 缩小到 $0.023529$，离散网格更密，在此算例中对负区间的表示更精细。

### 2. 量化粒度：Per-Tensor、Per-Channel 与 Per-Group

量化粒度决定了多少个权重共享同一组缩放系数（$S$ 和 $Z$）。

![按张量、按通道与按分组三种量化粒度的划分与误差权衡](/images/content-rebuild/0c99271a987832ae/fig-2.png)

1. **按张量（Per-Tensor）**：
   整个权重矩阵共享一个 $S$。如果矩阵里只有几个特别大的离群值（Outliers），整个矩阵的 $\alpha_{max}$ 就会被拉得极大，导致大量正常范围的数值被挤压在靠近 0 的少数整数格点中，精度损失严重。
2. **按通道（Per-Channel）**：
   针对权重矩阵 $W$，通常沿着输出通道维度（矩阵列方向）独立计算 $S$。每个输出通道拥有专属的缩放尺子，不同神经元之间的离群值相互隔离，互不干扰。
3. **按分组（Per-Group）**：
   当压缩到 INT4 时，单个通道内部沿输入累加维度也会出现局部异常值，Per-Channel 仍显粗糙。按分组量化将每个通道内部进一步切分为固定大小的连续块（如 Group Size $G = 128$），每个 Group 独立存储一组 $S$。

#### 分组量化的显存开销核算

以 INT4 量化、Group Size $G = 128$、每个 Scale 采用 FP16（2 字节）存储为例：
* 128 个 4 位权重占用显存：$128 \times 4\text{ bit} = 512\text{ bit} = 64\text{ 字节}$
* 该组附带的 1 个 FP16 缩放系数占用：$16\text{ bit} = 2\text{ 字节}$
* 平均每个权重分摊的实际比特数：$(512 + 16) / 128 = 4.125\text{ bit}$

相比纯 INT4 的 4 bit，元数据开销仅增加了 $3.125\%$，但由于量化尺度由 128 个相邻数单独决定，局部异常值被限制在组内，整体精度显著好于 Per-Channel INT4。

### 3. Weight-Only 与 Weight-Activation 全量化

在大模型部署中，量化方案主要分为两类：只量化权重的 Weight-Only 方案，与同时量化权重和激活值的 Weight-Activation 全量化方案。它们解决的硬件瓶颈完全不同。

| 维度 | 权重量化（Weight-Only，如 W4A16、W8A16） | 权重与激活全量化（W8A8、FP8） |
| :--- | :--- | :--- |
| **显存权重存储** | INT4 或 INT8 | INT8 或 FP8 |
| **核心计算单元** | FP16 / BF16 Tensor Core | INT8 / FP8 Tensor Core |
| **反量化时机** | 权重从显存读入寄存器/SRAM 后即时转为 FP16 | 不还原为 FP16，直接执行低精度乘加 |
| **Prefill 阶段表现** | 计算吞吐基本无提升，可能因反量化转换略微变慢 | 矩阵乘峰值算力翻倍，Prompt 计算吞吐显著提升 |
| **Decode 阶段表现** | 显存读取量减少 50%~75%，单请求生成延迟大幅下降 | 显存带宽与计算同时加速 |
| **校准与维护难度** | 较低，权重是静态的，离线处理即可 | 较高，必须跟踪动态激活的分布与异常值 |

![Weight-Only 与 Weight-Activation 在 Prefill 与 Decode 阶段的硬件执行流](/images/content-rebuild/0c99271a987832ae/fig-3.png)

#### 为什么 Weight-Only INT4 在输入长文本（Prefill）时无法提高吞吐？

大模型推理分为两个截然不同的阶段：
* **Prefill 阶段**：系统一次性处理用户输入的所有 Prompt Token。此时矩阵乘法的计算密度（算术运算量与访存量之比）非常高，瓶颈在 GPU 的张量计算核心峰值算力（Compute-bound）。
* **Decode 阶段**：模型自回归生成，每步只生成 1 个 Token。此时模型每次都要把全部权重矩阵从显存搬运进芯片，但只做一个向量的矩阵乘法，瓶颈在显存带宽（Memory-bound）。

在 Weight-Only INT4 下，显存里存的是 INT4 权重，但输入激活依然是 FP16。计算核心无法直接用 4 位整数去乘以 16 位浮点数。GPU 必须在将 INT4 权重读入片上缓存后，通过指令将其实时解包还原为 FP16，再送入 FP16 计算单元。因此：
1. 整个计算过程消耗的浮点算力上限没有变；
2. 反量化过程还额外增加了寄存器转换指令。

所以 Weight-Only INT4 主要是为了优化 Decode 阶段的带宽瓶颈：权重体积变小了，显存带宽读取耗时大幅减少，每秒输出 Token 数显著增加；但如果需要提升 Prefill 吞吐，必须采用激活和权重同时量化的方案（如 FP8 或 W8A8）。

### 4. GPTQ 算法：利用二阶曲率补偿量化误差

如果对权重直接采用最简单的就近取整（Round-to-Nearest, RTN），当压缩到 INT4 时，由于格点过疏，累积误差会导致模型输出胡言乱语。GPTQ 的核心思想是：**量化某一个权重带来的误差，可以通过微调同一层中其他尚未量化的浮点权重来相互抵消**。

#### 二阶误差目标

设某一层权重为 $W$，量化后权重为 $\hat{W}$，校准集输入激活为 $X$。量化的目标是让输出的重构均方误差最小：

$$\arg\min_{\hat{W}} \| W X - \hat{W} X \|_F^2$$

针对权重矩阵的每一行向量 $w$，展开其关于量化扰动 $\Delta w = \hat{w} - w$ 的二阶泰勒展开式：

$$E(w) \approx \frac{1}{2} (w - \hat{w}) H (w - \hat{w})^T$$

这里的 Hessian 矩阵 $H = 2 X X^T$。它刻画了输入激活在各个维度上的相关性与曲率。

#### 逐权重补偿逻辑

如果我们将第 $q$ 个权重四舍五入量化为 $\hat{w}_q$，为了使整体误差增量最小，全权重向量的补偿更新应当顺着逆 Hessian 矩阵的方向进行：

$$\Delta w = -\frac{w_q - \hat{w}_q}{[H^{-1}]_{qq}} [H^{-1}]_{:, q}$$

其中 $[H^{-1}]_{qq}$ 是 Hessian 逆矩阵对角线上的第 $q$ 个元素，$[H^{-1}]_{:, q}$ 是其第 $q$ 列向量。该式在第 $q$ 维恰好为 $\hat{w}_q - w_q$（使当前权重精确就位为量化值），其余未量化分量则同步获得二阶曲率补偿更新。

![GPTQ 算法利用二阶 Hessian 逆矩阵补偿相邻权重的误差传递机制](/images/content-rebuild/0c99271a987832ae/fig-4.png)

#### GPTQ 的工程优化

早期基于该理论的算法（如 OBQ）每量化一个参数就要重新求一次逆矩阵，处理 7B 模型需要数天时间。GPTQ 通过三项工程优化解决了这一问题：
1. **固定列顺序量化**：打破原有动态贪心寻找最小误差列的逻辑，按列序号固定顺序量化，不仅避免了高频排序检索，而且在大型网络中困惑度与贪心策略几乎无异。
2. **分块延迟批量更新（Lazy Batch Updates）**：将权重按列分组（例如 128 列为一个 Block）。在一个 Block 内部逐列累加更新量，量化完成后，利用高效的 GEMM 矩阵乘法一次性批量更新矩阵剩余的所有未量化列，将算法从显存带宽瓶颈转为算力瓶颈。
3. **Cholesky 分解稳定数值**：在对 $X X^T$ 求逆前加入对角线阻尼因子 $\lambda I$，并利用预先计算的 Cholesky 上三角分解因子执行更新，防止因协方差矩阵奇异导致浮点溢出。

### 5. AWQ 算法：激活感知与通道等价缩放

GPTQ 需要通过校准集求逆 Hessian 矩阵，当模型换用不同领域数据时，可能出现过拟合。AWQ（Activation-aware Weight Quantization）采用了另一种视角：**模型内部只有极少数权重起决定性作用，只要保护好这部分关键权重，其余权重即便简单量化也不会崩塌**。

#### 发现：权重的关键性由输入激活决定

研究表明，模型内部仅有 $0.1\% \sim 1\%$ 的权重对输出精度有决定性影响。但如果仅通过权重本身的绝对值大小去筛选，找出来的参数并不准。AWQ 发现：观察输入激活在各通道上的平均绝对值：

$$s_X = \frac{1}{N} \sum_{i=1}^N |X_i|$$

某些通道在几乎所有 Token 输入下都会产生极大数值（异常值通道）。**这些激活值极大的通道对应的权重参数，才是真正需要高精度保护的核心参数**。

![AWQ 通过激活特征识别显著通道并对权重实施等价缩放保护](/images/content-rebuild/0c99271a987832ae/fig-5.png)

#### 通道等价缩放机制

如果直接将这 $1\%$ 的权重保留在 FP16，其余做 INT4 混合存储，会导致 GPU 无法高效执行规整的矩阵乘法。AWQ 采用数学等价变换巧妙绕过了这个问题：

$$Y = X W = \left(X \cdot \text{diag}(s)^{-1}\right) \cdot \left(\text{diag}(s) \cdot W\right) = X' W'$$

针对显著通道，设置缩放因子 $s > 1$：
* 输入激活除以 $s$：$X' = X / s$；
* 对应的权重乘以 $s$：$W' = s \cdot W$。

在数学上两者的乘积完全保持一致。

**为什么放大权重能降低量化误差？**
在大模型中，权重通常采用按分组（Per-Group）量化，一个组内多个输入通道共享同一个缩放尺度 $S$。如果某些通道在输入激活中具有异常大的幅值，直接组量化会导致这部分关键权重在乘以巨大激活值后，其量化噪声在输出端被剧烈放大，主导整个输出重构误差。

AWQ 将显著通道对应的权重放大 $s$ 倍，使该通道在组内获得更大的数值动态范围与更多量化阶点，同时在数学等价变换下将输入激活缩小 $s$ 倍。在线性层输出 $Y = X W$ 时，该通道的输出误差贡献被转化为 $(X / s) \cdot \Delta W'$，巨大的输入激活被缩放系数 $s$ 平抑，从而显著降低了**最终输出特征的重构误差** $\| W X - \hat{W} X \|_F^2$。

#### 零运行时开销的算子融合

缩放系数 $s$ 通过在校准集上进行网格搜索确定。在真正部署时：
* 放大后的权重 $W'$ 离线完成 INT4 量化并持久化；
* 激活缩小系数 $\text{diag}(s)^{-1}$ 是对角矩阵，可以**直接吸收入上一层的 Norm 层（如 RMSNorm / LayerNorm）的权重中**。

在线推理时，计算图没有任何新增的算子节点，依然保持标准线性层的纯净结构，避免了额外的调度延迟。

### 6. KV Cache 量化与验收评测

在长文本对话或并发增加时，显存消耗的主力会从模型权重转向 KV Cache。

$$\text{显存占用}_{KV} = 2 \times \text{层数} \times \text{KV头数} \times \text{Head维度} \times \text{上下文长度} \times \text{并发Batch Size} \times \text{每个元素字节数}$$

在多头注意力（MHA）下 KV 头数等于 Query 头数；而在现代主流开源模型广泛采用的分组查询注意力（GQA）架构下，KV 头数远少于 Query 头数（例如 70B 模型通常仅有 8 个 KV 头）。即便如此，在处理 128k 上下文时，FP16 格式下的单请求 KV Cache 依然会占用数十吉字节。将 KV Cache 实施低比特存储是实现长上下文高并发服务的必然途径。

![KV Cache 量化在长文本高并发下的显存削减与精度评测对比](/images/content-rebuild/0c99271a987832ae/fig-6.png)

#### 数据格式适用条件

1. **FP8（E4M3）KV Cache**：
   * **适用架构**：NVIDIA Ada Lovelace（RTX 40 系列）和 Hopper（H100）原生支持。
   * **特点**：4 位指数配合 3 位尾数，动态范围优于定点 INT8，无需额外存储复杂的零点偏移，能直接释放一半 KV 显存，且在绝大多数下游任务中精度几乎无损。
2. **INT8 KV Cache**：
   * **适用架构**：Ampere 架构（如 A100、RTX 30 系列）及旧显卡，由于缺乏硬件 FP8 指令，INT8 是主流加速格式。
   * **挑战**：Key 向量经过 RoPE（旋转位置编码）后特定维度会出现周期性异常大值，使用粗糙的 Per-Tensor 量化会导致注意力矩阵点乘失真，一般需要配合 Per-Token 或 Per-Head 粒度。
3. **INT4 KV Cache**：
   * **现状**：低于 8 位时 KV Cache 极易发生精度崩溃，除非使用极其细粒度的分组量化（如 Group Size 32），目前在主流生产环境中通常不作为首选。

#### 精度退化评测方法

评估量化模型的可用性不能依靠肉眼抽查两句对话，需要通过分层基准检验：
1. **困惑度（Perplexity, PPL）**：在 WikiText-2 或 C4 数据集上测量自回归交叉熵。通常要求量化后 PPL 相对 FP16 基线的上升幅度小于 $1\% \sim 2\%$。
2. **长文本大海捞针（Needle in a Haystack）**：专门验证 KV Cache 量化后的注意力寻址能力。在不同长度背景噪声中随机插入特定事实，检查召回率。如果量化破坏了注意力区分度，在特定长度区间会出现召回失效。
3. **下游多步推理基准**：运行 GSM8K（数学推理）和 HumanEval（代码生成）。INT4 极低比特量化往往最先侵蚀多步严谨推理链的能力，如果数学得分发生大幅跳水，说明模型发生了严重的逻辑能力退化。

### 7. 方案选型指南

在实际工程部署时，不同量化方案的权衡决策如下：

| 量化方案 | 权重格式 | 激活格式 | 推荐硬件 | 典型适用场景与权衡 |
| :--- | :--- | :--- | :--- | :--- |
| **AWQ** | INT4 | FP16/BF16 | Turing 及更新架构 GPU（包括消费级显卡） | **单卡小 Batch 在线服务首选**。校准快，泛化能力强，显著降低单 Token 生成延迟，显存节省明显。 |
| **GPTQ** | INT4 / INT3 | FP16/BF16 | Turing 及更新架构 GPU | **极致低比特压缩场景**。在 3-bit 或参数极小模型的极限压缩下表现通常优于普通截断，但校准耗时较长。 |
| **FP8 全量化** | FP8 (E4M3) | FP8 (E4M3) | Ada Lovelace / Hopper 架构 | **高并发与长 Prompt 服务最优解**。利用硬件原生 FP8 Tensor Core，不仅省显存，而且 Prefill 吞吐近乎翻倍。 |
| **FP8 KV Cache** | 原生精度 | 原生精度 | Ada / Hopper 架构 | **长文本并发服务标配**。在不改动权重模型的前提下释放 50% KV 显存，显著提升系统最大并发容量。 |

### 8. 动手练习：验证等价缩放对 INT4 误差的影响

为了直观理解 AWQ“通过缩放保护关键通道”的机制，你可以用以下纯 Python 代码（无需 GPU）在本地运行验证：

```python
import numpy as np

def quantize_int4_symmetric(w):
    # 将输入的一维组权重对称量化到 INT4: [-8, 7]
    alpha = np.max(np.abs(w))
    scale = alpha / 7.0 if alpha != 0 else 1.0
    q = np.clip(np.round(w / scale), -8, 7)
    return q * scale

# 模拟同一量化组（Group Size=4）内的 4 个输入通道权重
np.random.seed(42)
W = np.random.randn(4) * 0.5
# 激活特征幅值：通道 1 出现异常高值（20.0），其余通道为正常幅值（1.0）
X_act = np.array([1.0, 20.0, 1.0, 1.0])

# 方案 A: 直接组量化 (RTN)
W_hat_a = quantize_int4_symmetric(W)
# 衡量线性层输出特征 Y = X * W 的重构均方误差
err_a = np.mean((X_act * W - X_act * W_hat_a) ** 2)

# 方案 B: 激活感知等价缩放保护 (类似 AWQ 核心机制)
# 针对关键通道放大权重以占用更多量化阶，并在输出端被等价缩小的激活抑制
s = np.ones_like(X_act)
s[1] = 4.0  # 对异常激活通道 1 实施缩放保护
W_scaled = W * s
W_hat_scaled = quantize_int4_symmetric(W_scaled)
W_hat_b = W_hat_scaled / s
err_b = np.mean((X_act * W - X_act * W_hat_b) ** 2)

print(f"直接量化输出特征误差: {err_a:.6f}")
print(f"AWQ缩放保护后输出特征误差: {err_b:.6f}")
```

**检验指标**：观察线性层输出特征的重构误差。你会发现应用激活感知的等价缩放后，输出特征的均方误差显著下降（从约 0.157 降至约 0.016），这就是 AWQ 通过保护关键激活通道来稳定维持 4-bit 输出精度的核心机制。
