评估或训练大语言模型时，我们常看到“千亿参数”、“万亿 Token”或“万卡集群”等宏观指标。这些数字背后并不是玄学，而是由确定的矩阵乘法规则、显存物理结构和硬件算力决定的。

大模型的“大”，具体体现在三个可精确测量的维度：
1. **参数量（$N$）**：模型所有权重矩阵中的数值总数，决定了模型的表达容量和存放模型所需的静态显存。
2. **训练数据量（$D$）**：模型在训练过程中处理的有效离散片段（Token）总量。
3. **训练计算量（$C$）**：训练全程执行的浮点运算总数，单位通常为 **FLOPs**（Floating Point Operations）。

这三者之间存在一个被广泛验证的工程换算关系：**在标准 Transformer 架构下，训练总计算量 $C \approx 6ND$**。

本文以一个贯穿工程任务为主线：**训练一个 7B（70 亿参数）的 Dense 模型，喂入 2T（2 万亿）个 Token，使用单卡标称算力 312 TFLOPS（半精度）的 GPU 集群，我们需要多少卡、多长时间、多少显存？**

## 1. 参数量 $N$：矩阵维度如何构成模型权重

参数量的物理意义是**神经网络中所有可学习权重矩阵的元素个数之和**，通常以“B”（Billion，十亿）为单位。

以标准的 Transformer 解码器（Decoder-Only）为例，假设隐藏层维度为 $h$，层数为 $L$，词表大小为 $V$。参数主要集中在两个子模块：

1. **自注意力子层（Self-Attention）**：包含查询（Q）、键（K）、值（V）与输出投射（O）四个矩阵。每个矩阵的维度均为 $h \times h$。单层注意力参数量约为：
   $$4 \times (h \times h) = 4h^2$$
2. **前馈网络子层（FFN）**：经典结构包含两层全连接，中间升维到 $4h$。上升投射矩阵维度为 $h \times 4h$，下降投射矩阵维度为 $4h \times h$。单层前馈网络参数量约为：
   $$(h \times 4h) + (4h \times h) = 8h^2$$
   （若采用 LLaMA 等使用的 SwiGLU 结构，通常包含三个 $h \times \frac{8}{3}h$ 的矩阵，参数量同样接近 $3 \times \frac{8}{3}h^2 = 8h^2$）。

每个 Transformer 块的核心权重加起来约为 $4h^2 + 8h^2 = 12h^2$。堆叠 $L$ 层后，再加上词表嵌入矩阵（Embedding，参数量约为 $V \times h$），Dense 模型总参数量近似为：

$$N \approx 12Lh^2 + Vh$$

![Transformer单层中注意力矩阵与前馈网络参数的维度构成](/images/content-rebuild/06358d546eec1de5/fig-1.png)

### 权重自身的显存占用（只读静态权重）
如果把模型加载到显存中，单参数占用的字节数取决于数值精度格式：
- **FP32（单精度）**：4 字节（Bytes）/ 参数
- **FP16 / BF16（半精度）**：2 字节 / 参数
- **INT8（8位整型）**：1 字节 / 参数
- **INT4（4位整型）**：0.5 字节 / 参数

对于贯穿案例中的 7B 模型（$7 \times 10^9$ 个参数），若采用半精度（BF16）存放：

$$\text{模型静态权重体积} = 7 \times 10^9 \times 2 \text{ 字节} = 14 \times 10^9 \text{ 字节} \approx 13.04 \text{ GiB}$$

这仅代表模型文件在硬盘或推理单卡上的纯权重体积。真实训练时的显存需求远高于此。

## 2. 训练数据量 $D$：从原始文本到有效 Token 吞吐

模型在训练时并不直接读取字符串或文件字节，而是读取由分词器（Tokenizer）切分出的整数 ID 序列（即 Token）。关于分词算法的具体实现机制，可参考 [/llm-100/basics/Token_是什么_为什么大模型不是按字理解世界.md](/llm-100/basics/Token_是什么_为什么大模型不是按字理解世界.md) 与 [/llm-100/basics/BPE_WordPiece_SentencePiece_分词有什么区别.md](/llm-100/basics/BPE_WordPiece_SentencePiece_分词有什么区别.md)。

工程上衡量训练数据集规模通常以“T”（Trillion，万亿）个 Token 计算：
- **英文语料**：在主流分词器下，1 个 Token 大约对应 4 个字符（约 0.75 个英文单词）。1 GB 干净英文纯文本大约可切分出 2.5 亿至 3 亿个 Token。
- **中文语料**：1 个汉字通常切分为 1 到 2 个 Token（取决于词表对中文子词的覆盖程度）。1 GB 干净中文纯文本大约切分出 1.5 亿至 2.5 亿个 Token。

![原始文本清洗与分词器切分为Token序列的数据流向](/images/content-rebuild/06358d546eec1de5/fig-2.png)

在计算训练开销时，数据量 $D$ 指的是**训练过程中模型实际遍历过的 Token 累计总数**（Tokens Processed）。例如：
- 若有一个 1T Token 的清洗后数据集，完整训练了 2 个轮次（Epochs），则实际训练数据量 $D = 2\text{T Tokens} = 2 \times 10^{12}$ Tokens。

## 3. 计算量公式推导：为什么单 Token 训练需要 $6N$ FLOPs？

在大模型训练中，浮点运算次数存在一个经典经验公式：

$$C \approx 6ND$$

其中 $C$ 是总计算量（单位 FLOPs），$N$ 是模型参数量（不含或略去嵌入层），$D$ 是训练 Token 总数。这里的系数“6”从何而来？

![单Token训练时前向传播与反向传播的算力分布拆解](/images/content-rebuild/06358d546eec1de5/fig-3.png)

在深度学习中，核心计算是矩阵乘法（GEMM）。考虑输入包含 $B$ 个 Token 的线性变换 $Y = XW$：
- 输入 $X$ 维度为 $B \times d_{in}$；
- 权重矩阵 $W$ 维度为 $d_{in} \times d_{out}$，参数量 $P = d_{in} \times d_{out}$。

### 步骤 1：前向传播计算量（$2N$ FLOPs / Token）
计算输出矩阵 $Y$（维度 $B \times d_{out}$）时，每个输出元素都是长度为 $d_{in}$ 的两个向量的内积。每次内积需要 $d_{in}$ 次浮点乘法和 $d_{in}$ 次浮点加法，合计 $2d_{in}$ 次浮点运算。

整批计算的总浮点运算次数为：

$$2 \times B \times d_{in} \times d_{out} = 2BP \text{ FLOPs}$$

平摊到每个 Token 的计算量为 $\frac{2BP}{B} = 2P$ FLOPs。把整个 Transformer 所有线性层的参数量累加起来（略去 LayerNorm、残差加法和 Softmax 等占比较小的非 GEMM 算子），前向传播处理每个 Token 的计算量约为 **$2N$ FLOPs**。

### 步骤 2：反向传播计算量（$4N$ FLOPs / Token）
在反向传播阶段，根据链式法则（详见 [/fundamentals/dl-basics/forward-backward-propagation.md](/fundamentals/dl-basics/forward-backward-propagation.md)），需要执行两个独立的矩阵乘法：
1. **对输入激活计算梯度（用于向前传播误差）**：
   $$\nabla_X = \nabla_Y W^T$$
   该矩阵乘法维度为 $(B \times d_{out}) \times (d_{out} \times d_{in})$，总浮点运算次数为 $2 \times B \times d_{out} \times d_{in} = 2BP$ FLOPs，单 Token 分摊为 $2P$ FLOPs。
2. **对权重计算梯度（用于更新参数）**：
   $$\nabla_W = X^T \nabla_Y$$
   该矩阵乘法维度为 $(d_{in} \times B) \times (B \times d_{out})$。梯度沿批次中 $B$ 个 Token 进行累加，每个输出元素是长度为 $B$ 的内积（包含 $B$ 次乘法和 $B$ 次加法）。总浮点运算次数为 $2 \times d_{in} \times B \times d_{out} = 2BP$ FLOPs，单 Token 分摊同样为 $2P$ FLOPs（若单看单个 Token 的外积仅有乘法无累加加法，但在批次训练累加下乘加齐全）。

两项相加，反向传播共需 $2P + 2P = 4P$ FLOPs / Token，对应到全网络约为 **$4N$ FLOPs**。

### 合计：$2N + 4N = 6N$ FLOPs / Token
- **前向传播**：$2N$ FLOPs
- **反向传播**：$4N$ FLOPs
- **单 Token 训练合计**：$6N$ FLOPs

> **注：重计算（Activation Checkpointing）的影响**  
> 如果为了节省显存而开启了全量激活重计算，在反向传播前需要重新执行一次前向传播，计算量会增加 $2N$，达到 $8ND$ FLOPs。在没有额外说明的标准核算中，普遍使用 $6ND$ 作为基准。若采用 FlashAttention 等融合算子，注意力部分的非 GEMM 内存搬运被极大优化，但全量 GEMM 的理论浮点数依然基本符合该经验值。

## 4. 算力受限下的权衡：Chinchilla 扩展律与推理导向

已知总算力预算 $C \approx 6ND$，如果给定固定的计算开销预算 $C$，参数量 $N$ 与数据量 $D$ 该如何分配？

- **Kaplan 扩展律（2020）**：早期研究认为模型性能主要取决于参数量，建议算力增加时优先扩充模型参数（例如 $N \propto C^{0.73}, D \propto C^{0.27}$）。这导致 GPT-3 等模型参数量高达 175B，但只训练了 300B Tokens（Token/参数比不足 2:1）。
- **Chinchilla 扩展律（Hoffmann 等人，2022）**：DeepMind 修正了该结论，指出在**训练计算量最优（Compute-Optimal）**的约束下，参数量与数据量应近似等比例扩展（$N \propto C^{0.5}, D \propto C^{0.5}$）。其最优 Token/参数比约为 **20:1**（即 1B 参数需配合约 20B Tokens 训练）。

![Chinchilla算力最优前沿曲面与模型训练欠拟合/过拟合区域](/images/content-rebuild/06358d546eec1de5/fig-4.png)

### 为什么工业界现代开源模型普遍打破 20:1？
Chinchilla 扩展律衡量的是**单次训练成本最低**。但在工程落地中，模型只训练一次，线上推理却要调用上千万次。部署 70B 模型的显存占用和推理延迟远高于 7B 模型。

因此，现代开源模型（如 LLaMA、Mistral 等系列）普遍采用**过度训练（Over-training / Inference-optimal）**策略：
- 7B 模型训练 2T 到 15T Tokens（比例达到 300:1 甚至 2000:1）。
- 这种做法在训练阶段消耗了超出 Chinchilla 最优的算力，但让一个小参数模型吸收了充分的信息，换取了线上推理长期极高的显存与吞吐经济性。

## 5. 训练显存拆解：为什么 14 GB 的 7B 权重需要 80 GB 显卡集群？

许多初学者常有疑问：“7B 模型权重半精度只有 14 GB，为什么单张 80 GB 的 A100/H100 显卡依然无法直接开始训练？”

因为训练阶段的显存由四部分构成，关于优化器的状态定义可参考 [/fundamentals/dl-basics/optimizers.md](/fundamentals/dl-basics/optimizers.md)：

![训练期GPU显存四要素分布与激活重计算的影响](/images/content-rebuild/06358d546eec1de5/fig-5.png)

### 静态显存：16 字节 / 参数（混合精度 AdamW）
在标准的 16 位混合精度训练中（FP16/BF16）：
1. **模型权重（Weights）**：半精度存储，占 **2 字节 / 参数**。
2. **梯度（Gradients）**：反向传播计算出的梯度，半精度存储，占 **2 字节 / 参数**。
3. **优化器状态（Optimizer States）**：AdamW 为保证更新稳定性，需要维护 FP32 精度的状态：
   - FP32 主权重副本：4 字节
   - FP32 一阶动量（Momentum）：4 字节
   - FP32 二阶动量（Variance）：4 字节
   - 优化器小计：**12 字节 / 参数**。

三项相加，静态显存为：

$$\text{静态显存总计} = 2 + 2 + 12 = 16 \text{ 字节 / 参数}$$

对 7B 模型：

$$\text{静态显存} = 7 \times 10^9 \times 16 \text{ 字节} = 1.12 \times 10^{11} \text{ 字节} \approx 104.31 \text{ GiB}$$

单张 80 GB 的显卡物理容量只有约 74.5 GiB，连最基础的参数与优化器状态都无法单独放进单卡显存，必须借助 ZeRO（零冗余优化器）分片或张量并行将静态状态切分到不同显卡上。

### 动态显存：前向激活值（Activations）
反向传播需要利用链式法则计算梯度，前向传播必须保存每一层的中间计算张量（如 LayerNorm 输出、注意力 Softmax 矩阵、线性层输入等）。

激活值显存与**批次大小（Batch Size）**、**序列长度（Sequence Length）**和**隐藏层维度**直接相关。特别需要注意：**训练阶段的动态显存开销由前向激活值主导，而非推理阶段的 KV Cache**。训练时使用 Teacher Forcing 模式，整个序列是并行送入计算的，必须依赖激活重计算（Activation Checkpointing）来压缩这部分显存。

## 6. 贯穿实例核算：7B 模型在 2T Tokens 上的完整预算推导

现在回到开头提出的工程任务，进行完整的数值推导与代码实现。

### 约束条件设定
- 模型参数量 $N = 7 \times 10^9$（7B）
- 训练数据量 $D = 2 \times 10^{12}$（2T Tokens）
- 硬件芯片：单卡半精度（BF16/FP16）理论峰值算力为 $312 \text{ TFLOPS} = 312 \times 10^{12} \text{ FLOPS}$（以常见 A100 80GB SXM 为例）
- 集群实际有效利用率（MFU，Model FLOPs Utilization）：设定为 $45\%$（在千卡规模下属于合理高效区间）
- 集群规模：$M = 1024$ 张卡

### 计算步骤
1. **总计算量 $C$**：
   $$C = 6ND = 6 \times (7 \times 10^9) \times (2 \times 10^{12}) = 8.4 \times 10^{22} \text{ FLOPs}$$
2. **单卡有效计算速率**：
   $$R_{\text{effective}} = 312 \times 10^{12} \times 0.45 = 1.404 \times 10^{14} \text{ FLOPS}$$
3. **单卡总耗时（GPU-Hours）**：
   $$\text{总秒数} = \frac{C}{R_{\text{effective}}} = \frac{8.4 \times 10^{22}}{1.404 \times 10^{14}} \approx 598,290.6 \text{ 秒}$$
   $$\text{GPU-Hours} = \frac{598,290.6}{3600} \approx 166,192 \text{ GPU·小时}$$
4. **1024 卡集群实际训练天数**：
   $$\text{天数} = \frac{166,192}{1024 \times 24} \approx 6.76 \text{ 天}$$

### Python 自动化核算脚本

```python
def estimate_llm_training(
    param_b: float,          # 模型参数量，单位：Billion (十亿)
    token_t: float,          # 数据量，单位：Trillion (万亿 Token)
    gpu_tflops: float,       # 单卡理论半精度算力 (TFLOPS)
    mfu: float = 0.45,       # 模型浮点利用率 (通常 0.35 - 0.55)
    num_gpus: int = 1024     # 集群卡数
):
    """
    大模型训练硬件与耗时核算函数
    """
    # 转换标准物理单位
    N = param_b * 1e9
    D = token_t * 1e12
    
    # 1. 理论总浮点运算量 (6ND)
    total_flops = 6 * N * D
    
    # 2. 单卡有效运算速率 (FLOPs/s)
    effective_rate_per_gpu = gpu_tflops * 1e12 * mfu
    
    # 3. 集群总有效速率
    cluster_effective_rate = effective_rate_per_gpu * num_gpus
    
    # 4. 训练时间计算
    total_seconds = total_flops / effective_rate_per_gpu
    total_gpu_hours = total_seconds / 3600
    cluster_days = total_flops / cluster_effective_rate / 86400
    
    # 5. 混合精度训练静态显存开销 (16 字节 / 参数)
    static_mem_gib = (N * 16) / (1024 ** 3)
    
    print("=" * 42)
    print("       大模型训练资源估算清单")
    print("=" * 42)
    print(f"模型规模: {param_b:.1f} B 参数")
    print(f"训练数据: {token_t:.1f} T Tokens")
    print(f"总计算量: {total_flops:.2e} FLOPs ({total_flops / 1e21:.2f} ZettaFLOPs)")
    print(f"静态显存: {static_mem_gib:.2f} GiB (按16字节/参数计)")
    print(f"单卡理论算力: {gpu_tflops} TFLOPS | MFU: {mfu*100:.1f}%")
    print(f"有效吞吐: {effective_rate_per_gpu / 1e12:.2f} TFLOPS/卡")
    print(f"总卡时开销: {total_gpu_hours:,.0f} GPU·小时")
    print(f"{num_gpus} 卡集群训练耗时: {cluster_days:.2f} 天 (纯计算时间)")
    print("=" * 42)

if __name__ == "__main__":
    estimate_llm_training(
        param_b=7.0,
        token_t=2.0,
        gpu_tflops=312.0,
        mfu=0.45,
        num_gpus=1024
    )
```

### 练习 2：显存排障判断
某工程师配置了一台 8 卡服务器（每卡 80GB 显存），打算直接采用纯数据并行（Data Parallelism，每张卡各保存一份完整的模型权重与优化器）对一个 30B 模型进行半精度混合精度训练。请问该方案是否可行？为什么？

<details>
<summary>点击查看参考答案与解析</summary>

**不可行**。

**原因**：
在混合精度 AdamW 训练下，每个参数需要 16 字节静态显存：
$$\text{单卡静态显存需求} = 30 \times 10^9 \times 16 \text{ 字节} = 4.8 \times 10^{11} \text{ 字节} \approx 447.03 \text{ GiB}$$
即使不计算反向传播的前向激活值显存，仅模型权重、梯度与 AdamW 状态就需要 447 GiB 显存，远超单卡 80 GB 的物理容量上限。纯数据并行要求单卡能完整存放静态状态，因此必然触发 OOM。必须采用 ZeRO-3、张量并行（Tensor Parallelism）或流水线并行（Pipeline Parallelism）将模型状态分片到不同卡上才能运行。

</details>
