在大模型开发中，许多棘手的工程问题表面上看是应用层异常，实际根源却深植于底层计算特征之中。例如，当你在服务器上部署一个问答接口，随着用户多轮对话将上下文拉长到数千 Token，即便请求并发数没有变化，系统响应也会逐渐变慢，甚至突然抛出 CUDA 显存溢出（OOM）错误。如果只把大模型当作黑盒 API，遇到这种问题往往只能盲目重启服务或缩短限制；但若理解了注意力计算过程中键值缓存（KV Cache）的显存分配规律，就能在部署前精确计算并发上限，并合理引入分组查询注意力（GQA）或分页缓存（PagedAttention）等优化技术。

大模型工程不是孤立技巧的随意堆叠，而是一套环环相扣的技术体系。本课程定位为连接基础算法认知与实际工程落地的进阶教程，通过拆解具体问题，帮助开发者建立推导严谨、可动手验证的技术认知。

### 课程定位与学习目标

很多开发者在掌握了 Prompt 编写或调用 LangChain、LlamaIndex 之后，在面对实际生产问题时依然容易卡住。这通常是因为不清楚技术方案生效的物理边界：

* 不清楚自回归模型逐 Token 解码（Decode）在常见的中小批量场景下通常受显存带宽限制（Memory-bound），在显卡选型时就容易忽视显存带宽的重要性；
* 不理解自注意力矩阵的计算开销与序列长度的关系，在设计长文档切分策略时就会在召回质量与计算延迟之间失衡；
* 不掌握工具调用协议的具体交互流程，就无法设计出面对网络丢包或模型格式漂移时依然稳定的智能体系统。

本课程不堆砌概念名词，每一讲均聚焦一个具体的工程目标，交付包含输入输出格式、计算过程解析、失效边界说明与可运行的验证代码。

### 十模块技术演进图谱

大模型100讲将完整的工程链条拆分为十个模块，每个模块包含10篇内容，循序渐进地展开：

1. **基础篇**：讲解词表与 Token 切分（BPE/WordPiece）、Embedding 映射向量、自注意力机制（Self-Attention）与前馈网络（FFN），掌握 Transformer 的数据流动与张量维度变化。
2. **训练原理篇**：讲解自回归因果语言建模、交叉熵损失函数、梯度反向传播机制，以及数据并行（DDP）和张量并行（TP）的基础同步逻辑。
3. **微调与对齐篇**：分析全参数微调、参数高效微调（LoRA 与 QLoRA）的权重更新差异，以及 DPO 与 PPO 偏好对齐的数据格式与优化目标。
4. **Prompt 工程篇**：解析上下文窗口构造、System/User 角色区分、基于 JSON Schema 的结构化输出约束，以及提示注入的常见防御手段与边界。
5. **RAG 检索增强篇**：分析文本切块粒度对检索的影响、密集向量召回与稀疏关键词检索的混合方案、重排序（Rerank）的作用与延迟权衡。
6. **Agent 基础篇**：建立基于工具调用的规范协议，拆解 ReAct 推理-行动循环，掌握单智能体状态机与死循环跳出条件。
7. **Agent 工程篇**：针对多步骤任务，实现计划-执行架构、状态持久化、会话中断恢复以及多智能体协作的消息路由。
8. **大模型应用系统篇**：搭建生产级 API 网关，设计长会话的滑动窗口与摘要机制，处理服务端流式传输（SSE）与多级语义缓存。
9. **部署与推理优化篇**：量化分析预填充（Prefill）与解码（Decode）阶段的性能瓶颈，推导 KV Cache 显存占用，掌握 INT8/FP8 量化与连续批处理（Continuous Batching）调度。
10. **评估、安全与综合实践篇**：构建测试集分级评估幻觉与准确率，搭建输入输出护栏系统，并进行全链路压测与故障排障演练。

### 单讲学习标准与推导演练

课程中的每一讲都遵循一致的学习逻辑：**明确输入与目标 → 运行过程推导 → 最小代码或算例验证 → 边界与失效分析**。

这里以自回归推理时的显存计算为例，展示如何通过量化推导建立认知。

在生成文本时，为了避免在每一步重复计算已有 Token 的 Key 和 Value 向量，推理引擎会将已生成的中间结果保存在显存中，这就是 KV Cache。在标准的多头注意力（MHA）配置下，单次请求的 KV Cache 显存占用满足如下公式：

$$\text{Memory}_{\text{KV}} = 2 \times n_{\text{layers}} \times n_{\text{heads}} \times d_{\text{head}} \times L_{\text{seq}} \times b_{\text{elem}}$$

* **$2$**：分别存储 Key 和 Value 两组张量。
* **$n_{\text{layers}}$**：模型的 Transformer 层数。
* **$n_{\text{heads}}$**：注意力头数（假设 Key/Value 的头数与 Query 相同，即 MHA 架构）。
* **$d_{\text{head}}$**：每个注意力头的特征维度。
* **$L_{\text{seq}}$**：当前请求累积的上下文总长度（输入 Token 数 + 已生成 Token 数）。
* **$b_{\text{elem}}$**：单个数值所占的字节数（如 FP16 或 BF16 精度下为 2 字节）。

**算例推导**：

假设运行一个 32 层（$n_{\text{layers}} = 32$）、32 个头（$n_{\text{heads}} = 32$）、头维度 128（$d_{\text{head}} = 128$）的模型，采用 FP16 精度（$b_{\text{elem}} = 2$ 字节）。

每增加 1 个 Token，该请求需要额外占用的 KV Cache 显存为：

$$\text{单 Token KV 缓存} = 2 \times 32 \times 32 \times 128 \times 2 = 524,288 \text{ 字节} = 512 \text{ KB}$$

当单个请求的上下文长度达到 $L_{\text{seq}} = 4096$ 时，仅该请求的 KV Cache 就需要：

$$4096 \times 512 \text{ KB} = 2,097,152 \text{ KB} = 2 \text{ GB}$$

**边界与工程推论**：

1. 如果显卡显存为 24 GB，FP16 模型权重占用约 14 GB，在忽略 CUDA 上下文常驻与瞬时激活值显存的理论假设下，留给 KV 缓存的可用空间约为 10 GB。若每个并发请求的上下文长度均达到 4096 Token（单请求约占用 2 GB），系统理论上最多支撑 5 个并发，超出该并发量就会引发显存溢出（OOM）。
2. 若模型架构采用分组查询注意力（GQA，如将 32 个 Query 头分为 8 组，KV 头数缩减为 8），则相同长度下的 KV Cache 占用直接降至原本的四分之一（约 0.5 GB），并发承载力将提升约 4 倍。

通过这种具体的算例，读者可以直观理解技术选型的依据，而不是单纯记忆抽象概念。

### 正向系统学习与逆向排障检索

阅读与使用本课程支持两种方式：

* **正向体系学习**：按照“基础 → 训练/对齐 → Prompt/RAG → 推理/应用 → 评估”的顺序阅读。每一步扩展都建立在前置计算原理清晰的基础上，适合系统搭建知识体系。
* **逆向排障检索**：当实际项目中遇到故障时，从现象反查原因。例如生产环境报告“智能体执行到第 5 步时输出乱码且延迟翻倍”，回溯路径为：应用网关历史消息拼接过长 → 触发推理模块的 Prefill 计算激增与上下文截断 → 需回到基础篇检查位置编码支持范围与 Prompt 模块的角色清理逻辑。

### 课程体系与延伸练习说明

为了保持学习路径清晰，所有内容分为主干课程与延伸练习：

1. **系统主讲（100 篇）**：承载模块核心骨干，包含完整的机制说明、计算公式推演与最小可复现用例。文章结构统一，覆盖从原理到落地的完整路径。
2. **延伸补充练习**：针对特定硬件平台适配、细微数值稳定性测试等进阶主题，作为主讲篇目的附录提供，方便有余力的读者进一步探索，不增加主干阅读负担。
