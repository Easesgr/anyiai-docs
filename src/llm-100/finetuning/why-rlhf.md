在完成基础的监督微调（详见 [/llm-100/finetuning/sft-instruction-tuning.md](/llm-100/finetuning/sft-instruction-tuning.md)）后，开发者常会发现：哪怕模型在验证集上的交叉熵损失很低，面对自由的人机对话时，依然容易出现答非所问、过度迎合提问者错误前提、或在回答末尾无限堆砌客套话的现象。

监督微调（Supervised Fine-Tuning, SFT）教会了模型遵循基本问答格式，但无法高效表达“什么样的回答比另一个更好”这种具有相对性的人类主观偏好。人类反馈强化学习（Reinforcement Learning from Human Feedback, RLHF）正是为了连接离散 Token 预测与全局文本质量评价而建立的工程管线。

![从监督微调到人类偏好强化学习的演进全景](/images/content-rebuild/8564d5b902aeafb1/cover.png)

理解这一演进，需要先从监督微调优化目标的机制局限谈起。

## 1. SFT 的优化目标与机制局限

监督微调本质上依然沿用自回归语言模型的最大似然估计（Maximum Likelihood Estimation, MLE）。给定提示词 $x = (x_1, \dots, x_m)$ 与参考答案序列 $y^* = (y^*_1, \dots, y^*_n)$，微调的目标是最小化负对数似然：

$$\mathcal{L}_{SFT}(\theta) = -\sum_{t=1}^n \log P_\theta(y^*_t \mid x, y^*_{<t})$$

在训练过程中，模型预测第 $t$ 个 Token 时，前文上下文完全来自标准答案 $y^*_{<t}$，这被称为教师强制（Teacher Forcing）。这种单步最大化概率的设定存在三个核心问题：

### 暴露偏差（Exposure Bias）
在实际推理时没有标准答案作为前文，输入只能是模型前几步自主采样的预测 Token $\hat{y}_{<t}$。一旦模型在某一步采样到低概率或次优词，输入分布就会偏离训练分布。由于训练时未见过这种错误前文，误差会在自回归循环中迅速放大，导致后半段回答质量急剧下降。

### 惩罚“诚实拒答”导致幻觉
假设用户提问：“某罕见化学试剂在特定反应中的活化能是多少？”，如果预训练参数中缺乏该精确数值，而 SFT 训练集配有专家撰写的标准实验数值，那么模型如果输出“我不清楚该数值”，在真实标注 Token 处的交叉熵损失会非常大，从而遭受强烈的梯度反向惩罚。为了最小化训练损失，模型倾向于利用浅层词共现强行输出一个貌似合理的伪造数值。单步交叉熵在机制上抑制了模型主动表达不确定性的能力。

### 局部 Token 优化无法度量全局语义质量
两个语义完全相同但表述方式不同的回答，在逐词交叉熵计算中可能差异巨大；反之，一段行文流畅但核心事实全错的文本，可能逐词的条件概率都很高。人类对回答质量的评估基于整段文本的连贯性、有用性与安全性，无法切分为每个离散字符的独立对错。

## 2. 偏好对齐的目标：从绝对打分到成对比较

为了衡量生成文本的整体质量，Anthropic 提出了 Helpful（有用）、Honest（诚实）、Harmless（无害）的“3H”评价框架：

*   **有用性（Helpful）**：理解用户意图，解答清晰详实，不敷衍兜圈。
*   **诚实性（Honest）**：如实反映知识边界，不编造事实，面对未知敢于拒答或说明概率。
*   **无害性（Harmless）**：识别恶意诱导输入，拒绝违法违规或危险操作指导，拒绝时保持客观中立。

![HHH 三维目标的相互制约与标量偏好映射示意](/images/content-rebuild/8564d5b902aeafb1/fig-2.png)

### 为什么选择成对比较（Pairwise Ranking）
如果直接让人类标注员为单个回答打出绝对分数（如 1 到 10 分），不同标注员的评分基准差异很大：宽松者可能普遍给 8 分以上，严苛者给 5 分以下，数据方差极高。

相比之下，人类对相对好坏的判断具备很高的一致性。针对同一个问题 $x$，提供两个候选回答 $y_w$（获胜样本，Winner）与 $y_l$（落败样本，Loser），标注员能够稳定判断 $y_w$ 是否优于 $y_l$（记作 $y_w \succ y_l$）。RLHF 的第一项核心任务，就是将这种相对偏好转化为连续可微的标量奖励信号。

## 3. RLHF 的三阶段标准流程

以 InstructGPT / PPO 体系为代表的经典 RLHF 包含三个阶段：

![RLHF 完整三阶段串行工程管线与数据流动图](/images/content-rebuild/8564d5b902aeafb1/fig-3.png)

1.  **阶段一：监督微调冷启动（SFT）**
    *   **输入**：精心清洗的指令问答对。
    *   **作用**：让基座模型适应指令交互格式。若跳过此阶段直接在基座模型上进行强化学习，模型的动作空间（数万个词表 Token）探索效率极低，难以采样出通顺的候选文本。
    *   **产物**：SFT 模型 $\pi_{SFT}$。
2.  **阶段二：偏好数据标注与奖励模型（RM）训练**
    *   **输入**：从提示词池采样 $x$，由模型生成多个候选响应，由人工或评估模型进行优劣成对排序，构造偏好数据集 $\mathcal{D} = \{(x, y_w, y_l)\}$。
    *   **作用**：训练一个标量奖励模型 $r_\theta(x, y)$，充当自动化、可微分的人工评分代理。
    *   **产物**：训练好的奖励模型参数 $\theta$。
3.  **阶段三：近端策略优化强化学习（PPO 微调）**
    *   **输入**：大规模未标注的提示词池，以及阶段一的 $\pi_{SFT}$ 和阶段二的 $r_\theta$。
    *   **作用**：策略模型生成完整序列，奖励模型给出终局标量分数，通过策略梯度与 KL 散度约束更新模型参数。
    *   **产物**：最终对齐后的对话模型 $\pi_\phi$。

在工程实践中，奖励模型的参数规模不一定与策略模型一致。虽然出于显存与吞吐考虑有时会尝试轻量级奖励模型，但若奖励模型容量显著落后于策略模型，更容易被策略模型生成的复杂伪造文本所欺骗（诱发奖励黑客）；因此主流实践中奖励模型通常与策略模型保持相当参数量，或采用更高能力基座训练。

## 4. 奖励模型的数学建模：Bradley-Terry 模型

奖励模型 $r_\theta(x, y)$ 通常采用与 SFT 模型相同结构的 Transformer，移除了原有的词表生成头（LM Head），替换为一个输出标量数值的线性层（Scalar Head）。

### Bradley-Terry 偏好概率
给定问题 $x$ 以及成对回答 $(y_w, y_l)$，Bradley-Terry 模型假定人类偏好后验概率由两个回答的标量差值经 Sigmoid 映射决定：

$$P(y_w \succ y_l \mid x) = \sigma\left(r_\theta(x, y_w) - r_\theta(x, y_l)\right) = \frac{1}{1 + e^{-\left(r_\theta(x, y_w) - r_\theta(x, y_l)\right)}}$$

### 奖励模型损失函数
通过最小化负对数似然，损失函数定义为：

$$\mathcal{L}_{RM}(\theta) = - \mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\left( r_\theta(x, y_w) - r_\theta(x, y_l) \right) \right]$$

![Bradley-Terry 奖励模型结构与成对反向传播机制](/images/content-rebuild/8564d5b902aeafb1/fig-4.png)

### 数值算例与梯度推导
假设输入如下数据：
*   **提示词 $x$**：“如何泡一杯好绿茶？”
*   **回答 $y_w$**：“建议水温 80-85℃，选用玻璃杯，先注水后投茶……”（逻辑严密、参数具体）
*   **回答 $y_l$**：“用 100℃ 沸水泡两个小时喝就行。”（存在水温与时间常识错误）

计算过程如下：
1.  **前向传播**：奖励模型对两个序列分别计算标量，假设输出 $r_\theta(x, y_w) = 1.20$，$r_\theta(x, y_l) = 0.80$。
2.  **分差与偏好概率**：
    $$\Delta r = 1.20 - 0.80 = 0.40$$
    $$P(y_w \succ y_l) = \sigma(0.40) = \frac{1}{1 + e^{-0.40}} \approx \frac{1}{1 + 0.6703} \approx 0.5987$$
3.  **损失计算**：
    $$\mathcal{L}_{RM} = -\log(0.5987) \approx 0.5130$$
4.  **对标量输出求导**：利用对数 Sigmoid 的导数性质 $\frac{d [-\log \sigma(z)]}{dz} = \sigma(z) - 1$：
    $$\frac{\partial \mathcal{L}_{RM}}{\partial r_\theta(x, y_w)} = \sigma(\Delta r) - 1 = 0.5987 - 1 = -0.4013$$
    $$\frac{\partial \mathcal{L}_{RM}}{\partial r_\theta(x, y_l)} = 1 - \sigma(\Delta r) = 0.4013$$

沿梯度下降方向更新参数时，获胜样本的梯度为负，使模型参数向推高 $r_\theta(x, y_w)$ 的方向调整；落败样本的梯度为正，使模型参数向压低 $r_\theta(x, y_l)$ 的方向调整。当两者分差极大（例如 $\Delta r = 5.0$ 时，$P \to 0.993$），梯度趋于 0，更新进入平缓饱和区。

## 5. 强化学习策略优化与 KL 散度约束

在完成奖励模型训练后，进入第三阶段策略微调。将文本生成映射为马尔可夫决策过程（MDP）：
*   **状态 $s_t$**：输入提示词与已生成的 Token 序列 $(x, y_{<t})$。
*   **动作 $a_t$**：当前步采样的词表 Token $y_t$。
*   **状态转移**：拼接当前 Token 构成下一步状态。
*   **奖励 $R$**：在生成结束符（`<eos>`）处，由奖励模型 $r_\theta(x, y)$ 输出整体得分。

如果优化目标仅为最大化奖励模型得分 $\max_\phi \mathbb{E}_{x, y \sim \pi_\phi}[r_\theta(x, y)]$，策略模型会迅速出现严重退化。

### 奖励黑客（Reward Hacking）
奖励模型只是在有限标注数据上拟合的近似函数。当策略模型通过强化学习不断探索时，会寻找奖励模型权重分布中的漏洞，表现出非泛化的作弊行为：
1.  **长度膨胀与客套堆砌（Verbosity Bias）**：模型发现无论回答内容如何，只要在结尾堆砌极度谦卑的感谢词或强行输出长篇排比段落，奖励模型的线性层就会倾向于打高分。
2.  **对抗乱码**：生成包含特定生僻词组合或乱码文本，正好命中了奖励模型在未覆盖区域的高分盲区，导致输出严重偏离正常语言语法。

### KL 散度惩罚机制
为了防止策略模型漂移（Policy Drift），RLHF 在奖励函数中引入了相对于初始冻结模型 $\pi_{ref}$（通常为阶段一完成的 $\pi_{SFT}$）的 KL 散度惩罚：

$$\max_\phi \mathbb{E}_{x \sim \mathcal{D}_{prompt}, y \sim \pi_\phi(\cdot \mid x)} \left[ r_\theta(x, y) - \beta D_{KL}\left(\pi_\phi(y \mid x) \parallel \pi_{ref}(y \mid x)\right) \right]$$

其中 $\beta > 0$ 为惩罚系数。在序列逐步实现中，通常将该惩罚拆解到每个生成的 Token 上：

$$r_{step}(s_t, y_t) = \begin{cases} - \beta \left( \log \pi_\phi(y_t \mid s_t) - \log \pi_{ref}(y_t \mid s_t) \right), & y_t \neq \text{<eos>} \\ r_\theta(x, y) - \beta \left( \log \pi_\phi(y_t \mid s_t) - \log \pi_{ref}(y_t \mid s_t) \right), & y_t = \text{<eos>} \end{cases}$$

![KL 散度作为安全边界防止奖励黑客的对比剖析](/images/content-rebuild/8564d5b902aeafb1/fig-5.png)

只要策略模型 $\pi_\phi$ 预测某 Token 的对数概率显著高于参考模型 $\pi_{ref}$，即时惩罚就会变大，迫使模型在追求更高偏好分的同时，文本分布始终约束在自然语言基准附近。

## 6. 系统显存开销与机制边界

基于 PPO 的标准在线训练链路工程复杂度很高，其主要瓶颈在于多模型协同部署时的显存占用与通信同步。

![PPO 在线训练阶段四模型实例交互拓扑与显存占用](/images/content-rebuild/8564d5b902aeafb1/fig-6.png)

### 四模型实例的状态与显存构成
在标准的分布式 PPO 训练中，集群中通常需要维护四个模型角色：
1.  **Actor（策略模型 $\pi_\phi$）**：处于训练态。负责自回归生成文本采样，并接收 PPO 策略梯度反向传播。显存包含模型参数、梯度、Adam 优化器状态（一阶动量与二阶动量，通常各占 4 字节/参数）以及反向传播所需的激活值。
2.  **Critic（价值模型 $V_\psi$）**：处于训练态。输入状态 $(x, y_{<t})$ 估计期望未来回报基线，用于计算广义优势估计（GAE），需要持续根据 TD 误差反向更新。显存同样包含参数、梯度、优化器状态和激活值。
3.  **Reference Model（参考模型 $\pi_{ref}$）**：处于冻结态。仅用于在前向推理中输出各步对数概率以计算 KL 散度，不需要梯度与优化器显存。
4.  **Reward Model（奖励模型 $r_\theta$）**：处于冻结态。仅在序列生成完成后前向计算标量奖励，同样不占用梯度与优化器显存。

尽管工程上可通过参数共享、LoRA 轻量微调或 Offload 技术降低显存占用，但多角色交叉推理与前向/反向通信交替仍显著提升了调度难度。

### RLHF 的能力边界
1.  **无法凭空注入新知识**：RLHF 是一种输出分布整形机制，并非知识记忆机制。它调整的是已有知识的激活概率与表达风格。如果模型基座在预训练阶段从未学过某专业定理的推导，强化学习无法无中生有使其学会该推导，强行拉高格式奖励只会让模型学会格式工整地伪造推导。
2.  **继承与放大标注偏差**：奖励模型只能拟合成对标注数据中的偏好。如果标注团队更偏好冗长、套话多或结构排比对称的文本，模型最终就会被训练成冗长谄媚的生成器。

为了简化这一工程流程并消除独立训练奖励模型的高昂开销，后续发展出了直接基于离线偏好数据优化策略的直接偏好优化方法（详见 [/llm-100/finetuning/dpo-vs-rlhf.md](/llm-100/finetuning/dpo-vs-rlhf.md)）以及多维度对齐评测指标（详见 [/llm-100/finetuning/evaluate-finetuned-model.md](/llm-100/finetuning/evaluate-finetuned-model.md)）。

## 7. 读者自测与实战检验

请结合文中所述机制完成以下自测：

### 检验问题
1.  **知识边界与似然损失**：在标准 SFT 阶段，面对基座模型未曾见过的生僻专业事实，如果训练集给出的标准答案是详细的学术解答，为什么模型输出“我不清楚该事实”会遭受严重的梯度惩罚？这种机制与模型在部署时产生幻觉有何关联？
2.  **KL 散度系数设为 0 的后果**：在基于 PPO 的强化学习阶段，如果将 KL 散度惩罚系数 $\beta$ 设为 0，策略模型在经过多轮迭代后通常会出现什么典型失效现象？其数学驱动力是什么？

---

### 参考答案
1.  **解答**：SFT 的损失函数是基于参考答案 Token 的负对数似然 $-\log P_\theta(y^*_t \mid x, y^*_{<t})$。当参考答案是详细解答时，其包含的具体学术词汇构成了真实的标签序列。如果模型尝试输出“我”、“不”、“清楚”，这些 Token 与标准答案的实际 Token 完全不匹配，在真实 Token 处的预测概率 $P_\theta(y^*_t)$ 极低，导致负对数似然损失极大，产生强烈的反向修正梯度。这种单步逐词强行对齐的惩罚机制迫使模型在面对不懂的提问时学会猜测词汇共现，从而埋下了部署时胡编乱造的幻觉隐患。
2.  **解答**：当 $\beta = 0$ 时，环境奖励仅剩下奖励模型的标量打分 $r_\theta(x, y)$。此时优化器会通过策略梯度极力最大化该标量，由于奖励模型只是一个在有限数据上拟合的神经网络，存在大量高维对抗盲区。策略模型会迅速发生策略漂移，出现“奖励黑客”现象：生成大量冗长套话、无实质内容的客套道歉或特定生僻字符乱码，以此触发奖励模型的高分权重，导致文本丧失正常的语言语法与语义连贯性。
